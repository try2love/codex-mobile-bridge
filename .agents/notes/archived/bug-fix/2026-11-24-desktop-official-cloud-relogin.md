# Agent Note: 旧官方云账号可直接重登新入口

Status: implemented
Archived: 2026-11-25

## Problem

桌面更换官方预设后，已配置账号仍拥有原来的精确 origin。网络页把它当作正常的自定义账号，隐藏登录入口，并继续读取旧网页地址和设备目录。用户必须先退出，才能看到新的官方入口。

## Decision

桌面只对已保存的旧官方中继 origin `https://bridge.waken.cloudns.be:8787` 显示新地址和「重新登录」，不再由面板读取这个旧账号的网页地址或设备目录。旧 origin 只用于识别历史配置，不作为自动回退地址。全局语言刷新不会覆盖迁移提示。打开和关闭表单不写配置，仍保留单独的本地退出操作；重登本身不依赖退出或访问旧站。

重登和找回密码锁定 `https://bridge.apijr.xyz`，不开放账号注册或切服。桌面在提交前核对显示的旧作用域，复用已有的 TLS 登录和网关登记；当前状态的 origin、账号及网关均匹配登录回执才显示成功。旧请求迟到不能覆盖已显示的其他账号，失败不自动重放。原生凭据库仍按精确 origin 分桶，旧令牌、密钥、手机许可和网页许可不复制。自建地址和直连不参与迁移。

## Existing decisions reviewed

- [官方服务默认值](../feature/2026-11-01-official-cloud-default.md)和[登录模态框](../feature/2026-11-01-cloud-login-dialog.md)部分重叠。保留预设和表单规则，只替换旧官方账号必须先退出的步骤。
- [赞助二维码和网页地址](../feature/2026-11-11-sponsor-dialog-and-web-address.md)部分重叠。正常账号仍从当前服务读取网页地址，面板不再读取已停用的官方入口。
- 邮箱验证、赞助资格、默认主机名及独立接入实例不决定官方域名迁移，不改动这些决定。

## Alternatives considered

- 自动退出旧账号最容易复用现有登录界面，但打开页面就会写盘，并可能等待已下线服务的退出请求。
- 就地替换登录状态的 origin 可以免输密码，但会让新域名继承旧信任，违反凭据和授权按 origin 隔离的规则。

## Testing

- `npm run test:desktop` 通过 1,882 项、跳过 1 项；四种 Chromium/WebKit 宽窄视口共 188 项通过。覆盖旧域离线、无需退出、全局翻译重绘、提交失败、迟到登录或状态回执以及相似自建地址。
- 43 项 Python 云账号测试通过。合成登录保持同一账号 ID，但只在新 origin 发送新凭据，生成独立的网关与密钥，旧凭据、绑定文件和网页许可未改。
- Mac arm64 Local 包通过签名、公钥、内置网关 TLS 和实际 Electron 窗口检查。窗口使用隔离的旧账号资料，只验证展示、打开和取消，不提交真实登录。覆盖 `/Applications/Codex Mobile Bridge Local.app` 时复用逐字节相同的网关；只重启界面，网关 PID、实例、三个直连入口与隧道就绪状态不变，当前新域登录配置及资料摘要一致。证据在 `.tmp/desktop-official-relogin-20261124/`。

## Consequences

旧服务离线也能进入新官方登录，不需要先写入退出状态。代价是桌面保留一个精确的迁移识别值；显式登录成功前，网关仍持有原配置，不清理旧域凭据记录或声称撤销远端授权。已经切到新域的本机不需重登。真实旧账号的重登录和手机扫码不由合成测试代验。
