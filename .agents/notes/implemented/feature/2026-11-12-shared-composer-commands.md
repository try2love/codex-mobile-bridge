# Agent Note: 共享输入框斜杠动作菜单

Status: implemented

## 问题

#154 希望输入 `/` 后选择聊天指令。原输入框将这类文字交给普通发送流程，无法直接进入现有模型、权限、Skill 和聊天管理界面。安装的 Codex App 将这些项目注册为前端动作；原生 TUI 也有独立 slash dispatcher，不能假设所有 `/xxx` 都是模型或 app-server 协议。

## 决策

共享 `ComposerCommands` 只为现有功能提供输入入口。主 Codex 和 `DesktopSessionsView` 使用同一组件，原生侧边聊天转入同一控制器后自然复用。模型、思考强度、权限、Skill、上下文、模式直接使用当前控件的能力和禁用状态；重命名、归档、删除等打开原有会话菜单页面。压缩仍需在现有上下文弹窗确认，不直接提交新 RPC。

`/plan`、`/goal`、`/default` 选择工作模式，附带文字保留在输入框，仍需明确发送。已知但不可用的指令不能落入普通发送；未知自定义指令和 `/Users/...` 等路径继续原有处理。菜单支持中文搜索、方向键、Enter、Tab 和 Esc；输入法确认不执行指令。点击时重新核验当前会话、入口、账号和能力，旧菜单不能操作新聊天。只消费输入框中的指令片段，不调用附件、引用或历史清空操作。

本批不声称复刻原生全部命令。MCP、原生分享、记忆、桌面伙伴、审查和初始化等没有接入现有功能的项目不加入菜单；动态 Skill 通过现有 `/skills` 选择器使用，沿用原目录和缓存。

## 备选方案

把斜杠文本直接发给模型无法可靠执行本地动作，也可能误发管理指令。复制一套模型、权限和会话管理页面会分叉确认规则与缓存，故使用现有控件和菜单。

## 影响

只改共享前端、两个控制器挂接、会话菜单初始页面参数和资源组合，不新增后端或客户端协议。中文菜单统一简体；指令名称保留可输入的英文标识。

六项新 Node 检查及二十项会话菜单回归通过；静态 URL 和资源映射检查通过。真实 Chromium 中生产资源启动成功，两个控制器均实际绑定组件，输入法、键盘、草稿、能力失效、跨会话迟到点击及路径保留等检查通过。全量相关旧界面检查中仍有十四项失败：十一项旧文件夹具缺少新宿主路径契约，三项旧发送夹具未声明能力；另行验证修正，不能将该组全称为通过。最终安装包及手机仍待后续验收。

原生实现对照：已安装 App `26.1106.51428` 的 slash 注册动作，以及[官方 TUI slash dispatcher](https://github.com/openai/codex/blob/main/codex-rs/tui/src/chatwidget/slash_dispatch.rs)。未操作正式 App 或调用模型。
