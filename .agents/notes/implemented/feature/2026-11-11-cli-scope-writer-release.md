# Agent Note: 按本机 CLI 配置释放原生写入者

Status: implemented

## 问题

同一 Codex home 的多个连接共用原生 daemon。逐行退订不能证明 writer 已解除；逐行退出又会对同一个服务重复操作。“全部释放”还必须限定当前主机、用户和配置，不能把其它 home 的连接一起结束。

## 决策

当前连接按 Codex family、注册主机、真实 home 和用户身份生成稳定的 `scopeKey`。POSIX 使用有效 UID，Windows 使用当前令牌 SID；PID、出生代次和连接 token 不放入分组 ID。当前连接与历史操作分别返回，重启服务不产生另一个配置组，旧成功回执也不删除或断开新连接。

既有 CLI 连接端点增加 `scopePreview`、`scopeWait`、`scopeForce` 和 `scopeCancel`。预览选择当前范围内单条或全部连接，返回具体连接键、整个 home 的已知影响及未列出任务的提示。确认摘要另绑定主机/home、原生代次、配置、保存会话身份和连接键；确认时和退出前重新核验。预览只读，不订阅、接续、启动或停止原生会话。

默认释放沿用现有释放 worker、五秒等待节流和同 home 维护账本。整个范围只派发一次正常退出，全部任务、审批、后台终端、Goal、已接受队列和未知业务结果均保留安全检查。任务繁忙或无法读取时等待，取消只作用于未派发的等待；关闭网关也取消自身未派发的 scope 等待。最后派发检查与取消使用原维护锁。配置或身份改变会结束该等待，要求重新预览。

worker 的 `releasing` 展示状态不代替派发证据：缓慢只读检查期间公开取消入口仍交由最终维护检查裁决。等待其它维护的请求只撤销自己的 worker 和取消标记，不改写其它操作的 home 回执；随后即使其它维护结束，也不能接着派发这个已取消请求。进入退出检查点后才拒绝撤回，并保留真实或未知退出结果。

正常退出复用原 `graceful_only` 平台通路与最终闲态核验；只有原生 writer 退出才报告 `released`。单条选择如需退出整个服务，也在同一预览中明确其它连接的影响。新的明确 `scopeForce` 意图复用[已核验代次的显式强制](2026-11-11-cli-explicit-force.md)，可以升级整个范围的等待或未知结果；旧未知业务不重放，旧操作结果保留。相同请求 ID 只返回回执，并发相同确认也只建立一个 worker。

本点接入可直接核验的本机默认与独立 Codex home。SSH/WSL 的稳定范围字段和回调采用相同合同，但目标端生命周期控制另行补齐；不以本机信号或退订冒充远端 writer 已释放。Claude 独占 stdio 执行器的释放与强制另行处理。

## 备选方案

将 daemon 代次放进 `scopeKey` 容易直接阻止旧确认，但每次重启都会出现重复配置组；代次和连接键独立进入确认摘要。继续逐行退出可以复用旧循环，却会对同一共享 writer 重复派发，因此同范围聚合为一次已有维护操作。全局修改卸载延迟或把退订当卸载都不能保证现有后台任务与 writer 的语义。

## 验证

独立 SQLite 与受控原生回归覆盖稳定分组、错误用户/主机/范围、单条影响包含其它连接、全范围仅一次正常退出、busy/unknown 等待后自然完成、配置变化、最终检查取消、未知释放的网关重启核验、旧回执不影响新连接、新 force 升级整组且保留未知业务、并发同 ID 仅一个 worker。既有单条释放与显式强制定向回归通过。

公开 `CliConnections.submit(scopeCancel)` 并发回归还覆盖阻塞只读检查时取消成功、退出检查点后拒绝撤回，以及等待另一个 waiting/unknown 维护时取消自身且原账本字节语义保持。

macOS 已安装原生 0.167.0 的隔离 home 实测：两个 CLI 连接中一个运行回环合成 turn；独立原生 stdio 执行器在释放前被 active writer 拒绝。单条预览和全部预览都列明两个连接，默认等待不打断任务。放行合成响应后仅正常退出一次，所选两条均报告已释放；另一独立原生执行器随后能 resume 两个原 ID，cwd/provider 不变。重复确认没有再次退出，scopeKey 在原代退出后不变。一次模型 POST 仅到回环替身、零付费；daemon 和两个独立执行器均确认退出。证据 `.tmp/feedback-20261111-10/cli-scope-release-native-result.json`。前两次夹具分别因客户端来源名、stdio 与 proxy 传输混淆而未进入释放，失败记录单独保留且自有 daemon 正常退出。

该实测证明原 writer 已解除、另一原生执行器可接管；实际 Codex App UI 接管仍由最终包与固定样本验收完成，本点不操作正式 App 或固定样本。Windows SID 分组复用现有令牌 SID/字符串转换原语，Windows 平台正常排空与强制证据沿用先前独立验收，本点没有宣称完成 Windows scope 端到端实测。

## 影响

调用者可以明确释放一个本机 Codex 配置的原生占用，并得到同范围全部所选连接的真实结果；默认任务保护和原 provider/auth/cwd 保留。历史 `wait/stop/unload/check/force` 请求与回执仍可读取，新的 scope 操作不会将其它主机或配置混入当前“全部”。
