# Agent Note: 根据原生来源折叠注入上下文

Status: implemented

## 问题

Harness 把用户输入和插件注入内容都记录为 `user/message`。只根据事件类型渲染会把工作区指令等上下文当成普通用户发言。

## 决策

DSH 适配器依据原生 `message.source.kind` 转换内容：明确且非 `user` 的生产者来源输出共享活动消息，`kind=context`、标题为上下文；`user` 或来源缺失时保持旧用户消息显示。正文和稳定消息标识保持原样，不根据正文中的标签或关键词猜测来源。

界面复用已有活动折叠组件，默认折叠，展开后刷新仍保留展开状态。其他 Agent 将来可以输出同一规范化内容，无需增加提供方分支。图片引用也保留原生会话绑定。

刷新时的节点更新和正文内部滚动保留遵循[共用聊天阅读状态](../bug-fix/2026-10-30-shared-chat-reading-state.md)，不在提供方页面内另写一套恢复规则。

## 备选方案

按 context 标签折叠更容易适配旧日志，但可能误折叠用户自己输入的文本，因此只信任原生来源字段。另建 DSH 专用折叠 UI 可以定制外观，但与现有过程展示重复，因此不采用。

## 测试

解析测试覆盖用户来源、缺失来源、工作区指令及未知插件来源，确认正文不变。界面测试覆盖默认折叠与刷新保留展开。相关图片/上下文解析 5 项及桌面 UI 166 项通过。

## 影响

仅改变已识别注入上下文的展示形式，不删除原文、不影响模型输入或普通用户消息。原生来源缺失的旧日志保持现状。检索上下文和折叠记录后，既有 Claude 上下文用量记录属于计量语义，无重叠；未替代任何历史决定。
