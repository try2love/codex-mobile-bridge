# Agent Note: CLI 跟随同一原生配置的账号与接入

Status: implemented

## 问题

原工具在同一 CODEX_HOME 更新账号、API 注入或提供商后，运行中的 CLI 可能仍使用原缓存与客户端配置。读取当前磁盘内容或看到原生账号类型相同不能证明已同步。用户显式继续或发起新工作时，应优先沿用已生效的原生接入；需要重建时安全等待，且不能把别的配置或网关进程的账号当作新来源。

## 决策

本机 CLI 来源的显式继续与新执行入口核对原主机、home、运行代次、当前配置和保存的会话身份。APP 来源与 IDE 的既有接入边界保持不变；读取历史或通知不触发维护。独立本机配置只跟随自己的原生账号，SSH 和 WSL 不借用本机账号。已运行任务的停止和审批沿原连接，异步问题卡答复需先重验原请求和内容。已明确接受的旧排队工作仍按原队列完成，不转交新账号或重发。新排队和补充在实际派发前核验新接入，任务刚变为空闲也不跳过。新请求发现接入尚待同步时保留未发送状态，不把草稿加入发送账本。

已核验的同 home 文件账号如果已被该代原生缓存采用，直接接续，不改文件或重建。API 比较实际缓存凭据，ChatGPT 比较原生登录的账号与用户身份；`getAuthStatus` 的认证数据只在内存中比较，错误输出不包含认证值。网关没有内存基线时，同代服务启动之后的文件变化也是变更证据；核验失败不使用旧缓存派发新操作。缓存仍旧、同 ID 接入定义变化或原生支持的提供商切换需要重建时，沿用[原待闲事务](2026-11-11-cli-recovery-waits-for-idle.md)，后台只继续发起会话，不发送该次消息。旧目标等待期间认证或配置再变化，旧事务失效；下一次显式继续按最新已核验配置重新进入。不重复退出或未知写入。

重建不改原生 auth/config，只采用该 home 已核验的文件认证或原生服务可核验的注入变量，不使用网关的默认值。文件认证启动时清除会覆盖它的 OPENAI/CODEX 注入；显式 provider 环境变量只采用同一旧代提供的值，缺失则拒绝。已成功释放的原会话可在相同 provider ID、可核验新文件认证下正常冷接续；原释放代次、操作与配置摘要保留，启动前写入原 `starting` 回执，启动后核验新认证。不能核验的写入、不同提供商或其他配置仍不借用旧凭据启动。

Codex 0.164.0 支持经身份校验的原生冷 `thread/resume` provider override；[0.167.0 的原生准入](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/app-server/README.md#model-provider-admission)要求保存与当前 provider ID 一致，即使接口仍有 `modelProvider` 字段。0.167 不执行注定失败的重建；已收到原生 `modelProviderMismatch` 时保留结构化只读原因，可在原工具选回原提供商，历史和未发送内容保留。网关不改原生账本、不借别名绕过，也不替用户创建新聊天。同 ID 的认证或端点变化仍可跟随。

## 备选方案

`account/login/start(apiKey)` 能更新原生缓存，但会写入共享认证并可能取消原登录；保留它用于[明确选择的受管同路由 API 同步](../bug-fix/2026-11-10-managed-cli-auth-sync.md)，不以它自动覆盖外部认证。`refreshToken` 不重读缓存的 API Key；调用不存在的 reload RPC 也无法保证生效。静默改原会话记录或自动 fork 不能保留原生准入与相同 ID，因此不使用。

## 验证

124 项恢复、账号同步和释放定向回归通过。覆盖已生效认证不重建、A→B 待闲且原草稿未发送、B 等待时 C 使旧事务失效、真实 RPC 错误结构转只读、认证错误不外泄、运行任务的停止控制、同 home 注入及独立/SSH/WSL 隔离、成功释放后同 provider 的新认证冷接续。评审修正先复现网关无基线时认证探测失败被放行，以及运行中新 queue/steer 绕过检查；修后拒绝且无原生派发、无新账本。已有异步答复仍可由原任务接收，新消息在活跃转空闲交错中仍不能绕过核验。另有 6 项本机/远端发送与 Goal 的受影响回归通过。

扩大回归时另发现，旧的文件认证夹具在运行状态提交普通发送，只能验证运行中发送模式的拒绝。修正后模拟网关已记录当前文件摘要而同代原生缓存仍旧，使用运行状态允许的补充模式。新补充经过认证校验后被拦截，不写发送账本；旧任务停止仍调用原连接，CLI 服务未退出。

已安装 0.167.0 的隔离零回合检查证明：合成 API Key 换文件后普通读取和 refreshToken 都仍返回旧缓存，显式 API login 会改写文件并更新缓存；provider ID A→B 后原生拒绝 override 并给出 `-32600/modelProviderMismatch`，原历史可读。同 ID 换端点可冷接续。网关隔离验证则在 0.167 用同 ID 采用新认证与端点，在本机已有 0.164 用原生 override 采用新 provider，均同 ID/cwd、一次原生 resume、未写 auth/config、无模型回合和付费请求，所有自有进程正常退出。证据为 `.tmp/feedback-20261111-10/cli-auth-provider-native-result.json`、`cli-account-follow-native-result.json`、`cli-provider-override-164-result.json`。

## 影响

同一原生配置在显式操作时可以采用可信的当前接入，而不会让被动页面激活聊天。需要重新创建原生客户端时要等本配置的工作结束；新的消息仍需用户送出。自动重建限已核验正常退出能力的 macOS/Linux 本机 CLI，Windows 未扩展退出通路。系统钥匙串、不明来源、原生未核验的版本或其他主机不推断文件可用。0.167 的跨 provider ID 同会话限制仍由上游决定；真实 OAuth 换账号、实际模型请求及 Windows/Linux 包验收不属于本次原生夹具证据。本点不启用自动代理跟随或强制恢复。
