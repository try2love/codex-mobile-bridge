# Agent Note: 当前项目文件和目录引用复用工作台

Status: implemented

相对 Markdown 草稿和中间附件对话框的决定已被[原生项目附件修复](../bug-fix/2026-10-29-native-project-attachments.md)部分替代。下文保留当时的理由与验证范围；项目内访问边界和复用文件页继续有效。

2026-11-12 用户通过 #160 授权[只读宿主机目录导航](2026-11-12-host-file-navigation.md)，替代下文对文件页只读浏览的项目限制；发送引用、上传和 Git 仍保留原项目范围。

## 问题

用户希望在手机聊天中引用电脑文件和目录，并从消息进入文件页或预览。已有文件标签页、服务端目录边界、图片预览与文件菜单，不需要再建立一套宿主文件浏览器。

## 决策

用户明确限制本轮只支持当前会话项目。聊天回形针提供“从本机上传”和“引用宿主机项目文件”。后者直接复用工作台目录列表与元信息接口，选择文件或当前文件夹，不下载内容；原有文件子页的“引用到消息”也保留。两个入口都重新读取文件元信息，核验会话仍是原会话，将转义后的相对 Markdown 链接追加到现有草稿，展开输入区，不自动发送。Codex、Claude 与 DSH 复用相同组件；输入禁用或会话切换时不插入。

原生历史中的用户文本链接及 Files mentioned 原生附件头纳入现有文件引用索引。附件元信息保留完整路径，名称按路径精确匹配获准文件，不按 basename 猜测。项目内名称打开现有下载阈值与定位菜单；项目外或已失效的名称点击后只显示短提示，不读取内容。用户链接仅授权项目根内真实文件和目录，不能借助 Codex visualizations 根或符号链接扩大访问范围。图片复用原预览与缩放功能。

## 备选方案

项目外文件引用覆盖更多场景，但需要额外目录授权，用户选择先不做。新增附件类型和上传电脑文件内容可改善模型附件标识，但会重复上传已在原会话项目中的文件并扩展协议，因此本轮采用明确路径引用。

## 影响

草稿保留原文、引用可编辑且只在用户发送时提交。不会上传文件副本，不创建新的文件权限。不保证每个模型都会自动读取引用文件；它收到的是项目相对路径。

定向验证包含项目文件、目录、中文与特殊字符、目录穿越、项目外 visualizations、符号链接逃逸、会话切换以及不自动发送。完整前端 1303 通过、1 项既有跳过；四布局浏览器 120 项通过。完整后端初跑 2818 项，出现两项旧契约断言：旧插件源码指纹与不识别用户文件链接；修正后相关 56 项通过，38 项平台夹具按源码模式跳过。

检索工作区定位、文件复制和原生历史图片笔记：均仍保留独立职责，本改动复用而不替代其决策；图片历史读取见 [共享原生历史图片](2026-10-29-shared-native-history-images.md)。

后续回形针补充验证覆盖直接选目录/文件、保留草稿、只请求元信息、会话切换和迟到响应、原生附件点击以及下载阈值。用户提供的旧 Excel 附件实际位于项目外，预期为短提示，不扩大访问范围。
