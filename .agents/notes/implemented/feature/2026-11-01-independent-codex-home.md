# Agent Note: 独立 Codex 配置接入

Status: implemented

## 问题

Issue #106 的独立 CODEX_HOME 中包含 VS Code 原会话。此前来源过滤排除了 codex_vscode，新增入口也不能绑定独立目录。只增加路径而不隔离入口、账号与执行身份，会混入默认历史或连接错误 owner。

## 决策

沿用 Codex 入口注册表，新增本机 codex-local 子入口，不增加 Agent 标签。桌面「添加接入 → Codex」提供浅层扫描、原生文件夹选择、手动输入。目录规范化后拒绝默认目录、别名和重复登记；保存设备与 inode 身份，路径替换后拒绝继续使用。配置管理仅走桌面已有 IPC，不增加远程任意目录配置接口。

每个入口复用同一 Bridge 类，以独立 home、账本、草稿身份和入口 ID 隔离。物理本机与展示入口分开：文件操作走本机共享实现，原生 IPC 的 hostId 仍为 local。Web 复用 Codex 页面、模型、Skill、项目选择器、权限、附件与 CLI 释放服务；选择独立入口时列表与新建请求只访问该入口，返回默认入口恢复原列表。

原 VS Code owner 在线时先跟随其连接；保存、扫描、列表和通知不会启动原生执行。只有明确确认 owner 缺席，用户主动继续时才连接或启动所选 home 的原生服务。超时及未知归属不启动第二执行器。Windows 单一共享管道中，重复 UUID 或其他目录不可读时拒绝推断 owner。独立入口不打开默认 Desktop，不提供默认账号切换；账号仍由原 VS Code / CLI 管理。

## 备选方案

- 合并所有目录到默认入口：界面简单，但入口身份与账号不清晰，也会使同 UUID 的历史混淆，放弃。
- 每个目录多开一个 Desktop：可借用现有窗口流程，但依赖 GUI 生命周期，与无头需求不符，放弃。
- 为 VS Code 复制聊天、附件、项目和释放逻辑：便于独立推进，但重复维护共性行为，放弃。
- 请求中覆盖卸载延时：理论上可以让独立无头会话快速交还写入者。实测安装的 0.162.1 对 thread/start、thread/resume 的此覆盖不生效，daemon start 的覆盖也没有改变结果，因此删除无效覆盖。
- 自动改写用户 config.toml 或停止共享服务：原生配置中的卸载延时实测生效，但这些办法会改变其他原客户端行为或影响任务，当前接入不采用。

## 影响

原生运行组件来自已有 Codex 安装；若独立 home 尚无 daemon 包，由 Codex 自己准备其原生组件，不引入 Node、Homebrew 或其他 App。IDE 未保存文件和编辑器即时上下文需要原 IDE 在线，无头恢复仅使用原生已保存会话。

独立 home 的 sqlite_home 指向其他目录时暂时明确拒绝登记，避免错误读取默认数据库。配置扫描只检查用户目录和默认 home 的同级 .codex* 目录，不递归扫描磁盘。

停用独立入口复用操作门，先排空已接受的写入；旧请求持有的对象在关闭后不能继续发送、上传、写文件或创建项目。默认入口的行为不变。

主动释放保留既有 released/detached 区分：取消订阅后网关不再自动接回，原 VS Code/共享服务客户端可继续；独立 codex exec 进程仍可能遇到原生写入占用，须等原生卸载。不能将 detached 宣称为写入占用已经释放。

## 验证

- 真实 VS Code 独立测试聊天，Luna / low：原 owner 接入身份一致；网关取消跟随后，原 VS Code 成功回复 ISSUE106_VSCODE_RELEASE_OK。
- 专用临时 .codex-headless，真实 Codex 0.162.1 和本机合成模型：独立 home 与默认 home 并存，列表不启动服务，主动无头恢复保留原 ID/provider/cwd，发送回执接受；释放后新原生共享客户端接回同 ID 并完成回复，网关保持断开。专用测试 daemon 最后正常停止。
- 原生独立 exec 接回失败已单独确认，是原生 writer 仍被保留；只在临时配置加入卸载延时 1 秒可观察到 notLoaded/thread/closed。未改真实用户配置，未停共享原客户端。
- Python 定向回归：初轮 152 项；最终配置/CLI/释放 78 项，账号与历史 36 项；Node 表单与导航 113 项及后续导航切换回归通过。模块边界维持 22 个既有例外；Chrome/WebKit 宽窄窗口下，独立目录列表和共享项目选择器 4 项通过。
- Mac Test 2.1.7-test.20261101.issue106.1 已安装并运行；实机原生文件夹选择、手动输入、扫描空结果、默认目录去重、独立配置保存与停用通过。正式版 8787、原生执行进程、绑定、网络设置及草稿保留。最终包在 LAN / HTTPS 下均能单独读取临时目录的 IDE 会话，原 ID 不变；三次只读检查合计分别约 62 ms / 1912 ms，不代表模型回复耗时。
- 构建与安装证据保留在本地 .tmp/issue106-20261101，不提交凭据、历史或安装包；合成模型临时入口验收后停用。Windows 原生联调未纳入本轮已验证结论，Windows 管道隔离有定向合约测试。SSH 完整测试模块有既存旧夹具缺失 released_cli 的失败，本次操作门两项定向测试通过，未扩大范围修正其他夹具。
