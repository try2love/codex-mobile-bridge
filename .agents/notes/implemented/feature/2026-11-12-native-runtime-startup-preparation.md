# Agent Note: 启动时自动准备原生侧聊连接

Status: implemented

## 问题

原生侧聊必须与原 App 共用运行时；手动初始化虽能避免独立 writer 冲突，却让正常新用户先经历失败才能找到配置入口。Windows 冻结网关更新还会改变适配器启动路径，旧配置存在不等于当前可连接。

## 决策

默认本机 macOS、Windows 的已启用 Codex Desktop 在网关启动或重新启用时，由后台流程复用账号模块的准备事务。已核验的共享 owner 直接复用，不审计或重启；App 停止时先准备再启动；运行中但未共享时，仅在唯一进程、配置身份及实时桌面任务均通过核验后正常重启。忙、任务状态未知或其他事务占锁时每 60 秒重新检查，等待不占用账号操作门锁。纯 CLI、独立配置和 Linux 保持原路径。

账户模块保留显式“重新准备连接”及未知任务状态下主动确认的恢复入口。准备成功前，创建持久侧聊不另起 writer；[临时侧聊](2026-11-12-temporary-side-chat-shared-ui.md)是用户明确选择的另一种生命周期，不作为静默降级。

所有网关在同一 CODEX_HOME 的 initialization_lock 内读取 `preparation.json`。首次停止、保存配置或启动之前写入 pending，确认共享连接后才写 complete；新的网关进程也不能自动重放结果未知的启动。若后来核验到真实共享 owner，则可以完成该记录。停止接入或关闭网关会取消后台准备；配置及退出等待之后、启动之前再次检查取消，已开始的事务保留待核验记录。

共享能力不支持时，只有无既有共享配置、无 pending、严格确认 App 停止且未开始准备写入，才允许一次普通 App 启动，继续显示侧聊准备失败原因。已有运行 App、配置损坏、身份变化和未知启动均不自动降级或重复启动。

## 备选方案

继续手动初始化可减少生命周期自动化，但不能满足首次使用无需排错的要求。启动时无条件重启最直接，却可能中断任务，并在两个网关或未知回执下重复启动，因此不采用。仅把防重复标记保存在单个网关的数据目录无法约束共享 CODEX_HOME 的另一实例，必须与共享锁放在同一目录。

## 影响

普通已共享启动没有桌面重启；安全条件未满足时，现有聊天照常使用，侧聊准备延后。新后台检查只在待准备期间运行；失败写操作不轮询重放。不会修改原 App 安装包、账号、模型配置或聊天历史，不安装后台服务，不强杀。无法在不重启原 App 的条件下改变既有进程的启动环境，因此不承诺运行中所有情况都立即准备好。

45 项账号/准备回归与 3 项客户端调度定向回归通过，覆盖跨网关 pending、忙和未知任务、取消、普通冷启动及显式恢复；模块边界检查通过。此前同模块测试中 `test_disable_waits_for_accepted_workspace_mutation` 的旧 mock 不接受已有的 history_path 关键字，109 项客户端生命周期检查有这一项夹具失败；未借此修改无关产品代码。已安装 0.167 原生 CLI 与生产适配器的隔离验证通过：自动准备、共享 owner 复用、父 writer 存活时原生 attached 创建、配置不变及 EOF 正常退出；桌面生命周期使用合成 owner，没有操作真实 GUI 或调用模型，不能算作真实桌面重启验收。最终安装证据另见本轮交付回执。
