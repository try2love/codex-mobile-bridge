# Agent Note: 共享会话菜单与原生分类写入

Status: implemented

## 问题

PR #92 将列表长按、右键及标题详情入口统一为菜单，并增加 Codex 原生项目和分区操作。直接整合会丢失 Claude、DSH 的聊天通知设置入口，将原有归档确认改为上下排列，且分类请求超时后再次打开菜单能够重复提交。旧项目迁移记录也可能在明确移出项目后将列表重新归类。

## 决策

共享 `SessionMenu` 负责菜单布局、复制反馈、长按与键盘操作；`sessionMenuContext` 按原始 provider、host、session 和接入能力提供操作。菜单打开本身不打开聊天、不激活原生会话。列表长按消费后续点击，移动手指取消长按；右键与 Shift+F10 打开相同行菜单。保留标题入口及聊天通知设置。PR #92 初次整合时，未提供原生项目和分区 API 的 Claude、DSH 不显示这些操作。用户后续接受的带作用范围提示的整理入口见[显示分类及改名回执](2026-10-28-desktop-session-display-metadata.md)；仍不以本地标签伪装原生分类。归档、分支等仍由对应接入能力和后端安全检查决定。

[本地优先置顶](2026-10-26-local-first-session-pins.md)与[确认后停止、释放并归档](2026-10-27-confirmed-disconnect-archive.md)继续有效。归档确认显示目标标题、客户端/主机与中断后果；左确认、右取消，同款等大，默认聚焦取消。此次菜单整合不扩大任何客户端的原生归档能力。

分类读取仅调用 `thread/read`、`project/list`、`threadSection/list`；写入分别使用 `thread/metadata/update` 与 `thread/section/move`。移动分类不修改 cwd、模型提供商或账号，也不执行 `thread/resume`、`turn/start`。本地和 SSH 使用原运行时、原 CODEX_HOME；WSL 只连接原运行时，不隐式启动它。

`OrganizationCommands` 在派发前记录原目标、预期分类、执行身份与请求 ID。结果未知时，仅通过后续原生读取核对；重启、再次打开菜单、更换请求 ID 都不能重发未知操作。相同请求 ID 不得用于另一操作，已确认回执也不能把后来变更的分类改回去。确定尚未发送的验证失败允许修正后再试。文件写入函数由应用组装层传入，避免新增业务层向应用层的反向依赖。

已确认的原生项目操作使对应会话的原生成员关系优先于旧迁移记录，含明确移出后的空值；未迁移的其他旧会话仍保留既有显式成员关系。仍不根据 cwd 猜测项目。回执按本地/SSH/WSL 数据目录隔离。

窄屏菜单横杠及非按钮标题区域支持下拉关闭；内容区保留滚动，横拖和取消指针不关闭，短拖回弹。共享 `back` 根据当前视图逐级返回：详情、改名、项目、分区、归档确认返回主菜单，主菜单才关闭。Web Escape 与 Android 原生返回沿用同一 `cancel` 路径。返回不撤销已经派发的写入，忙碌状态保持至请求结束，防止返回后重复提交。减少动态效果偏好下关闭回弹动画。

## 验证

菜单复制按钮在创建时具有原生剪贴板识别标记，保证捕获阶段的首次真实点击即可授权；不能在点击处理器中才添加标记。Codex 优先显示并复制原生深度链接，其他接入显示并复制原生 Session ID。收到复制确认后关闭当前菜单并显示短暂提示，避免提示被 modal 顶层遮挡。复制失败不显示成功、不放宽真实点击与单次消费限制。

- 原生剪贴板兼容回归直接调用生产菜单渲染，覆盖四客户端首次点击、合成点击拒绝和确认后提示顺序；不将脚本夹具等同于手机真机验收。

- 已安装 Codex 运行时导出的 schema 包含本 PR 使用的原生方法。在空隔离 CODEX_HOME、新建合成项目/分区/会话中，通过项目移动与移出、分区移动与移出；id、cwd、modelProvider 保持不变。未发送模型请求，未使用真实凭据或修改真实会话。
- 原 PR 的超时写入通过合成请求复现二次派发。补充回归覆盖持久化未知结果、重启/新请求 ID 不重放、读取确认、旧回执不回滚新分类、目标失效、认证/CSRF、Windows 扩展路径和 SSH 自包含载荷。
- 菜单能力测试覆盖 Codex Desktop/CLI、Claude Code/Cowork/CLI、DSH 官方与手动接入；仍保留对应接入的独立能力边界。[DSH 通用插件](2026-10-28-dsh-generic-plugin-binding.md)不因共享菜单而退回指定应用名称或自动绑定。
- 浏览器使用生产页面与资源、隔离合成 API。独立组件测试用于布局/异步/复制检查；列表入口测试必须经已登录页面中的真实会话行长按或右键，不以登录页上直接弹出组件的截图作为列表验收证据。覆盖 Chromium/WebKit 宽窄视口、深浅主题、取消不发送、无详情加载/原生激活和等大按钮。
- 后续菜单修正的 16 项 Chromium/WebKit 宽窄测试覆盖逐级返回、拖动边界和三家作用范围提示；9 项旧手机复制兼容测试保持通过。证据位于 `.tmp/session-followups-20261028/menu/`。未将浏览器手势夹具称为真机验证。
- 构建、安装结果及日志保存在忽略目录 `.tmp/pr92-20261028/`。本地浏览器与协议夹具不等同于 Windows/WSL/Linux 实机或 iPhone 安装验收。

## 备选方案

保留各客户端独立菜单可减少接入改动，但复制反馈、归档确认和入口会继续分叉，因此采用共享菜单配合真实能力约束。直接采用 PR 的纵向危险确认按钮与删除通知入口不符合已确认行为，故保留既有契约。

只依赖预期分类比较能拦截显式冲突，但超时后旧快照仍可能触发第二次写入，因此增加持久化回执。直接复用归档回执类需要将分类伪装为布尔归档状态，不利于正确核对，故保持独立的分类回执实现；复用现有私有原子文件写入函数。

将所有空原生分类视为未归类很简单，但会丢掉 Codex 尚未迁移的旧成员关系；保留所有旧成员关系又会覆盖用户明确移出操作。因此仅由已确认的原生项目操作覆盖对应旧记录。

## 影响

[Android 电脑选项菜单](2026-10-28-android-gateway-options-menu.md)是独立原生入口，返回先关闭该浮层，再沿用本篇 HTML 菜单的逐级 cancel 路径。

三家客户端具有一致的列表菜单交互，既有通知、置顶、归档保护继续可用。分类写入新增私有回执文件；结果未知时可能需要在原客户端核对，不以重复提交换取表面成功。旧 Codex 不支持相关原生 API 时显示错误，不回退到修改原生数据库或伪造成功。

PR 作者的两个原始提交作为合并祖先保留；整合修正单独体现在本地合并结果中。本轮不推送、不发布、不关闭远程 issue。
