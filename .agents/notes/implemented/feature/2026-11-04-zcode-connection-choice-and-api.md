# Agent Note: ZCode 统一连接选择与可保存的 API 配置

Status: implemented

后续[共享账号编辑器与 ZCode 状态](2026-11-04-shared-account-editor-and-zcode-readiness.md)将手机方式入口移入账号管理、复用 Codex 模型获取，并补齐原生额度和官方模式冷启动；本文的持久保存、互斥传输与任务保护继续适用。

## 问题

官方远控 Test 能接续会话，但列表把应用通道就绪和具体聊天订阅混为一谈，仍显示“重试连接”。原管理页同时暴露兼容端口和多套连接按钮，手机不能选已配置的连接方式，官方链接也缺少独立保存入口。ZCode 账号页只能保存已登录账号，不能创建原 App 支持的个人 API Provider。

## 决策

同一个 ZCode 入口只选择一种传输：默认 `private-pipe`，或用户明确配置的 `official-remote`。选择保存在当前网关资料目录的 `zcodeConnectionMode`；已有 `zcodeOfficialRemote` 只用于迁移读取，明确选择后移除旧布尔项。不自动跨方式回退，不增加重复聊天列表，也不通过切换传输退出原 App。私有管道接不上已普通启动的进程时，用户另行执行共享初始化流程，经任务检查后正常退出、由网关启动。原退出保护和未知回执不重放规则继续适用。

桌面、Web、iOS 与 Android 所载网页复用 `ClientLifecycle` 的能力驱动方式按钮与切换确认。非秘密的 `connectionModes` 描述可配置与可选择状态；选择沿用应用开关请求的 `connectionMode`，不向远端传递官方登录凭据。后端在同一客户端写门锁内替换适配器、废弃旧绑定和读缓存。界面同时使旧审批与写权限失效，保留输入、已上传附件对象和阅读位置；具体聊天按既有接续流程重新核验，不重放消息。通道已就绪时不在聊天列表显示连接摘要或重试按钮；当前方式由账号管理中的选择状态表达，异常与读取失败继续可见。

官方远控链接独立存于 `zcode-official.json`，登录继续由 Electron safeStorage 加密保存。旧密文中的链接在启动时迁移到独立配置；切回本机模式不会删除登录。清除官方登录只断开终端并清凭据，保留链接与所选模式，不暗中切换到本机。链接必须匹配本机 MID；连接中不允许直接把保存的目标换成另一 SID。认证失效仍需用户重新验证，持久保存不保证令牌永不过期。后续[三端本机 RPC](../architecture/2026-11-04-official-local-rpc-platforms.md)补齐 Windows/Linux 通道与安全存储检查；两端的真实官方登录和配对仍需分别验收。

用户明确取消 TCP 兼容选项，管理界面与初始化选择器不再展示它；旧配置也不再使生产管理流程扫描或打开 17742。私有管道启动是唯一的本机接入路径。旧端口设置请求返回明确错误，不自动转换为可能退出原 App 的操作。此决定替代[原应用管理记录](../architecture/2026-11-03-zcode-desktop-management.md)中保留可选端口的部分，其余任务、身份与弱网保护仍沿用。

API 接入复用共享账号编辑器、私有副本以及 restore/rollback 事务。允许填写名称、Base URL、API Key、模型 ID，以及原 App 支持的 `anthropic-messages`、`openai-chat-completions`、`openai-responses`。保存不调用模型、不修改运行中的原 App；先停用手机接入并正常退出原 App，才能应用保存项。

应用写入当前 `provider_config.json` 的 `schemaVersion: 1` 结构，合并专属 `cmb-api:<uuid>` Provider，使用 `api-key` access，不写已退役的 `config.json.providers`。保留其他 Provider、OAuth、默认模型和留存模型参数；配置容器未知或回滚前发生外部变化时拒绝覆盖。API 配置与官方登录共存，因此界面区分“待应用”“已配置”与聊天中的模型选择。私有副本沿用目录 0700、文件 0600；公开状态和编辑回包只提供 `hasKey`，不返回 API Key。

## 首次连接引导

三端桌面网关在同一 ZCode 官方远控面板内复用既有折叠说明与编号步骤样式：启动原 App 并登录官方账号 → 打开左下角移动端远程控制并复制链接 → 在网关保存链接 → 按原 App 相同站点和方式登录同一账号 → 显式连接官方远控 → 未运行时启动网关 → 核对两端状态。API Key 不能代替配对所需的官方账号登录；已运行的网关不需要为此重启。说明不增加自动登录、模式切换或后台请求。

首次读取状态未配置时展开步骤；已配置时默认收起，仍可随时打开。后续刷新与保存不重置用户的展开选择，也不把展开状态记为未保存的设置。产品文案明确区分登录成功与连接成功。

绿色语义依据固定官方源码 [WorkspaceWebRemoteControlTrigger](https://github.com/zai-org/ZCode/blob/a9fe401eede6e6e5e01be9048679c206fe6f02d9/packages/ui/src/WorkspaceWebRemoteControlTrigger.tsx)：只有 active 显示绿色，starting/connecting/running 为黄色，error 为红色。绿色也可能对应其他已连接终端，因此引导同时要求本网关显示“官方远控已连接”，不把颜色单独作为网关已配对的证明。

2026-11-05 用户在 Windows 独立 Test128.14 完成官方登录后，真实认证HTTP确认官方方式 configured/connected/ready，聊天列表359ms、原生项目125ms，登录密文与链接均已保存。没有输出凭据、没有模型消息，也没有启停App。随后 Windows Test 128.15 以相同应用身份和原资料目录正常重开，未再次官方网页登录即恢复 configured/connected/ready；8793 正常认证，原项目157ms、历史140ms。既有独立聊天显式接续1078ms、详情516ms，原ID/cwd保留、发送权限为true，仍为GLM-5.3-Flash/low，没有模型消息。原ZCode主进程及启动身份未变。更新只重打外壳并替换静态字典，717个网关文件中后端EXE等未变文件沿用已核验哈希；不初始化、覆盖或迁移已登录资料。引导相关3项UI检查和生产JS/CSS合成浏览器中英文展示通过；不扩大到未变功能回归。

## 备选方案

继续分别增加 ZCode 专属连接按钮能减少初期改动，但会让桌面与手机拥有不同状态和操作规则，因此改为能力描述驱动的共享选择器。保留 TCP 作为第三方案曾能兼容旧原型，现在用户明确取消该方案，生产入口不再提供它。自动在本机与官方之间回退可提高表面连通率，却会改变数据经过的服务和会话绑定，因此只允许明确选择。

API 热应用可省去退出步骤，但会扩展原生服务写入协议，并与原 App 的内存配置竞争；本轮选择已有停用/退出/应用事务。直接覆盖完整 Provider 配置更简单，却可能丢失原生设置和其他账号，因此只合并本条 Provider。

## 验证

官方适配器与切换路由 13 项、私有管道生命周期 13 项通过；覆盖未配置方式不能破坏旧绑定、模式切换不退出原 App、旧端口配置不再扫描监听、正常初始化仍受任务确认保护。官方控制器 8 项通过，覆盖链接/加密登录重建、旧配置迁移、清除登录保留链接、目标校验与私有 IPC 认证；IPC 用例在放行临时 Unix socket 后通过，未重跑其余已通过用例。

受影响的共享连接界面套件首次 324 项中 322 项通过，两项旧端口预期随功能移除更新；随后仅补跑 19 项直接相关检查，全部通过，包括同字段提交、未配置方式禁用、就绪隐藏重试，以及切换后草稿/附件对象/阅读位置保留且旧写权限失效。API Python 8 项、共享账号 UI 37 项通过。三个协议用固定官方源码的真实配置编解码器完成 roundtrip，3/3 通过。没有改动真实原 App 的 API 配置或调用模型。

Mac Test 128.9 的独立冻结验收还通过假 API 配置保存、编辑回包脱敏与移除。真实桌面界面显示两种方式、已保存官方链接和 API 协议编辑器，兼容端口选项消失；网关正常退出并更新后，原官方登录自动恢复。真实切换发现旧管道属于旧网关路径，随后用户确认空闲并授权正常重启；原 App 正常退出。新私有组件又暴露[macOS 中文路径查询问题](../bug-fix/2026-11-04-macos-process-query-utf8.md)，修复只影响进程查询，未放宽身份校验。

最终签名 Test `2.2.0-preview.test.128.10` 基于 `7483a68` 安装到原 8788 资料目录，官方登录密文和保存链接保留。原 ZCode 3.17.2 由新私有管道冷启动为 6010 ms；同一验收 Fork 恢复 18 条消息、发送权限与 Flash/low，详情读取 71 ms。经手机同用的应用接口切回官方远控为 1629 ms，仍为同一 Fork，详情 517 ms；固定 HTTPS 读取为 2182 ms。以上是本机本轮样本，不代替弱网或跨平台验收。原 App 未被强杀、没有发送模型消息、没有修改真实 API Key。最终保留官方连接供用户操作。

## 影响

连接方式、官方登录、个人 API Provider 与聊天所选模型成为各自明确的操作，保留原会话执行者。用户只需在电脑配置一次，手机可选择已准备好的连接方式；凭据过期和普通启动缺少管道仍需相应操作。官方方式依赖账号与中继，本机方式依赖由网关启动的原 App，两者均不自动启动模型请求。成品界面、真实持久登录和模式切换验收与源码测试分别记录；没有真实 API Key 的上游连通性仍未验证。手机选择器已用共享 UI 与真实 HTTP 契约验证，本轮没有 iPhone/Android 真机触控复验；移动原生源码未变，不重编手机壳。
