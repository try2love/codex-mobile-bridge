# Agent Note: 注册与找回入口直接显示在云登录页

Status: implemented

## Problem

用户要求注册与找回入口可见，原 `Cloud account help` 抽屉使这些入口不易发现。当时只读参考了 [GitLab 登录页](https://gitlab.com/users/sign_in)和 [Proton 登录页](https://account.proton.me/mail)：找回靠近密码输入，创建账号位于主操作下方。

## Decision

登录页显示密码旁的找回入口和主按钮下的创建账号入口，验证/重发仅属于注册页。各流程在现有模态框内有独立视图及返回登录动作；移除服务器探测按钮，但显式登录仍内部读取 capability，不额外增加被动请求。

官方服务保持首项和默认项，只显示名称；自建服务 origin、凭据作用域、HTTPS 与手机授权独立不变。服务器和邮箱草稿保留，密码及确认值在换页、换服、提交或关闭时清除。等待写入禁止导航/关闭，未知回执不报成功也不重放；找回反馈不暴露账号是否存在或保证送达。

原来的布局实现先提交密码，再进入链接验证；这部分后来由[验证码](2026-11-01-email-verification-codes.md)及[邮箱优先注册](2026-11-02-email-first-registration.md)取代。这里仅持有可见入口和表单边界，不把原先“未改服务端”的范围套到后续流程。

## Alternatives considered

把辅助操作放入抽屉能压缩登录页，但用户明确要求注册/找回直接可见，因此采用密码旁与主按钮下的入口。参考公共页面只取信息层级，不复制额外认证能力或改变桌面视觉体系。

## Consequences

常见账号操作容易找到，各表单继续隔离，代价是模态框需维护多个视图和草稿清理规则。本篇部分取代[登录对话框](2026-11-01-cloud-login-dialog.md)的帮助抽屉，其他登录边界继续由原篇持有。

## Testing

2026-11-01 的 38 项 Edge 宽窄浏览器和 1,324 项 Node 回归通过，覆盖可见入口、原生表单、只发邮箱的找回、注册/验证切换、拒绝与回执、不重放和翻译。后续纠正也覆盖验证只出现在注册页、无探测按钮及登录 capability 约束。检查了合成登录/注册/找回截图；没有真实注册、邮件、配对、WebKit 或手机验收，未操作用户已打开的认证窗口。
