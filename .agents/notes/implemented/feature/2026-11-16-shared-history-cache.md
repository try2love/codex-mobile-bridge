# Agent Note: 各客户端最近历史共用有界持久缓存

Status: implemented

## 问题

原最近历史缓存仅在页面内存中，重新打开手机或网页后丢失。读取原客户端稍慢便再次展示空白加载页，已有历史不能帮助首屏。

## 决策

共享 IndexedDB 保存展示用途的最近页，Codex 保留最近 20 条，其余客户端保留最近 40 条。作用域沿用经过认证的网关登录身份、目标主机、接入实例与会话标识；不同作用域不能读取彼此记录。保存 7 天，总计不超过 32 MiB、256 页，单页最多 2 MiB，超预算的旧记录淘汰。浏览器不允许存储、配额失败或打开阻塞时继续现有内存缓存与网络读取，不阻塞连接。

缓存只用于展示，不恢复权限、审批、任务状态或未确认写入。实时请求独立并行，任何已返回的新页面（包括断开状态的历史页）优先于迟到缓存。切会话、切身份及退出登录使旧缓存回调失效；退出登录清除历史缓存，单会话清理不删除其他会话。临时侧聊不写持久缓存，仍按原结束与网关重启约定清理。

清理时间戳与正文写入在同一数据库事务内核对，覆盖其他标签页已开始但尚未落盘的写入。同毫秒的写入保守跳过一次缓存，网络读取不受影响。原生账号切换仅清所属客户端命名空间；明确的空历史覆盖旧内容，加载占位不覆盖。淘汰通过时间与字节索引读取键，不把全部缓存正文读回主线程。

资源复用现有 activity.js 组合入口，不添加额外首屏请求或原生手机专用存储实现。本批只解决最近页跨重开复用；旧页持久缓存、动态显示窗口及原生完整快照的接收开销另行处理，不能据此宣称长会话已完全解决。

## 备选方案

扩大 localStorage 能延续现有列表快照风格，但正文同步写入和配额较小，容易阻塞主线程。IndexedDB 写入异步且可独立淘汰。缓存完整详情虽然改动更少，却携带过期控制权限，故只保存展示字段。

## 影响

重新打开会话可先看到缓存内容，再等待当前连接核验。首次访问和超预算页面仍需原历史接口；缓存不保证离线附件可访问，不替代文件授权，不调用模型。原生历史可被修改，因此缓存不被认定为控制或永久不可变的权威来源。

## 既有笔记审计

[共享阅读状态](../../implemented/bug-fix/2026-10-30-shared-chat-reading-state.md)继续约束滚动位置与节点复用，本篇仅补持久存储；[独立客户端实例](../../implemented/architecture/2026-11-05-independent-client-instances.md)的身份隔离继续适用。历史与控制的拆分沿用 docs/architecture/history-control-separation.md，原生首次完整快照限制没有变化。其余模型缓存、通知和 CLI 路由笔记不改变，未发现同题待办需要替代。

## 验证

Chrome/WebKit 宽窄屏 8 组标准测试通过：14 类存储场景，以及两个实际页面间的会话、账号命名空间与全清竞态。覆盖 7 天过期、容量与条数淘汰、存储拒绝/阻塞、清理后迟到写入和新写入。仅使用专用合成 origin，不清理真实用户浏览器数据。原 UI 214 项通过，新增桌面接线 3 项及 timeline 接线 4 项通过；资源入口 11 项通过。未据此宣称手机原生 WebView 或长会话完整快照问题已通过。
