# Agent Note: 桌面主题、独立原生连接与 Test 下载管理

Status: implemented

## 问题

按过时的本地 Preview 3 分支头构建，会漏掉同名已发布分支后续的历史版本与下载缓存管理。分支名、祖先关系和既有测试通过不能替代最新发布 SHA 与功能覆盖核对。桌面已有系统深色样式，但缺少手动选择；原生连接又嵌在提醒折叠中，桌面与远程都不容易找到。Test 独立身份还将版本浏览、下载与安装一并禁用。

## 决策

本地集成正常合并已发布 Preview 3 的 `d79a89c0`，保留当前额度、网关凭据、普通启动和历史缓存保护。历史版本、保留与勾选删除下载缓存、手动安装旧版的配置兼容、包内数据格式声明及移动图标使用该发布线的实现，不重写另一份更新器。构建前同时核对实际发布身份、源码覆盖与成品内容；测试结果按影响范围记录，不能用旧用例通过代替功能完整性。

桌面顶部提供跟随系统、浅色和深色。主进程通过 Electron `nativeTheme.themeSource` 同步原生界面与既有 `prefers-color-scheme` 样式，不重建网页或丢弃未保存输入。选择写入资料目录的 `desktop-appearance.json`，启动及显式更换资料目录时读取；更新备份包含该文件。Web 与手机的聊天外观设置保持原有独立范围。

`AccountsPanel` 将原生连接区块放到已保存接入之前，位于桌面高级路径设置之后，并移出提醒与 Codex 更新折叠。远程复用同一组件。平台能力、目标配置、账号操作、任务状态与显式初始化确认保持原有校验，入口移动不启动、切换或重启原 App。

已打包 Test 可读取官方版本目录、选择与下载适合本机的包、复用及管理已验证缓存。安装能力单独报告给界面，更新器与 IPC 都拒绝 Test 安装动作，不调度 Test 后台检查。正式包继续使用原有安装事务及确认。下载、安装与缓存删除仍复用发布版的身份核验、互斥和原生确认。

## 备选方案

仅重写三个界面入口可以快速改变观感，却会继续漏掉发布版数据格式和旧版兼容修复，因此先完整整合发布成果。直接开放 Test 自动替换能复用正式流程，但可能用正式包替换独立 Test 身份，因此只开放目录、下载及缓存管理。用额外 CSS 手动切换也能改页面颜色，但会与原生窗口和现有系统主题样式分离，因此使用 Electron 的原生主题来源。

## 影响与验证

用户可以直接发现连接入口并即时选择桌面外观，Test 也能体验完整下载管理；Test 内安装仍需手动完成，避免混淆正式安装身份。新主题文件随同现有资料保留，异常偏好读取回到系统主题，非法写入保留原文件。

完整 Node 1866 项（1865 通过、1 条件跳过）、后端更新影响 76 项通过；Chrome/WebKit 宽窄窗口共16项有效检查通过，覆盖系统主题、初始化、版本与缓存、桌面及远程独立区块。主题命名可访问性与隔离夹具重复选择器首次失败后定向修正复验。定向回归验证主题持久化与无效修改、Test 下载校验及保留缓存且不调用安装器。浏览器与成品验收分别记录；源码夹具不等同真实安装或原 App 初始化。原执行器仍在使用的冻结适配器保持原位，新适配器只在任务安全结束后的显式初始化时载入。
