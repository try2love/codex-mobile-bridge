# Agent Note: 图片保存到当前查看设备

Status: implemented

## 问题

共享图片查看器只能预览与添加到对话，手机用户无法将图片保存到手机。保存目标是当前查看设备，不能把网关宿主机当成用户设备。增加按钮后，窄屏工具栏也需要容纳完整按钮文字。

## 决策

图片查看器提供保存到本地入口，复用 Web、iOS、Android 的既有文件下载与系统保存流程。工作区图片复用其下载 URL；聊天图片从经过会话身份校验的原图接口下载，保留原文件名，不将缩略图或屏幕截图作为原图。原生下载只新增已确认的图片路由与显式下载参数，不接受任意 URL、跨站地址或 data URL。

查看器与工具栏共享一份实现。顶部始终单行排列“关闭、文件名、引用”，长文件名省略；保存入口用带可访问名称的下载图标，放在底部“适应屏幕”右侧最末位。手机仍保存到系统文件位置，本次不新增相册权限。下载只由用户点击发起，不预取或轮询。

## 相关决定审计

[原生历史图片](../../implemented/feature/2026-10-29-shared-native-history-images.md)与本提案部分重叠：沿用会话绑定和源文件重校验，增加已授权图片的下载用途；不改变被动读取不得激活会话的约束。既有下载与图片预览测试继续作为对应边界的验收依据。

## 备选方案

将预览图转换为浏览器 Blob 下载很直接，但会绕开手机现有下载管理，也可能保存缩略图或丢失原文件名，因此采用已认证的原文件 URL。直接保存相册便于查找图片，但引入新的平台权限和分叉流程，本次使用已有系统文件保存入口。

## 验证

共享下载检查 18 项、桌面图片 HTTP 检查 8 项、Codex 上传与活动检查 25 项通过；覆盖原始字节、附件文件名、会话隔离及跨源、重复参数、中继范围拒绝。Android Java 与 iOS Swift 生产下载器编译和原有传输夹具通过，增加图片入口边界。浏览器组件在 320、390、844、1280 像素各通过 31 项，含同时显示两个操作按钮，390 像素截图已核验。图片夹具不包含真实图片内容，截图仅证明工具栏布局。最终 Mac Test zcode11 的 HTTPS 页面已实际上传独立 68 字节 PNG，经生产图片查看器与共享下载器保存后逐字节一致，原文件名保留。iOS 与 Android Test build 42 已重新编译签名；Android 签名与既有 Test 一致。用户暂不连接 iPhone，手机覆盖安装与系统文件保存尚未验收，不用浏览器结果替代。

## 影响

工具栏调整后的针对性浏览器夹具在中文、英文及 320、390、844、1280 像素各通过 47 项检查，并核验 390 像素截图；顶部无换行，底部图标可见且不溢出。保存链接、文件名和原生下载器未改，不重复既有已通过的传输测试。

原生图片下载需要手机壳识别新路由；旧手机壳不能被当作已支持。图片接口未提供分段响应时不虚报断点续传，保留现有中断后重下提示。
