# Agent Note: Antigravity 原生控制的结果核验与来源边界

Status: implemented

## 问题

原生归档、分支和独立任务控制复用手机端共享操作入口，但取消 RPC 成功并不代表任务已经空闲，创建成功也不能证明标题写入成功。适配原生能力时必须保留原服务身份和未知写入不重放的约束。

## 决策

归档的“先停止”选项在取消返回后，重新读取原生会话、实时任务、审批和待发队列。只有状态已知且空闲时才提交归档；停止后仍忙、仍有待交互或状态不可核验时，归档保持未发送。新建标题写入绑定创建时核验的原服务身份；标题写入未确认时仍保留已创建会话和已发送消息，返回标题待核对信息，不重复创建或写入。

分支只调用原生 `ForkConversation`，不重放历史。空闲检查和分支 RPC 绑定同一已核验的服务身份；原会话项目目录必须仍存在，创建结果必须通过原生结果、同来源数据库或同身份轨迹核验新会话的唯一项目归属。原服务换代时拒绝写入；已创建但项目归属无法核实时返回结果未确认，不重发创建。

后台任务列表与停止绑定同一实时服务身份。保存的子任务关系只用于展示；可停止状态与父子关系必须经原生轨迹核验。独立任务停止复用管理器的取消门闩，绕过普通写锁和模型展示读取；原生后台列表、轨迹核验和取消使用独立传输锁，避免等待正在发送的消息回执。子代理停止在取消前推进该来源、该子会话的停止代次并设置 Hook 停止标记；不停止父会话，也不自动重放未确认的取消。

上下文容量使用原生 generator metadata，系统消息复用共享活动消息。消息与 turn 使用同一个终止状态投影，失败不会标记为最终成功回答。分页消息首末时间只作为消息时间，不能作为整轮起止；没有可信原生 turn 时钟时不输出 `turnStartedAt` 或 `turnCompletedAt`，也不使用本机当前时间补齐。

本记录与[原生接入](2026-11-10-antigravity-native-integration.md)部分重叠，补充原生控制开放后的约束；与[停止整树和并发取消](../bug-fix/2026-11-16-antigravity-stop-tree-and-concurrent-stop.md)部分重叠，只负责取消之后能否进行下一项原生写入。没有删除或归档已有决定。

## 备选方案

取消成功后立即归档可以减少一次读取，但取消被接受与任务完全结束不是同一个事实，且审批、排队消息可能保留，因此必须复验。标题失败时让整个新建操作失败可以简化返回值，却会掩盖已经创建的会话并诱发重复提交，因此保留创建结果并报告标题待核对。

只把工作区 URI 交给原生 fork 实现较简单，但 `CURRENT_WORKSPACE` 可能依赖原客户端当前窗口；结果未提供项目归属时，不能以请求参数代替结果证据，因此复用新建会话的项目核验链。

只放开管理器的 `stop-task` 锁改动较少，但适配器模型读取与原生任务核验仍会等待发送锁，因此取消链的三个入口共同适配。以本地 SQLite 的运行标记直接授权停止兼容旧协议，却不能把当前原服务与子任务归属绑定，缺少实时证据时只允许查看。

从当前页消息时间推算整轮耗时可以立即显示时长，但分页缺起点、合并后的工具结果和条目生成时刻都不能证明任务起止，因此只采纳原生容量、系统消息与一致的状态字段，暂不提供该来源的推算耗时。

## 影响

手机端可使用原生改名、归档和新建标题。归档可能要求用户先处理尚未结束的任务或保留队列，不自动清理用户待发内容。`test_antigravity_annotations.py` 九项回归通过，覆盖停止后仍忙、审批、队列、未知状态以及标题失败；未操作真实 Antigravity 客户端。

`test_antigravity_fork.py` 六项回归通过，覆盖合法完成轮次、分页锚点、幂等、服务换代、目录失效及结果项目不匹配。原生 fork 的真实客户端兼容性仍需另行验收。

任务与中断回归覆盖来源换代、旧父子关系、父会话及无关任务拒绝、准备中旧消息失效、阻塞发送期间的任务核验与取消，以及重复请求不重放。测试使用合成传输，不操作真实任务。

上下文和状态回归覆盖原生容量、读取失败回退、系统消息、分页/缺失/倒序时钟不产生耗时、失败不标记最终成功，以及消息与 turn 状态一致；没有恢复中间内容折叠。
