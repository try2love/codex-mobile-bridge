# Agent Note: 已连接的手机优先回到局域网

Status: implemented

## 问题

固定和临时 HTTPS 的往返耗时会波动，排序不应触发公网间换线；但回到本地网络后，继续使用公网会产生没有必要的绕行。原有的[网关绑定与选路设计](../architecture/2026-11-02-mobile-gateway-channels.md)已经能在不重建聊天的情况下换线。本次改变选择条件，沿用原有的身份验证、通知、超时和写入回执。

## 决策

进入电脑仍取首个验证成功的启用地址。活动聊天的自动模式中，本地网络可用时允许从公网切向验证成功的局域网；局域网失效后可回到可用公网。公网失效且没有可用局域网时提示手动选择，绝不自动跳到另一条公网线路。手动模式始终由用户选择。刷新延迟只更新启用地址的样本，不能触发选路；地址、数值和选中标记互不替代。低于 100 ms 用绿色，300 ms 起用橘色，1000 ms 起用红色；无样本或不可达不显示虚假的耗时。

共用页面脚本依据当前信道、网络类型和已启用地址选择候选；原生层对照绑定清单后再探测。只在前台做活动会话测速，收到网络变化时立即检查；稳定时局域网尝试间隔 90 秒。已有成功的受认证 API 流量可跳过一次定时健康检查，也会清除已过时的断线显示；它不能冒充身份挑战成功，不能授权新地址。公开登录/认证查询和错误响应不计入成功流量，迟到的探测失败也不能覆盖后来的实际成功。具体绑定恢复和状态边界见[网关绑定与选路设计](../architecture/2026-11-02-mobile-gateway-channels.md)。每个绑定的清单同步间隔至少 90 秒，内容相同不重写；手动测速不受清单更新间隔限制。保留两次失败确认、退避和通知长轮询。

常规通知巡检的列表、详情、发现、探测只进入调试日志；不再为写巡检日志反复读通知游标。保留达到两秒的慢扫描、投递结果、请求失败以及发送回执关联。正常静态资源请求保留关联 ID，默认不写逐跳记录。

## 备选方案

始终保持健康地址可以避免跳动，但回到家中仍会走公网。反过来，每轮都测全部地址并选最快会反复切换固定域名和临时域名。按本地网络变化尝试一次，并在失败后限频复查，可发现稍后才恢复的局域网，又无需持续探测所有公网入口。

## 验证

共享选路用例覆盖公网失效不横跳、自动回 LAN、手动模式、被禁用的 LAN 和以活动流量减少请求。窄屏 WebKit 实际点击刷新，核对右对齐、刷新中禁用、更新后的分档及没有发出切换命令。iOS 18.2 模拟器用专用 Test 绑定、真实 HTTPS 和 LAN，注入公网探测失败与本地网络变化：没有选另一条公网，恢复后通过 LAN 读取了认证响应，并保留同一 WKWebView、输入框和时间线。部分尝试未在夹具的 16 秒等待窗口内完成交接，未据此推断固定切换时延。没有调用模型，验收绑定已注销。

## 影响

构建 45 的 iOS 和 Android 壳复用上述规则，网关 Test 提供相应样式。此轮没有实测运营商网络、Android 真机交接或整机耗电；网络请求和日志的减少不能外推为电池续航百分比。
