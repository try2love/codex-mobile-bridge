# Agent Note: 桌面批准手机身份且不设配对期限

Status: implemented

## Problem

用户要求把云二维码改为桌面逐手机批准，并明确配对不设到期时间；直连 LAN/HTTPS 配对独立。

## Decision

桌面批准要求手机加密证明和本地计算的安全码。八组、每组八位十六进制保留完整 SHA-256 指纹，绑定 X25519 共享秘密、origin、网关/关系身份和双方控制/预览公钥；服务器 OTP 或仅账号登录不能代替。证明元数据按 origin/账号/网关保存，本身不授权；决定前重新核对当前设备身份及不可变本地密钥。未知写入不自动重放，网络等待上限不等于关系到期。

## 原实现与后续归属

原手机在所选 origin/账号中选择电脑，先保存请求身份及密钥，再发一次请求；重开只查状态。服务器保留不超时请求，通过桌面批准/拒绝或手机撤回改变状态，访问仍受会话与服务资格约束。桌面自动显示默认关闭的逐设备开关，关闭弹窗保留请求；当时撤销先删本地 pin，即使远端失败也如此。迁移 006 保留 active 绑定与密钥、取消旧 QR、增加名称并移除请求期限；会话时间清理不应级联删除设备。

手机手动请求和关闭即撤销由[同账号目录与可逆开关](2026-11-03-account-device-auto-discovery.md)部分取代；旧入口、表和迁移再由[当前云契约](../simplification/2026-11-04-prerelease-cloud-contract-cleanup.md)取代。本篇保留独立证明、安全码、不重放及原决定理由。三端需协同，旧服务器由 capability 拒绝，不回退云 QR；直连 QR、凭据、原 owner/会话和通知同意各自独立。

## Alternatives considered

云 QR 可以一次性指定关系，但用户明确要求电脑开关且无配对超时，因此采用桌面批准；加密证明仍必须独立完成，不能改为账号即授权。

## Consequences

是否接入由桌面逐设备决定，安全码覆盖控制和预览身份；代价是证明、显示状态与许可需协调，过期的会话/资格仍会阻止业务访问。原迁移与旧数据保留只属于当时方案，当前取舍见后续笔记。

## Testing

2026-11-03 使用合成账号、隔离 PostgreSQL、假 IPC、Edge 回环、Rust 和 Flutter/FFI，覆盖作用域、证明、跨语言安全码、默认关闭、撤回/拒绝、不超时、重启持久化和未知写入。65 项云 Python、97 项 Go、50 项 Rust、1,367 项 Node、268 项 Flutter 通过；默认宿主 FFI 跳过由实际 DLL 单独验证通过，分析、clippy、vet、边界和空白检查通过。宽窄 Edge 覆盖批准弹窗、开关和无期限，检查合成截图；测试 PostgreSQL 已停止并保留数据。

当次无真实配对、邮件、推送、部署、签名或安装，也未重启生产服务；原部署约束要求已识别安装的加密备份、演练和三端配套，不代表本轮操作了这些对象。
