# Agent Note: 额度恢复后自动继续与手机额度圆环

Status: implemented

## 问题

账号额度页不能在聊天中直接表达剩余用量；额度中断的任务需要人工逐条恢复。PR #256 提供候选实现，但 preview.3 的 hosted Desktop、systemError 和未知写入保护需要同现有执行链路一致。

## 决策

总开关默认关闭，仅支持默认配置、官方账号、本机 Codex Desktop。明确额度错误或 usageLimited 目标登记等待，不要求轮询恰好命中零额度；恢复前以 fresh IPC 读取核验原 owner、cwd、最后轮次、目标、归档、审批、账号配置和当前个人额度。hosted 入口沿原 codex_home 选择，不启动第二执行器。

手动停止按轮次持久化；逐聊天排除名单跨重启保留，清单可解除排除。开关或排除变化递增代次，在扫描、写前回调及服务最终门禁检查。首次写入前保存不可重放标记，预检暂时失败可再次读取，写入结果未知不再派发。默认生命周期仍拒绝 systemError，只有严格额度预检允许这一终态。

额度显示的首次实现位于手机标签栏，后由[通用额度展示](2026-11-21-shared-quota-display.md)接管为模型工具栏、模型设置和账号页共享组件。自动继续仍独立控制。远程浏览器及手机将开关放在默认 Codex 账号管理的“Codex 原生会话连接”下方，聊天列表不再承载该设置；独立配置、WSL 和共享中继不展示该全局开关。仅在账号页可见时读取状态，设置异步写入串行，隐藏页面不接受迟到结果。桌面网关保留概览入口。

来源为 a32556376 的 PR #256，提交 4ca0795e511c881c96504ad640c741412b203b40；本地适配保留原作者归属。

## 备选方案

只保留额度恢复通知能避免自动派发，但不能满足已确认的自动继续需求，因此提供默认关闭和排除控制。

按预计恢复时间或第三方预测直接继续请求更少，但不能证明当前个人额度可用；使用实时额度及原生中断证据。

整体接纳贡献版可减少整合工作，但无法覆盖本地 hosted owner 与逐聊天排除，因此沿现有执行通道适配。

## 影响

用户可集中控制额度中断任务；增加本地等待、停止和排除记录及可选后台只读轮询。自动继续指令不能保证模型不重复工作，原生审批仍有效；已经派发的任务不因排除而撤销。CLI、IDE、SSH、WSL 和独立配置暂不开放。

## 验证

合成状态覆盖错过零额度、手动停止、排除、配置变化、写前故障及重启不重放。真实 DesktopIPC 与 HostedSessions 的 socket 夹具验证 fresh 读取保持原 hosted owner，且不调用 resume/start；派发另由 Bridge 回归验证。浏览器两引擎宽窄视口覆盖圆环与跨页开关。未耗尽真实账号额度，未宣称真机或真实配额恢复验收。
