# Agent Note: HarmonyOS 单入口实验网页壳

Status: implemented

## 问题

PR #248 提供鸿蒙工程，但其 Huawei 推送类型与后端不符，跨地址切换未沿现有绑定证明，并复制共享注入脚本。直接开放全部能力会产生不可验证的平台承诺。

## 决策

保留工程、扫码和地址入口，采用独立实验 bundle。仅存规范地址，不存配对片段或自造设备身份；网关 Web UI 使用 ArkWeb 自身 Cookie。导航限定原 origin 和设备前缀，禁文件访问与混合内容，TLS 错误取消。

返回列表保留 WebView；已有 controller 用 loadUrl 切换地址，先明确确认，提交失败恢复原导航授权 base。一次仅处理一个扫码/连接/移除。移除地址不清 Cookie，不自动登出网关。

不装入不匹配的推送、多信道证明、深链及原生 prompt/文件桥；不复制 shared/web。来源为 Aplier 的 PR #248，原提交 bda256624c9e2eabc7ba171e57b64aa10efce5ff。已清除贡献者本机签名配置。

## 备选方案

整体采用贡献版覆盖面更大，但缺服务端 Huawei 提供方和认证信道合同，不能作为完整可用平台。

移植 Android/iOS 全套原生桥能增加换线和文件能力，但需要新的设备凭据及导航安全验证，不在本次实验范围内。

## 影响

保留可继续开发的入口和独立安装身份；功能明显少于 Android/iOS，切换地址需要重载网页。系统 WebView 和扫码权限行为必须由 DevEco/真机验证，源码规则测试不能替代它。

## 验证

离线回归执行生产地址存储逻辑，验证未初始化不能写入、非法地址和配对片段不能覆盖已保存地址、重复地址规范化，以及工程入口和资源引用完整。它仍不验证 ArkTS/ArkUI 编译；没有 DevEco/SDK 时不能将这些检查描述为 HAP 构建通过。

Node 执行生产 URL 规则，覆盖允许地址、pair 格式、非根路径、编码绕过、跨 origin/设备前缀拒绝。Web src/loadUrl 和 UIContext 对话框使用官方文档核对。当前环境未构建 HAP、未安装真机、未验证系统 Cookie 生命周期。

后续的[鸿蒙原生桥与分记录离线归档](2026-11-24-harmony-native-offline.md)在用户授权后扩展本篇的网页壳范围，保留独立实验身份及未完成原生构建的限制；不匹配的 Huawei 推送与无证明的自动换线仍不纳入。
