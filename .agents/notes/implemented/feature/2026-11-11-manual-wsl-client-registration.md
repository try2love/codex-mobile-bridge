# Agent Note: 在共用添加表单中手动登记 WSL 配置

Status: implemented

## 问题

WSL 扫描只能发现默认或运行中已暴露的配置。用户已经知道非默认 Codex/Claude Code 目录时，添加客户端仍只有 Windows 本机目录，既不能指定 Linux 用户，也容易把 Linux 路径交给 Windows 选择器。

## 决策

Windows 的 Codex、Claude 共用既有添加表单，通过运行环境选择切换本机和 WSL。只有后端明确给出 WSL 能力且桌面宿主为 Windows 才显示选择。WSL 输入发行版、Linux 用户和绝对配置目录，分别展示 `.codex`、`.claude` 示例；本机与 WSL 的目录草稿分别保留，不自动转换或填入示例。WSL 不调用 Windows 文件夹选择器。关闭只关闭表单，已经发出的保存请求仍以实际登记结果为准；迟到响应不自动打开管理页。

`client-profiles` 的保存请求复用 family，并以 `kind=wsl-cli` 加入 distribution/user/home。控制层只在 Windows 为 Codex/Claude 接受该组合，不把字段传入本机 profile 解析器。目标执行前仍走 `wsl.command(..., allow_start=False)` 对运行发行版的即时检查；检测为停止则拒绝调用，不通过 UNC stat 探测。检查与随后的 WSL 调用不是原子操作，不能承诺消除用户恰在两者之间停止发行版的竞态。

在指定 Linux 用户下用 pwd 复核实际用户名/UID，解析真实目录，核现有目录所有者与读/遍历权限。允许同 UID 的显式非默认目录，不把路径限制为固定用户家目录。Codex 只核所选目录的配置标志与必要的 wslpath 元数据，不使用扫描分支遍历进程或读取环境；Claude 沿既有 WSL 发现规则核 Linux 原生 CLI 文件及目录，所选模式不遍历进程。不执行 CLI 或查询登录，不读认证内容。Windows/UNC/相对路径、控制字符、错误用户和跨所有者目录均拒绝。

核验结果进入原候选与 configure 持久链，ID 继续绑定发行版、用户和 canonical Linux 配置路径。既有 Windows/WSL 共享 Codex 目录冲突和登记数量限制保留；已有登记即使停用也不被新保存覆盖或启用。登记不建立执行 owner、启动 daemon 或打开账号面板。已有账号、历史、草稿、权限与后续显式接入的运行时校验不变。

新增手动条目先原子持久化再发布到内存。写入异常时，仅在实际登记文件的完整字节与本次预期内容一致后确认已落盘；否则不发布新条目，并保留旧条目和已有临时文件。该核验不再次写入、不回滚未知文件、不更改旧的已登记条目启停行为。

## 既有记录核对

- [独立客户端实例](../architecture/2026-11-05-independent-client-instances.md)：部分重叠，共用外壳和本机 profile 合同保留；WSL 继续使用原注册表，不写入本机实例目录或借用默认配置。
- [WSL 账号管理](2026-10-25-wsl-account-management.md)：部分重叠，账号读写和任务预检继续以原注册身份为准。本点不修改认证来源或账号事务。
- 其他命中的 WSL 会话生命周期、释放和手动 DSH 插件记录不定义新增配置表单，与本点无关；没有记录被吸收、删除或归档。

## 备选方案

沿扫描结果登记可以完全复用旧 UI，但仍无法选择未在运行进程中暴露的非默认目录。把 Linux 目录转换成 Windows UNC 能复用本机选择器，却可能唤醒停止发行版并混淆用户/执行语义。另建 Codex/Claude 两套 WSL 页面能减少单个表单分支，但重复身份、草稿和错误处理，因此保留一个能力驱动表单和两种既有注册表。

## 影响

已知配置可在原客户端管理入口完成登记，代价是显式保存需要目标发行版已运行且具备 Python；失败保留表单和真实原因，不把目录存在称为连接或账号有效。Linux 同 UID 目录元数据与模拟传输/界面检查不等于 Windows/WSL 真机或打包验收，真实平台证据另行记录。没有新增权限、跨平台 WSL 入口、CLI 启动、账号迁移或模型请求。
