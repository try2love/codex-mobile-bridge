# Agent Note: 原生持久侧边聊天与标准聊天界面复用

Status: implemented

## 问题

Bridge 的临时侧边聊天由独立运行时持有，无法作为原生侧边聊天在 Codex App 中查看。原 App 创建的侧边聊天又被混入普通聊天列表，父子关系和关闭语义不一致。

## 决策

原生父子归属只采用 `attached_thread_parent_id`，普通 `forkedFromId` 不等同于侧边聊天。聊天列表在分页之前隐藏父聊天仍处于当前配置可访问范围的原生子聊天；父聊天缺失或不在此配置范围时保留子聊天，并标记其身份，避免历史消失。已归档子聊天仍包含在父聊天的侧边聊天目录中。

退出及归档的任务检查覆盖 attached 与 subagent 两种关系组成的完整后代集合。删除回执的存在性检查只接受上层已核验权限的标识集合，不扩大访问范围。

新建调用原生 `thread/fork` 的 `attachToSource: true`、`excludeTurns: true`，不传 `ephemeral` 或 `deferGoalContinuation`。先核对当前安装运行时的 schema，再提交；不支持时明确拒绝，不退回临时聊天。创建沿用父聊天的配置目录、模型、思考强度、权限和工作目录，并写入侧边讨论的边界，避免继承历史被误当作待执行请求。元数据进程不调用 `turn/start`，正常释放后仍由标准聊天连接路径接续；不会在被动列举时切换原 App 前台。

创建复用已有持久操作账本。响应丢失后相同操作 ID 不重复 fork；原生已返回子 ID 后，后续校验或注入失败也保留该 ID，供用户核对。原生关系和模型配置确认后才追加边界与标题。

父聊天保留工作台“侧边聊天”标签，标签内显示可访问的原生子聊天及共享会话菜单。创建或点击子聊天进入现有完整聊天路由，保留原生子 ID；输入区、附件、审批、停止、通知和历史均复用标准实现。子聊天提供“返回主聊天”；关闭目录标签或子聊天视图只离开视图，不停止、归档或删除。升级前已打开的旧临时页面仍可完成原生命周期，但新版入口不再创建临时运行时。

## 备选方案

继续使用临时独立运行时能保留原面板，但与双端原生同步及持久保存的目标冲突。把全部 fork 都当作侧边聊天最省代码，却会隐藏正常分支，因此只使用原生 attached 字段。当前改动不通过 SQL 写入或改造 Codex 安装包伪造关系。

继续在侧边标签中维护另一套输入、附件和审批代码可以避免页面导航，但已经造成能力分叉。当前采用完整标准聊天页面，并明确返回父聊天；不增加第二套聊天控制器。独立元数据进程能沿用现有创建链路且无需前台操作，但无法借此保证当前已打开的原 App 父聊天立即刷新，因此不发送伪造的 owner 广播。

## 影响

`SessionStore` 仅增加元数据读取，旧 schema 保留原行为；不会启动或切换原 App 聊天。`test_store.py` 20 个测试、`test_native_side_chat.py` 4 个测试、`test_side_chat.py` 23 个测试通过。后者保留旧临时运行时的兼容检查，不把它作为新版入口。新增浏览器回归在本机 Chrome 与已有 WebKit 的宽、窄布局共 4 项通过，覆盖标准路由、共享菜单、未知响应重试身份及关闭不销毁历史；标准聊天未改变的发送与附件用例不重复执行。

使用安装包内运行时与全新 `CODEX_HOME` 创建父、子、孙三个原生聊天，仅注入合成参考文本，不发送模型请求。每次元数据进程退出后仍可读取相同 attached 关系，根目录只出现父聊天；主集成随后用同一组三个 fixture 验证删除并清理。第一次实验发现原生拒绝 `attachToSource` 与 `deferGoalContinuation` 组合，当前实现已遵循原 App 的参数组合。工作树 `.tmp` 的 receipt 只为本地证据，不提交。

明确边界：原 App 附属目录查询采用 `staleTime: Infinity`、`gcTime: 0`，未发现定时刷新或可验证的 follower 创建接口。新子聊天已是同一份持久原生对象，下一次读取目录可发现；本轮未验证当前已打开的父聊天即时新增标签，也未执行真实用户会话的模型收发或跨系统原 App UI 验收。不能据本轮元数据证据宣称双端即时显示已完全实现。
