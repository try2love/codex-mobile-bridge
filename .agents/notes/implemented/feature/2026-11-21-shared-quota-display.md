# Agent Note: 各接入复用额度窗口、圆环与额度池详情

Status: implemented

## 问题

PR #256 的手机标签栏双环只覆盖 Codex，PR #257 的紧凑模型工具栏与可展开额度池更适合共享，但其前端在不同面板重复渲染，后端存在按模型名称猜池、仅按 surface 缓存和刷新目录时间的问题。

## 决策

采用 #257 的紧凑模型小环、对齐窗口列、可展开额度池方向；`quota-display.js` 与配套 CSS 为唯一共享展示实现。Codex、Claude、ZCode 的账号窗口复用同一组件，余额仍保留金额。模型设置和原生聊天只消费适配器提供的 `quotaWindows`，不按 provider 名称复制展示规则。手机与宽屏使用同一独立“剩余额度”工具入口；模型设置仍保留额度区。入口拆分及共享状态约束见[独立额度工具](2026-11-22-remaining-quota-tool.md)。

Antigravity 的 `quota.py` 将原生额度池转换为既有 `windowDurationMins`、`remainingPercent`、`resetsAt` 格式。模型归属只接受明确原生成员或唯一精确名称，不依据家族名称猜测。缺失、布尔、非有限和越界数值为未知；明确零值保留。新 RPC 缓存按原生进程与账号隔离，读取前后核验，失败也限制重试频率；同身份失败保留成功值与时间，身份变化清空。模型目录更新时间不被额度刷新覆盖。

模型面板只在前台可见、具有窗口数据时每分钟读取，保留选择及展开状态；关闭、离开或销毁停止刷新。Claude 的手动查询边界保持成立。自动继续仍使用独立的 fresh 后端门禁。

来源：windowmmk 的 PR #257，提交 `6c69a3dcf4a2e4b9109b594ebae49227655b56dd`，作者 `196895690+windowmmk@users.noreply.github.com`。本地选择性改写保留贡献归属，不声明远端合并。

## 既有笔记审计

[自动继续与初版圆环](2026-11-21-quota-continuation-and-mobile-rings.md)部分重叠，显示由本文取代，自动继续决定保留；[Claude 手动额度](../bug-fix/2026-10-12-keychain-access-and-manual-quota.md)与[ZCode 每日额度](2026-11-03-zcode-official-daily-quota.md)为数据来源约束，继续适用。其余账号切换和接入记录不被本次展示改动取代。

## 备选方案

保留 #256 独立双环实现成本较低，但产生两套相同额度表现，不满足共享显示要求。整包应用 #257 保留贡献版更完整，但会复制前端和沿用不充分的缓存身份，因此按现有窗口契约整合。

## 影响

模型工具栏更紧凑，账号页和模型设置共享详细呈现；按实际数据支持任意窗口与每日 token，缺失值不等于耗尽。Antigravity 展示增加有界只读调用；源数据没有明确模型归属时只展示额度池。展示范围扩大不扩张自动继续授权。

## 验证

单元回归覆盖未知与零值、周窗口列对齐、账号和进程切换、迟到响应、失败保留时间、原生不支持时节流与目录时间不变。浏览器用真实共享资源及合成数据覆盖宽窄布局、展开详情、刷新和模型选择保留。真实上游额度与手机 WebView 未验收。
