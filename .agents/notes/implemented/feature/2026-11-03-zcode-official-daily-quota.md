# Agent Note: ZCode 官方账号显示按模型分开的每日额度

Status: implemented

当前已建立原生控制通道的接入，按[共享账号与 ZCode 状态记录](2026-11-04-shared-account-editor-and-zcode-readiness.md)使用账号绑定的原生额度查询；本文的日志回执继续作为严格的可归属回退，不放宽时间门禁。

## 问题

ZCode 免费账号给 GLM-5.3 与 GLM-5.3-Flash 分配不同的每日额度。已有账号页面能展示额度窗口，但 ZCode 适配器没有提供可核对的上游数值。

## 决策

网关按需读取当前本机 ZCode 原 App 已取得的官方账单回执，并显示官方查询时间。只接受来自本地原生 host 的官方成功查询，按订阅、模型、每日 entitlement 和有效周期关联剩余及总 token。账号页共用现有额度卡、剩余进度和刷新入口。手动刷新重新检查本机回执；登录发生变化后丢弃旧缓存。没有可归属的回执时显示数据暂缺。

回执本身没有用户 ID。适配器只在单一官方登录来源可确认时工作，根据官方凭据文件的最近变更时间排除可能属于上一次登录的回执；读取前后复核同一代登录，过期或无法确认的数据不显示。网关不解密原 App 的登录材料。此能力与会话调试端口无关。

## 备选方案

让原 App 的私有 host 服务立即向官方重新查询，能得到更近的读数，但普通启动的 ZCode 没有为本机外部客户端开放该入口。用会话统计估算剩余额度不能反映其他设备的消耗，也无法准确处理独立的模型额度桶。

## 影响

Mac 原 App 的免费账号回执和本机读取结果一致，GLM-5.3 与 Flash 两个额度桶保持独立。用例覆盖零余额、切换登录、错误 host、有效期、链接边界和共享账号页显示。检查不产生模型请求。原 App 尚未查询、当日回执已过期或已滚出日志读取范围时，网关不能提供当前数值。此前[账号快照和切换](2026-10-31-zcode-shared-capabilities.md)的权限边界继续适用。
