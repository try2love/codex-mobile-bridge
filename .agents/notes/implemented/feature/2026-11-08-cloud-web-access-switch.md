# Agent Note: 桌面独立授权网页云访问

Status: implemented

## Problem

用户要求桌面端决定是否允许网页云访问，并选择同账号网页访问总开关。原 Web 通道随云账号登录自动连接，缺少独立的桌面授权。

## Decision

桌面云服务增加“允许网页访问本电脑”，默认关闭，已有安装升级后也不自动授予。许可按精确服务器 Origin、账号和网关身份存储，重启保留；切换账号不会继承其他作用域许可。浏览器仍使用云账号登录，不增加逐浏览器审批。

许可独立于手机中继、手机可信密钥、直连和云账号登录状态。只允许本机管理 IPC 修改，操作携带当前身份和许可 revision，过期界面不得授权新账号。关闭先设置当前账号作用域的运行时拒绝，再保存并取消网页请求、销毁网页本地会话、断开网页 WSS；磁盘失败时本次运行继续拒绝，明确提示重启前修复存储，并提供只保存关闭状态的重试入口。开启只在成功持久化后解除拒绝，异步连接也核对 revision。网页通道关闭不退出云账号或改变手机许可。

`cloud_access.WebAccess` 保存独立 `cloud-web-access.json`，只接受布尔值和安全整数 revision，损坏或不可读时关闭。运行中的桌面快照经本机管理通道取当前拒绝状态，旧网关未提供此字段时禁用新控件并要求重启新版网关。云端不保存此许可，只按通道是否在线提示检查桌面网页访问设置或版本。

## Alternatives considered

- 逐浏览器批准能细分设备，但用户明确选择总开关。
- 把许可加入现有 cloud-account.json 可减少配置文件，但该配置变化会使手机中继重新连接，因此采用独立许可存储。

## Testing

2026-11-08：111 项 cloud Python 测试、19 项资源布局/网关状态/离线管理测试、45 项 Node 云面板与 IPC 测试通过；模块边界检查通过。用例覆盖默认关闭、持久化与作用域隔离、旧 revision、畸形许可、关闭销毁真实本地 HTTP 授权并取消流、关闭后再开启拒绝旧连接、存储失败运行时拒绝，以及手机通道不被 Web 开关修改。

164 项浏览器测试在本机 Edge Chromium 与 WebKit 宽/窄视口通过，实际加载生产面板、CSS、翻译，检查总开关、写入参数、手机权限独立、中文与英文反馈和无横向溢出。旧浏览器夹具还期待被先前源码移除的后台资格刷新，现与 Node 回归一致：初始及定时渲染只读，延迟资格测试由显式点击发起。

Windows PyInstaller 网关和沿用现有 shell 的 app.asar 已构建。Android 入口缺少项目要求的 JDK 17，iOS 入口受限于 Windows 无 macOS/Xcode，均未完成编译；手机真机未验证。测试截图与安装校验存入 `.tmp/web-access-20261108/`、`.local/web-access-update-20261108/`，不提交。

本机安装已更新并复核哈希，云中继 connected，网页许可为 false/revision 0，3 个既有手机配对和稳定数据哈希未变。Edge 真实登录态刷新云目录后显示网页未就绪且无连接入口；真实账号没有被自动开启权限。云端提示已部署，HTTPS 资源与原生入口健康检查通过，数据库、HTTPS 和 P2P 容器未变。

## Consequences

用户可独立撤销网页访问，升级后需要主动开启；许可文件和本机运行时状态成为需要同时维护的边界。磁盘无法保存关闭状态时只能保证本次进程拒绝，必须明确报告并在重启前修复；已交给编码客户端执行的写入无法撤回，也不得重放。若后续需要区分浏览器身份，应另行设计逐浏览器授权，不从当前总开关推断设备信任。
