# Agent Note: 明确选择桌面更新渠道并保留当前资料

Status: implemented

## 问题

正式版不能主动检查预览版，预览版也不能经应用内的明确确认返回较低的正式版。旧更新器只允许升级；直接放宽版本比较会把未经检查的历史版本引入现有账号、授权和草稿资料。Linux 原本没有受支持的应用内 ZIP 替换事务。

## 决策

后台检查沿用当前安装的渠道。用户显式选择另一个渠道后只获得候选，安装前使用原生确认框展示当前版本与目标版本，并绑定该次检查的不可变候选身份。检查代次、渠道变化或正在进行的写入会使旧确认失效。

签名清单保持 schema 1，新清单签入 `dataFormat: bridge-data-v1`。此字段标识本轮真实保留的数据格式，不是任意历史版本兼容保证。较低版本只开放 `2.2.2-preview.N` 返回精确 `2.2.1`，同时要求 `return-stable` 意图；同版本、未知较低目标、未知资料格式继续拒绝。选择更新的正式版属于升级，仍允许 `return-stable`，但该意图不能安装预览目标。私有 worker 在替换前独立核对安装内 `update-version.json` 的当前版本与 transition 的 `from`，并检查 `to` 与已验签目标一致。没有 transition 的既有升级控制器保留原协议。

本轮源码对照确认：`v2.2.1` 与当前版本的设备授权存储、客户端登记、账号身份和草稿命名空间一致。新增账号字段是可选的路径来源及独立共享服务退出回执；旧正式版忽略新回执，不能由它授权切换或重放请求。回退时，配置必须为已知容器，登记必须为 version 1，账号索引与设备授权关键字段必须可识别，账号切换必须已完成，未完成账号恢复会拒绝回退。此检查不初始化账号服务、不运行候选程序的 snapshot，也不连接原客户端。

Mac/Windows 更新助手在原控制器退出、受管网关正常停止后重新读取当前配置并建立安全副本，再替换应用。副本位于当前资料目录的 `update-backups/<随机目录>`，独立于应用旁的临时事务；每个文件记录 SHA-256 与大小。Unix 目录为 0700、文件为 0600；Windows 复用已有受保护的当前用户专属 DACL。白名单只含 Bridge 配置、授权、连接、登记、已保存账号凭据与必要元数据；不复制原生聊天、工具、Claude 的 Cookie/LevelDB 等不透明资料，也不跟随外部配置目录或符号链接。它是有限的安全副本，不是完整原生资料归档。

用户回退和安装失败恢复都只替换应用程序，继续使用当前资料，不恢复旧用户目录或旧账号快照。副本不会因事务清理删除。准备阶段只预检；应用真正替换前再次检查并备份最新值，以保留准备后新增的账号或授权。

Linux 新清单签入 x64/arm64 的 DEB 与 AppImage 名称、大小和 SHA-256；发布核验同时校验这四项与原三项桌面 ZIP。下载必须先通过发布签名和内容摘要。DEB 交给系统安装器，AppImage 保留文件并交用户手动处理；没有新增自动替换、提权、sudo 密码或安装完成声明。旧 `2.2.1` 清单未签 Linux 资产，用户确认后先建立当前配置副本，再提供精确官方发布页，不能用非签名 SHA 清单替代发布签名。Linux 的备份逐文件读取，不宣称运行中各配置构成跨文件事务快照。

## 备选方案

允许所有同名数据格式的历史版本回退可以覆盖更多版本，但现有正式包没有兼容性声明，也没有逐版本回退证据，因此只保留精确检查过的组合。恢复升级前的整个用户目录容易回到旧格式，但会丢弃预览期间新增的账号、配对和草稿，因此不采用。

在 Linux 新增完整 AppImage 替换事务可以自动重启，但当前没有该平台的应用退出、替换、健康确认及失败恢复链路。复用系统安装器与明确手动交接能保持真实能力边界，旧清单缺签名的下载继续由用户从官方发布页处理。

## 影响

跨渠道操作有独立确认和精确目标绑定，默认后台渠道不被一次性选择改变。备份含私有认证资料，保留在原资料目录的独立私有子目录，只返回路径与文件数，不输出内容。新增备份占用有限磁盘空间，默认不自动清理；单文件 16 MiB、总量 64 MiB、数量 10,000 的边界防止把非配置资料纳入副本。

定向源码回归覆盖签名、渠道、候选确认、Linux 安装方式、篡改 Linux 包且重算 SHA 清单仍被拒绝、备份权限与摘要、账号/授权保持、备份独立留存、符号链接拒绝和成功/失败回退均只恢复应用。原生成品升级、返回正式版和平台安装器是否完成，以单独的成品验收记录为准，不以模拟用例代替。本机源码测试未连接真实账号、退出日常客户端或执行系统安装。

既有[更新交接归属](../../implemented/bug-fix/2026-11-03-desktop-update-handoff-scope.md)、[父进程退出判断](../../implemented/bug-fix/2026-11-10-desktop-update-parent-exit.md)和 [Windows 持有进程预检](../../implemented/bug-fix/2026-11-10-windows-update-zcode-holder-preflight.md)继续有效；本记录补充用户明确选择版本及数据保留，不替代这些决定。
