# Agent Note: 新建会话在首次输入前确认模型与思考强度

Status: implemented

## 问题

Issue #131 要求在四种 Agent 的新建会话中选择模型和思考强度。Claude 和 ZCode 的原生创建会直接发送首条消息，创建完成后才切模型会先使用默认接入产生一次推理。只读取账号管理中的全局模型列表也不能证明所选项目的配置、CLI 原进程环境或独立 Codex 配置目录相同。

## 决策

Web 与手机的新建弹窗使用同一 `CreationModelPicker`，复用现有模型目录格式、能力字段和 `ModelStore`。已确认的原生当前模型或唯一 `isDefault` 可以作为初值；没有默认依据时要求用户选择，不按目录顺序选择第一项。思考强度只显示原生提供的档位，保留原生手动输入能力；明确 `supportsEffort: false` 的模型不显示手动强度入口。目录刷新保存到原有同作用域缓存；晚到响应不能覆盖另一项目或环境。缓存目录核验期间允许操作，用户编辑会增加选择版本；同一身份下晚到的初次响应保留这次选择，账号或目录身份改变仍清空并要求重选。提交动作在异步目录注册之前快照模型、强度和身份，后续刷新不能改写已点击提交的意图。

新建请求携带 `model`、`effort` 和 `modelCatalogIdentity`。实际创建前重新核对账号/环境及目录身份，拒绝已失效选择；旧请求没有这些字段时保留原客户端行为。配置或账号变化不会自动改选新的默认模型，需要用户重新选择。

### 各原生创建入口

- Codex App、CLI、SSH 和 WSL 的 `thread/start` 同时传递 `model` 与 `config.model_reasoning_effort`，核验创建回执，不调用 `turn/start`。Desktop 临时创建者退出后，显式创建流程还要将选择交给原 App 的实际 owner 并回读确认；只核对临时运行时不能保证原 App 的首次发送。独立 Codex 的空项目使用当前接入 ID 和自己的数据目录，不路由到默认 Codex 账号。
- Claude Desktop Code/Cowork 的同一次原生 `start` 携带模型、强度及首条消息。本机已安装 App 的 `startSession` 源码确认消费这些字段；不修改安装包。
- Claude CLI、SSH 与 WSL 复用 `creation_launch_options`，通过原生 `--model`、`--effort` 设置本次进程，初始化后只读核验 `get_settings`，然后才写第一条 `user`。设置只作用于本次子进程，不改账号或项目配置。默认强度按原生 `auto` 语义处理。
- ZCode 的同一个 `createSession` 同时设置 `config` 和 `firstInput.modelSelection`，不先按默认模型发送。
- DSH 先创建不含消息的空会话，再通过原生 `selectModel` 回读确认，之后才返回可发送状态。新能力由 `createModels` 明确声明；旧插件拒绝新模型创建参数时返回已知未派发状态，不能静默忽略或留下未知首条发送回执。插件主源与 revision 由本轮整合统一同步。

### Codex Desktop 原 owner 交接

空聊天的临时 app-server 退出后，原 App 可能重新采用默认模型与强度。显式创建先持久化聊天 ID，再用既有模型设置路径完成原 owner 交接。设置前确认聊天 ID、cwd、provider、空会话和空闲状态；有强度时复用现有能力校验，无强度控制时只更新模型，不虚构 low 等档位。不修改全局账号或项目配置。

创建记录的 `modelSettingsPhase` 为 pending、unknown 或 applied。owner 未就绪保留 pending，原请求继续同一个聊天；写入前保存 unknown，结果不明只回读，不能重放。完成后重复请求只返回原 ID，不覆盖之后在电脑端的改选。被动历史、进入已有聊天、订阅和发送均不增加设置写入，CLI 保持原 daemon/runtime，不增加桌面交接。失败沿用创建弹窗与请求 ID，并明确说明聊天已创建但模型尚未应用；实际状态未确认前不显示假的已选择值。

### 缓存、配置与回执

Codex Desktop 的新建目录按目标 cwd 读取，不借用全局账号目录代替项目配置。共享 `Catalog.model_identity` 纳入 cwd 及父级候选 `.codex/config.toml` 摘要，项目层覆盖改变会使旧目录失效；摘要不包含可公开还原的配置或凭据。CLI/SSH 复用原 daemon 的有效配置、账号和执行环境证明及 `native_model_store`。WSL 复用现有 `WslModelCatalog`；没有线程的新建预览不添加线程巡检定时器。

原生配置与身份已核验、但上游模型目录不可用时，无旧缓存的响应仍携带该身份，状态明确为 `unavailable`，不附成功更新时间、不保存空目录。这样既有手动填写入口能通过创建前的身份复核；此前虽显示手动输入，却因缺少目录身份始终无法提交。同身份已有缓存时继续优先返回旧模型及原时间，账号或项目变化仍拒绝旧选择。此规则不能绕过运行时缺失、配置读取失败或未知执行环境。

Claude Desktop 按 Code/Cowork 过滤同账号缓存。Claude CLI 优先复用同账号、主机、目录的模型缓存；没有已接入会话且没有可复用目录时允许明确手填，不为探测目录持有新的 CLI 会话。此时手动刷新不能伪称取得了新目录，保留缓存和时间并说明限制。本机目录选择不会额外访问不相关 SSH 主机。

新建、聊天设置和账号目录按已核验的执行身份共用模型目录。Claude Desktop、DSH、ZCode 的新建和聊天设置都从同一账号目录取得数据；Claude 的 Code/Cowork 使用目录身份加 surface 的投影身份，并保留完整分组。已有原生分组缺少目标 surface 时返回空目录，不能借用另一个 surface 的模型；只有明确的纯 API 分组可共用上游模型。返回的 `cache.directoryIdentity` 与 `cache.surface` 让前端同步基目录更新，同时保持投影边界。

Codex Desktop 的新建和已有聊天都按真实 cwd 读取目录，不用全局账号目录覆盖项目配置。原生 `config/read` 已确认的默认 provider 可与相同显式 provider 归一；别名随完整配置指纹失效，不把未知默认值猜作 `openai`，也不在被动会话展示时启动探测。CLI、独立配置、SSH 和 WSL 继续使用完整主机、账号与项目身份，不能为共享缓存跨过配置边界。

前端共用 `BridgeModelCatalogCache`，按网关、主机、接入实例与服务端目录身份保存模型数据。新建项目查询只登记到已核对身份的别名；账号面板刷新可更新已知 Code/Cowork 投影，新建和聊天设置不再各保存一份会互相过期的目录。缓存只保存模型和来源元数据，不缓存会话当前模型、思考强度、权限或连接状态。较旧响应不能覆盖较新的成功刷新；账号切换清理对应接入的目录和别名，退出登录清理全部内存缓存。未取得可靠身份的会话仍先请求核验，不提前显示其他作用域目录。

项目、正文、模型和强度属于创建意图。`modelCatalogIdentity` 与环境版本属于执行前置条件：刷新它们不能将未知创建变成新请求 ID，也不能绕过已有未知回执重发首条消息。明确未派发的阻止结果允许用户修正后显式重试；已有创建回执按原 ID 返回。

## 备选方案

先按默认模型创建并发送，再切换设置，容易复用原按钮，但无法避免第一次收费请求，故不采用。DSH 的空创建没有消息，属于可在首条前完成配置的原生路径。

Claude CLI 在初始化后调用既有 `set_model` 看似可直接复用聊天设置，但本次隔离原生验证未得到成功确认。采用官方原生启动参数并只读核验，既不需要第一条消息建立运行状态，也不会为验证设置而调用模型。

使用全局账号模型缓存可以减少读取，但会绕过项目覆盖和 CLI 原进程环境；每个页面独立建立新缓存又会重复刷新、保留不同版本。因此复用已有按执行身份保存的目录，并将视图投影与会话状态分离；不能证明作用域时不跨账号复用。直接把默认 provider 写死为 OpenAI 可以消除一部分重复键，但会错用自定义上游，故只采用原生读取已确认的别名。

仅把创建选择存到网页能保持显示，却不能改变首次发送实际继承的原 App 设置；在每次 attach 或发送时套用选择又会覆盖电脑端后续改选，因此只在显式创建中完成交接。禁用缓存核验期间的选择可以规避竞态，但会让已缓存目录变成网络阻塞项，因此保留操作并按选择版本处理晚到响应。

## 验证

2026-11-08 的隔离复现分别发现：原 App 接管后 Astra/low 变成默认 sol/medium；缓存核验晚到覆盖用户改选；目录注册等待改变已提交选择。共享表单修复的 13 项 Node 用例通过，浏览器缓存选择用例在 Chrome/WebKit 宽窄四种组合通过。Claude Code/Cowork 的 1 项原生载荷夹具、ZCode 的 2 项 createSession 夹具及 DSH 独立 HTTP 创建/选模回读夹具通过，未发现三家漏传模型字段；它们均受共享表单竞态影响。没有调用 Claude API 或任何真实模型。

Codex 创建交接的隔离用例覆盖非默认模型双向切换、首次发送继承、model-only、未知回执只读核验、已创建 ID 保留、后续改选不覆盖、已有内容或身份变化拒绝以及 CLI 保持同 runtime。原创建套件 24 项通过、1 项 Windows 专用跳过。新增创建锁序回归改前失败、修正后通过；4 项受影响创建回归与 4 项现有模型设置/Fast 夹具通过。创建和公共设置入口共用已解析 session 的内部应用函数，持 action_lock 时不重新激活 owner。这里验证的是实际 Bridge 业务函数与协议夹具，不等于 Mac/Windows 原 App 和真机完成验收。

## 影响

首条输入与用户选择保持同一次原生创建语义，避免隐式默认模型消费。Codex Desktop 显式创建增加一次 owner 设置与回读；原 App 未就绪时保留原聊天并提示继续同一请求，没有新增常驻监听或轮询。缓存验证增加配置摘要读取；只读取候选配置文件，不增加全量目录扫描或额外 CLI 会话。需要目录确认或账号发生变化时，用户可能需要刷新并重新选择。

本记录不把原生参数/回显夹具等同于真实付费模型响应。Windows/Linux 使用相同创建与界面逻辑，三端构建和实际平台收尾由本轮整合另行核验；本文不宣称子 Agent 已完成三端真实模型收发。

2026-11-05 的缓存同步定向检查使用独立合成数据：Node 覆盖创建与聊天双向刷新、账号/主机/实例隔离、晚到响应、Code/Cowork 分组和显式 API 目录；Chromium 实际运行 14 项断言，包含刷新失败保留目录和时间、新建与聊天互相立即显示刷新结果、不继承另一聊天选中模型。未调用真实模型。用户随后暂停 Windows/Linux 验证，本轮后续成品验证范围为 Mac，不能将旧三端包的结果当作新改动已部署。

Mac 后端定向回归共 208 项通过，其中 11 项新增目录同步检查覆盖原生默认 provider 的首次读取与持久别名、账号/项目变更、旧合并接口刷新后采用新目录、当前 CLI owner 的能力隔离，以及 ZCode 切换工作区不重复取账号目录。模块边界检查通过，原 22 条历史例外未增加。没有真实模型或远端操作；被沙箱阻止绑定套接字的未运行 HTTP 夹具不计入通过数。
