# Agent Note: 聊天交互保留原生日期时间

Status: implemented

## 问题

消息标准化与页面渲染丢失原生交互时间，部分连接层还会在白名单投影时提前剔除时间字段。用接收时间补齐会使历史、刷新和重连产生错误日期。

## 决策

消息契约增加可选 `timestamp`：原生 epoch 毫秒或带明确时区的 ISO 时间。Claude Desktop 连接层保留事件 `timestamp`，Code/Cowork/CLI 的共用转换保留该字段。DSH 使用事件 `time`；ZCode 实时快照使用行 `createdAt`，只读历史使用消息表 `time_created`。Codex 历史读取保留 rollout 事件时间；原生回合 `turnStartedAtMs` 作为该回合首条用户消息的时间依据，不能把开始时间当作助手完成时间。

共享 `activity.js` 负责格式化，所有聊天渲染入口复用。日期按查看设备本地时区显示，当天为 24 小时 `HH:mm`，跨日补日期、跨年补年份，完整带时区时间保留在语义标签与提示中。缺失、无效或无时区的字符串不生成时钟；不使用会话更新时间、到达时间或当前时间替代原生证据。Claude/DSH 同一事件拆分的多个内容片段只显示一次时间。

已安装 DSH 的 `dsh-client-ui-chat` 源码确认 `formatMessageClock` 使用事件毫秒、当天/跨日/跨年规则，用户消息用 `data.time`，助手用 `closing.time`；ZCode 已安装源码从消息 `info.time.created` 投影为时间。应用包仅只读检查，没有提取发布第三方代码，没有连接或修改真实会话。

## 既有笔记审计

交互时间/时间戳检索命中账号缓存、通知事件和模型目录记录，均不拥有消息显示决定。历史与控制分离仍保持原有边界，没有可废弃的同主题提案。

## 备选方案

只改前端最小，但被适配器丢弃的时间无法恢复。统一用会话更新时间易实现，却会给全部历史消息标上同一个错误时间。保留原生瞬时时间和共享格式化既复用 UI，也允许没有证据的旧记录保持缺失。

## 验证

原生字段投影、Claude 白名单、Codex 历史/分页/增量、ZCode 保存历史、未知时间和时区偏移均有定向检查。四种聊天渲染通过 WebKit 与本机 Chrome 宽窄视口合成浏览器检查，确认可见时间、无横向溢出、无时间的旧消息不造值和刷新节点保留。

## 影响

所有客户端具备一致的原生交互时间展示；不引入新的后台观察或写入。当前是数据语义与共享界面的验证，未做各原生应用逐屏对照或 iPhone/Android 真机验收，不能称为全部原生版本的像素级一致。原生缺失消息时间时仍会缺失；Codex 仅提供回合开始时间的快照只标首条用户消息。
