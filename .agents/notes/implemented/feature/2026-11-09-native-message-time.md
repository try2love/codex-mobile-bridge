# Agent Note: 聊天交互保留原生日期时间

Status: implemented

## 问题

消息标准化与页面渲染丢失原生交互时间，部分连接层还会在白名单投影时提前剔除时间字段。用接收时间补齐会使历史、刷新和重连产生错误日期。

## 决策

消息契约增加可选 `timestamp`：原生 epoch 毫秒或带明确时区的 ISO 时间。Claude Desktop 连接层保留事件 `timestamp`，Code/Cowork/CLI 的共用转换保留该字段。DSH 使用事件 `time`；ZCode 实时快照使用行 `createdAt`，只读历史使用消息表 `time_created`。Codex 历史读取保留 rollout 事件时间；原生回合 `turnStartedAtMs` 作为该回合首条用户消息的时间依据，不能把开始时间当作助手完成时间。

首条用户消息的回合时间回退在共享标准化层完成，子智能体保存记录与主聊天使用同一语义。分页窗口中已省略的首条输入不能把时间转给后续引导消息。CLI 和临时侧聊保留原生 `turn/started` / `turn/completed` 中以秒表示的 `startedAt`，转换为现有 `turnStartedAtMs`；同一原生消息的后续快照省略 `timestamp` 时保留先前收到的时间，明确提供新值时使用新值。无自身时间的助手消息仍保持缺失，不用回合开始、完成通知到达或当前时间填补。

连接后的 `LiveSession.view()` 仅以同 session、turn、原生消息 ID、类型和角色的唯一键从保存视图补齐时间。rollout `response_item` 保留明确的原生 ID；缺失 ID 的显示序号带 `_syntheticId`，不能参与关联。`_timestampSource` 区分日志消息记录、原生 `item_completed` 完成事件及 `native-turn-start` 回退；精确消息时间优先于首条用户的回合开始回退，实时消息自身已有时间则保持。重复键、不同原生 ID 的重复文本及跨会话或跨回合记录均不关联，不修改实时控制状态。

实时快照没有消息时钟时，既有后台历史刷新也覆盖已连接的本机会话。它从有界展示缓存提取缺失时间的原生消息身份与回合状态，同一组最多补读四次，使用现有退避与在途合并；文本增量和轮询序号不会重置预算。新的消息或回合状态允许新的有限读取；时间补齐后不再读取。SSH 仍不引入后台历史轮询。仅时间变化时，前端只更新操作栏时钟，保留正文、选区和播放器节点。

原生索引优先读取仍保留项目原有的分页与只读边界。索引消息缺少时间时，额外读取最多 2 MiB rollout 尾部，只按稳定身份补充消息记录时间或 `item_completed.completed_at_ms`，不调用完整历史读取。截断首行不参与解析；缓存身份包含 thread、文件路径、设备、inode、大小与纳秒修改时间，返回索引前再核验文件状态。原生索引消息已有时间时不覆盖。日志消息自身仅有记录写入时间时，可由同一唯一原生 ID 的明确完成事件提供完成时间；没有完成时间字段的完成事件保留其原生日志时间。超出尾部预算或缺少可靠身份的旧记录仍可能没有时间。

共享 `activity.js` 负责格式化，所有聊天渲染入口复用。日期按查看设备本地时区显示，当天为 24 小时 `HH:mm`，跨日补日期、跨年补年份，完整带时区时间保留在语义标签与提示中。缺失、无效或无时区的字符串不生成时钟；不使用会话更新时间、到达时间或当前时间替代原生证据。Claude/DSH 同一事件拆分的多个内容片段只显示一次时间。

消息操作栏按复制、引用、具备能力时的编辑或分支、时间排列。初建和后续增加操作按钮均把时间放在末尾，时间跟随按钮，不以自动外边距推到整行右侧。子智能体保存详情提供复制、引用和时间；引用复用现有草稿组件，在点击时核对当前工作台以及完整 provider、host、session 身份，切换聊天后不把旧详情写入另一个草稿。只读子智能体记录不推测编辑或分支能力。原生侧聊使用标准聊天时间线与同一操作栏。

已安装 DSH 的 `dsh-client-ui-chat` 源码确认 `formatMessageClock` 使用事件毫秒、当天/跨日/跨年规则，用户消息用 `data.time`，助手用 `closing.time`；ZCode 已安装源码从消息 `info.time.created` 投影为时间。应用包仅只读检查，没有提取发布第三方代码，没有连接或修改真实会话。

本机两份原生日志的字段级只读核验确认：助手 `response_item.payload.id` 分别有 7/7 与 2/2 条与 `item_completed.item.id` 对应，完成事件携带明确 `thread_id`、`turn_id` 及 `completed_at_ms`。核验只提取字段形态与匹配计数，不输出聊天正文、不启动模型。该证据证明当前日志格式的关联途径，不保证没有原生 ID 的旧版本记录可恢复。

## 既有笔记审计

交互时间/时间戳检索命中账号缓存、通知事件和模型目录记录，均不拥有消息显示决定。历史与控制分离仍保持原有边界，没有可废弃的同主题提案。

## 备选方案

只改前端最小，但被适配器丢弃的时间无法恢复。统一用会话更新时间易实现，却会给全部历史消息标上同一个错误时间。保留原生瞬时时间和共享格式化既复用 UI，也允许没有证据的旧记录保持缺失。

## 验证

原生字段投影、Claude 白名单、Codex 历史/分页/增量、ZCode 保存历史、未知时间和时区偏移均有定向检查。实时事件替换回归覆盖 CLI、临时侧聊和有原生开始时间的首条输入，检查不把时间转给窗口内后续输入或没有时间的助手。浏览器回归覆盖复制与引用顺序、动态增加编辑或分支按钮、子智能体详情、原生侧聊及切换聊天后的引用隔离。WebKit 与本机 Chrome 分别运行宽窄视口合成检查，确认时间邻接按钮、无横向溢出、旧消息不造值和刷新节点保留。

存档补齐的 10 项专项回归覆盖稳定身份与来源、双侧重复键、重复文本、跨 session/turn/type、回合开始回退优先级、索引原生时间冲突、同 inode 修改失效、缓存复用、字节预算与首行截断、线程隔离及扫描中修改拒绝。与原有时间、历史路径和控制分离套件合计 31 项检查完成，其中 30 项通过、1 项 Windows 扩展路径检查在 macOS 预期跳过。既有增量测试另确认仅时间变化、正文版本不变时仍推送新行；前端对完整行进行比较，因此该更新会重绘时间。

2026-11-12 真实 8788 Test 对照：反馈音频聊天处于历史模式时，五条助手回复都有原生时间；另一个正在运行的真实聊天 `connected=true` 时，一条助手回复没有时间，同一行身份在本机原生索引中已有明确完成时钟。根因是历史刷新跳过所有已连接会话，已有补齐函数一直使用旧保存视图。新增两项回归先失败再通过，覆盖不重连、不改实时状态、退避上限及新消息继续补读；时间和历史/控制隔离相关 27 项通过。页面也复现了迟到时钟重建消息的问题，补读后按时钟单独更新，保留媒体节点。真实网关安装新版后的在线补齐仍纳入最终验收。

## 影响

所有客户端具备一致的原生交互时间展示；复用既有后台读取，不增加独立巡检定时器或写入。当前是数据语义、共享界面及上述真实只读对照，未做各原生应用逐屏对照或 iPhone/Android 真机验收，不能称为全部原生版本的像素级一致。原生缺失消息时间时仍会缺失；Codex 仅提供回合开始时间的快照只标首条用户消息。
