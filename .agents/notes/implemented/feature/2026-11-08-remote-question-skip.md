# Agent Note: 远程逐题跳过异步问题并保留其他草稿

Status: implemented

## 问题

原生 Codex 的异步问题可以只跳过其中一道，Bridge 原先要求回答卡片内所有问题。原生 App 的跳过状态只在 renderer 内存中，尚无已验证的 IPC 读写来源；不能通过伪造答案、提交空回答或修改原 App 实现双端同步。用户接受先提供网关范围的逐题跳过，其他问题仍由用户明确回答。

## 决策

共享 `QuestionSkips` 以网关数据目录、宿主机和 Codex 配置目录区分实例，再按聊天、请求和问题 ID 保存跳过状态。文件仅保存不透明标识，使用现有私有 JSON 写入函数持久化，权限为 0600；落盘成功后才发布状态。重复跳过返回相同回执，写失败不隐藏问题。状态不随重连或网关重启丢失，不新增轮询或监听。

现有 respond 接口接受 `action: skip` 和 `questionId`，只校验当前已连接原会话中的异步问题，不激活会话、不提交消息、不调用模型。视图、通知和后续回答校验复用同一投影，原始历史及退出安全判断保持原生数据。命令、文件和权限审批仍走原有原生请求，不能用跳过绕过授权。已经送达系统通知中心的历史通知不撤回。

共享 Web 卡片按问题 ID 复用控件。跳过只移除目标问题及其未提交草稿，同卡片其他问题和其他卡片保留原 DOM 与输入。确认后的 HTTP 回执只作用于当前仍存在的目标，不能用旧请求列表覆盖更新的推送状态。正常回答仍显式提交剩余问题；发送完成 owner 解析后，在 action_lock 内重新核对问题和文本，避免与跳过竞态或与 CLI 主动释放形成反向锁顺序。

这是 Bridge 手机/Web 之间共享的跳过状态，不宣称原生 Codex App 的局部跳过与远程双向同步。原生端随后提交真实答案时，既有历史解析继续生效。若将来取得可信原生跳过协议，再另行决定合并和迁移规则。

## 既有记录核对

[跨轮次保留异步问题](../bug-fix/2026-10-28-pending-async-cards-across-turns.md) 部分重叠：历史解析、原生接口缺口和不伪造回复继续成立。本篇是用户明确接受局部跳过后的新决定，取代旧篇“不添加只清除 Bridge 卡片入口”的范围限制；不改写旧理由，不把局部能力描述为原生同步。相关通知、侧边聊天及创建模型记录职责独立，未被本篇吸收，无需归档或删除。

## 备选方案

- 完整原生双向同步最符合最初目标，但当前没有可信读写来源，读取或注入 renderer 内存也不符合原 App 接入边界。因此保留明确限制。
- 只在前端隐藏无需落盘，但刷新后会重现，通知和其他手机仍认为待回答。共享网关投影避免各端复制规则。
- 提交空回答可以沿用原回复接口，却可能让模型继续并消费额度，还会改变其他问题语义，因此不采用。

## 验证

隔离 IPC 用例先复现无法跳过，再覆盖逐题跳过、其他问题照常回答、持久恢复、普通审批不可跳过、重复回执和发送前并发校验。存储夹具覆盖配置/宿主机/聊天/请求/问题隔离、0600、写失败和不修改原生历史。通知套件 55 项通过；完整 Bridge 套件首轮 108 项通过、2 项 Windows 专用跳过，锁顺序调整后只重测受影响的异步回答用例。

浏览器在 Chrome/WebKit 宽窄四种组合验证同卡片与其他卡片草稿保留、跳过不发送其他答案、乱序回执不恢复已处理问题。最后 8 项通过。新增并发释放夹具首次把另一操作安排在已持有宿主机串行门的 send 内，得到预期阻塞而非业务失败；改为在 send 进入门之前交错两条操作后通过，未放宽生产串行门。

本轮没有操作真实用户卡片、调用模型或宣称原 App 双向同步。运行中 Test 的覆盖安装与真机验收独立于这些源码夹具结果。

## 影响

远程可以独立处理多问题卡片，重连不恢复已跳过问题；共享实现覆盖 Web、iOS 和 Android。代价是每次首次跳过写入一个小型私有文件，标识记录随用户跳过数量增长。没有清空历史或自动过期，避免旧历史卡片再次出现。原生 App 仍可能显示它自己尚未跳过的问题，这是当前明确的范围边界。
