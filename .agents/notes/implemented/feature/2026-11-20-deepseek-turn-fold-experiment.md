# Agent Note: 独立分支的 DeepSeek 式过程折叠实验

Status: implemented

## 问题

完成耗时已使用原生回合数据，但平铺的长执行过程仍占据大量空间。用户要求在非折叠功能修复与两端模拟器验收之后，另开可丢弃的实验分支测试过程折叠，手测通过后才决定合并。

## 决策

实验从完整非折叠基线 `19bd0ed1` 开始，保持原生 `timeline/changes/detail` 读取与分页，不恢复过程目录或增加隐藏正文预取。只有原生回合身份、明确成功终态及最终回答标识同时存在时，中间思考、工具与明确 commentary 默认收起。用户输入、穿插补充、文件结果和最终回答保留在原位置。运行、失败和中断保持展开，未知回合或最终回答标识缺失时沿用平铺。

同一回合只增加一个完成入口，复用[原生耗时](2026-11-19-native-turn-completion-time.md)，没有合法起止时间就不显示数值。入口在第一条过程行之前；各消息继续是同级节点，收起只切换过程节点的展示类，不搬移媒体或建立嵌套容器。用户手动展开在当前会话增量刷新和历史补载时保留；新会话不继承。正在选择的过程文本不会被成功更新强行隐藏。

本决定是与[平铺基线](../simplification/2026-11-19-unfold-native-chat-process.md)并行的实验，不能据此自动合入本地集成分支。旧的活动分组与过程目录决定仍不恢复；本次只借鉴 DeepSeek 的原生回合、最终回答锚点以及运行/错误/中断保持展开的规则。

## 备选方案

恢复旧的整轮包装容器可以复用更多旧 UI，但会重新引入多层分组、过程目录和跨页读取边界；因此只使用现有平铺消息与一个状态入口。把最后一条助理消息一律当最终回答可以覆盖更多适配器，却会隐藏尚未确认的中间说明，因此证据不足时保留平铺。

## 影响

成功长任务可快速收拢，原生补充输入仍可见。没有明确最终回答元数据的客户端可能继续平铺，这是实验边界。浏览器合成回归覆盖运行到成功、失败/中断、缺时间、缺最终回答、空闲回退、手动展开与历史补页；移动端由已安装的 Test 壳在隔离合成服务中验收，不发送真实模型请求。Android API35 已实际点击完成/展开/刷新/失败并保存原生截图及状态；iOS18.2 官方 XCUITest 两项通过，覆盖成功、中断、手动展开、键盘与选择框。所有业务 POST 为零。用户实际测试是是否合并的最终依据。
