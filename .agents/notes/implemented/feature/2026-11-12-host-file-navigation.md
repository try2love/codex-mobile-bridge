# Agent Note: 文件页支持只读宿主机目录导航

Status: implemented

## 问题

#160 要求文件页从聊天项目目录开始，支持上级目录和完整路径导航；没有项目目录的聊天从已核验的原生记录位置开始。原实现把浏览、上传和发送引用全部限制为项目相对路径，无法定位项目外的文件。

## 决策

现有工作区接口增加明确的 `scope=host`，只开放列表、元信息、预览和下载。文件页复用原工作台、目录列表、缓存、预览与下载组件，增加可编辑的完整路径；服务端返回绝对路径和父目录，浏览器不猜测 Windows 盘符或根目录。再次进入文件标签页保留既有列表，定位优先复用已加载目录；异步元信息定位使用代次避免迟到请求覆盖后续操作。

宿主机路径仍通过原有目录句柄和普通文件检查，不跟随目录中的符号链接、Windows junction 或重解析点。Windows 只接受本地盘符以及当前项目已选中的 UNC share，不能通过新输入触发另一网络共享的凭据访问。SSH/WSL 在目标端执行同一独立模块，不在网关机器解释远端路径。

聊天消息中的文件使用同一只读入口。新增路径映射只解析实际显示的 Markdown、文件引用或原生附件，不在列表渲染时读取磁盘；用户点击后，目标主机上的工作区接口再检查文件身份、权限、链接和下载大小。路径解析独立于网关系统，避免 Windows 网关把 SSH/WSL 的 Linux 路径解释为本机路径。外部 URL、新网络共享和目录穿越不生成宿主链接。

旧的可信图片 artifact 保留 ID 和原生预览；新增宿主文件标为 `image=False`，项目外图片先显示文件链接，不能单凭模型正文触发自动图片读取。音视频仍使用不预加载的共享播放控件。旧 artifact 的元信息也返回绝对路径以便定位，原下载权限不变。

列表与元信息另返回 `projectPath`。只有原项目内目标可以上传或引用到消息，引用前仍重新核验；Git、上传和引用接口不接受宿主范围。回形针选择器继续使用项目相对路径。原生 cwd 不因文件浏览而变化。无 cwd 的 Codex 使用 Store 已核验的 rollout 路径作为初始目录，不能推测一条尚不存在的聊天记录。

## 备选方案

把所有操作的根目录改为磁盘根可以减少接口参数，但会同时扩大上传、Git 和模型附件范围，故不采用。新增独立文件管理器会复制现有分页、预览、下载和移动端交互，因此继续在共享工作台中实现。启动时扫描全部盘符与网络共享会增加阻塞和外部访问，改为用户输入完整路径。

## 影响

文件页导航、聊天消息链接和其他客户端无 cwd 的记录定位分别提交。Claude Code/Cowork 先通过原生 getSession 核验 ID，再在已验证的 dataHome 中定位唯一 metadata 文件；Cowork 的 VM 路径不会冒充宿主目录。Claude CLI/WSL 使用原生记录路径；Antigravity 保留 APP/CLI/IDE 各自目录，优先真实 transcript，否则使用已存在的 summary DB；ZCode 使用已核验 task 对应的正文或索引数据库；DSH 仅在插件提供 sessionPersistence.stat 且返回同一 ID 的真实 JSONL 位置时启用。旧插件或尚未落盘的聊天不猜测目录。记录位置复用原有 10 秒和 binding epoch 缓存；用户明确输入完整路径时不再等待不可用的记录位置。

五项宿主文件回归、十五项既有工作区检查通过；其中四项 HTTP 需放行本机监听后通过。十二项前端相关检查通过，复审发现的迟到定位请求另补一项回归。真实 Chromium 使用生产 GatewayServer 完成十一项导航、预览、缓存和引用边界检查；320px 窄屏十二项通过，路径输入宽110.6px，无横向溢出。Windows 和 Ubuntu 均通过隔离原生目录、Range 下载、根目录和项目写入限制验证；Windows 还验证了新 UNC 与 NTFS 替代数据流拒绝。最终桌面程序和手机仍需安装后验收。

消息链接补验包括六项新 Python 检查（含实际 WSL 时间线分页与完整详情调用）、既有 artifact/引用边界回归、桌面共享附件引用以及时间线检查；一项 Windows 专项在 Mac 跳过。前端十一项时间线检查通过。生产 HTTP 元信息检查通过，真实浏览器六项点击流程验证了项目外文本预览、绝对定位、下载入口以及图片不自动加载。独立复审未发现阻塞问题。

本改动按用户新授权部分替代[当前项目文件引用](2026-10-29-project-file-references.md)的只读浏览限制；发送引用与上传仍遵守该笔记的项目边界。[音视频播放](../bug-fix/2026-11-12-chat-media-playback.md)继续复用相同授权下载接口。

记录定位补验：七项专门检查、Claude 原生 ID 核验及 ZCode 存储位置回归、HTTP 登录和 scope 边界通过；DSH 两项原生插件契约检查通过。Mac 真实 Claude metadata 20 个文件均匹配定位函数；AGY 真实日志和 summary DB 路径布局对照通过，未冒充原生 API 端到端验证。ZCode 在 Python 3.12/SQLite 3.45.3 的正常 mode=ro 产品调用中六条全部成功（五条正文库、一条索引库）；更早的另一运行环境曾报 unable to open database file，未修改原生库或降级读取限制，不能将该次失败的根因视为已定位。DSH 真实已安装版本的 stat 契约已核对，旧 Linux 插件不具有该可选能力时仍需新版插件。独立增量复审无阻塞问题。

无 cwd 的生产 HTTP 浏览器夹具六项通过：从真实临时记录目录开始、上传不可用、显示记录、共享预览可读、返回复用列表、无异常提示。首次等待误用了夹具不存在的 DOM ID，修正测试条件后通过，未因此改产品。
