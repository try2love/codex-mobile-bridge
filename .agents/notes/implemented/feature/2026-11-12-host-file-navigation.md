# Agent Note: 文件页支持只读宿主机目录导航

Status: implemented

## 问题

#160 要求文件页从聊天项目目录开始，支持上级目录和完整路径导航；没有项目目录的 Codex 聊天从已核验的原生记录位置开始。原实现把浏览、上传和发送引用全部限制为项目相对路径，无法定位项目外的文件。

## 决策

现有工作区接口增加明确的 `scope=host`，只开放列表、元信息、预览和下载。文件页复用原工作台、目录列表、缓存、预览与下载组件，增加可编辑的完整路径；服务端返回绝对路径和父目录，浏览器不猜测 Windows 盘符或根目录。再次进入文件标签页保留既有列表，定位优先复用已加载目录；异步元信息定位使用代次避免迟到请求覆盖后续操作。

宿主机路径仍通过原有目录句柄和普通文件检查，不跟随目录中的符号链接、Windows junction 或重解析点。Windows 只接受本地盘符以及当前项目已选中的 UNC share，不能通过新输入触发另一网络共享的凭据访问。SSH/WSL 在目标端执行同一独立模块，不在网关机器解释远端路径。

列表与元信息另返回 `projectPath`。只有原项目内目标可以上传或引用到消息，引用前仍重新核验；Git、上传和引用接口不接受宿主范围。回形针选择器继续使用项目相对路径。原生 cwd 不因文件浏览而变化。无 cwd 的 Codex 使用 Store 已核验的 rollout 路径作为初始目录，不能推测一条尚不存在的聊天记录。

## 备选方案

把所有操作的根目录改为磁盘根可以减少接口参数，但会同时扩大上传、Git 和模型附件范围，故不采用。新增独立文件管理器会复制现有分页、预览、下载和移动端交互，因此继续在共享工作台中实现。启动时扫描全部盘符与网络共享会增加阻塞和外部访问，改为用户输入完整路径。

## 影响

这是 #160 的文件页导航部分；聊天消息中的项目外文件链接及其他客户端无 cwd 的原生记录位置另行完成，不把本提交视为该 issue 全部验收。

五项宿主文件回归、十五项既有工作区检查通过；其中四项 HTTP 需放行本机监听后通过。十二项前端相关检查通过，复审发现的迟到定位请求另补一项回归。真实 Chromium 使用生产 GatewayServer 完成十一项导航、预览、缓存和引用边界检查；320px 窄屏十二项通过，路径输入宽110.6px，无横向溢出。Windows 和 Ubuntu 均通过隔离原生目录、Range 下载、根目录和项目写入限制验证；Windows 还验证了新 UNC 与 NTFS 替代数据流拒绝。最终桌面程序和手机仍需安装后验收。

本改动按用户新授权部分替代[当前项目文件引用](2026-10-29-project-file-references.md)的只读浏览限制；发送引用与上传仍遵守该笔记的项目边界。[音视频播放](../bug-fix/2026-11-12-chat-media-playback.md)继续复用相同授权下载接口。
