# Agent Note: 主动释放网关持有的 CLI 连接

Status: implemented

## 问题

手机接入 CLI 后，用户需要在电脑继续同一会话。关闭页面并不等于释放网关的订阅或执行器，且不同客户端的释放语义不同。

## 决策

共享会话菜单在标题点击与列表长按处提供释放入口；设置中的 CLI 连接管理聚合当前网关已经持有的本机、SSH、WSL 连接。列举只读缓存，不发现或启动其他运行时。批量操作固定连接世代，逐条报告结果，默认等待任务完成；停止并释放需要显式确认。

`CliConnections` 统一管理持久化回执与至多一次派发；每个适配器在操作前核验原会话和连接身份。未知结果不会重放。网关重启时未完成操作转为待核对，普通读取不会恢复释放任务。等待检查仅存在于用户发起的未完成释放操作。

Claude 通过原执行器的 interrupt 和 stdin EOF 正常退出，不强杀。Codex 本机、SSH、WSL 复用同一原生 unsubscribe 流程，释放后持久化禁止自动接入，只有显式继续会话才能恢复。保留原 session ID、provider、auth、cwd 和历史，不关闭共享 daemon 或 WSL 发行版，不归档聊天。

## 原生边界与证据

真实 Codex 0.164.0 隔离会话证明：`thread/unsubscribe` 成功后，另一个执行器立即 `exec resume` 仍可能遇到 active writer。取消订阅不是同步卸载。上游的线程延迟卸载由加载时配置决定，且其他订阅者也可能保留运行时。结果只有在只读 `thread/read` 确认 `notLoaded` 后显示完全释放；否则明确显示网关已断开、原生占用待核对，不能声称电脑端已接手。此项真实即时交接仍未通过。

隔离实验保留另一会话连接，并在 finally 中只停止独立 CODEX_HOME 的测试 daemon。共享接口、身份漂移、重启不重放、活动目标等待、Claude EOF 及另一执行器保全已通过针对性测试；Chrome/WebKit 宽窄布局的共享菜单与批量操作通过。

本机 Claude 原生 CLI 独立测试会话以 `claude-sonnet-4-5-20250929` 初始化，正常 EOF 释放耗时 561 毫秒，另一原生 CLI 随后以原 session ID 初始化成功，耗时 480 毫秒；用户与助手消息内容、UUID 和父级关系不变，运行时元数据允许原生更新。没有新增模型轮次。此证据只覆盖本机真实交接；SSH/WSL 的释放路径已做针对性回归，不据此声称三端真实 CLI 交接均已通过。

macOS、Windows、Ubuntu 的 Test 均已在目标平台构建，新增冻结模块、分发 Web 文件与源码匹配，Windows/Ubuntu 最终可执行文件启动帮助检查通过。Mac Test 已替换运行，正式网关与原生 Agent 进程、配置和绑定均保持；Windows/Ubuntu 仅生成产物，未替换旧 Test。细分构建、失败原因与修正记录保留在本轮本地临时目录，不作为原生端到端验收的替代。

## 备选方案

只关闭页面实现简单，但不释放后端占用。停止整个 daemon 能解除 writer，却会中断其他会话。归档再恢复可能触发卸载，但会改变原生聊天状态且不是释放协议。全局修改保留时间会影响其他客户端与后台任务。因此均不采用；保留并明确呈现原生协议限制。

## 影响

UI、回执、批量结果与手动释放规则共用一处。用户得到明确的停止或等待选择；Codex 上游延迟卸载仍限制不同执行器的即时交接，不把断开订阅伪装成完成交接。只操作网关持有的 CLI 连接，原 App 会话不进入批量目标。
