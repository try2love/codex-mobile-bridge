# Agent Note: 显式强制退出已核验的 CLI 服务

Status: implemented

## 问题

普通恢复和释放会等待此配置的任务安全结束。原生任务状态无法读取、退出回执未知或某个任务一直等待时，用户需要能另行明确中断该配置的原进程。把强制作为默认重试或把已退订当作写入者退出，都会给出错误结果。

## 决策

原恢复和释放仍走各自安全入口。显式强制先预览当前注册的本机 CLI 主机和 CODEX_HOME，读取保存的原会话身份、原生 PID 记录和进程代次，列出已知受影响连接与排队会话，并说明整个共享服务包含未能列出的任务。预览不联系原生任务列表、不中断或启动会话。未核验的主机、目录、会话来源、进程代次或权限继续拒绝。当前强制能力限可直接核验进程的本机 Codex CLI 配置。

确认使用新的请求 ID 和预览摘要。摘要绑定主机、home、代次、原配置、目标会话、已知影响和已有维护状态。执行复用同 home 的维护锁；发出退出前在原进程句柄仍有效时重核验并记入回执。macOS 通过 audit token 核对代次，Linux 用 pidfd，Windows 使用有终止权限的原进程句柄。正常路径没有强制兜底。

已等待或旧结果未知时，可经新的明确确认升级。原未知业务和维护回执保留，不重复执行；原生同配置旧排队可标为取消并保留原文字。相同请求 ID 只能查旧回执，不再次发出退出、启动或消息。原进程实际退出后才记录释放；旧 socket 仍在时只接受已核对的旧路径和已退出的原生进程，由原生启动流程处理旧端点，不自行移除文件。明确强制恢复仍采用已核验的同配置环境，接续原 ID/cwd 由原生 provider admission 裁决。原接续结果未知或新配置、认证来源无法核验时，可以只确认原写入者已退出，不能猜测重建或重放原接续。

原接续未知的约束留在当前维护记录，强制退出或释放后不会由自动发送绕过。确认旧代退出后，原检查入口可提供从当前保存状态重新连接的选择，用户再用新请求 ID 和当前配置、代次、ID/cwd/provider 摘要确认。新连接不携带旧 provider override、不发消息；旧接续结果仍未知。新连接若再次回执未知，保留新的进程代次，不能自动重试；后续仍可明确中断该代再重新确认。这个新意图复用原恢复和普通接续通路，不新增队列。

## 备选方案

原生 `daemon restart` 的期限兜底会把默认等待变成可能的强制结束，也不能与一次用户确认精确绑定代次。按 PID 字符串直接杀进程无法防止 PID 复用。清除旧账本后重新发送会把未知业务误当成从未执行；本实现保留证据并区分新的中断意图。

## 验证

定向回归覆盖预览无副作用、错误主机/home/代次/配置拒绝、旧等待升级、旧未知结果保留、重复确认只观察、真实退出才释放、原队列取消与内容保留。Windows 单元回归另核对通过原句柄打开终止权限、检查失败不发命令、确认回执先于退出调用。

未知接续的状态机回归覆盖强制成功后普通恢复仍阻挡、未证实旧代退出时不提供重新连接、明确新确认后恢复连接、旧结果保留及重复新确认不重启或接续；强制释放后的普通继续也保留该约束。另用真实 `CliSessions`、非重入启动锁和连接失败分支，核对重连有界返回未知、没有第二次启动；接续不持启动锁，仍持账号/home 维护边界并在派发前后核验新意图、配置和代次。已带派发核验回调的受控接续只连接已有服务，代理连接失败不再触发普通冷启动兜底。

macOS 已安装原生 CLI 0.167.0 在隔离 home 连接一个回环替身。另一会话运行中时，原账号同步实际进入等待；明确确认后只终止原代一次，原生重新启动后同 ID/cwd 接续并读取新合成凭据。旧排队文字保留且状态为取消，旧未知写入仍未知，同 ID 重复确认没有二次派发。一次模型 POST 仅到回环替身，零付费；两个自有进程都退出。证据 `.tmp/feedback-20261111-10/cli-explicit-force-native-result.json`。

Windows 使用冻结平台模块、Python 3.11 和已核验签名的原生 `0.167.0-alpha.3.2` 完成六项隔离实测：同 home/SID/FILETIME/映像核验、错误代次拒绝、持原句柄强制一次并确认退出、原生 start 自行替换真实残留 socket、旧代请求不能命中新代、新代随后正常退出。实际强制检查点一次、正常关闭一次，零 turn/模型 POST；回环代理另拒绝六个 CONNECT，不据此宣称网络层零外发。全部隔离进程、映像和 socket 已独立确认消失。证据 `.tmp/feedback-20261111-10/windows-force-r1/observe.json`。该实测验证 Windows 平台原语和端点重建；重复请求 ID 与未知接续状态机由共享回归和 macOS 完整 API 链覆盖。Linux 的 pidfd 通路有定向回归，本点未追加 Linux 原生实测。

## 影响

用户有明确途径结束已核验的共享 CLI 服务，即使任务无法读出。能证明新服务接续时报告恢复；只能证明原进程退出、或新启动和接续仍未知时分别显示其真实结果。范围选择、全部释放和界面分组由后续同一后端契约接入。
