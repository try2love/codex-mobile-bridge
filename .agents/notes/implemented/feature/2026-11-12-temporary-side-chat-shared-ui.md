# Agent Note: 临时侧聊复用标准聊天界面

Status: implemented

## 问题

原生侧聊迁移后只能新建持久子聊天，临时共享上下文的用途丢失。直接恢复旧面板会同时恢复另一套输入、附件和审批界面，继续产生功能差异。

## 决策

侧边聊天目录同时保留原生持久创建和明确的临时创建。临时创建复用原有 SideChats、独立运行时和 ephemeral fork，只沿用创建时的上下文与配置；不继续主聊天任务，也不调用主聊天 resume 或 turn/start。原生创建失败不会自动降级为临时创建，未知写入继续沿用原操作标识。

临时子 ID 通过窄范围的 TemporarySession 适配器进入标准聊天 HTTP 合约。工作台、时间线、输入区、模型、权限、审批、上传和消息管理复用现有组件；临时适配器没有到父执行器的默认转发。归档、删除、重连、消息分支等持久操作被明确拒绝。临时会话继续要求网关密码保护，上传预览不持久缓存。项目引用在排队提交前重新按临时会话工作目录验证。

关闭标签只离开视图；“结束”中断当前临时回合、关闭独立运行时输入并等待正常退出，成功后清除内存和上传目录。正常退出超时不强杀、不清除内容，保留临时路由身份供重试；网关重启不恢复临时会话。主聊天、原生历史和共享 daemon 不被释放。

标准消息列表只接收 queued/unknown 待办，已接受的临时消息通过共用回执查询确认，避免误显示为未知发送。原生消息缺少时间时仅为新到达的临时消息记录接收时间，不伪造历史时间。

## 备选方案

恢复原先独立面板改动更少，但复制的输入、上传、权限和消息回执已经与标准界面分叉。将所有临时操作塞入主 Bridge 会侵入持久会话、账户和历史读取，且容易把临时 ID 误交给原桌面运行时。因此保留已有临时运行逻辑，只增加明确的标准合约适配。

把原生失败自动转为临时会话会改变持久性，也会在原生响应丢失时重复创建，故两种创建始终由用户明确选择。

## 影响

临时侧聊不再需要原生共享初始化，仍限于已有本机桌面侧聊入口；不借此开放 SSH 或 CLI 父会话。临时内容不进入原生历史，没有后台通知及持久历史操作，界面按实际能力展示。

定向回归覆盖标准 HTTP 鉴权、CSRF、操作白名单、时间线增量、关闭超时后路由身份、排队引用重验和原生创建不降级。已安装运行时的隔离测试保留父 writer，验证上下文、Skill、模型、思考强度、权限、计划模式、图片及排队发送；模型响应来自本机合成服务，没有正式账号或付费请求。原生线程列表不包含临时 ID，父历史字节不变，正常结束清空内容并退出进程。浏览器检查与三端成品验收的具体结果记录在本轮交付回执，不将该运行时测试等同于三端成品验收。

## 历史决策核对

- [原生持久侧聊](2026-11-07-native-attached-side-chats.md)：部分取代其“新入口不再创建临时会话”决定，原生持久归属、共用界面和不隐式降级约束保留。
- [共享运行时](../architecture/2026-11-08-codex-shared-runtime-data-deletion.md)：原生持久操作仍要求同一 writer；临时 fork 的独立 child 不替代该要求。
