# Agent Note: 上传跟随当前宿主目录

Status: implemented

## 问题

#263 指出文件页虽然可浏览项目外目录和无项目聊天的宿主目录，上传仍根据 projectPath 禁用。界面允许查看目标，却不能向用户当前选择的目录上传。

## 决策

按用户明确授权，部分替代[只读宿主目录导航](2026-11-12-host-file-navigation.md)的上传范围决定：scope=host 只新增 upload，Git、终端与发送文件引用继续按原项目边界。上传按钮在目录读取成功后可用，确认界面显示完整目标目录，写入路径由该目录和单独文件名组成；根目录遵循同一规则，由目标机器的实际权限决定能否保存。

HTTP 保持登录、CSRF、Origin 和 20 MiB 限制；宿主路径继续通过原目录句柄/普通文件检查和 Windows UNC、重解析点规则，复用完整写入后原子发布、同名不覆盖与相同内容确认。无 cwd 会话使用已核验原生记录作为起点或用户指定的完整路径，不创建虚假项目。上传体读取后在原客户端锁中复核 enabled 和绑定代次，避免期间重新绑定后向旧目标写入。SSH/WSL 继续在目标端执行相同独立模块。

## 备选方案

只启用前端按钮仍会被服务端只读限制拒绝，或错误上传到旧项目根。将全部 workspace 操作开放为宿主范围会扩大 Git、终端和模型文件引用权限，超出请求，因此仅开放明确的 upload。新建专用上传端点会重复已有安全与原子写入规则。

## 影响

历史笔记中的上传只读决定被本篇部分替代，其他读取、会话 owner、账号与引用边界保留。按钮不猜测目录可写性，真实权限错误由服务端显示。浏览其他目录不修改会话 cwd。

## 验证

15 项工作区、6 项宿主文件、122 项客户端生命周期、7 项记录定位及 46 项原生会话后端检查通过；新增无项目 HTTP 上传还单独复验。4 项 Node 路由检查与4项 Chromium/WebKit 宽窄屏交互通过。覆盖项目外和无项目目标、根目录路径拼接、同名冲突、路径穿越/链接拒绝、CSRF/Origin，以及上传体到达前重新绑定拒绝。目录交互使用隔离夹具，不上传用户真实资料。
