# Agent Note: 聊天通知入口收敛与默认策略

Status: implemented

## 问题

输入区提醒按钮与会话菜单的聊天通知设置重复；菜单还依赖该按钮的 onclick，直接删除会破坏保留入口。

## 决策

移除主聊天和其他客户端共享输入区的提醒按钮。菜单直接调用 `openChatNotifications` 或共享客户端通知方法，保留请求通知、完成通知及逐会话继承/覆盖设置。新配置默认开启两类全会话通知；已有保存的全局值、逐会话覆盖与旧 watch 偏好保持权威，不执行配置迁移覆盖。

通知策略仍受通道启用和客户端启用状态限制，不因修改默认值启用通知通道或额外客户端。原配置、绑定、任务和通知数据不作修改。

## 既有笔记审计

[共享会话菜单](2026-10-28-shared-session-menu.md)部分重叠：本次保留其通知菜单入口，仅移除输入区重复按钮。通知隔离与手机事件记录保持独立，没有被替代的提案。

## 备选方案

仅隐藏按钮改动更小，但遗留 DOM 依赖和无用途状态更新；因此删除按钮及专属绑定、保留独立设置函数。升级强制开启全部现有设置会覆盖用户选择，采用仅改变缺省值的方式。

## 验证

菜单与通知表单回归覆盖主聊天、其他客户端、保存失败、迟到响应和作用域隔离。默认值检查确认全新配置两项开启、已有关闭保持关闭、旧 watch 不被覆盖。浏览器检查确认四客户端输入区不再显示重复按钮。

## 影响

减少输入区占用且保留细粒度控制。未保存全局策略的配置采用新缺省值；用户已保存的显式选择不变。未发送真实通知或执行手机系统推送验收。
