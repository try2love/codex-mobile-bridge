# Agent Note: DSH 通用插件与显式档案绑定

Status: implemented

## 问题

第三方 DSH 客户端可能调整程序名称、启动方式和数据目录。按桌面可执行文件匹配会将单个合法 Harness 实例误报为未知或多开，且扫描不到时没有独立入口。Issue #59 的 Windows DSH Desktop 0.12.1 现场体现了启动形态差异；它不是本轮 Tauri 实测对象。用户明确要求通用插件、自定义连接和隐藏未安装未配置的客户端，不接受只限定某个 Tauri 外壳。

## 决策

独立包 `dsh-codex-mobile-bridge` 复用官方接入的同一份 `host.mjs`；薄封装从核心 `profileContext` 取得真实 home、profile 和目录，生成私有 `binding.json`、`connection.json`，共享原回环认证协议。插件包不携带账号、令牌、会话或核心。官方一键安装保留；手动模式不依赖可执行文件名称，也不交给官方生命周期管理器启动或退出。

网关选择绑定文件，或在用户明确选择的 Harness 数据目录中查找 `profiles/*/codex-mobile-bridge/binding.json`。发现只读身份文件、跳过符号链接档案、不连网络、不自动选择。绑定核对目录关系、插件源文件版本、实例 ID，随后通过回环认证读取协议修订。重启恢复核对原实例；错误不会回退到官方或其他客户端。没有桌面档案时，连接提示指向 Web/第三方客户端的插件扫描与绑定；已手动绑定而端点未加载时，提示在原客户端重新加载该档案插件，不再误导用户重复安装桌面接入。目录、端点、配置改变仍沿用既有身份保护；账号面板只读所绑定核心，不改第三方认证配置。

同一网关保留一个活动 DSH 档案。切换前仅停用手机接入，沿用 `_changing` 清理读缓存及绑定代次。写请求继续使用既有幂等回执、未知结果不重放和归档确认流程。手动模式禁止网关退出第三方应用，也不对第三方做原生强退。插件端保留实例 ID 和 token，端点 generation 随每次加载改变；活跃同档案重复加载会被拒绝。

客户端列表按本机安装、配置、启用、运行或手动绑定状态显示；没有安装且没有配置的空行不显示。统一“添加接入”始终可用，DSH 入口直接展开手动安装与绑定。内部 provider ID 与既有手机聊天 UI 不变；WSL 条目独立判断，不把聚合状态当作本机桌面可用。

## 备选方案

- 为每个第三方程序名称增加发现和进程特例，能复用已有官方一键接入，但客户端改名或启动变化仍会失效。因此保留官方快捷路径，新增按实际档案绑定的通用路径。
- 导出包含当前网关配置的专用插件，用户绑定步骤更少，但会把本机凭据与路径装进可分发包。采用无凭据通用包，由运行中的核心创建独立私有身份。
- 针对第三方重写一份完整连接器能自由适配，却会让聊天、审批、通知与归档分叉维护。导出使用同源 host，实现改变时需同步更新手动插件；这也意味着旧包不能未经核验继续绑定。
- 让网关直接管理每个第三方的账号文件与退出行为，可以保留所有管理按钮，但目前缺少对应版本的验证。手动接入将这些操作留在原客户端，接受账号管理范围较小的代价。

## 验证

真实 macOS arm64 Tauri v0.25.0 与其 Harness 0.2.1-rc.2 在独立 `.tmp` 数据目录运行。通过真实插件管理器本地安装 ZIP 解压目录、重新加载和绑定；回环假模型完成聊天与原生 bash 权限审批。相同审批请求 ID 重放返回原回执，测试文件仅写入隔离项目。通知工作器实写手机收件箱并发送至本地 Webhook；活跃会话通过原生停止再归档，随后同 ID 恢复。原生侧栏确认归档隐藏，原始列表保留 archived 标记供归档视图使用，不能把“原始列表仍包含该 ID”误判为归档失败。

Python 测试覆盖无凭据导出、精确版本/实例核验、显式扫描无网络、绑定失败关闭、官方配置保留和账号只读。Node 测试运行真实封装与同源 HTTP host，验证稳定身份、端点换代和拒绝重复写入者；UI 事件测试验证手动禁用不退出客户端、取消不发送绑定、无客户端仍可添加、WSL 不冒充本机条目。隔离浏览器检查实际桌面 HTML 的空列表、添加菜单与 DSH 入口。

最终源码回归：后端 2,717 项、39 项按平台跳过，无失败；前端 1,256 通过、1 项既有平台跳过；Chromium 与 WebKit 宽窄屏各 34 项通过。Android APK 与 iOS 无签名编译通过；模拟冻结资源布局可导出完整七文件插件包。模块边界检查和 77 篇 Agent note 校验通过。

本轮验收日志保存在忽略目录 `.tmp/dsh-plugin-20261028/`，不提交源外数据。模型服务未调用付费上游；通知结果不等于本轮重新验证手机系统通知唤醒。Windows/Linux 第三方客户端、Issue #59 指定版本及其他核心版本没有本轮实机结果；不宣称全部兼容。

2026-11-12 补验 Ubuntu 的 Harness `0.2.1-rc.2` Web 档案：已有通用插件 `0.2.1`、协议修订 9，启动日志显示因同档案旧实例占用而未激活。经用户确认无任务后，核验进程身份，使用原程序、参数及环境正常退出并重启；原插件成功生成端点。8788 Test 通过既有预览、停用接入、绑定和启用流程完成认证握手，原生接口读取 2 条聊天，任务核验为空闲且无待确认操作。未重复安装、未修改账号或聊天。旧端点已消失，无法据此认定冲突来自进程重叠还是 PID 重用，本次不声称修复该启动冲突。新增两项回归分别验证 Web 提示和已绑定档案的重新加载提示，并确认没有创建桌面档案、改绑定或发送原生请求；真实浏览器交互及新版包验收仍待后续完成。

## 影响

用户能接入扫描识别之外的兼容 Harness 客户端，无需更名或修改进程识别规则。代价是手动安装、显式档案选择及版本同步；插件安装目录和绑定文件需保留。只存在核心或相似 Web 页面不保证具备插件所需服务。若未来支持同时连接多个 DSH 档案，需要先扩展 provider/host 身份模型，不能复用一个固定 provider 偷换目标。

### Windows 绑定回执数据库的生命周期修正

v2.1.7 Test 实机回归发现，初始化 `requests.sqlite` 后的 `with sqlite3.connect(...)` 只完成事务提交或回滚，并不关闭连接。Windows 因未及时释放文件句柄而拒绝删除测试目录。初始化现在嵌套 `closing` 与连接事务上下文，在成功和异常路径均关闭临时连接；后续 manager 持有的回执连接仍按既有生命周期管理。新增用例保留初始化连接的引用并确认绑定返回后它已关闭，避免依赖垃圾回收或仅靠 Unix 可删除已打开文件而漏检。不更改绑定协议、数据库格式或 UI。
