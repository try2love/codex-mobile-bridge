# Agent Note: 共享账号编辑器与 ZCode 启动、额度和输入区状态

Status: implemented

## 问题

前一版 ZCode API 编辑器只提供手填模型，导入账号与编辑表单混排，没有复用 Codex 的模型获取和布局。手机连接方式按钮占据聊天列表顶部。历史状态缺少模型显示名和展示能力，接续后才插入 Skill、权限和工作模式，导致输入区跳变。官方模式仅连接中继，未启动已关闭的原 App。额度按钮只重读本机日志，原 App 凭据文件更新晚于最新回执时，既有安全门禁拒绝该条数据，刷新无法解决。

## 决策

`web/features/accounts/api-editor.js` 承担共享连接字段、模型选择、草稿请求代次、取消和迟到结果处理。Codex 的现有表单和 CLI API 编辑器，以及 Claude、DSH、ZCode 的账号面板均复用它；保留 Codex 既有位置、默认模型与保存行为。客户端差异通过协议、固定地址、单/多模型及只读模型能力表达。三客户端的 API 和扫描入口收进卡片下方的管理折叠区。`/accounts.js` 用有序源清单合并共享模块，不增加网页请求；桌面单独按同一顺序加载。

共享 `api_drafts.model_draft` 只 GET 模型元数据，复用地址、认证、返回体大小、超时和禁止重定向边界。查询不保存、不切换、不发推理。编辑已有接入而留空 Key 时，只有地址、协议和认证方式完全相同时才读取已存私钥，防止凭据被发送到新上游。DSH 保留官方地址限制；不因编辑器共享虚构客户端能力。

手机“连接方式”移入账号管理的通用 action slot，应用管理仍能在原 App 关闭时选择并开启。统一使用“连接方式”“重新连接”。模式选择继续经过同一应用操作接口和身份检查，不在列表顶端另建入口。

ZCode 的 `composerCapabilities` 仅描述输入区槽位可见性，不授予发送、权限或模式写入能力。历史、离线与实时投影保留同一结构；模型显示名复用原生 ID 的显示边界，路由 ID 保持不变。共享输入区用真实能力和连接状态控制禁用，并保留草稿、附件和阅读位置。仅展示的工作模式不能进入发送参数。工具条在窄屏保留可辨识的模型宽度，空间不足时横向滚动，折叠按钮固定可达；发送行不改布局。

显式开启官方模式时，先按现有平台生命周期确认原 App 状态；未运行则正常启动原生 App，不加私有管道或 TCP 参数，已运行则保留原进程。刚启动的 App 会废弃旧终端绑定，并在既有 120 秒连接预算内对同一已归属设备的在线状态按 1、2、4、8 秒退避检查；设备上线之前不申请终端票据。普通重连不进行这轮启动查询；错误账号、认证失效不重试，取消会终止等待，不自动争抢其他终端，也不重放会话写入。

额度改为通过当前原生服务的 `usageStatsService.getEntitlementSnapshot` 查询。请求绑定当前账号的 Start Plan Provider，禁止退回环境 API Key，前后核对账号 identity/provider。返回只规范化属于该 Provider、当日有效的 token 桶，保留真实查询时间和各模型剩余值。账号页首次读取，五分钟复用缓存；手动刷新限制为三十秒，失败保留同账号未过期旧值并明确显示未更新。只读额度预算为三十秒，覆盖原生十五秒查询与传输回执，不扩大写操作超时。没有原生接口时仍只能使用可归属的本机回执，不放宽旧日志的账号变更时间门禁。

## 备选方案

复制 Codex 的样式能快速改善外观，却会继续分叉模型获取、草稿取消和保存规则，因此抽取实际共用组件。把所有历史能力直接标成可用能稳定布局，但会提升未确认的写权限，因此展示能力与执行能力分离。为官方连接失败要求用户手动打开原 App 可减少生命周期代码，但不满足远程操作，故复用正常启动入口。放宽日志回执时间条件能显示数字，却无法证明属于当前账号，因此改用前后身份绑定的原生查询。

## 验证

官方适配器/生命周期十六项与官方协议六项通过，覆盖正常冷启动、保留原进程、只在启动时等待上线、取消与超时、错误账号及终端替换不重试。共享上游模型探测通过本机 HTTP 夹具，覆盖三协议认证、GET-only、空 Key 继承与改目标拒绝、重定向拒绝和 DSH 固定地址；不使用真实上游 Key。

额度读取失败已用实际记录定位：最新成功回执比凭据文件更新早 0.38 秒，不能通过旧门禁。新增十一项 Python、两项 renderer 定向测试，验证原生快照、缓存、失败旧值及账号变化。共享编辑器、资源加载、只读输入区和用户草稿保护均有定向回归；真实浏览器检查与最终成品结果单独记录，不把模拟接口算作模型收发。

真实隔离 Chrome 在 390/1280 宽度验证 Codex API 基线和四客户端共享编辑器，发现并修正了多模型输入框标签关联与共享保存按钮样式。窄屏长表单的保存按钮可滚动到达；最终按钮背景、边框、文字和字重与 Codex 一致。390 输入区冷热几何、草稿、已上传附件和阅读位置保持，模型能显示 `GLM-5.3… · low`，工具条横滑而发送行不溢出。只补跑变动后的定向项，没有重跑无关通过用例。

最终签名 Mac Test `2.2.0-preview.test.128.11` 基于 `61022f1` 安装于原 8788 资料目录，官方密文、保存链接、原生账号副本与用户命名保持。独立 8790 烟测核对新额度白名单、启动等待参数转交、共享资源和本地模型 GET；无真实账号、无模型 POST。真实官方接口首次返回原生额度约 1890 ms，GLM-5.3 剩余 3,000,000/3,000,000 tokens、Flash 5,000,000/5,000,000，桌面账号卡已直接显示两个进度条和查询时间。

用户确认空闲并授权本轮最多两次正常重启后，分别通过私有管道冷启动和官方普通冷启动。两种方式均接回同一验收 Fork、18 条消息及发送权限，模型保持 Flash/low。官方方式由手机同用的接口正常启动已关闭的 App，并在约 8991 ms 完成接入；详情约 553 ms、固定 HTTPS 约 1142 ms。私有方式的管道身份和额度查询也通过；没有强杀、没有改 API 配置、没有发送模型消息。诊断脚本曾在解码无关的全进程 ps 输出时失败，只修正观测方法并保留已通过结果，没有增加重启次数。最终保留官方连接。

## 影响

共用界面保留客户端真实能力差异，避免配置逻辑再次分叉。显式启动不会要求用户先到电脑点开 ZCode；官方远控开关及有效官方登录仍是预先配置条件。新额度查询属于账号元数据读取，不产生模型回复。真实 API 推理、iPhone/Android 原生触控及未验证平台不由本轮源码测试推定。移动原生代码未变，不要求重装手机壳；网页新资源需重新打开 Test 入口加载。本轮重复候选与烟测目录清理约 411 MiB，已安装版本、回滚与验证记录保留，未推送或发布。
