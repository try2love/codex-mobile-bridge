# Agent Note: 会话列表显示最后用户输入时间

Status: implemented

## 问题

#265 要求列表显示最后一条用户输入的时间，并明确当天也显示日期，固定为 HH:mm MM:dd。原列表使用 recency 或 updatedAt，只显示月日，模型输出、归档等活动会改变显示时间，不能代表用户输入。

## 决策

列表独立使用可选 lastUserInputAt，原生毫秒或带时区的 ISO 时间；排序仍沿用原活动与置顶规则。共享 activity.js 新增列表格式化函数，使用查看设备本地时区，始终输出两位时分、两位月日，不因当天或跨年更改形式。消息操作栏继续沿用[原生消息时间](2026-11-09-native-message-time.md)的既有格式，两个显示用途不混用。列表持久展示缓存保留新字段，只有时钟变化也触发重绘。

Codex 使用数据库核验的 rollout_path，在原 Codex 数据目录内从文件末尾按 64 KiB 向前查找原生 user_message 或 UserMessage 完成事件；不把 injected response_item、助手输出或文件修改时间当作输入。前后核对文件身份，路径/thread/设备/inode/大小/纳秒修改及创建状态绑定有限内存缓存，未变化的文件不重复解析。SSH 继续注入同一独立 SessionStore，不导入目标端不存在的模块。

Claude CLI 在既有保存记录扫描中记录真实用户事件，排除元信息、合成内容和工具结果，不增加历史扫描。其他客户端复用原有每轮最多八个会话的异步详情补充与绑定代次缓存，提取最后用户消息的原生 timestamp；Claude/DSH 同一事件拆分行按已有原生 ID 前缀关联其首行时间，不能跨原生事件补时。已知原生列表时间优先于后台旧缓存。未加载或没有原生证据的时间保持空白，不用当前时间、会话活动或缓存写入时间补齐。

## 备选方案

将 updatedAt 直接格式化仍会把助手输出视为输入。用网关发送到达时间会遗漏电脑原生输入，刷新后还可能丢失。每次同步读取全部会话完整历史会阻塞列表，因此 Codex 使用反向记录查找与文件身份缓存，其他客户端使用既有有界后台读取。

## 影响

本篇与原生消息时间笔记部分重叠并互链，沿用其真实时间原则；不替代消息操作栏格式。仅改变列表展示证据，不激活会话、切换 owner、改变最后活动排序或写入原生日志。其他客户端在后台取得证据后显示，旧记录缺失时不伪造。

## 验证

原生输入时间专项3项、Claude CLI49项、展示读取10项、Bridge128项（2项既有跳过）通过；276项相关Node检查通过。16项Chromium/WebKit宽窄屏整体验收涵盖四项需求，其中列表验证当天日期、两种列表相同格式及模型输出不改输入时间。真实本机Codex三条列表记录只读字段核验均找到原生用户时间；不调用发送或会话激活。完整回归和原生三端构建另外记录，不把浏览器夹具视为真实原客户端操作验证。
