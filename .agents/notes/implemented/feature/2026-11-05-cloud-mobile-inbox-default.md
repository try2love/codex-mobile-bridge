# Agent Note: 云服务首次启用默认开启手机接力收件箱

Status: implemented

## Problem

用户开启云服务后，桌面通知配置 `mobileEnabled` 仍默认关闭，必须另到“手机 App 接力”手动启用通知收件箱。用户要求云服务启用后默认开启该项。云服务资格会定时刷新、断网后恢复，不能把每次 active 都当成用户再次开启通知。

## Decision

在本机第一次取得有效、active 的云服务资格时，持有通知设置写锁，原子写入 `mobileEnabled: true` 和内部标记 `cloudMobileDefaultApplied: true`。此前默认写入的 false 一并启用，已有开启状态保持；标记随通知设置保留，之后手动关闭不会被刷新、服务恢复、重新登录或进程重启覆盖。仅状态读取、登录失败、资格过期和网络失败不初始化默认值，直连独立默认继续关闭。

初始化只改收件箱开关，不改变“通知链接优先打开手机 App”、第三方接收地址、逐聊天提醒策略、内容标题开关、手机通知同意或桌面授权。Controller 负责确认云服务有效，通知模块负责带锁合并配置；不把展示缓存当作授权。启用收件箱不会产生合成事件或发送测试通知。

## Alternatives considered

- 仅在前端勾选能最少改界面，但无法覆盖无窗口启动、恢复已有云账号或后端读取，且勾选未必已保存，因此由云资格确认驱动持久化。
- 每次确认云服务 active 都写 true 不需要标记，但每分钟刷新或网络恢复会覆盖用户手动关闭，故用本机一次性初始化标记。
- 只修改全局默认为 true 最简单，但会改变未使用云服务的直连配置；本次限定到云服务首次成功启用。

## Consequences

启用云服务后不再需要到另一个页面打开手机收件箱。通知格式增加一个内部布尔标记，维护时必须和通知配置一起保留；文件缺失会重新采用云默认值。首次成功启用会将此前已保存的 false 改为 true，这是用户要求的云默认行为；初始化完成后关闭会持久保留。云服务可用不保证手机权限、推送厂商网络或锁屏通知已就绪。
