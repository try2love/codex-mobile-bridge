# Agent Note: 邮箱验证之后才接受注册密码

Status: implemented

## Problem

用户纠正先提交密码的注册流程，要求先验证邮箱，再显示新密码及确认。

## Decision

邮箱和六位码同屏，验证成功才进入密码阶段；完成注册后回登录，不自动登录或配对。密码阶段证明仅保存在内存，绑定精确服务器/邮箱，关闭、切换、到期或提交即清除。发送/验证代码不带密码，重发按邮箱/服务器冷却，未知结果不重放，不完整回执不能解锁密码或报成功。

服务器用独立注册挑战、带密钥摘要、到期与五次猜测上限；证明只存摘要，并在创建账号时原子消费。加密 SMTP outbox 属于挑战，发码前不建账号。客户端要求 `registration_flow: email_code_password`，旧服务器需升级，不回退旧密码接口；selfhost 公共注册关闭，本地配对独立。

当时迁移 005 保留已有账号、重置邮件，并允许旧待验证账号在新证明和密码后完成。用户随后取消旧数据保留要求，这部分由[当前云契约](../simplification/2026-11-04-prerelease-cloud-contract-cleanup.md)取代：旧激活路径与迁移删除，注册不能覆盖任何已有账号。本篇继续持有邮箱在先和短期证明的决定，并部分取代[验证码记录](2026-11-01-email-verification-codes.md)的密码提交顺序。

## Alternatives considered

先提交密码再验证可复用旧账号验证实现，但不满足用户明确要求的邮箱在先，因此将挑战与账号分开，密码只在证明完成时提交。

## Consequences

证明前不保存注册密码或创建账号，代价是多一个短期证明及其作用域、超时和重发失效状态。主进程 IPC/Python 修改需重启控制器，渲染器刷新不能替代。

## Testing

2026-11-02 在隔离 PostgreSQL 18.1 上 78 项 Go、vet、28 项云 Python、1,326 项 Node、58 项 Edge 宽窄回归通过，检查注册截图；未验证 WebKit、race、手机或真实 SMTP，没有提交、打包、部署或真实账号操作。当时上层导入仍失败，后来由[监听器组装](../architecture/2026-11-02-cloud-listener-injection.md)修复，原验证范围不追溯改写。
