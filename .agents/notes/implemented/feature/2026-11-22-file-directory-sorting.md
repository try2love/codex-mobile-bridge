# Agent Note: 文件目录六种排序

Status: implemented

## 问题

#262 要求文件页支持名称、修改时间、大小各自升降序，并把入口放在目录计数与“返回项目文件夹”之间。目录使用分页，只在浏览器中排序已加载行会使跨页顺序错误。

## 决策

沿用独立 Workspace.listing，在目标机器读取目录元信息后按 name、modified 或 size 排序，再切出每页 200 项。六种合法 sort 值明确校验，默认 name-asc 与既有行为一致；目录始终优先，相同值使用名称作为确定性次序。宿主目录、本机、SSH 和 WSL 共用相同参数契约，不新增传输模块或元数据扫描。

入口放在摘要行计数与返回项目按钮之间。选择保存在当前工作台会话中，切换排序取消上次目录请求并重置到第一页；搜索、隐藏文件、上级目录和上传继续使用当前目录。排序不改变聊天 cwd 或文件权限。

## 备选方案

仅排序当前 DOM 会遗漏未加载页。把所有文件发到浏览器排序会放大传输和手机内存开销。为每个平台维护单独排序容易导致同一目录在本机和 SSH 中次序不同，因此仍复用原独立模块。

## 影响

新增可选 sort 查询参数，未提供时保持名称升序。大小排序只使用普通文件大小，目录不递归计算；目录优先规则高于升降序。与[当前宿主目录上传](2026-11-22-host-directory-upload.md)共享目录状态，但不改变上传目标选择。

## 验证

17 项工作区后端测试通过，新增 205 文件跨页验证六种全局顺序、目录优先及非法排序拒绝。4 项 Chromium/WebKit 宽窄屏文件交互检查通过，核验控件位置、六选项传参、第一页重载及无横向溢出。
