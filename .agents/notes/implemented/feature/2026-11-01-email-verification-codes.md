# Agent Note: 邮箱所有权验证使用数字验证码

Status: implemented

## Problem

用户选择邮件数字验证码，验证与重发只属于创建账号流程，不继续使用邮箱验证链接。

## Decision

验证码为六位数字，十分钟有效，重发倒计时六十秒并绑定精确服务器/邮箱；换页、换服、关闭或提交清除验证码。验证不创建登录会话、不启用中继或授权手机。等待写入禁止导航，语言重绘不重放；旧链接服务明确要求升级，selfhost 继续由管理员建用户。重置密码链接与邮箱所有权验证分别处理，可见注册/找回入口和隐藏官方 origin 的设计不变。

最初实现先提交密码建待验证账号，再通过 `verify-code` 激活；当时迁移 004 删除验证链接及邮件、保留重置和账号，验证码使用账号范围 HMAC、五次猜测上限及持久限速，只有加密 outbox 保存正文，重试同步替换待验证密码和验证码，邮件使用 MIME 编码。

密码提交次序由[邮箱优先注册](2026-11-02-email-first-registration.md)部分取代，旧激活接口、旧表和迁移再由[当前云契约](../simplification/2026-11-04-prerelease-cloud-contract-cleanup.md)删除。本篇保留数字码、作用域、时限和不自动登录的决定及原实现取舍。

## Alternatives considered

验证链接能直接在邮件中完成跳转，但用户明确选择应用内数字码，所以旧验证页面、表单、JS 和翻译一起退役；密码重置仍独立使用链接。

## Consequences

邮箱验证留在注册交互内，重发与错误尝试可明确约束；需要维护码/证明的到期、失效和限速，且必须与服务端协同，不能回退旧链接回执。

## Testing

2026-11-01 的 1,325 项 Node、27 项云 Python、46 项 Edge 宽窄回归通过，并检查合成登录/注册/验证码截图。隔离 PostgreSQL 18.1 上 Go 有 68 个通过事件，覆盖当时旧路由删除、迁移、重置保留、过期、猜测、重发、并发和隔离。没有真实注册、邮件、厂商推送、配对、提交或部署，未验证 WebKit、race 或手机注册。未操作已有认证窗口；CJS/Python 修改需要重启桌面和网关。原上层导入缺口后来由[监听器组装](../architecture/2026-11-02-cloud-listener-injection.md)修复。
