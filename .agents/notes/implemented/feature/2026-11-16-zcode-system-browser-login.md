# Agent Note: 官方授权使用系统浏览器并支持回执

Status: implemented

## 问题

#174 的官方登录弹窗在部分用户电脑无法使用，需要在默认浏览器完成授权，并为自动返回失败提供手动回执入口。登录不能绑定某个 App 版本，也不能把任意粘贴的 token 当成已完成授权。

## 决策

在现有官方登录面板增加系统浏览器方式。仍由官方页面创建登录流程和轮询结果，只把实际官方授权页交给系统浏览器；保留原窗口及占位子窗口，避免官方页面因窗口关闭而取消轮询。没有识别为授权入口的受信任页面继续显示为内嵌窗口，不隐藏必要交互。

手动回执只接受本次流程的完整官方 HTTPS 回调地址。提交前核对 state、回调来源与路径、原固定参数、单个授权码、登录代际、目标连接和原配置文件身份；十分钟内单次使用，结果未知不得自动重放。授权码不保存到配置或草稿，完成或退出登录后清空输入。窗口关闭或授权取消后，已排队的浏览器打开操作不会继续执行。

## 备选方案

重新实现官方 token 交换会复制客户端登录业务；读取系统浏览器 Cookie 或接受任意 token 会绕过原授权绑定。均不采用。直接拒绝官方弹窗会令其轮询失效，因此保留官方占位窗口。真实 Electron 验证现有导航守卫可拦截直接弹窗的首次授权导航，不额外增加 Session 请求拦截器。

## 影响

复用已有登录隔离、加密保存和连接配置。官方流程完成后仍需由用户选择连接远控，不自动替换原 App 账号。回执按钮不依赖初次打开时的能力快照；最终权限由提交时的状态检查决定。状态刷新不从渲染函数递归发起。

## 验证

控制器与共享管理面板 119 项测试通过，新增覆盖取消、回执匹配、过期、重放、弹窗可见性、草稿保留和单次刷新。真实 Electron 44.5.1 合成 HTTPS 页面核验空白占位及直接弹窗两种流程：系统浏览器调用各一次，内嵌授权页未请求，回执真实加载，子窗口随主窗口销毁。夹具使用假的加密适配器和授权码，已退出；未完成真实用户账号授权，不能宣称真实账号端到端登录已验收。
