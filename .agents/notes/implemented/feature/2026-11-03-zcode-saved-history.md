# Agent Note: 普通启动的 ZCode 可读取本机已保存文字

Status: implemented

## 问题

ZCode 桌面窗口和工作区 host 通过进程内转交的 MessagePort 通信。[原型](2026-10-31-zcode-native-session-prototype.md)通过本机调试端口取得原 owner。普通启动不会开放这个入口。ZCode 官方远控使用外部中继，用户要求会话数据仅经过本机网关。

## 决策

已启用的本机接入从同一原生配置的任务索引和 CLI 记录读取文字。索引任务须为本地 GLM 任务，原会话 ID 和工作目录须相符；与 VS Code 原生 owner 校验共用目录比较，本机 Windows 可用文件系统身份确认同一目录的不同写法。SQLite 连接使用只读 URI，连同 WAL 读取当下已提交的数据。读取离开请求后关闭连接。数据文件与侧文件不能通过符号链接指向其他配置。

读取只选择原生标注对界面可见的用户和助手文字。运行程序向模型提供的隐藏指令也可能以 user 角色存储，仅凭角色会把这类输入暴露给手机。移动端复用已有历史分页，以当前会话的原生消息标识为游标。任务列表和历史都标记只读；历史状态不能证明正在执行、等待审批或者可以安全退出。

## 备选方案

复用官方远控可以操作原 host，但需要同账号在外部中继配对和传输消息。用独立 CLI 加载磁盘记录也能产生新回复，却无法证明与原窗口共享当前任务。保留原型的显式兼容接入与普通 App 的本机历史各自的能力边界。

## 影响

Mac 上从普通原生数据目录读取独立验收聊天，分页取得用户消息与回复，隐藏的模型环境提示未返回。测试覆盖同名目录归属冲突、远程记录、已删除记录、归档、跨会话游标和指向其他库的链接。此入口只提供保存的文字，实时消息、停止和审批要求有可验证的原会话连接。此前原型的真实收发记录仍仅适用于当时经过验证的连接方式。

桌面项目树登记的本机会话可能尚无 CLI 聊天记录行。针对已选 ID，详情可以显示该索引项及空历史；没有对应记录时不读取孤立消息行，也不授予写权限。显式接续仍由原 App 核对项目、ID 和订阅。若对应记录被删除、目录不匹配或任务属于远端，继续拒绝。

每条助手回复的模型/思考档位取自同一会话、同一条回复的模型调用记录；缺少记录时仅使用该回复及其明确关联输入的字段。不同模型之间不移用思考档位。原生快照、已保存消息和共享渲染器沿用相同的展示字段。
