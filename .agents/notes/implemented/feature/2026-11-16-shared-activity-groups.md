# Agent Note: 共用思考与执行过程分组

后续用户验收否定了统一外层与三级结构，现由[正文与连续操作独立展示](../bug-fix/2026-11-16-inline-activity-disclosures.md)替代该展示决定；下文保留原决定与验证局限，稳定节点和阅读状态约束仍适用。

## 问题

连续的原生思考、命令和子任务分别显示折叠行，会把用户输入与最终回答隔开。仅对 Codex 增加分组会使其他接入继续使用不同布局；每次更新拆开分组再重新挂载，也会破坏此前已经修复的正文滚动和阅读位置。

## 决策

共享活动模块按照渲染器明确标注的原生中间角色分组，思考与执行过程为一级、连续工具操作为二级、已有原生详情为三级。普通用户发言与最终回答保持在分组之外；不根据消息正文猜测角色。没有过程数据的接入不凭空生成思考内容。

两条聊天渲染路径复用同一分组方法。组节点与成员节点按稳定键复用，历史前插后可通过已有成员继承原组状态；更新不拆开所有子节点。阅读锚点的获取与恢复都以最外层可见组为准，正文仍复用既有内部滚动保护。已结束的组默认折叠；明确仍运行的末尾组默认展开，用户主动开关后保留其选择。加载另一会话或原生重置不继承上一会话的组状态。

各级摘要使用现有消息字号与行高，没有逐级左缩进；详情正文继续使用用户设置的代码字号。展开区域有相对字号的高度上限并可内部滚动。原生数据尚未提供统一可信耗时，界面不拿接收时间或最后消息时间拼出虚假耗时。

## 备选方案

- 直接采用 PR136 的 Codex 专用分组：参考其连续活动归并思路，但其中每轮先拆开再创建组的策略与稳定节点约束冲突，且没有共享桌面会话实现，因此未直接合入该 PR。
- 把所有 assistant 内容都折叠：会错误隐藏最终回复，因此只采用协议明确提供的 activity、reasoning、commentary 标记。
- 为每个客户端复制折叠 UI：会使字号、滚动和开关行为漂移，故在已有共享活动模块实现。

## 测试

两条页面路径的 231 项 Node 回归通过；既有阅读、历史和显示窗口浏览器回归 16/16 通过。新增 Chrome/WebKit 宽窄屏 4/4，每组 106 条断言覆盖五 Agent、三级展开、阅读位置、节点稳定性、历史前插、turnId、选择保护，以及深浅主题的 10/16/32px 字号。390 深色大字号与 1280 浅色截图已目视核验。测试发现并修复旧组在裁剪后仍被 Map 持有的问题；无活动节点时清除该引用。证据在 `.tmp/recovery-20261116/folding/`，不把合成原生消息当作真实模型调用。

## 影响

只改变过程内容的组织方式，不改原生历史、任务状态、权限、草稿和发送协议。三级详情仍保留原有文件定位、附件与正文按需读取。共用阅读约束继续见[聊天阅读状态](../bug-fix/2026-10-30-shared-chat-reading-state.md)；[注入上下文折叠](2026-10-29-native-context-folding.md)负责原生来源识别，两者部分重叠但职责不同，未替代原解析规则。
