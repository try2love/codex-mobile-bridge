# Agent Note: 原生会话永久删除与范围确认

Status: implemented

## 问题

Issue #138 要求在归档下方提供永久删除。原生侧边聊天持久化后，只删父项的 Bridge 显示记录会留下原会话；直接删除父项又可能遗漏已经归档的附属聊天，或者在响应丢失时重复执行。

## 决策

共享会话菜单提供二次确认，展示原生父项和全部可访问的附属聊天，另显示子智能体数量。确认后的 ID 集合必须与即时元数据一致。关闭菜单、返回和迟到的范围响应不触发删除；默认焦点为取消。当前适用于本机 Codex 及独立 Codex 配置；SSH/WSL 和其他客户端没有已验证的原生删除入口，不能显示成可用。

删除使用原 app-server 的 `thread/delete`。原生附属关系按子项到父项处理，已归档的附属聊天也在范围内；普通分支不据 `forkedFrom` 推断为附属项。运行中、待确认、后台任务和待核对写入阻止删除。Bridge 不为删除恢复一个会话、不终止用户 App、不直接修改原生数据库或删除项目文件。

删除前按配置持久记录未知回执。部分删除、连接中断和未确认的原生错误不得重放；只有整个已记录范围均从原生存储消失才确认成功。首项明确返回方法不支持、`-32600` 且精确匹配目标 ID 的 `already has an active writer`，或派发前检查失败，才清除本次未执行的意图；其他错误仍按未知处理，不能将全部 RPC 错误视为未执行。子项已删除后出现的错误保持未知。与账号切换、主机身份、认证和 CSRF 相关的保护继续复用现有入口。

用户重新打开删除菜单时，网关按原生元数据核对仍存在的范围，并返回相交的未知回执 ID。旧请求不会自动重放；用户必须另行勾选“已核对”，再次确认当前范围，新请求使用不同 ID 并携带精确的旧回执集合。期间新出现的未知回执或范围变化会阻止执行。检查失败、明确未发送时保留旧回执；新意图实际发出后才链接旧回执到新请求。只重试一个子树不能清除父范围中其他聊天的未知状态。

## 备选方案

- 只移除 Bridge 列表项：不能满足原生永久删除和双端一致性。
- 先归档再静默删除：混合两个不同的用户意图，并掩盖不可撤销操作。
- 自动停止任务再删除：容易扩大中断范围；用户先显式停止，再确认永久删除。
- 超时后重新提交：可能在部分完成后误删新关联内容，因此保留未知回执并要求核对。

## 影响

无需新增常驻进程或轮询，仅在打开确认和执行时读取元数据。删除仍受当前原生运行时能力及写入者限制；界面提供入口不等于所有客户端版本都支持此方法。原生删除会处理自身的关联内容，确认文字不能将其描述成仅隐藏列表。旧未知结果需要用户核对后重新确认，不能静默清除记录来方便重试。

当前 Desktop 的原生删除通过自身 owner 的 `requestClient` 执行，而公开 follower IPC 没有删除入口。独立短时 app-server 无权删除被原 App 保留写入权的聊天，哪怕聊天当前没有任务。因此这类聊天仍须在原客户端删除，或在其自然释放写入权后重试；Bridge 不自动归档、不抢写入权、不退出原 App。

## 验证

8 项后端定向检查通过：包含归档附属项和子智能体、排除普通聊天、运行状态阻止、范围变化、持久未知回执、部分删除不重放、方法不支持及 HTTP 登录/CSRF/确认字段。Chrome 与 WebKit 的宽窄屏共享菜单检查均通过，覆盖取消默认焦点、确认范围和迟到响应。模块边界检查通过，未增加历史例外。已安装 Codex 运行时另在本轮隔离 CODEX_HOME，通过生产删除路径删除新建的父、子、孙三条聊天，原生存储核验全部消失；没有 turn/start 或模型请求，未接触用户聊天。三端成品验收尚待本轮集成完成，不以合成测试代替。

2026-11-08 针对真实持有者补验：当前 ChatGPT/Codex 26.1103.41825 的运行时在隔离 CODEX_HOME 中重现“第二个运行时删除空闲/附属聊天”返回 active writer 拒绝，零模型请求。修复后该拒绝为 `DeleteNotSent`；原持有者正常结束后，旧未知回执经显式重新确认可删除同一附属聊天并核对原生记录消失。12 项后端回归及 Chrome/WebKit 宽窄屏共享菜单通过。该验证证明拒绝分类和恢复，不代表能跨 owner 强制删除；用户真实那条聊天未被操作。
