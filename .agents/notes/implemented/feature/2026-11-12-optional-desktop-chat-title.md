# Agent Note: 原生新建聊天可选名称

Status: implemented

## 问题

#161 要求聊天名称默认留空。共享桌面客户端表单原来填写“新会话”并要求非空，Claude 适配器也补上同名默认值，阻止原客户端决定名称。

## 决策

共享表单名称留空，使用简体中文占位提示“留空将由 Agent 自行命名”；只有明确填写时才提交名称。保留原生首条消息、模型、项目和不支持自定义名称的接入能力。Code、Cowork 不再补默认名称；Code 无名称时使用原生 `generateTitleViaCli`，自定义名称时不传该标志。DSH 原本就只对非空名称调用 rename，无需另建命名流程。

## 备选方案

仅清空输入框仍会被适配器补回默认名称。复制原生自动标题模型调用会增加费用和另一套命名流程，因此只使用已存在的能力。

## 影响

四项共享界面回归、两项 Claude 创建契约回归和简体/英文操作文案检查通过。真实 Chromium 的 HTML 必填校验接受空名称，首条消息仍按接入要求校验，自定义名称保留。浏览器请求为隔离合成事务，没有发送模型请求。

已安装 Claude 4.23118.1 的 Code start 支持可选 title 与 generateTitleViaCli，后者通过原生自动命名并持久化；有名称时不能设置 true。Cowork 的标题生成由原生 UI 驱动，底层 start 没有同一开关，因此不保证后台新建立即产生自动标题。DSH 0.2.2-rc.1 显式 rename 会写入 user 来源并停止自动命名；省略 rename 保留既有自动标题机制。以上为原生源码核验，真实生成仍受登录和模型可用性影响。

Codex 的可选名称部分暂不集成。隔离实测 0.167：thread/start 后无名称的空线程尚未落盘，立即读取完整历史、resume 和分页均失败；非空 thread/name/set 会触发持久化。metadata-only 可读，正常退出独立创建进程后可重开，但共享 daemon 不能为新建一个聊天而退出。无覆盖的 settings update、单线程 unsubscribe 均不能解决；不能靠清除 Git 信息、假造历史或重启共享服务绕过。后续需单独验证空会话的正常持久化与共享运行时接续，再去除 Codex 的默认名称。原有功能暂时保留，未将这项缺口标为完成。
