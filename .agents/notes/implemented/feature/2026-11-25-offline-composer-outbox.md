# Agent Note: 设备离线草稿与待发消息

Status: implemented

## 问题

断网后，热阅读器锁住了整个输入区，手机冷启动的阅读页面还会隐藏输入框。网关已有队列和发送回执，但设备尚未联系网关时，用户点击发送的意图没有持久存放的位置。原生离线页和网关页面还可能使用不同网页来源。

## 决策

文本、光标、引用、已选附件信息、工作模式和工具栏布局在本机保存。模型、用量和额度面板展示当前会话账号已同步的值与时间。单个接口返回 502、503 或 504 时，页面先核对网关能否正常响应认证，而系统断网信号可以立即启用本机输入。显式切换账号后，重新核实账号的会话才能读取对应记录。撤销或退出的配对沿用原生归档的访问状态。

点击「存入待发」用一次版本写入将消息加入会话队列并清空已提交的草稿。随后输入的另一份草稿独立保存。原生应用通过同一份配对归档访问两个页面，浏览器用 IndexedDB 读写事务。重连后按网关、客户端接入、主机、会话和账号核对可发送状态，再将原消息编号交给已有的发送路径。设备在请求出发前持久标记投递已开始。响应中断时按编号只读查回执，网关在自己的操作账本里做幂等处理。

Codex 在交给原生客户端之前拒绝的 Skill、附件或模式校验使用明确拒绝码，并将拒绝回执绑定原账号和请求内容，持久保存在现有账本。迟到的拒绝不能覆盖另一请求已写入的回执。同编号内容冲突不代表原请求未发送；它保留未知结果保护。临时忙碌或尚未取得模型设置继续等待，不视为永久失败。

明确失败的本机待发消息可以原位编辑或移除。保存编辑生成新的提交编号、清除旧错误并恢复待发，位置和其他附件、Skill 保留；后续消息和独立草稿不动。旧编号的迟到页面操作不能改动替代记录。请求已经进入原生发送路径后，普通异常不转为可重试拒绝。历史 `checking + notFound` 记录没有未发送证明时也不自动释放。

## 备选方案

沿用[加载阶段的禁用工具槽](../bug-fix/2026-11-11-shared-composer-loading-slots.md)可以保持布局，但也限制了读缓存和编辑本机数据。仅放开文本框、借用网关队列能节省设备存储，却要求用户在重连后再点一次发送。单独使用网页本地存储能恢复普通浏览器标签，原生冷启动页却可能读取另一个来源。无条件重放超时请求能缩短表面等待，但在网关已接收的情况下有重复执行的风险。只返回拒绝码改动较小，但丢失错误响应后仍无法证明未发送；沿用原编号编辑会碰到已保存的旧内容指纹，因此采用新编号并保留原位置。

## 影响

已上传的附件按原编号投递。尚未上传的本地文件在重新打开应用后需要重新选择。计划和目标草稿保留工作模式，联网后由用户发送。完全离线时，普通浏览器需要已有页面，原生应用使用随包提供的离线页面。回执丢失且网关无法证明结果时，队列会等待核对。用户仍可编辑下一条草稿。保留账号的归档只允许浏览，原生存储写入失败时输入区保留用户内容。

## 验证

WebKit 和 Chromium 的窄屏、宽屏用例通过真实输入框完成待发 A、草稿 B、冷页重开与恢复投递。另用两个浏览器标签共享真实 IndexedDB 并发重连，验证 A 只提交一次。原生页面测试使用模拟宿主，iOS SQLite 和 Harmony 归档夹具单独验证版本写入及账号隔离。用本地 HTTP 和 Agent 夹具核对网关拒绝身份变化、旧编号及重复请求的行为。

拒绝恢复回归覆盖 Skill 移除、附件失效、模式不可用、错误响应丢失后重启查询、迟到拒绝与已接收请求竞争、原位编辑和未知结果不重发。浏览器回归从失败卡片打开真实编辑弹窗，核对新编号、原草稿与撤回入口。平台模拟及浏览器夹具不替代新版手机包的真机验收。
