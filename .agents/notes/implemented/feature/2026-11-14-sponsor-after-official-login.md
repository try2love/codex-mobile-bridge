# Agent Note: 登录官方云账号后显示赞助支持

Status: implemented

## Problem

未登录时登录表单默认选择官方云，桌面因此显示整块赞助支持。用户明确要求这块内容只在登录官方云服务后出现。

## Decision

赞助区显示条件使用当前账号的 `configured` 状态及精确官方 HTTPS origin，两者同时满足才显示。登录表单中选择官方云或填写官方地址不会显示赞助区；登录自建云、退出账号及初次加载时隐藏。官方云已登录但未激活、过期或服务状态查询失败时继续显示，便于购买和兑换。

显示范围变化沿用现有重绘及弹窗关闭逻辑，隐藏赞助区时关闭已打开的购买弹窗。二维码请求的迟到回复不能重新打开弹窗。服务端图片接口、兑换及认证权限保持现有边界。

## Existing decisions reviewed

- [原赞助入口](../../implemented/feature/2026-11-11-official-cloud-sponsor.md)：部分取代其未登录显示决定；保留精确 origin、激活状态与手动兑换边界，以及历史交付证据。
- [二维码弹窗与网页地址](../../implemented/feature/2026-11-11-sponsor-dialog-and-web-address.md)：部分重叠；购买弹窗与服务端图片读取继续适用，更新显示范围的归属链接。
- [云登录对话框](../../implemented/feature/2026-11-01-cloud-login-dialog.md)和[官方默认值](../../implemented/feature/2026-11-01-official-cloud-default.md)：只更新相关说明与链接，不改变默认服务器或登录表单。
- 检索 proposed、implemented、rejected 中的 sponsor、赞助及登录购买，没有其他同目的提案需要合并或归档。

## Alternatives considered

继续在未登录时按官方云选项显示可以提前提供购买入口，但不符合用户要求的登录后显示。绑定云中继在线状态可以反映实际连通性，却会让已登录但尚未激活或离线的用户无法找到购买入口，因此只依赖已登录账号身份。

## Testing

先修改已有浏览器断言，在旧代码上复现未登录赞助区仍可见的失败。修正条件后，49 项云面板、IPC 和翻译 Node 回归通过；Chromium/WebKit × 宽窄视口的 12 项赞助浏览器检查通过，覆盖未登录、官方/自建选择、已登录不同服务器、不同资格状态、真实退出按钮及刷新后的隐藏。退出或切到自建账号关闭购买弹窗，迟到图片不重新打开弹窗；测试确认没有额外云请求或外层设置提交。已检查未登录宽屏及已登录窄屏截图。

## Consequences

未登录时云面板只展示登录入口和连接状态，避免提前展示购买内容；代价是需要先登录才能发现购买入口。此修改只调整界面显示条件，不把赞助区可见性作为服务端授权或已付款证明。浏览器使用合成账号，没有提交真实登录、购买或兑换。
