# Agent Note: 云服务资格由服务器自动决定

Status: implemented

## Problem

用户要求登录后隐藏登录/中继启用按钮，有效服务期自动具备中继资格，兑换后立即更新服务状态；同时报告刷新提示未翻译，并禁止控制其电脑。

## Decision

本地账号已配置时隐藏登录与说明，退出后恢复；手动 `enabled` IPC 一并删除。登录、确认兑换和显式刷新后读取服务器资格，经过校验的 active 决定保存的 enabled。读取失败使资格失效，但不把已经确认的登录或兑换误报为写入失败。

连接前和后台周期性重新核验资格，包括保存为 disabled 的配置。显示缓存按服务器/账号/网关隔离且会老化，不提供离线授权；单调时钟截止从请求前开始，网络延迟不能延长服务。到期、切账号、核验失败和退出封锁证明、转发与通知。网关生命周期仍显式控制，云管理不启动网关或编码会话；本地可信密钥、授权、E2EE、CSRF 和精确 origin 仍必需，未知写入与已消费 refresh 不重放。

兑换回执与资格刷新错误分别返回，只重试只读对账；迟到读取不能越过作用域或覆盖新兑换状态。资格刷新可能写资格或轮换凭据，因此纳入更新写入门锁；私有响应等待允许登录后再读资格，不重试登录。中英文共享结果消息（含 `Cloud service status refreshed.`），语言事件只重绘缓存与日期并保留草稿。

## Alternatives considered

保留手动启用按钮可让用户分别控制服务，但与用户要求的有效期自动资格冲突，因此删除按钮及执行入口；显示缓存也不能替代服务器授权。

## Consequences

登录与兑换后的状态及时反映服务器资格；后台核验带来额外只读请求和失效状态，界面必须区分确认写入与刷新失败。主进程/Python 修改需要重启桌面和网关，仅热刷新无效。

## Testing

2026-11-02 用真实生产 Python/JS、合成请求、内存 vault、临时文件和 Node DOM 测试，44 项云 Python、26 项定向 Node、1,353 项完整 Node 通过，无跳过；浏览器夹具只更新并检查语法，未执行。没有操作用户窗口、真实账号、编码会话、部署、打包、重启或配对。那次上层导入检查仍失败，未扩大例外；后来由[监听器组装](../architecture/2026-11-02-cloud-listener-injection.md)修复，原测试范围保留。
