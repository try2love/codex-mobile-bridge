# Agent Note: 同账号自动目录与可逆桌面许可

Status: implemented

## Problem

手机需要自动显示同账号电脑，桌面关闭连接后还应能重新允许；手动申请和关闭即永久撤销不能同时满足这两项要求。

## Decision

后续 [云账号 Web](2026-11-07-cloud-web-proxy.md) 新增无需逐浏览器批准的可信云代理入口；本篇的手机本地密钥批准规则保持独立。

采用同账号自动目录，发现只提供路由元数据，不是桌面信任。新手机默认不允许连接，首次批准核对加密身份与八组安全码，不自动弹批准窗口。手机显示选定服务器/账号下的电脑、访问及在线状态；pending/disabled 只读展示信息和安全码，云设备不提供删除、撤回或侧滑操作，直连删除独立保留。

## 接口与状态

- 服务端登记按账号串行化，无论登录顺序都补充稳定的 pending 关系；目录 GET 不创建或批准绑定。
- 手机/网关目录和桌面 access POST 使用不可变身份与单调 revision。每次关闭都推进栅栏，较早开启不能覆盖关闭。
- `cloud-access.json` 独立于可信密钥。关闭先封锁通道，再访问 vault/网络，保留核验密钥并丢弃待发通知；未知开启保持封锁，不重放，存储失败有仅本次运行有效的提示。
- 手机前台同步不依赖云页面或聊天忙锁，通常每三秒执行，退避且不重叠；账号/生命周期变化取消原生 HTTP/证明任务。目录凭据租约不可变且按作用域隔离，不持有串行账号写入队列。
- 验证后的访问恢复可恢复预览凭据，但不授予推送同意；发现、许可和通知不启动或切换编码会话。

## 记录归属

本篇部分取代[手动桌面批准](2026-11-03-desktop-approved-cloud-pairing.md)的请求流程，保留其加密证明约束。当时迁移 007 保留 active 身份与撤销事实；原任务的部署/安装授权要求备份、迁移演练、三端配套和 Android 保留数据，禁止自动批准真实手机。用户后来取消旧开发数据保留要求，迁移决定由[当前云契约](../simplification/2026-11-04-prerelease-cloud-contract-cleanup.md)部分取代；这些历史操作不构成本轮部署或设备操作授权。

## Alternatives considered

手动请求可限制每次建立的目标关系，但不符合登录后自动显示同账号设备的要求；关闭即永久撤销能简化清理，却破坏再次直接开启的体验。因此采用自动目录和独立可逆开关，可信密钥仍由桌面决定。

## Consequences

发现与访问许可解耦，关闭后可恢复且迟到响应不能反向授权；代价是需共同维护目录、密钥、权限 revision、预览和通知同意。多设备、登录顺序、过期/撤销、未知响应和直连均需回归，源码测试不能替代签名 iOS 或厂商送达。
