# Agent Note: 已确认的 CLI 恢复等待共享任务结束

Status: implemented

[同 home 原生账号跟随](2026-11-11-cli-follows-native-account.md)将显式继续时发现的已核验账号变化接到本事务；任务等待、取消、代次与未知回执保护保持不变。

## 问题

本机 CLI 恢复先检查同一 CODEX_HOME 的全部任务。以前只要其他聊天运行、待审批或任务状态未知，预览就拒绝恢复，用户必须反复检查并重新确认。直接在请求内等到空闲会占用页面，跳过核验或调用原生 restart 又可能提前终止共享任务。

## 决策

在已核验的本机 macOS/Linux CLI 0.164.0、0.167.0 中，恢复预览仍是只读。明确确认后若该 home 未证实空闲，原 `cli-daemon-recovery.json` 使用 `purpose=recovery`、`phase=waiting` 保留一个维护事务，绑定发起线程的 ID、cwd 和提供商，以及主机、home、配置、已核验原生代次和预览摘要。纯代理恢复也保存目标身份；原生与保存元数据即使一起变化，旧确认仍失效。派发前再读取目标，接续使用原身份。相同确认返回同一个操作 ID；不同操作不能覆盖等待或未核验写入。取消使旧确认失效，再尝试须使用新的预览。记录只保存身份、摘要和状态，不保存认证值或原生环境。

只有明确确认启动等待，每次核验之间释放维护锁并间隔五秒。状态查看和取消不等待原生检查；取消和首次写入或退出派发共用短时记录锁。在检查结束前取消，旧 worker 不写代理设置、不退出或接续。网关关闭停止等待，重启只显示保留的等待记录，再确认同一操作后才继续核验。接入停用、原进程/配置变化或原会话已被释放时，不再接续该请求。

每次仍核对同一配置已加载的聊天、审批、目标、后台终端及网关排队/未知写入，检查不到任务信息也等待。空闲后复用既有退出、启动和显式恢复；仅发送一次同一代进程的 graceful-only SIGHUP，不用默认到期会升级强制的 daemon stop/restart，不中断任务或自动重发消息。现有退出、设置、启动、resume 的待核验回执在派发前持久记录，未知结果不重放。同 home 的恢复、释放退出及释放后的启动复用文件锁，防止不同网关同时执行相同服务的维护动作。不同网关仍各自保留本次请求的结果。

网络预览在有任务阻挡时提供 `willWait`；确认仍传 `confirmed` 和 `generation`。等待结果含 `operationId`、`state` 和 `canCancel`；状态或取消通过同一线程的 `cli-network` 提交 `action=status` 或 `action=cancel` 和该 `operationId`。这组字段由共享界面接入，读取状态不触发维护或写权限变化。

## 备选方案

继续要求用户等任务结束再手动重试，能保持最少后台工作，但无法延续用户已经确认的恢复。同步阻塞请求能简化收据，却占用交互并难以取消。另建一套恢复队列会与已有退出和未知结果账本产生双重权威，因此只在原事务上增加待闲阶段。原生 restart 虽简洁，不能提供默认仅正常排空的保证。

## 验证

跨线程有任务时原实现返回不可恢复；定向回归先复现，再验证一次确认自动等待、重复确认复用、空闲后一次正常退出/启动/接续。恢复、释放与账号同步共 110 项受控回归通过，覆盖慢检查中的状态与取消、进程变化、重启只读、同 home 互斥、未知任务与最后检查新出现的任务、未知操作不重放，以及已有成功释放回执兼容。评审修正另先复现纯代理目标的两侧元数据一起改变仍能恢复，修后 cwd 和同路由提供商变化均不退出/启动/接续；最后空闲检查期间改变目标也拒绝派发，原有成功接续核验原身份。

macOS 隔离 home 使用已安装 0.167.0 实际 daemon、两个自有线程和回环合成 Responses 上游。原线程有真实待审批时，后台检查仍保持 PID 67355，未派发退出；原客户端拒绝审批并完成后，仅一次正常退出并启动 PID 67722，只接续目标线程一次，ID、提供商和工作目录不变，目标无模型回合。两个模型协议 POST 都进入自有回环，上游付费和第三方通知均为零；两个自有 PID 退出后确认不存在。证据 `.tmp/feedback-20261111-10/cli-maintenance-native-result.json`。先前 PATH 冷启动也已用真实镜像和 PID 记录两次核验代次，见 `.tmp/c10/native-path-cold-result.json`。

## 影响

恢复可以等待已有工作安全结束，查看历史或查看状态不会启动维护。确认或取消以 home 和操作 ID 为范围；不同 home 不共享任务或认证。等待不可核验任务时可能长期暂停，需要取消或在原客户端核验。原生 API 没有原子化“仅空闲时正常退出”接口，原客户端在最后核验之后的新工作由原生排空规则处理，仍应避免在退出时新开任务。真实验证的上游为回环夹具；Linux 原生、Windows 和远端不计为此次真实验收。本点不改变账号或代理变化的触发规则，也不提供强制退出。
