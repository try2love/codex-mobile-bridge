# Agent Note: Codex 普通 GUI 启动自动接入

Status: implemented

后续[双端初始化与接口增量兼容](2026-11-22-codex-shared-initialization.md)补充应用管理、断线提示和 Linux 菜单入口；本篇保留 macOS 普通启动登记机制及实机边界。[Windows/Linux 后续实现](2026-11-22-codex-windows-linux-ordinary-launch.md)另行记录普通图标和菜单验收。

## 问题

新版原生执行器使用 App 内部的 stdio，已有适配器只在网关指定启动环境时加载。用户从 Dock、访达等原入口打开后又失去接入，需要反复远程关闭再启动。用户明确允许初始化、持久接入和必要的自动重启，要求尽量减少操作。

## 决策

macOS 初始化成功或核验到现有共享连接时，为当前用户的 GUI 会话登记 `CODEX_CLI_PATH`，指向私有的原生启动分派器。Launch Services 的普通启动继承该值；无需改动或重签 Codex 安装包，也不替换其钥匙串、账号、提供商与会话目录。新连接仍由原 App 持有既有适配器和原生执行器，沿用[新版宿主接入](../bug-fix/2026-11-21-hosted-codex-desktop.md)的控制、身份、审批和未知写入规则。旧主进程路径继续由原适配器处理，不根据 App 版本选择。

分派器在原生进程路径、所选 App、CODEX_HOME 和 CODEX_SQLITE_HOME 匹配时才调用适配器；默认 home 没有显式环境变量时只在匹配后补给该子进程。完整父子归属及进程代次仍由 Python 接入层再次核验。其他配置目录、其他 App 安装和缺少网关可执行文件的情况直接使用调用 App 自带的 CLI，保留参数、标准输入输出和环境；不另起 writer，不改原生启动参数或认证。分派器支持当前与旧安装布局中的原生 CLI 路径。

GUI 会话变量作用于该用户今后的 GUI 启动，因此分派器必须检查调用者和目录，不能只按变量存在建立接入。已有第三方 `CODEX_CLI_PATH` 保留，不静默覆盖。冲突或准备组件失败只报告 `ordinaryLaunchError`，当前已核验连接继续可用，也不因此重启 App。调用者明确传入的启动环境继续优先于 GUI 会话默认值。

分派器按最终二进制摘要存入不可变目录；普通启动配置原子发布，已运行适配器及其冻结归档不覆盖。网关更新可登记新的分派器和执行路径；旧进程继续持有旧文件。会话环境在用户登出后由系统清除，因此初始化在用户 Library/LaunchAgents 保存一个私有的 RunAtLoad 登录任务，只调用分派器的 `--register-environment` 后立即退出，不开启常驻服务。该模式在登记前同样保留第三方启动覆盖，网关已移除时不再登记。接入停用后没有网关远程权限，已初始化启动入口可继续透传原 App；网关已移除时仍保留原生启动。

已有未适配进程不能通过修改其启动环境获得当前连接，仍复用首次初始化的实时任务检查和正常重启事务；忙或未知任务不强杀。已适配的当前 App 可以在运行中登记后续普通启动，当前任务无需重启。

## 备选方案

修改 `Info.plist` 的 `LSEnvironment` 可以把配置局限于 App，但会破坏原包签名；重签还可能改变钥匙串、应用组及系统权限身份，不采用。改写 asar 或注入调试接口同样增加更新与签名维护成本。每次发现普通启动都自动重启虽然可减少点击，仍可能遇到任务未知并反复打断使用，因此只保留首次必要准备和真正换代恢复。只登记原有 shell 启动器不能安全区分其他安装，也依赖已导出的 CODEX_HOME，因此使用能透传原生 CLI 的独立分派器。

## 验证

原生隔离夹具执行 10 项检查，覆盖登录登记及第三方覆盖保留、普通 Launch Services 启动、默认 home 无显式变量、其他安装和配置目录、独立 SQLite 目录、网关移除、不可托付配置，以及原参数和输入输出透传。测试恢复原 GUI 会话变量，不访问真实聊天或模型；登录任务的真实注销重登未执行。

原签名 Codex 的 APFS 隔离副本在独立 home 和 userData 中连续两次通过普通 GUI 启动加载同一连接方案，约 4.8 秒和 3.4 秒就绪；两次均成功读取原生列表。启动命令未逐次指定 CODEX_CLI_PATH，未修改或重签 App，也未发送模型请求。日常 App、适配器和执行器身份保持不变。隔离需要的 home/userData 参数不作为普通用户的额外步骤。

最终签名 Test 包中的分派器及冻结适配器再次通过两次真实隔离 GUI 启动，约 6.4 秒和 2.5 秒就绪，并成功读取同一原生连接。254 项 Python 定向回归、101 项 Node 回归、模块边界和笔记格式检查通过。8788 Test 已自动切换，当前 App、适配器、执行器及它们正在使用的旧归档未重启或替换，8787 保持原实例。实际管理接口报告 `ordinaryLaunch: true`，用户登录任务及当前 GUI 会话变量均已登记，原 App 签名仍通过完整核验。证据保存在私有 `.local/installations/20261122-ordinary-launch/`；没有执行真实注销重登，也未把隔离副本验收当作已重启用户主 App 的证明。

## 影响

初始化后，正常从原 App 图标打开可以自动具备网关控制连接，减少重复关闭、启动操作。代价是 GUI 会话中的一个用户环境变量、一个登录登记任务及一个小型分派进程；分派进程随 exec 进入现有适配器或原 CLI，登录任务只登记环境后退出。本篇首次验收范围是 macOS；Windows、Linux 的普通启动能力与原生证据由后续互链记录补齐。未来改变 CLI 包布局或原生初始化协议时继续拒绝误接并重新验证，不能以未写版本号代替兼容证据。
