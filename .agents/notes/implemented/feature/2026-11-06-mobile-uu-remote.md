# Agent Note: 手机按电脑绑定 UU 远程

Status: implemented

## 问题

手机用户需要在查看聊天时打开当前电脑的画中画或完整远控。一台电脑可能有多个 Agent、独立配置和连接地址，按会话或 URL 保存绑定会重复授权，也可能在切换电脑时使用错误的设备。

## 决策

所有 Agent 使用同一手机「外观与显示」开关和同一右上角菜单。开关按电脑默认关闭。共享手机脚本决定菜单和设置的展示。iOS、Android 壳负责本机设置、设备选择回调和系统调用；网页只读取能力、开关、是否已绑定等展示状态，没有发起远控的桥接命令。打开 UU 只来自原生菜单的明确点击。

平台信息复用已认证的网关响应，只为 Windows 和 macOS 被控电脑提供入口。绑定使用同一网关电脑 ID（由认证 cookie 的名称计算），与地址、Agent 和聊天无关。手机本地保存 UU 选择器返回的设备标识；用户需要在 UU 中选择这台电脑，协议没有提供从网关地址推导 UU 设备的途径。移除电脑或退出其登录会清除对应绑定。普通浏览器不注入这些设置。

两端分别使用与安装包身份对应的回调 scheme。绑定及小窗请求携带一次性随机值，并记录目标电脑、操作和过期时间。匹配后消费请求；迟到、重复、移除后以及已切换到其他电脑的回调不能覆盖绑定。首次绑定成功后用户再点击所需模式，避免在回跳或冷启动时自动发起远控。小窗成功以 UU 的回执为准，全屏只交给 UU，遵循[网易跨 App 协议](https://github.com/netease-uuyc/uuremote-integration-guide)和 [Issue #113](https://github.com/try2love/codex-mobile-bridge/issues/113)。

Android 只向 `com.netease.uuremote` 发送用户点击产生的链接。清单按官方包声明查询可见性，版本已知且低于 4.42 时才提示升级。查询不到版本或版本名格式未知时仍尝试启动，实际启动报告缺少入口或系统拒绝时清除等待中的回调并分别提示。[Android 包可见性文档](https://developer.android.com/training/package-visibility/use-cases)说明查询可见性与启动其他应用是不同操作。

## 备选方案

在网关采集屏幕可以自行控制聊天内预览，但需要新的权限、媒体通道和持续资源开销。沿用 UU 系统画中画，视频与控制由已安装的 UU 负责。将远控放在各 Agent 的聊天菜单内可以利用单个会话上下文，却会重复建立电脑绑定。因此入口属于手机访问的电脑。

## 验证

网易官网分发的 Android 4.46.0 声明了上述包名和可由外部打开的 `uuremote://external` 入口。隔离夹具运行 build 49 的真实 `open` 代码，在允许启动但预查询返回空的条件下复现升级误报，记录到零次启动。修正后在同一条件下、版本不可读或带前缀时均向官方包发起一次启动。夹具还覆盖已知旧版本、绑定/小窗/全屏、实际找不到入口及启动被系统拒绝。未取得报告设备的包管理器返回值，真机实际失败的系统原因与修正后的绑定仍待复测。

共享设置的浏览器夹具覆盖真实点击、默认关闭、小窗能力不足、平台隐藏、解绑和草稿保留。Swift 协议夹具使用隔离偏好验证绑定、含特殊字符的设备标识、全屏无回调、小窗回执、重复和跨电脑回调、移除后的迟到结果。Android 普通 APK 和 iOS arm64 真机目标均从当前源码编译，成品资源与工作区一致。Android 包签名与已有 Test 相同。iOS 已生成 unsigned IPA，现有开发描述文件未覆盖此前验收的 iPhone，尚未生成可供该设备安装的签名包。真实 UU 账号选择、系统画中画、全屏控制及移动网络切换仍需真机验收。

## 影响

无需网关升级。手机不使用 UU 时没有新增轮询或远控会话。独立原生适配增加了两端回调和设备权限的维护成本。设备离线可由用户重试，UU 返回设备失效时只清除该电脑的旧绑定。已检索活跃笔记，与[共享客户端外壳](../architecture/2026-11-02-shared-client-shell.md)仅在菜单职责上相关，保留其原有决定。
