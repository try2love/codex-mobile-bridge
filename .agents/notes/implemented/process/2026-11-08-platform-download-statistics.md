# Agent Note: 按平台统计公开安装资产下载量

Status: implemented

## 问题

GitHub 的总下载徽章包含更新元数据和校验文件，不能表示安装资产的下载量。平台资产名随版本变化，Shields 的 GitHub 下载接口按完整文件名匹配，不能用通配符汇总历史版本。

## 决策

`scripts/build-download-stats.py` 分页读取公开 Release，包含预览版、排除草稿，按平台标记和允许的文件后缀汇总资产下载次数。Android 统计 APK；iOS 统计专用源码 ZIP 与 IPA；Linux 统计 DEB 与 AppImage；macOS 统计 DMG 与更新 ZIP；Windows 统计 EXE 与 ZIP。更新 JSON、YAML、签名、校验文件和 blockmap 不进入计数。按资产 ID 去重，不统计 GitHub 自动生成的仓库源码归档。

现有 Pages 工作流每日、发布后或手动运行时生成五份 Shields endpoint JSON 和一份汇总。只部署 `main` 的产品网站，不写回源码、不提交统计快照、不构建 App。请求失败使本次部署失败，保留上一份完整网站与计数，避免发布错误的零值。生成数据只包含平台计数、统计口径和时间，不导出 Release 正文、诊断、账号或本地验收资料。

## 既有记录核对

已按“下载统计、下载次数、download stats”检索活跃笔记、文档和工作流，没有相同统计机制。App 下载与更新器处理的是分发和验签，不被本流程修改。

## 备选方案

GitHub 总下载徽章无需维护，但会把频繁检查更新计入安装量。按具体文件名添加徽章简单，但每次发布都要修改且不能汇总历代资产。单独部署服务或新增写入统计分支可以更新计数，但现有 Pages 已能提供静态 JSON，因此不新增服务或源码写入权限。

## 影响

README 展示五个平台的累计资产下载次数，允许重复下载和自动更新下载，不代表独立用户或成功安装人数。删除 Release 资产可能使累计值降低。刷新有每日调度和徽章缓存延迟；完整 API 查询与 Pages 部署增加少量 Actions 用量。首次合入并部署后徽章才可用，不能把本地生成说成已上线。

## 验证

定向测试覆盖平台归类、元数据排除、iOS 源码与 IPA 合计、草稿及重复 ID、分页入口、无效计数失败，以及输出字段不携带正文。真实公开 Release 清单单独用于核对匹配范围；未部署 Pages 或推送代码。
