# Agent Note: 合并上游 v2.2.0 并保留云访问边界

Status: implemented

## Problem

本分支在共同基点 `0721aa7d` 后包含云账号、持久中继、EasyTier P2P、网页授权和开发热刷新；上游 `try2love/main` 的 `41e833ab` 包含新的客户端实例管理、ZCode、会话管理和 v2.2.0。两侧同时修改桌面入口、网关管理回调、网页资源及测试，直接选择一侧会丢失另一侧功能。

## Decision

按用户要求以上游实现为主，以普通双亲合并保留双方历史；本地独有能力只保留必要接入点。桌面入口同时加载云面板、开发热刷新与上游 API 编辑器和 ZCode 服务；网关管理使用上游的实例感知账号回调，同时继续注入本机云管理回调。

采用上游的设置字段白名单与按需客户端扫描，云面板仍独立即时保存；开发重载恢复视图后不主动扫描所有客户端或启动已停止网关。图标使用上游的客户端 family 解析，同时保留云代理前缀；终端在云网页及备用信道中均使用现有 HTTP 通路。构建同时保留 P2P 工具链与 Intel macOS 静态 cryptography 处理。

通知采用上游 `mobileEnabled: true` 与 `includeTitle: true` 的新安装默认值，已有明确保存的选择继续优先。云登录与资格刷新只管理云账号，不读取或改写手机通知开关；删除 `enable_mobile_for_cloud`、资格保存后的通知调用和一次性迁移标记的读写。旧配置中的 `cloudMobileDefaultApplied` 作为未知附加字段保留但不再参与决策，不为删除废弃字段增加新的自动写入。通知默认开启不代表云资格已确认，也不代表手机系统权限已授予。

旧云收件箱初始化方案在全局默认关闭时，将首次有效云资格作为启用时点，以锁内的一次性标记保护之后的手动关闭，并保留其他通道、链接和标题选择。用户确认采用上游默认值后明确要求删除这层检查与初始化；当前规则由通知模块统一持有，云服务不再拥有通知默认值的迁移职责。第三方投递、逐聊天提醒、手机后台同意和系统权限继续独立，云连接不产生合成通知或启动编码会话。

## 记录归属

检索活跃记录中的 upstream、上游、合并 main、开发热刷新、网页授权、客户端实例和通知默认值。现有记录分别描述运行时约束，没有合并交集的归属：[开发热刷新](../feature/2026-11-02-desktop-development-reload.md)、[网页总开关](../feature/2026-11-08-cloud-web-access-switch.md)、[独立客户端实例](../architecture/2026-11-05-independent-client-instances.md)与本篇部分重叠，约束继续成立并互链。旧云收件箱初始化决定由本篇完全取代，其历史迁移标记与已安装版本验证仍有排查价值，归档冻结；入站文档改指本篇。其余命中为模块内部上游调用或无关历史说明，不移动、不归档。proposed/rejected 无重复的上游集成方案。

## Alternatives considered

逐项挑选上游提交能缩小初次冲突，但无法满足完整合并 main 的要求，也会分割上游跨模块改动。整文件选择一侧容易消除文本冲突，却会丢失云连接入口或新的客户端身份逻辑，因此逐块组合兼容行为。

继续保留云初始化可以把旧安装的关闭值改为开启，但会覆盖明确保存的选择，用户要求直接采用上游通知规则，因此删除。旧方案曾排除只在前端勾选（无法覆盖无窗口启动与后端读取）和每次 active 都写 true（刷新或恢复会覆盖手动关闭）；这些限制现在由云账号完全不写通知设置来满足，无需迁移标记或额外 UI。

14 处文本冲突已逐块处理。Node 全量 1,563 项中 1,562 项通过、1 项跳过；随后新增图标 family 与代理前缀、云网页/备用通道终端 HTTP 回退的交集回归，相关 120 项通过。Edge Chromium 与 WebKit 宽/窄视口浏览器 376 项全部通过。Python 云服务专项 111 项通过，覆盖网页授权默认关闭、账号作用域、手机独立许可、撤销请求与未知写入不重放。模块边界检查通过，保留 22 条既有显式例外。

首次 Python 全量源码检查执行 3,523 项、跳过 237 项，报告两项失败：通知默认值断言仍期待旧版关闭；连接监测测试出现一次意外断开。监测用例的云专项复测、单用例重复 40 次、完整 discovery 后的账号组 40 项以及包含全部前置用例的顺序复测 1,167 项（39 项跳过）均通过，未据此改动生产连接监测逻辑。

通知旧迁移测试由三项跨模块回归替代：有效云资格不创建通知配置、不覆盖已保存的关闭/标题/第三方设置，旧迁移标记不再改变手机开关。三项在删除前均失败，删除后通过；最终云服务 111 项、通知行为 55 项和通知存储 8 项共 174 项通过，模块边界和笔记门禁通过。测试日志保留在忽略目录 `.tmp/upstream-main-20261108/`，不将初次全量结果报告为通过。

## Consequences

普通合并保留上游 v2.2.0 和已有分支历史，以后的上游同步仍有共同基点；本地专有云/P2P 接入点需要继续覆盖合并交集，不能用整文件保留本地版本取代上游行为。

通知默认值只有上游通知模块一个来源；云账号操作不再争用通知设置写锁或因通知配置写入失败而受影响。已有安装保存的关闭值会继续关闭，缺少配置时直接使用上游默认开启；该差别是采用上游配置优先级的结果。

归档记录按原文封印，`.gitattributes` 仅将归档树固定为 LF，避免 Windows 自动换行转换使 SHA-256 校验失效。

源码检查明确跳过原生编译/执行类。Android 构建缺少项目要求的 JDK 17，iOS 受限于 Windows 无 macOS/Xcode；模拟测试不代表真实客户端、手机或已安装版本验收。此次只合并源码，不更新运行中的网关、服务端或已安装桌面程序。
