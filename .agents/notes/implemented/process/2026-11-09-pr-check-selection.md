# Agent Note: 按 PR 改动范围选择校验

Status: implemented

## 问题

原工作流只筛选移动编译，纯界面改动仍运行后端矩阵和桌面逻辑测试；普通分支推送与 PR 还可能重复运行整套检查。

## 决策

`ci-test-scope.py` 复用已有完整 Git 差异读取，包含删除和重命名前后的路径。纯 Web CSS 选择 UI 资源和浏览器检查，不选择后端、桌面逻辑或移动编译。脚本、依赖、工作流、未知路径和资源清单保守全量；文档豁免只覆盖已知文档位置的 Markdown，不豁免架构 JSON 契约。

Android 和 iOS 源码分别选择对应编译，共享移动源码选择两端。后端共享业务和协议变更同时选择前端与浏览器检查。首版按测试组选择，不声称已分析函数级依赖或精确选择单个平台的全部后端测试。

`desktop-tests` 保留既有必需检查名，并用 `always()` 汇总所有依赖。分类必须成功、输出必须是布尔字符串；选中任务必须成功，未选的普通任务必须跳过。远端 main 实时读取确认还要求五个具名 Python 矩阵检查，因此保留这些名字：未选后端时在 Linux 只运行选择校验，跳过 checkout、依赖安装和所有功能测试；选中时按原平台运行。汇总要求这五个保留检查成功，不接受失败或取消。其他选中任务的意外跳过同样不能放行。主分支、版本标签、手动触发保持全量，其他分支由 PR 事件覆盖，避免 push 再跑全量。CI 摘要显示实际选择。

## 既有笔记审计

检索活跃笔记中的 `ci-mobile-scope`、`mobile-scope`，没有既有同主题决定。测试与架构边界记录保持独立，本次不更改其通过标准。

## 备选方案

工作流级 paths 过滤最简单，但被跳过的必需工作流可能持续 Pending。标签或“纯 UI”文字无法证明影响范围，因此采用可测试的路径分类，并对未知路径保守运行。全量最保守，但无法满足小改动减少无关执行的目标。

## 验证

分类及门禁单测覆盖纯样式、混合路径、平台编译、未知路径、依赖和取消/失败/意外跳过；已有差异读取测试覆盖删除、重命名和零基线。工作流通过 YAML 解析。通过 GitHub CLI 只读核对 main 保护：五个 `test (OS, Python)` 和 `desktop-tests` 为必需检查，分支规则集没有额外必需状态项。连接器缺少管理读取权限，未使用其失败结果推断没有规则。未推送或触发远端 Actions，未修改远端分支保护规则。

## 影响

减少纯样式与文档 PR 的无关检查，保留完整发布回归。新增模块若未分类会多跑而不会默默漏跑。路径边界需要随架构变化维护；浏览器组仍执行现有界面交互回归，CSS 可能改变点击与可见性，不能只做语法检查。
