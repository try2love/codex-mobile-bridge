# Agent Note: 已发布旧包的手动覆盖升级与回滚验收

Status: implemented

## 问题

既有 `smoke-update.cjs` 与 `smoke-update-controller.cjs` 验证当前构建的更新协议、替换及失败恢复，但旧版本由当前构建夹具模拟，不能证明真实 v2.2.1 包升级后的兼容性。稳定版更新选择器会过滤预发布版本，不能为验收临时放宽这一规则。

## 决策

Preview 3 的 Mac/Windows 基线直接使用原包的“更新并重启”安装签名的 CI Preview 4 ZIP。已发布的原 Preview 4 作为独立基线，Mac/Windows 通过原更新器的历史版本列表选择同版补丁；普通检查更新仍不会发现同版本。当前验收工作流以既有发布密钥签署冻结构建的桌面产物，矩阵验证原公钥、准确摘要和版本后提供受限的本地下载传输；不替换安装器、ACK 或回滚逻辑，不发布验收清单。原其他三种基线的手动覆盖、Linux 手动安装，以及候选回稳定版、取消、故障回滚和账号绑定草稿保留继续单独验证。

原 Preview 4 的官方 API 摘要、原签名清单与真实 ZIP 字节须一致，且候选 ZIP 摘要必须不同；Windows 同时下载原 NSIS 和 ZIP。原 P4 GUI 先载入列表，再实际点击“刷新”触发 `loadUpdateVersions(true)`，要求产生新目录请求、选中候选新摘要并明确确认同版安装。使用原包完成 `update-prepare` 和 helper 交接，匹配新 GUI ACK、真实恢复的网关和最终配置备份后继续原账号、绑定、草稿及故障回滚断言。该路径不注入 P3 专用旧连接夹具。Linux 原 P4 仍走系统安装器，并对同版候选显式使用 `--reinstall`，不能把“已安装该版本”当作补丁字节已经覆盖。结果分别保留原 P4 与候选包摘要；同版安装结果须以托管成品验收为准。

Mac 正向升级在原 P3 完成准备并暂停、其管理 worker 已关闭后，加入合成的 enabled 旧连接与 bool 凭据索引；不让旧 GUI 自动读取测试索引，也不改写真实 plan 的运行状态。实际新包必须恢复网关、写匹配 ACK，显示待迁移状态及可见迁移入口，并保留新增配置和索引。只有此场景通过才移除新增的合成连接，继续既有回退场景；不能把无连接的回退证据描述为带旧连接的冷启动成功。成品没有做钥匙串调用级监控，零 backend 调用来自源码陷阱测试，须区分这两类证据。

该补充来自 [Mac 更新启动故障](../bug-fix/2026-11-25-update-legacy-connection-startup.md)：旧验收的“手动覆盖候选 → 候选更新器回稳定版”未覆盖“旧更新器 → 新候选”，不能凭此前矩阵通过推断正向更新可靠。

`mac-arm-reuse` 仅重建 Mac ARM64，复用已成功的 Intel Mac、Windows 与 Linux 双架构原产物。Windows 复用同时要求 ZIP 与 NSIS，继续核验具体平台作业成功、冻结源码仅有允许的验收差异、artifact 来源及完整摘要；整体 run 中其他作业失败不能抵消被复用平台的成功证据，也不能把失败平台算作可复用。

草稿身份刷新夹具为每条合成回复提供固定时间和模型，避免无关的历史补读改变序列。受控调度证明，缺任一字段时在第二次读取后释放后台补读会得到 `3 != 2`，即使原生 revision 没有变化；完整字段不触发补读。保留原身份、锁、序列和空行差分断言，并用包装真实方法的 spy 明确要求本场景无补读。该修订只修正测试前提，不改变历史恢复行为。

手动 `desktop.yml` 的 `acceptance_only` 模式调用可复用 `upgrade-acceptance.yml`，不要求把新工作流合入 main。普通构建模式保持默认，checkout 采用本次 run 的不可变 SHA；显式 `source_ref` 优先。验收从真实 v2.2.1 与 v2.2.2-preview.1 至原 v2.2.2-preview.4 Release 下载对应平台包并校验发布的 SHA256SUMS，从指定成功 Desktop builds run 下载候选包。`source_ref` 必须是完整 40 位提交、包含已发布 Preview 3 基线 `d79a89c0b58f212323dac2a28b8d99baa32bd281`，且版本为 `2.2.2-preview.4`；候选 run 与它之间只允许脚本声明的精确验收文件差异。验收 checkout 与产品源码之间只允许验收脚本、工作流、测试及本笔记差异，不能夹带未构建产品修正。候选包实际安装后还须通过包内版本、平台、架构和真实 GUI 版本核验，不能只相信下载文件名。最终产品提交由发布负责人明确冻结，新增验收流程无需再次编译 App。

脚本只接受 GitHub hosted runner，拒绝本机和 self-hosted。macOS 在任务目录替换同一路径的 App，Windows 使用真实 NSIS 同一目标目录静默覆盖，Linux 在临时托管 runner 上通过 apt 安装真实 Debian 包并允许回滚降级。三阶段均使用同一隔离 `CMB_DATA_DIR` 和浏览器持久目录，不读取日常用户配置，不连接真实 Agent，不发送聊天。旧运行时创建合成配置和真实配对 cookie；真实浏览器在产品 `ComposerDrafts` 中写入合成未发送草稿，候选及回滚均验证配置原字节、原配对信任、浏览器原 cookie、草稿文本与选择位置。每阶段记录真实 GUI 和网页截图，关闭的仅是本任务启动的 GUI 与隔离网关。

此流程验证手动安装预览后的数据保留，并在新候选中实际通过历史版本列表、明确选择、单独下载及 `switch-version` 返回官方 2.2.1；不声称旧稳定版能自动发现预览。历史列表使用保存的官方 API 原始发布元数据，包摘要与大小仍对照原发布清单，下载不替换公钥或重新签名旧包。先验证单独下载不创建安装事务或配置副本，再确认安装；失败恢复后验证完整缓存仍在且重试没有重复下载。Linux 下载真实 DEB 并核对安装交接，最终 apt 安装仍在托管环境执行。调试器在真实主进程 `update-prepare` 后暂停时，通过 `Debugger.evaluateOnCallFrame` 一次读取计划、归档和请求证据；不能先用等待 Promise 的 `Runtime.evaluate` 再恢复执行，否则形成等待暂停解除的死锁。断点按准备调用之后的位置定位，不与手动安装分支中的同名保存调用混淆。

Preview 2、Preview 3 与原 Preview 4 分别只看到截至自身的预览目录，保持渠道检查为 current，并各自验证官方 stable 发现。正常账号、配对和草稿夹具只创建 `accounts/*/api.json`，不创建 CMB1 连接或 ZCode 登录，因此成功返回 stable 只证明旧格式资料保留，不能证明旧版能读取新凭据。每个候选安装后另建隔离的 CMB1 头部合成资料，用候选真实网关运行时调用 `update-backup`，验证返回 stable 和切换 Preview 3 在常规备份、手动安装交接备份两种模式下均因凭据拒绝，且不创建更新备份、不改写原配置与旧设置副本。结果仅记录拒绝目标、模式和字节保留结论，不上传资料目录或合成密钥；此检查不声称完成加解密、钥匙串迁移或完整自动安装。自动 `update-prepare` 使用相同的配置快照门禁，暂存前拒绝旧 Preview 的源码回归仍保留。产品凭据门禁不替换、不放宽，详见[凭据回退边界](../bug-fix/2026-11-24-update-credential-backup-and-legacy-guard.md)。

结果与 provenance、公开发布元数据作为独立 artifact；不上传合成密码、配对 cookie、浏览器 profile 或完整数据目录。移动端真旧包验收仍由移动构建流程单独覆盖，不从桌面结果推断 Android/iOS 安装成功。

历史版本的官方发布说明会把安装按钮推到首屏之外。真实 Chromium/CDP 复现中，按钮纵坐标为 1280，而视口高度为 823；直接发送该坐标的鼠标事件不会触发按钮，也就不会出现原生确认。验收点击前须先滚动到目标，核验可见矩形、视口与命中元素，再发送真实鼠标按下和释放事件。不得用 DOM 强制点击绕过遮挡或禁用状态；确认内容、默认取消及实际安装断言保持不变。这是验收脚本修正，产品包输入未变，可继续验收已经构建的同一成品。

旧版保存前先创建明确指定的隔离 Codex home，不放宽产品目录校验。GUI 退出等待使用实际子进程 `exit` 事件，已退出状态同时识别数值 exitCode 与 signalCode；发送 kill 请求或 `killed` 标记不能代替退出，超时仍失败，且只关闭本任务启动的进程。Windows-only 复验通过验收专用 `acceptance_target_os` 传入平台选择作业，仅从既有五项矩阵筛选 Windows，拒绝未知值；默认仍为完整五平台，普通构建路径不受影响。已经成功的其他平台无需为测试等待逻辑修正重新安装。

`desktop.yml` 的读取权限需要由可复用调用者显式授予；`release.yml` 仅在 `jobs.build` 补齐 `contents: read` 与 `actions: read`，不改变其他作业权限，也不增加写权限。回归同时核验调用链读取权限与普通构建默认模式。该权限修正及其精确测试文件允许作为非打包输入差异，不导致已经冻结的产品包重编。

发布标签的 ARM iOS 与移动更新检查因托管容量未启动而取消后，`mobile.yml` 分支版本提供默认关闭的 `intel_fallback` 手动补验。补验仅接受完整冻结源码，核验 checkout 与请求 SHA 一致且当前版本为 `2.2.2-preview.4`；iOS 原资源、归档、编译步骤保持原样。移动更新作业原样保留 Java 17 与原 CI 六条脚本，均在 `macos-15-intel` 同源执行。普通调用仍使用 ARM，不改 main 或标签。该独立 run 的结果必须单独引用，不能冒充原 ARM 标签 CI 绿色；历史 run `44144504734` 仍为容量取消导致的失败。Intel 补验是否通过以实际 run 为准，不由配置或本地结构回归推断。

构建后只修正 `tests/browser/chat-time.browser.js` 与 `tests/browser/send-feedback.spec.cjs` 的夹具前提时，等价核验仅豁免这两个精确测试路径；它们不参与桌面或移动打包。时钟夹具给不同原生任务明确 turnId，避免把被后续回复替代的中间消息当作可见最终回复；上下文检查按真实用户操作依次展开任务、工具组和内容。全部原按钮、时间、可见性、发送结果与跨会话断言保留，不使用强制点击。浏览器 DOM 诊断与截图区分折叠状态和实际布局故障，不为测试改变产品折叠规则。

Preview 4 的 Windows 后续修订仅改变四个夹具：`test_antigravity_reading.py` 从当前测试目录生成本机 file URI，核验系统路径不再写死 POSIX 形式；`test_retained_index_history.py` 的本地子进程替身明确使用 UTF-8 输入输出，以对应生产 SSH 传输并保留中文警告。两个纯分页预算夹具在合成 turn 中补齐模型，避免缺失模型触发独立后台历史补读，保留原调用上限和真实 patch 失效断言。四者不进入产品包，复用门禁只增加这四个精确测试路径，继续拒绝任何产品差异、失败平台或未完成构建。已通过的四个平台包可保留原摘要，Windows 需重新构建并执行原检查；来源证明记录实际构建提交与最终候选提交，不能把复用描述成重新编译。

同轮浏览器修订将真实 IndexedDB 持久化、及时命中的条件传输和超过 50 毫秒预算的在线回退分开核验。仅将 `tests/browser/session-transfer-http.spec.cjs` 与对应测试记录纳入精确非产品差异清单，产品传输预算和缓存实现没有修改。复用仍需核对这些具体差异、原平台作业成功及产物摘要。

Windows Node 夹具分别按平台核验权限，并接受源码的 LF/CRLF 换行：POSIX 继续要求主题文件为 `0600`，Windows 仍检查偏好持久化与无效修改不覆盖；Harmony 仍运行相同 URL 边界用例。原生 Claude 夹具的首次普通退出曾超出 15 秒，其他同源运行通过；诊断仅补充合成进程和输出状态，不放宽等待、跳过或修改产品退出逻辑。三个精确测试路径允许复用原成品，原生超时仍须由后续真实 Windows 检查核实，重跑通过不能反推超时原因已经得到证明。

## 既有记录审计

`2026-10-28-regression-and-dependency-gates.md` 部分重叠，保留其源码、浏览器和原生运行证据边界；本记录只增加真实发布包的跨版本安装层，不替代既有更新器失败恢复检查。其余客户端、协议、界面笔记与本验收流程无关，没有已失效提案需要迁移。

## 备选方案

- 复用当前构建生成的旧版本夹具可覆盖更新器分支且成本低，继续保留；它无法代表真实旧运行时、旧资源和落盘格式。
- 放宽 stable 更新过滤可直接走应用内按钮，但会改变产品的发布渠道行为，与预发布要求冲突，因此不采用。
- 在用户日常电脑安装可覆盖真实环境，但会影响活动应用和数据；这里使用托管临时环境，真机体验仍明确区分。

## 影响

本地通过脚本语法、工作流 YAML 结构、拒绝非托管环境两项回归以及笔记格式检查；既有 iOS 构建 6 项、发布资产 6 项、Java/Swift 移动渠道检查与更新器 35 项通过（1 项 Windows 原生跳过）。真实下载、安装、GUI、升级及回滚结果须以手动 workflow 的五个平台矩阵结果为准；未运行或失败不得当作通过。v2.2.1 的 Linux 回滚通过显式 `--allow-downgrades` 执行；自动更新通道不变。

Preview 4 适配的本地定向回归通过：Python 3.12 的来源与版本门禁 10 项、发布升级与发布资产 Node 27 项、既有更新资料安全 33 项。新 Node 用例通过真实源码网关 worker 核验四种 CMB1 拒绝，成品运行时的同项结果仍须由托管验收产生。来源下载测试使用合成官方响应与字节，不计作真实下载或安装。来源脚本沿用托管 Python 3.13 的 `hashlib.file_digest`；系统 Python 3.9 对依赖该函数的单个完整下载夹具明确跳过，其余 9 项来源与门禁测试通过。
