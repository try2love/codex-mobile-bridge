# Agent Note: 已发布旧包的手动覆盖升级与回滚验收

Status: implemented

## 问题

既有 `smoke-update.cjs` 与 `smoke-update-controller.cjs` 验证当前构建的更新协议、替换及失败恢复，但旧版本由当前构建夹具模拟，不能证明真实 v2.2.1 包升级后的兼容性。稳定版更新选择器会过滤预发布版本，不能为验收临时放宽这一规则。

## 决策

手动 `desktop.yml` 的 `acceptance_only` 模式调用可复用 `upgrade-acceptance.yml`，不要求把新工作流合入 main。普通构建模式保持默认，checkout 采用本次 run 的不可变 SHA；显式 `source_ref` 优先。验收从真实 v2.2.1 Release 下载对应平台包并校验发布的 SHA256SUMS，从指定成功 Desktop builds run 下载候选包。`source_ref` 必须是完整 40 位提交、包含已审基线 `bf69297f`，且版本为 `2.2.2-preview.1`；候选 run 的 head SHA 必须与它相同。验收 checkout 与产品源码之间只允许验收脚本、工作流、测试及本笔记差异，不能夹带未构建产品修正。候选包实际安装后还须通过包内版本、平台、架构和真实 GUI 版本核验，不能只相信下载文件名。最终产品提交由发布负责人明确冻结，新增验收流程无需再次编译 App。

脚本只接受 GitHub hosted runner，拒绝本机和 self-hosted。macOS 在任务目录替换同一路径的 App，Windows 使用真实 NSIS 同一目标目录静默覆盖，Linux 在临时托管 runner 上通过 apt 安装真实 Debian 包并允许回滚降级。三阶段均使用同一隔离 `CMB_DATA_DIR` 和浏览器持久目录，不读取日常用户配置，不连接真实 Agent，不发送聊天。旧运行时创建合成配置和真实配对 cookie；真实浏览器在产品 `ComposerDrafts` 中写入合成未发送草稿，候选及回滚均验证配置原字节、原配对信任、浏览器原 cookie、草稿文本与选择位置。每阶段记录真实 GUI 和网页截图，关闭的仅是本任务启动的 GUI 与隔离网关。

此流程验证手动安装预览后的数据保留，不验证稳定版自动发现预览。结果与 provenance 作为独立 artifact；不上传合成密码、配对 cookie、浏览器 profile 或完整数据目录。移动端真旧包验收仍由移动构建流程单独覆盖，不从桌面结果推断 Android/iOS 安装成功。

旧版保存前先创建明确指定的隔离 Codex home，不放宽产品目录校验。GUI 退出等待使用实际子进程 `exit` 事件，已退出状态同时识别数值 exitCode 与 signalCode；发送 kill 请求或 `killed` 标记不能代替退出，超时仍失败，且只关闭本任务启动的进程。Windows-only 复验通过验收专用 `acceptance_target_os` 传入平台选择作业，仅从既有五项矩阵筛选 Windows，拒绝未知值；默认仍为完整五平台，普通构建路径不受影响。已经成功的其他平台无需为测试等待逻辑修正重新安装。

`desktop.yml` 的读取权限需要由可复用调用者显式授予；`release.yml` 仅在 `jobs.build` 补齐 `contents: read` 与 `actions: read`，不改变其他作业权限，也不增加写权限。回归同时核验调用链读取权限与普通构建默认模式。该权限修正及其精确测试文件允许作为非打包输入差异，不导致已经冻结的产品包重编。

发布标签的 ARM iOS 与移动更新检查因托管容量未启动而取消后，`mobile.yml` 分支版本提供默认关闭的 `intel_fallback` 手动补验。补验仅接受完整冻结源码 `1561a0c82d8eb4f02f02c7a608f94812ba87a75f`，iOS 原资源、归档、编译步骤保持原样；移动更新作业原样保留 Java 17 与原 CI 六条脚本，均在 `macos-15-intel` 同源执行。普通调用仍使用 ARM，不改 main 或标签。该独立 run 的结果必须单独引用，不能冒充原 ARM 标签 CI 绿色；原 run `44144504734` 仍为容量取消导致的失败。Intel 补验是否通过以实际 run 为准，不由配置或本地结构回归推断。

构建后只修正 `tests/browser/chat-time.browser.js` 与 `tests/browser/send-feedback.spec.cjs` 的夹具前提时，等价核验仅豁免这两个精确测试路径；它们不参与桌面或移动打包。时钟夹具给不同原生任务明确 turnId，避免把被后续回复替代的中间消息当作可见最终回复；上下文检查按真实用户操作依次展开任务、工具组和内容。全部原按钮、时间、可见性、发送结果与跨会话断言保留，不使用强制点击。浏览器 DOM 诊断与截图区分折叠状态和实际布局故障，不为测试改变产品折叠规则。

## 既有记录审计

`2026-10-28-regression-and-dependency-gates.md` 部分重叠，保留其源码、浏览器和原生运行证据边界；本记录只增加真实发布包的跨版本安装层，不替代既有更新器失败恢复检查。其余客户端、协议、界面笔记与本验收流程无关，没有已失效提案需要迁移。

## 备选方案

- 复用当前构建生成的旧版本夹具可覆盖更新器分支且成本低，继续保留；它无法代表真实旧运行时、旧资源和落盘格式。
- 放宽 stable 更新过滤可直接走应用内按钮，但会改变产品的发布渠道行为，与预发布要求冲突，因此不采用。
- 在用户日常电脑安装可覆盖真实环境，但会影响活动应用和数据；这里使用托管临时环境，真机体验仍明确区分。

## 影响

本地通过脚本语法、工作流 YAML 结构、拒绝非托管环境两项回归以及笔记格式检查；既有 iOS 构建 6 项、发布资产 6 项、Java/Swift 移动渠道检查与更新器 35 项通过（1 项 Windows 原生跳过）。真实下载、安装、GUI、升级及回滚结果须以手动 workflow 的五个平台矩阵结果为准；未运行或失败不得当作通过。v2.2.1 的 Linux 回滚通过显式 `--allow-downgrades` 执行；自动更新通道不变。
