# Agent Note: 扫码后复用显示与工具栏偏好

Status: implemented

## 问题

原生显示缓存把外观与轮换的登录凭据一起分区，重新扫码配对可能读不到之前的偏好。输入框工具栏仅保存于文档的 localStorage，也未进入已验证地址切换的交接清单。

## 决策

仅外观和工具栏布局使用原生已验证电脑身份的稳定显示分区。读取时迁移当前凭据分区的旧值；其他电脑不共享。历史、草稿与其他显示记录继续保持原凭据分区，显示设置不授予任何会话权限。

共用原生脚本持久化工具栏偏好，恢复后通知所有输入框刷新；用户已编辑时拒绝迟到恢复。地址切换的显示交接同时包含工具栏偏好。原生 token、当前视图、origin、前台与回调代际检查保留。

## 备选方案

仅使用网页地址的 localStorage 无法覆盖原生页面重建和已核验地址切换。把全部缓存改成电脑分区会把历史与凭据脱钩，因此只迁移两个非敏感显示键。为每次配对复制全部旧缓存既多余，也无法表达私有聊天边界。

## 影响

同一已验证电脑轮换凭据后保持字号和工具栏排列。首次迁移需要先在旧绑定仍可用时读取旧设置；不扫描其他凭据分区。新逻辑随手机 App 的共享注入脚本交付，更新网关本身不能替换旧手机包中的脚本。

共用脚本回归覆盖新文档恢复与迟到编辑保护。Swift 使用生产存储实现，在隔离目录验证旧值迁移、凭据轮换、工具栏、跨电脑及历史隔离；手机签名安装与实际扫码仍独立验收。
