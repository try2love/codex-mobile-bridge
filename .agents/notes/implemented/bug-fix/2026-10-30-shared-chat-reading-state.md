# Agent Note: 聊天更新共用稳定节点与活动阅读位置保留

Status: implemented

## 问题

DSH 思考摘要展开并滚动后，下一次后台同步会让摘要回到顶部。v2.1.7 的桌面会话页虽然复用未变化的节点，仍对整个消息容器调用 `replaceChildren`，使这些节点离开再进入文档。隔离浏览器中使用实际渲染函数与合成长摘要，完全相同的消息也会把内部 `scrollTop` 从 200 变成 0；展开状态仍为真。原有 Node DOM 夹具不模拟这种浏览器布局行为，因此仅检查节点身份和展开状态未能发现问题。

Codex 时间线原本跳过未变化的节点，但内容变化时也只保留展开状态。两条路径没有共享“阅读中的活动正文不得因更新跳回顶部”的契约。

## 决策

`web/features/chat/activity.js` 提供共用的 `syncChatMessageNodes`、`captureChatActivityState` 与 `restoreChatActivityState`，由 Codex 时间线和 Claude/DSH 会话页直接使用。稳定消息键限定在当前聊天容器；相同位置的相同节点不移除、不重新插入。只删除失效节点，并按目标顺序插入或移动必要节点。

替换同键消息或移动已有节点前读取活动折叠项的展开状态及正文纵横滚动偏移，挂载完成后恢复。内容变短时由浏览器按新的可滚动范围截断偏移。Codex 的活动正文异步补全和工具图片显示切换也复用状态保留函数。切换聊天或时间线重置先清空旧容器，不跨会话继承相同键的阅读状态。

共享函数放在两条路径已经加载的聊天活动模块，不新增资源 URL、网络请求、计时器或提供方分支。各客户端继续负责原生数据转换，Codex 的游标、分页和增量协议与 Claude/DSH 的快照协议保持原样；外层聊天的锚定和跟随规则沿用各自已有处理。

## 备选方案

- 各页面自行保存并恢复每个摘要的滚动值：改动表面较少，也能补回偏移；但复制同一阅读规则，并继续让未变节点脱离文档，无法保留稳定节点及其浏览器内部状态，因此不采用。
- 把桌面会话整体迁入 Codex 时间线：可以统一更多渲染代码；但会牵涉不同历史接口、游标、正文分页及请求状态，扩大本次滚动缺陷的修复范围，因此只提取两者确实共有的节点更新规则。

## 测试

`tests/browser/chat-reading-state.browser.js` 使用三种会话的真实渲染器和生产样式，检查未变化刷新、追加回复、历史前插、顺序变化、摘要增长、元数据更新、正文缩短及聊天切换。未变化刷新还通过 MutationObserver 断言消息容器没有子节点移除与重插。桌面快照另覆盖移除其他消息；Codex 活动展开后的异步正文读取使用合成响应。

同组保留已有历史分页浏览器回归，验证正文加载与当前状态、草稿隔离。Node DOM 夹具补齐标准 `firstChild` / `nextSibling` 行为，不以模拟 DOM 的滚动数值代替真实浏览器证据。具体执行结果记录于 `.tmp/dsh-reasoning-scroll-20261030/`。Chromium/WebKit 回归不等于 iPhone 真机、已安装 Test 或正式版已更新。

本机定向验证：208 项 Node 回归通过；Chromium/WebKit 的 1280px 与 390px 组合共 8 项浏览器用例通过，其中阅读状态用例每组执行 64 条断言，另覆盖已有历史分页。102 篇笔记的目录、格式与相对链接校验通过，归档封印检查通过。

## 影响

未变化的消息不再反复脱离文档；思考摘要、工具活动与已折叠上下文共用阅读状态规则。每轮更新仍有按消息数线性增长的节点映射与顺序比较；只有替换或移动的活动项读取并恢复滚动偏移，不为每个摘要增加监听器或持久缓存。本修复不改变轮询频率、控件布局、权限、发送与原生会话生命周期。

历史笔记审计：[原生上下文折叠](../feature/2026-10-29-native-context-folding.md)与本篇部分重叠，继续约束来源识别与默认折叠，并引用此处的阅读状态契约；[共用原生任务状态提示](../feature/2026-10-29-shared-chat-progress.md)虽位于同一源码模块，但约束运行状态显示，与此处节点生命周期决定无重叠，保持原状。列表刷新、文件预览滚动与被动历史读取记录分别处理其他容器和读取边界，不被本篇替代；没有需要废弃或归档的提案。

首次打开聊天时，没有阅读记录表示跟随最新消息；零偏移仅在用户实际读到顶部后才是已有位置。延迟解码的图片会改变时间线高度：跟随最新时保持在底部，向上阅读时按可见消息恢复位置。共享详情加载失败会保留已有标题、草稿和缓存，并用同一个提示区域提供重试。390 像素视口的 Chromium 与 WebKit 均覆盖了首次打开、上滑和图片延迟解码。
