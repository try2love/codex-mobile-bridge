# Agent Note: 大型 Git 变更分页

Status: implemented

## 问题

#264 的大型变更列表超过原有 2 MiB Git 输出限制后整体失败。[历史按需读取](2026-11-20-git-history-on-demand.md)保证历史可用，但没有解决查看和操作大量变更的问题。

## 决策

保留完整 porcelain v2、NUL 路径与全部未跟踪文件枚举，通过临时文件分块读取，不因状态输出超过传输上限而中止。仓库元数据和全部真实变更文件身份仍参与同一版本指纹；过滤、目录折叠和分页只发生在完整状态计算之后。新界面显式请求每页最多 200 个路径；旧调用及内部写入校验不传 limit 时继续取得完整状态。大量未跟踪路径可按首级目录展开，合成目录行不能当作单文件暂存。

界面使用全局计数，分页时明确全部暂存、取消暂存和提交作用于整个项目。提交预览独立按已暂存文件分页，并绑定原版本；首批读取失败或仓库变化时禁止提交。实际写入仍重新读取完整状态和核验版本。写入命令不消费无用的长 stdout，避免成功提交被原输出上限中断；返回码、超时与不确定结果不得重放的规则保留。

## 备选方案

仅增加字节上限会延迟同类失败。截断后按部分列表生成版本会漏掉分页外变化。改用普通目录级未跟踪枚举会忽略目录深处文件变化，因此仍以完整文件清单计算指纹。返回无限列表会使手机传输和 DOM 开销随仓库增长，采用明确的有界分页。

## 影响

历史默认入口、SSH 目标端独立执行、只读配置限制、项目与仓库范围、hooks 和原 Git 身份保持原契约。分页查询可绑定版本，变化时要求刷新，不自动重放操作。响应中的 counts 为全项目计数，viewCounts 为筛选后真实文件计数，total 为折叠后分页行数；不能混用。

## 验证

隔离仓库 10,000 个长名称文件产生 2,270,045 字节状态输出，旧实现失败，新实现完整读取。25 项 Git 后端测试通过，验证分页外变化同时拒绝旧翻页和写入、全部暂存与提交覆盖 240 个分页文件、无效分页参数写入前拒绝。8 项 Chromium/WebKit 宽窄屏浏览器检查通过，验证目录展开、无合成路径写入、分页预览和过期预览禁止提交。测试不操作用户实际项目的 Git 索引。
