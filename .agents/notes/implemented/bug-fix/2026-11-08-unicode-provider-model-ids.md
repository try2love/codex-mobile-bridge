# Agent Note: 第三方供应商 Unicode 模型 ID

Status: implemented

## 问题

CC Switch 可通过原生 `model_catalog_json` 暴露包含中文路由段的模型 ID，例如
`xmy:日卡/deepseek-v4.1-flash`。Codex Desktop 能直接选择并应用该模型，但网页模型
目录、聊天模型设置、侧边聊天和账号 API 录入共用的 ASCII 正则将其拒绝。网页保存时
显示“模型 ID 格式不正确”，请求没有到达原桌面 owner。

## 决策

在 `bridge/features/accounts/models.py` 提供一个共享校验函数。模型 ID 长度保持
1–200 个字符，允许 UTF-8 中的正常 Unicode 字符，同时拒绝任何空白、Unicode
控制字符及格式字符。目录过滤、主聊天、侧边聊天和账号 API 录入只调用该函数，
不再各自复制近似正则。

不通过删除长度或空白检查来兼容中文；不修改 Codex Desktop、CC Switch 配置或
模型 ID。网页仍然把用户选择作为现有聊天下一次原生 `threadSettings` 更新发送，
保留原会话 owner、provider、cwd、认证和审批策略。

## 现有记录审计

[API 模型认证与思考能力](../bug-fix/2026-10-29-agent-model-settings-fallback.md)
只讨论 Claude/DSH 的自动模型与手动设置兜底；[CLI 模型目录](../feature/2026-10-18-ssh-cli-model-catalog.md)
只讨论 SSH 目录来源与身份。两者都没有定义 Codex 网页的模型 ID 字符边界，本篇只
补充共享校验，不改变它们的来源合并、原生能力核验或写入语义。

## 备选方案

- 继续只接受 ASCII：会让网页拒绝桌面和原生运行时本来就支持的供应商路由，放弃。
- 允许任意非空字符串：可消除报错，但会放开换行、控制字符和异常标识；输入格式
  与原生协议之间没有必要承担这个风险，放弃。
- 只修主聊天：账号 API 和侧边聊天仍会用不同规则拒绝同一模型，并继续产生不一致
  的目录缓存，放弃。

## 影响

正常 ASCII 模型 ID 的行为不变。仓库内明文模型 ID 仍属于外部供应商标识，不进入
翻译流程。该修复面向所有 Codex 模型来源，不把中文识别为某个供应商或模型；是否
可用仍由上游目录、原生账号和桌面运行时决定。
