# Agent Note: 外部接入识别只依据当前生效配置

Status: implemented

## 问题

Issue #259 报告从 Magpie 切回原配置后仍被标记为外部管理。旧文本判断扫描注释及全部表，结构化判断也把未启用的 model_providers.magpie 当作当前接入；合成配置可稳定复现。

## 决策

账号读取边界使用现有 TOML 解析器，Python 3.11 使用 tomllib，较旧版本复用仓库已携带的 wsl_tomli，不增加依赖。共享识别函数只消费结构化字典，保持 SSH 源码可独立定义，不在它内部导入 Bridge 包。将选中 profile 合并后，只核验当前 model_provider、实际采用的 endpoint 和仍生效的 Magpie 模型目录；保留未启用的 provider 定义和历史注释不再锁住切换。

显式外部管理偏好继续优先，配置不可读、TOML 无效或结构无法确认时仍阻止覆盖。该判断不写原生配置、不复制凭据，也不凭 Magpie 是否安装或进程是否退出来授予写权限。

## 既有笔记审计

[WSL 账号管理](../feature/2026-10-25-wsl-account-management.md)部分重叠：其外部/受管配置保护保持成立，本次只纠正对当前生效来源的误识别。没有将 Linux CLI 能力推断为 Desktop 自动接入。

## 备选方案

保留宽泛字符串扫描更保守，但一个注释即可永久锁定已恢复的普通接入。按 Magpie 进程存在与否判断可减少配置读取，却不能证明落盘提供方和原生模型目录的实际归属，因此均不采用。

## 影响

切回普通提供方后可恢复账号管理；真正的 Magpie 接入、显式外部模式与未知配置仍受保护。解析增加一次有界配置读取之后的内存计算，沿用已有解析器；原生账号和任务状态仍由原写前门禁核验。

## 验证

新增回归在修复前复现未启用表、历史注释、profile 覆盖和无效 TOML 的错误结果；测试同时核验真实外部模式不写配置、切换失败时保留外部改动，以及同一管理器读取新配置后即时更新。目标系统与真实原 App 的验收另行记录。
