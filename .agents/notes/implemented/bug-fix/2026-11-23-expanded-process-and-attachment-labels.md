# Agent Note: 展开过程自动读完与附件单次标注

Status: implemented

## 问题

展开一个聊天回合只读取一页过程，还需要逐次点击“加载后续过程”。上传文件的正文已提供超链接，附件区域又重复显示普通文字；已有去重仅覆盖图片。

## 决策

用户展开回合后，沿已有游标逐页补齐过程并渐进绘制，保留有限大小的请求。关闭、切换会话或版本失效时停止后续补读；失败保留重试入口。实时自动刷新仍独立工作，不把整段过程拼成一次巨型请求。

运行中过程的自动展开和各类过程元信息由[中间过程元信息与顶部只读提示](2026-11-25-process-metadata-and-readonly-banner.md)补全；此处的附件链接与去重约束继续适用。

正文中经当前文件映射确认的链接按文件路径或已确认的上传名称去重，不依赖“附件：”段落前缀。没有链接时保留普通名称；同名外部网址不能吞掉上传附件。正文完整内容或文件元数据重绘时同步核对附件标签，旧的普通名称不会与后来出现的链接并存。离线附件仍使用本机读取入口。

## 备选方案

保留手动分页无法满足一次展开查看全部的体验。无限扩大单页会增加内存和阻塞时间，继续逐页读取。删除全部附件标签会让没有正文链接的上传失去名称，因此只消费已存在的附件链接。

## 影响

主动展开长回合会产生多次过程读取，可以关闭取消后续读取。正文的分段展开策略不变。附件去重不改变文件下载、预览和离线附件的授权边界。

单元用例验证三页自动补齐、关闭停止、链接缺失及同名外部网址的标签回退。Chrome/WebKit宽窄屏验证过程自动出现，以及上传附件初次绘制和元数据到达后均只保留一个有效链接。
