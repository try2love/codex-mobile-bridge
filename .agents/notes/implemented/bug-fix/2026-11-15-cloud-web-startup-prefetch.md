# Agent Note: 云网页启动预加载服从会话流量上限

Status: implemented

## Problem

Mac 网关云网页显示正在恢复连接。生产云服务、Mac 网关和网页许可均正常，已安装的 76 个固定资源与源码一致；这些检查不能证明已登录网页已经启动。

隔离的 Go/Python 真代理中，WebKit 通过 HTTP/1.1、每个桌面请求延迟 500 ms 时约 5.6 秒启动且无失败。加入与生产一样的 HTTPS/HTTP2 后，无界脚本 preload 超过同一网页会话 8 路流量上限，26 个请求返回 429，启动约 29.4 秒并进入恢复提示。HTTP/1.1 的浏览器连接调度掩盖了这个问题。该复现确认加载器与云流控之间存在冲突，不等同于已取得用户手机当次完整请求轨迹。

## Decision

仅账号 Web 启动采用有界预加载：先完成必需样式，再保持最多四个脚本预加载请求；下载完成或失败才补充下一项。脚本仍按原依赖顺序逐一执行，预加载成功不代表执行成功。普通网页和手机原生宿主保留现有下载调度；云端账号、资格、8/64 流量限制、认证和未知写入不重放均保持现有职责。

页面离开、启动失败和完成后，迟到的预加载事件不再提交下一项。失败资源沿用现有三次有界重试与版本 URL，预加载事件不延长停滞时限。验证必须覆盖真实 HTTP2、Go 网页会话限额和 Python 桌面转发，不能仅以无延迟 HTTP/1.1 的夹具记作通过。

## Alternatives considered

- 提高服务器每会话并发能容纳首次 preload 风暴，但提高每个浏览器的资源占用，且把客户端启动策略问题转移到服务容量，因此保持现有上限。
- 所有脚本完全串行最容易约束请求，但会叠加每个资源的云往返；四路下载窗口保留预取收益，执行仍串行。
- 全宿主统一收窄代码更少，但旧记录已有普通弱网全部预发现的收益，当前约束来自账号 Web，故只调整该宿主。

## Testing

同样的 HTTP2/500 ms 条件下，WebKit 从约 29.4 秒、26 项 429 变为约 7.4 秒、无资源和脚本失败，并进入列表。新增 Node 检查在旧实现上两项失败；修复后启动定向 91 项通过，全量 Node 1661 项通过、1 项平台跳过，Python 云网页实际回环 HTTP 15 项通过。窗口上限、样式屏障、依赖顺序、不支持 preload 和退休后迟到事件均有回归。

真实 Go TLS/HTTP2、Python 桌面转发和 500 ms 延迟的 Chrome/WebKit 宽窄屏四组完整流程通过，覆盖列表、预览、两电脑与多标签存储和退出，全部请求保持原八路上限。普通启动的 36 组真实浏览器故障恢复检查通过。慢转发首次暴露 Chromium 在最终列表刷新尚未结束就执行退出的夹具竞态；请求轨迹证明 502 仅来自退出撤销中的读取，夹具等待当前刷新完成后再单独验证成功退出，没有放宽启动失败断言。服务端本机隔离 PostgreSQL 下 140 项测试及 go vet 通过。

Mac 候选只改变 bootstrap、外层资源封印与外层可执行签名；冻结网关、私有启动器和本地发布者证明逐字节不变。嵌入的本地公钥与既有本地身份一致，组件证明、启动器绑定和完整应用签名均通过。已使用同文件系统的原子目录交换更新 `/Applications/Codex Mobile Bridge Local.app`，运行网关直接返回新 bootstrap，其 SHA-256 为 `bb3541c5e8f35981c169bf513a6baa1354a44398ee64310d4b89b907e408f0c0`。PID 30107、进程启动身份与网关实例未变，云连接仍为 connected，账号、配置和两类权限文件摘要不变；未停止网关或编码客户端。

可回退原包及本轮证据保存在忽略目录 `.tmp/mac-cloud-startup-20261115/`。Tabbit 中的生产网页当前未登录，未修改账号、生成生产网页会话或读取浏览器凭据；不能把合成浏览器结果和本机资源检查当作用户手机的最终验收。

## Consequences

云网页不再以全部脚本的请求风暴冲撞已有会话上限，保留四路下载窗口及逐一执行屏障。代价是样式后多一个有界下载阶段，且预加载复用依赖浏览器；资源失败继续由原有三次重试处理。未取得已登录生产浏览器前，不能声称用户手机画面已恢复；未来修改八路上限或启动资源调度需重跑 HTTP2 与慢转发组合。
