# Agent Note: 消息管理同步 Codex 桌面队列

Status: implemented

## 问题

Codex App 中选择“完成后发送”的消息属于原生队列。消息管理此前只读取网关的发送账本，因此原生条目即使还在等当前任务结束，手机也显示没有待发送消息。

## 决策

只对当前本机接入中已核验的桌面聊天读取原生队列。读取应用服务器的 `queue_1.sqlite` 和仍在使用的桌面 `queued-follow-ups` 存储，按原生条目身份去重。仅显示正文和附件名，读取失败与空队列分开。打开消息管理时刷新读回；编辑、拖动和切换账号不接收过期的刷新结果。

## 备选方案

- 接听桌面队列广播可让更新更快，但当前版本的应用服务器队列独立于旧版桌面广播，打开时也需要已有条目。读取已提交的队列同时覆盖两种来源。
- 将原生条目导入网关账本可以复用管理按钮，却会改变派发所有权并可能重复发送。原生条目单独展示，操作留给 Codex 桌面。

## 影响

使用本机安装的 Codex 0.169.0-alpha.11.1、临时配置及回环假供应商，对比原生 `thread/queue/list` 和同会话 SQLite 结构。源码回归覆盖隔离会话、两种存储、已发送状态及原网关账本；窄屏 Chromium 和 WebKit 验证条目自动出现、移除以及操作边界。
