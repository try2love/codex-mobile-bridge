# Agent Note: Antigravity 新版发现、有界读取与消息撤回

Status: implemented

## 问题

PR #245/#250 揭示新版环境令牌和较旧聊天读取缺口；#246 的撤回缺少公共写路由，并默认回退文件；#247 的首次未知发送缺少立即核对入口。

## 决策

沿用[原生接入](../feature/2026-11-10-antigravity-native-integration.md)的来源和端点核验。macOS/Linux 在无 csrf 参数时只读同用户原进程指定环境变量，前后核验世代、监听和令牌。Windows 不添加未经实现的环境读取。

只读数据库对暂时错误有界重试；strict 查询失败保持未知。旧聊天按 128 个原生 ID 的批次定位 gateway UUID，再按主键取摘要。历史缓存限 16 页，按完整文件身份和页参数失效，读取前后稳定才缓存，返回副本。新建/发送超时 30 秒，其余 RPC 8 秒，不重试写入，日志仅记错误类型。

撤回进入公共 WRITES 和持久回执链；参数包含原生步骤与内容/媒体摘要，fresh 转录核验后请求 RevertToCascadeStep。运行、审批、Hook 队列和未知写入阻止撤回。默认 conversationOnly=true，文件回退必须勾选；UI 提交前后核验作用域，迟到结果不回填其他聊天。首次未知发送直接显示消息管理，同样检查写入作用域。

## 备选方案

整体接纳 #245 能同时放开运行中发送，但把数据库错误当 idle 会失去写前证据，因此仅采用读取与诊断部分。

按最新 300 条查找更简单，却不能定位早期聊天；全表加载摘要增加成本，采用分批 ID 定位。

撤回默认连文件一起回退接近贡献版，但扩大用户未明确选择的影响，因此默认仅对话并保留独立选项。

## 影响

扩大新版与旧聊天可访问范围，并增加明确撤回入口；缓存占用有界内存，读取重试增加失败延迟。原生接受回执不等文件结果已核验，未知结果不重放。合成跨平台发现不替代原生 2.34 真机验证。

## 验证

发现、SQL 故障、旧列表外会话、文件替换/改写、缓存副本、HTTP 到原生撤回、重复请求和过期锚点均有定向回归。UI 覆盖默认仅对话、显式文件回退、提交前换聊天与提交后迟到结果；时间线测试验证锚点传递和更新。
