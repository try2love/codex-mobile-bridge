# Agent Note: 聊天组件弱网下载并行

Status: implemented

## 问题

打开聊天时按依赖顺序逐个下载执行组件，弱网每个脚本都增加一次往返；之前仅初始页面脚本有并行预取。

## 决策

复用已有 preload 策略，在加载聊天组件组时并行下载同 URL 的脚本，仍按原顺序执行，前置依赖失败时不执行后续脚本。成功或失败后移除预取节点，保留组件加载去重及超时重试规则。

## 备选方案

直接并发插入全部脚本也可减少往返，但前置脚本下载失败后后续脚本仍可能执行，破坏既有依赖失败处理。

## 影响与验证

bootstrap 回归覆盖并行发起全部下载、顺序执行、失败后重试、不重复执行慢脚本及弱网不主动预取。该优化不改变认证或历史语义；真实弱网耗时另外记录，不将夹具结果称为真实网络改善。
