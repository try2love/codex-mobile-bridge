# Agent Note: Codex 聊天列表按主机渐进显示

Status: implemented

本文保留最初按主机渐进显示的设计。后续[列表优先与缓存复用](2026-10-22-startup-resource-recovery.md#列表优先与分层组件)将快照扩展为当前认证身份下的持久缓存，并允许成功主机的部分结果推进展示分页与快照；只有全部主机成功才确认全局空态和通知已读。下文“完整成功才保存快照和推进 offset”是被替代的旧规则。

## 问题

进入已登录的网关时，Codex 列表等待所有 SSH 主机读取完成才返回。本机已有聊天仍被慢主机挡住；首次请求前页面还会显示“没有找到聊天”。刷新失败时，旧列表与分页进度也需要保持可用。

## 决策

认证后的页面先显示同一网关实例、同一认证会话和同一搜索、归档、来源筛选下最近一次完整成功读取的 `sessionStorage` 快照。`/api/auth` 在确认登录后返回由服务端计算的 SHA-256 摘要，输入是网关启动实例 ID 与该认证会话 CSRF 值；原始 CSRF 不写入快照键或内容。页面必须先得到当前认证结果，才能恢复快照。服务端计算保证普通 LAN HTTP 上没有 Web Crypto 时仍可使用。退出、认证失效和未认证入口清除这些快照；网关重启或重新登录自然产生不同键。

`/api/sessions?scope=host&host=local` 返回本机列表及已配置的远端主机 ID。页面随后并发读取每个远端主机，并在每个成功结果到达时按时间合并显示。单主机响应的 `complete` 和 `unavailableHosts` 只证明该主机的读取结果；页面只在全部主机成功后确认全局空列表、推进合并分页的 offset、保存快照及确认移动端通知已读游标。失败主机保留此前已显示的行，错误交给原列表提示与重试入口。已从配置移除的主机行在本机结果到达后移除。旧聚合接口仍供既有调用者使用。

每个主机读取从头取到当前合并页末尾后的一行，由页面统一排序并切页。这样慢主机不阻塞其它主机呈现，同时最终分页边界仍由全部主机决定。列表请求只读现有会话存储，不触发创建或恢复。

## 备选方案

- 保留单个聚合请求并只加前端等待文案，接口最少变化，但本机和快主机仍被最慢主机挡住。
- 先读本机再发起一次完整聚合请求，可以改善本机首屏，但快 SSH 主机仍必须等慢 SSH 主机，也不能逐主机保留旧数据。
- 将列表放入全局网关缓存可减少重复读取，但缓存需要额外的认证身份边界与失效规则；本次使用认证后、会话范围内的页面快照。

## 测试

Node 回归覆盖慢 SSH 主机期间的本机和快主机首屏、未完成空态、失败主机旧行与错误关闭状态保留、分页与滚动、通知已读完成门、深链接等待应用发现、认证会话快照隔离及无 Web Crypto 的 LAN 页面。Python 回归覆盖逐主机请求不读取其它主机、HTTP 认证与分页读取范围、服务端快照标识的会话隔离。未运行真实 SSH 或手机 WebView。

## 影响

已验证的列表可在同一认证会话的页面重载后立即出现，冷进入时本机和快主机逐步出现。代价是每个远端主机有一个只读 HTTP 请求，后续合并分页会从各主机重读所需前缀；现有远端存储短时缓存仍可复用。主机暂不可用时列表保持部分可读，但不会声称全局读取成功。
