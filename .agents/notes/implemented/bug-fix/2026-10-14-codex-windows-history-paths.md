# Agent Note: 按目录身份读取 Windows 原生 Codex 历史

Status: implemented

## 问题

Windows 原生 Codex 可能在 SQLite 中保存 `\\?\C:\...\sessions\...jsonl` 形式的记录路径，而网关接收的同一 `CODEX_HOME` 是普通的 `C:\...` 路径。`Path.resolve()` 保留这两种不同表示。此时按路径文本进行父级检查会将真实存在的记录判定为位于 Codex 主目录之外：聊天仍在列表中，但网关重启后无法读取保存历史。隔离的已安装网关测试中，JSONL 内存在预期回复，但读取在解析前就被拒绝。

## 决策

`SessionStore` 对发现诊断和历史读取使用同一个记录路径包含关系检查。普通解析路径继续使用既有父级检查。Windows 上该检查不匹配时，使用 `Path.samefile()`，将每个已存在的记录祖先目录的实际身份与解析后的 `sessions` 或 `archived_sessions` 目录比较。不可访问的祖先目录不能授权访问。记录文件本身在检查前已解析，因此指向主目录之外的子符号链接仍被视为越界。CLI 和 Desktop 来源、provider 及运行时归属规则不变。

## 备选方案

延长 HTTP 详情响应等待无法通过这一永久的包含关系检查。去掉扩展路径前缀，或接受字符串前缀，会把路径拼写当成授权依据，可能混淆相邻目录或其他 Windows 路径形式。对所有普通路径都做身份检查会增加不必要的文件系统工作，包括 SSH 历史读取；因此回退仅限 Windows 上普通父级检查失败的路径。

## 影响

原隔离 Windows 保存记录在重启后可以读取，无需激活原生写入者。回归夹具继续拒绝外部目录、前缀相似的同级目录及逃逸主目录的符号链接；普通路径不使用身份回退。Windows 回退只读取有限数量的目录身份，不可访问的目录仍拒绝访问。成功读取期间，原隔离 SQLite、WAL 和 JSONL 的哈希保持不变。

## 缺失历史文件与目录读取

2026-11-12 Windows Test 日志确认另一个独立情形：数据库记录仍在，但对应 rollout 已不存在；模型目录先读取历史，因此在 `stat` 处失败。目录入口现在仅对历史文件缺失使用已核验会话元数据中的项目目录和 provider，继续复用原目录缓存与读取逻辑。此规则三平台共有，不更改聊天历史、不激活会话；权限拒绝和越界路径仍报错。没有把缺失历史伪装为空聊天，也没有退回其他账号的全局模型。

真实 Store 与 Bridge 的冷目录回归先复现相同异常，修复后模型可读；另验证正常历史设置、项目身份及权限拒绝，共四项通过。Windows 最终程序验收另行记录，不能由隔离回归推定已通过。

## 已删除项目的只读目录辅助进程

Windows `.11` 最终浏览器验收发现：聊天已连接，但模型设置仍报运行时无法启动。原生程序存在且版本查询成功；失败的是会话保存的项目目录已被用户删除，`Popen(cwd=原目录)` 返回 `WinError 267`。这与 WSL 入口是否可用无关。

目录查询仅将只读辅助进程的启动位置调整到最近仍存在的祖先目录，保留项目祖先的配置语义；`config/read`、`skills/list`、权限读取、缓存键及会话本身仍使用原始项目路径，账号和 provider 不变。原目录存在时不调整，权限拒绝仍报错。选择此方式而非重建用户已删除的目录或改写聊天 cwd；一律从用户主目录启动可能丢失原项目祖先的配置，因此不采用。

回归先复现缺失目录启动失败，修复后验证真实子进程启动、原始 RPC 目录、provider、`CODEX_HOME`、正常目录及权限失败不重试；目录测试共 36 项通过。Windows 已安装的原生 `0.167.0-alpha.3.2` 对照验证中，辅助进程从存在的祖先启动并读取原项目上下文，返回 8 个模型，无需恢复旧目录或启动模型回合。修复后的冻结程序界面验收另行记录。
