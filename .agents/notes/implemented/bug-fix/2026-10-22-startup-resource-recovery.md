# Agent Note: 启动资源恢复与脚本执行顺序

Status: implemented

## 问题

Issue #62 报告固定 HTTPS 入口在蜂窝网络首次进入时显示 `loading / 0s / resource`，刷新后成功。v2.1.3 将第一次 CSS/JS 资源错误直接显示为启动失败，同时继续放行下游脚本；资源和启动认证均没有自动重试。首屏连接提示立即显示，错误诊断直接追加到正文。现场具体失败资源与传输错误尚未确认。

## 决策

下文记录最初的启动恢复决定。[后续错误归属与缓存重试决定](2026-10-27-startup-error-attribution-and-cache-retry.md)仅替代“失败重试仍复用原 URL”和“所有窗口运行时错误均立即中止”两项规则；原有加载顺序、次数和时限、剪贴板及写入边界继续保留。

共享 bootstrap 对样式与有依赖顺序的经典脚本最多尝试三次，普通资源失败后分别等待 500 ms 和 1500 ms，重用原 URL。样式保留四路并发与级联位置。样式加载期间预加载全部必需脚本，由浏览器调度下载，但一次只插入一个可执行脚本；前置资源成功后才插入下一个。预加载只用于下载，不参与执行确认。不支持 preload 的浏览器沿用单个脚本顺序加载。

资源错误交给加载器，window 的捕获监听不能抢先报错；语法或运行时错误仍终止启动。正在挂起的脚本不能因计时到期插入第二份，因为移除节点不能保证旧脚本不再执行。12 秒无进展只改变等待提示，每次资源取得进展后续期 30 秒；最终失败后，晚到回调不能推进队列。

阻塞型 bootstrap 位于 head，在可见内容解析前读取已有主题偏好；基础 style.css 提供与后续界面相同的调色板。DOM 进入 interactive 时注册错误处理，在 DOMContentLoaded 后检查并加载必需资源；若此时基础 stylesheet 缺失、规则为空或读取规则抛错，则补偿这次未被监听到的失败。浏览器可能在 503 后保留一个读取 cssRules 时抛出 SecurityError 的样式表，因此检查必须捕获该异常，不能让检查本身终止启动。包括初始请求在内仍最多三次。message-actions.js 保持原有 defer 提前加载。其失败后的两次补偿请求立即接续，避免重试计时器的空档让旧 APK 的 WebView load 注入早于剪贴板定义；其成功也是后续脚本的前提。bootstrap.js 自身不能由尚未执行的 bootstrap 恢复，HTML/CSS 保留可见兜底。

只有启动 GET /api/auth 使用可取消的三次重试，每次最多 8 秒。网络错误、408、429、5xx 可重试，普通拒绝和成功响应中的 JSON 语法错误不重试。通用 api 只补充响应解析错误的 HTTP 状态，便于识别返回 HTML 的 5xx；不增加通用请求重试。POST 配对、登录、发送和审批不进入该策略，配对未知结果仍只允许查询状态或重新扫码。被取消的启动认证读取或其过期结果不得继续初始化；进入浏览器往返缓存时保留被暂停的启动状态，不扩大到配对写入的取消保证。

启动提示由首屏 CSS 延迟 400 ms 显示，应用就绪与资源队列完成后隐藏。该零时长动画只延迟切换 visibility，没有位移、缩放或渐变；减少动态效果的通用规则不禁用这项计时，否则慢连接和 bootstrap 缺失时的提示会一直隐藏。其他动态效果仍受原规则控制。最终错误正文简短，诊断默认折叠，继续移除来源域名、查询参数和片段。不改变内容哈希、缓存响应头、CSP、原生授权或任何网关数据。

## 既有笔记审计

按 bootstrap、data-bridge-src、启动资源、静态资源缓存和原生剪贴板检索活跃笔记；命中的 CLI 冷启动笔记涉及客户端进程，属于无关机制。没有需要替代的启动资源恢复决策。原生剪贴板的提前加载约束由已有 clipboard 回归与历史修复解释，本次保留并增加失败恢复检查。

## 备选方案

- 只延长 12 秒超时：改动很小，能减少慢请求报错，但第一次 error 仍立即失败，也不能恢复缺失依赖。
- 在现有四个可执行脚本并发队列中补插失败脚本：保留下载并发，但已插入的下游脚本可先执行，补插不能恢复依赖顺序。
- 自动刷新整页：能重新建立完整运行环境，但会重建界面并增加配对和已执行初始化的边界；局部可确认的资源失败可以直接恢复，无需自动重放页面。
- 所有脚本下载完全串行：最容易保证顺序，但冷启动会叠加网络往返；独立预加载保留下载窗口，执行仍受前置成功约束。

## 影响

短暂资源失败可以自动恢复；持续失败有次数和时间上限。代价是 bootstrap 需要分别维护下载、执行和认证生命周期，浏览器回归必须覆盖真实资源事件与 load 时序，不能只验证插入顺序。预加载复用依赖浏览器实现，移动网络性能与 HarmonyOS WebView 手感仍需现场验收。

Node 回归覆盖资源失败、级联和执行顺序、软硬期限、运行时异常、只读认证重试、取消与晚到结果、往返缓存和原生剪贴板。原配对测试继续确认未知写入不重放。浏览器夹具只监听 loopback，使用生产资源和合成认证，覆盖快速/慢启动、资源与认证故障、提前剪贴板加载、bootstrap 缺失和配对未知结果；不连接真实网关或聊天。没有构建、安装或发布应用。

## 2026-10-22 复核后的修订与验收

补充读取 cssRules 抛错、样式缺失、成功样式复用与失败次数上限的 Node 用例。新增抛错用例在修订前失败，修订后定向 40 项全部通过；完整前端测试 862 项通过、1 项 Windows 专用测试在 macOS 跳过。静态资源内容版本及依赖回滚等 8 项 Python 测试通过。

真实 Chromium 使用生产资源的隔离夹具共 22 项通过，包括基础样式连续失败、宽屏/390 px 窄屏、减少动态效果、启动脚本缺失、认证超时与配对未知结果。模拟 300 ms 延迟、250000 字节/秒下载带宽时，JS 前两次失败后约 13.3 秒自动恢复，不需要手动刷新；配对未知结果只有一次 POST。减少动态效果下慢启动与脚本缺失时约 400 ms 显示提示，快速启动不显示遮罩。

基础样式完全缺失时仍可能先显示无样式 HTML 提示；不把它误记为已应用样式的遮罩闪现。Chromium 有时对解析器创建的同一个 link 发起额外 HTTP 请求，加载器上限按初始 link 加两次补偿计算，浏览器夹具分别记录 DOM 尝试与服务器请求数。原故障的 HarmonyOS/ArkWeb 蜂窝网络与 Cloudflare 现场仍需报告者复测；以上不等于手机原生壳实机、生产缓存命中或真实 BFCache 已验收。

## Cloudflare 入口与首次下载复核

用户的 8788 Cloudflare 固定域名可稳定复现启动阶段 0 秒失败。浏览器定位到 Cloudflare 注入的统计脚本被现有 CSP 拦截；全局资源错误监听误将这个外部可选脚本当作工作台依赖。仅隔离该统计脚本的错误传播，同一入口即可成功启动。修订后只由所属资源加载器处理资源错误，窗口运行时异常仍终止启动；没有允许外部脚本、关闭 CSP 或修改 Cloudflare 配置。

排除该阻断后的冷加载瀑布约 16 秒，多数请求约有 1 秒等待。原来的样式完成后才启动脚本预取，以及按执行进度最多预取四个脚本，叠加了多轮网络等待。现在在样式加载期间声明全部必需脚本的 preload，下载由浏览器调度，执行仍保持前置成功与失败重试屏障。URL、内容哈希和 script 目标保持一致，复用现有 HTTP 缓存；不支持 preload 的浏览器保留顺序加载回退。

新增回归覆盖：外部统计脚本被 CSP 拦截但工作台成功启动、样式等待期间脚本提前下载、全部必需依赖预发现、preload 不支持时的执行顺序。生产资源浏览器夹具继续覆盖原生剪贴板 load 时序、资源失败恢复、运行时异常、未知配对写入不重放、宽窄屏及减少动态效果。实装后的冷/热加载数据与配置绑定核验记录保存在本机 `.tmp/issue62-performance-20261022/`，不把合成弱网或本机网络结果等同于用户蜂窝网络实测。

## 列表优先与分层组件

启动只等待认证和列表必需资源，复用已有身份隔离列表缓存。普通聊天的 Markdown 与时间线组件组成共享按需组；列表读取成功并完成绘制后延迟 1.5 秒低优先级加载，省流量、低带宽和 2G 环境跳过预取。用户提前打开聊天时立即请求同一组，复用正在加载的任务并提升请求优先级；快速切换或返回后，晚到结果不能打开旧聊天。公式、终端和文件预览仍仅在使用时加载，可选组件失败不升级为整个工作台启动失败。缓存 URL 和内容哈希保持既有机制，不另存跨身份列表。

列表快照随每个成功主机的结果发布而更新，不等待 SSH／WSL 全部完成；失败主机保留已有分组，全失败不覆盖旧快照。沿用身份、过滤器和入口组成的缓存键，以及请求代次校验。旧方案只在全部成功时保存，导致本机结果已经可见、重入却无缓存；分主机另建存储虽可独立刷新，但会重复既有分组和快照机制，因此只调整保存时机。部分结果不能作为通知已读或完整刷新成功的证据。

`tests/session-list-cache.test.cjs` 覆盖慢主机期间缓存、部分失败后重入、全失败和迟到回包。实际 Chromium 生产页面配合隔离 WSL 故障验证了远端仍在等待时已有本机缓存、重开先显示缓存；真实 Mac Test 网关读取验证了当前列表与快照一致。故障注入不等于 Windows 真实 WSL 端到端验收。

等待界面仅保留简洁文字和原有 400 ms 显示延迟；删除四条占位图，不把等待界面称为已加载的聊天列表。共同调色板前移到基础样式，避免后续 presentation 样式改变首屏底色。未知发送、配对、账号和草稿边界均保持原行为。

直接点击聊天可能等待尚未缓存的渲染器；这是减少首屏下载的代价。后台预取失败保持静默，用户操作时可重新请求，不能插入仍可能执行的重复经典脚本。性能报告分别记录列表可用、实际聊天可用和热缓存表现，不能只用等待界面出现时间宣称加速。
