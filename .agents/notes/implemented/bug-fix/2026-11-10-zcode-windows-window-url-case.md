# Agent Note: Windows ZCode 私有管道保留窗口地址的路径大小写

Status: implemented

## 问题

Windows 的进程身份查询把可执行文件路径规范化为小写，以便核验同一安装。私有管道持有进程把这个身份字段继续传给 `PipeTransport`，后者据此生成 renderer 的文件 URL。ZCode 窗口报告原安装路径的大小写，目标匹配与页面内地址保护均使用精确 URL；因此已启动的正确窗口仍被当作未就绪，连接会停在 `window` 阶段直到超时。

直接传入原安装路径的底层夹具不会覆盖这个问题。实机上的 `F:\ZCode\ZCode.exe` 经直接管道探测约 9 秒取得应用就绪和可新建能力；已安装冻结包经独立资料目录的真实 `serve → management-stream → holder` 链持续显示连接中。两条路径的 launcher、管道传输和管理器代码经冻结字节码比较相同，差异在于持有进程传给传输层的路径。

## 决策

Windows 持有进程用已经解析、核验且实际启动的 `application` 构造 `PipeTransport`。规范化的 `owner['image']` 继续用于原进程身份比较，不再作为窗口文件 URL 的拼写来源。目标 URL 和页面内地址保护保持精确匹配。

Linux 仍使用原生运行时的可执行文件路径；AppImage 的启动文件与挂载后运行时可以不同，不能把此次 Windows 修复扩展为跨平台替换。

本决定补充[ZCode 应用管理与私有管道](../architecture/2026-11-03-zcode-desktop-management.md)的进程身份和窗口定位边界；该记录继续管理正常退出、任务保护和连接观察。

## 备选方案

将所有窗口 URL 转小写可以消除当前差异，但同时放宽页面身份校验，并混淆其他平台区分大小写的文件路径，因此不采用。延长连接期限不能修复永远不匹配的目标地址。只验证直接 `PipeTransport` 会遗漏生产持有进程的参数转换，因此回归从 `serve` 初始化与身份核验开始。

## 影响

Windows 的已核验安装路径保留正确 URL 拼写，进程身份核验、同用户与同桌面限制、私有管道白名单和原有超时不变。修改不保存账号、绑定或正式配置，不启用 TCP 调试端口，不发送模型消息。

## 验证

回归覆盖真实 `serve` 分支创建传输对象、规范化 Windows 身份以及 `_with_window` 对原窗口 URL 的匹配。修复前返回 `ready=false, stage=window`；修复后取得 `ready=true` 并进入目标附着。私有持有进程、管道传输、Windows 管道和 ZCode 生命周期四组用例执行 28 项，其中 Windows 原生夹具在 macOS 跳过 1 项。

已安装正式冻结包的超时复现与修复后冻结包的同链原生验证分别记录，不能把底层直接探测成功当作打包修复完成。修复后的冻结运行时验收尚待完成。
