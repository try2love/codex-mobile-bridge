# Agent Note: Linux 更新后的旧进程仍参与身份核验

Status: implemented

## 问题

更新器可先删除旧程序，再写入新版；Linux 仍允许旧进程继续运行。原进程发现严格解析 /proc/PID/exe，内核返回带 deleted 标记的已删除路径时解析失败，导致旧进程从安装状态和退出核验中消失。

## 决策

读取内核链接原值，移除内核追加的 deleted 标记，保留同 UID、绝对路径及精确可执行路径匹配。可执行文件在磁盘上是否存在，不再决定旧进程是否仍存在。所有使用共享 Linux 进程发现的桌面客户端复用同一修复。

## 备选方案

按进程名称识别能发现旧实例，但会扩大退出范围；保留 strict resolve 则会把仍运行的更新前实例视为已退出。均不采用。

## 影响

不新增信号或自动退出行为；旧实例可继续被生命周期检查看到，不因删除旧文件就被忽略。无法读取进程元数据时的既有处理保持不变，当前改动不宣称解决全部 Linux 权限或进程查询失败场景。

## 验证

两项新增测试先复现失败，修复后 Linux 模块 10 项测试通过。Ubuntu 真实内核上复制已安装 sleep 到隔离目录，启动独立子进程后删除副本：旧解析方式漏检，新库存和精确路径查询仍检出；其它路径不匹配。最后仅对自己的子进程发送 SIGTERM 并确认退出，无强杀、无真实 Agent 或网关操作。原生验证文件与源码 SHA 一致，证据位于本轮 .tmp/recovery-20261116/linux-deleted-image/。
