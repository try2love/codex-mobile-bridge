# Agent Note: 原生侧边聊天不重复进入独立会话列表

Status: implemented

## 问题

Codex Desktop 的侧边聊天与普通聊天具有相同 originator、source、thread_source。列表只排除 subagent，导致附属于主聊天的原生侧边聊天被显示为“未归类”的独立会话。实际只读元数据确认原生索引已有 attached_thread_parent_id；rollout 的 attached_thread 标记也与之吻合。

## 决策

SessionStore 在搜索、置顶、排序和分页之前排除 attached_thread_parent_id 非空的行，来源选项使用相同范围。旧 schema 缺少该字段时保持原有行为，不通过标题、cwd、普通 fork 关系猜测。原生将侧边聊天转为独立会话并清空该字段后，它自动回到列表。

隐藏只影响独立列表，不删除、不归档、不更改项目或原始文件；get、历史、任务生命周期核验和通知发现继续保留原权限与行为。共享读取器同时用于本机、SSH 和 WSL，不另建操作系统分支。

## 备选方案

保留行并增加“原生侧边聊天”标签可避免误解，但有可靠的父会话标记时仍重复占据主列表；仅在未来不具备可靠分类条件时再考虑。按 forked_from_id 隐藏实现简单，但会错误隐藏普通分支，不能使用。

## 影响

列表与 Desktop 的原生父子关系一致。回归先复现旧逻辑失败，再验证分页、搜索、归档、来源、CLI 读取器、转独立会话及任务核验保留。实际用户反馈会话在只读原生数据库验证中不再进入独立列表，原会话和主会话仍可读取；没有发送消息或修改原生数据库。
