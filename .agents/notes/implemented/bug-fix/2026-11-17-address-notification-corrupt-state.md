# Agent Note: 入口通知损坏状态的局部降级与证据保留

Status: implemented

## 问题

`AddressNotifications` 在网关启动组装期间直接读取持久状态。全零、空白、截断 JSON、非法 UTF-8 会抛出解析异常；合法 JSON 的错误类型还会在构造或巡检时触发类型错误，令可重建的入口提醒影响网关可用性。

## 决策

入口通知独立读取一次原始字节，校验实际消费的容器、标识、地址、首次提醒与投递退避字段；允许未知字段及已有无 `eventId`、旧版单地址状态。无效状态先以创建即私有的唯一 `address-notifications.json.corrupt-*` 文件保存原始快照，刷新并同步数据后才允许入口通知按既有每实例语义重新生成状态。诊断警告只记录路径，不记录原始内容。

保存证据不移动或删除原状态路径，避免将读取之后另一写入者提交的新状态移走。原文件在下一次正常巡检写入前保留。读取或证据保存失败只停用本实例的入口通知，不抛出启动异常，也不覆盖原状态。

共享 `channels.read_json` 保持仅对文件不存在返回默认值的契约；账号、设置、普通消息投递与完成账本不获得这项降级，避免丢失投递证据后重复发送。

## 备选方案

- 共享读取函数统一吞掉解析异常：改动最少且可统一恢复，但账号和投递账本不能安全地变成空状态，故限定在入口提醒。
- 将原状态重命名为隔离文件：能立即移除坏入口，但读取后可能已有其他写入者替换路径，重命名会移动新内容；保留读取快照不改该路径。
- 不保留证据直接覆盖：恢复步骤最少，但无法诊断全零或截断现场，故证据保存失败时禁用提醒而非覆盖。

## 影响

有效同实例的成功投递、重试退避与事件 ID 保持原行为；新实例仍按既有规则发送启动提醒。损坏恢复会生成新的入口事件，无法证明损坏前是否已发送；此边界仅适用于可重建入口通知。每次发现损坏会新增一份私有证据，不自动清理历史文件。

历史笔记审计：CLI 释放与共享运行时删除笔记的私有状态约束、Android 菜单与 ZCode 共享能力笔记的存储描述、跨平台 CI 笔记均不决定入口通知损坏恢复策略，无需替代或改写。

## 测试

新增回归在修复前复现解析异常及类型错。`python3 -B -m unittest tests.test_address_notifications` 22 项通过；另行定向验证解析深度超限的嵌套状态也保留证据而不抛启动异常。覆盖全零、空、截断、非法编码、顶层及嵌套错类型、原始私有证据、证据失败停发、读取失败、并发替换不被移动、警告脱敏、共享读取仍拒绝坏账本，以及已有同实例去重和退避。原有本地 HTTP 接收夹具在允许回环监听的执行环境验证；没有启停真实 App 或 daemon。
