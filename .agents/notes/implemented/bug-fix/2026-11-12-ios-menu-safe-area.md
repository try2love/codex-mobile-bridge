# Agent Note: iOS 连接探测期间保留菜单安全区定位

Status: implemented

## 问题

Issue #159 的原生更多按钮只有 WebView 顶部约束。进入电脑时先清理旧 WebView 并显示地址探测页，按钮已显示但缺少纵向约束；再次清理时同样失去定位。

## 决策

保留一个低优先级的安全区顶部约束。已有 WebView 顶部 required 约束仍决定聊天页面的位置；WebView 尚未建立或被清理后，菜单使用安全区顶部加 4 点。备用约束使用 defaultLow，低于连接字幕的纵向抗压缩和贴合优先级，避免为了移动菜单而压缩字幕。

[UIKit 约束优先级](https://developer.apple.com/documentation/uikit/nslayoutconstraint/priority)允许低优先级约束在 required 关系移除后提供布局目标；此处不改变菜单操作、页面导航、Cookie 或配对校验。

## 备选方案

每个进入/退出分支单独重建 required 菜单约束可以修正定位，但会增加与 WebView 生命周期同步的分支。保留已有聊天锚点并提供常驻低优先级备用约束，改动仅两行。

## 验证

在已安装的 iPhone 17 模拟器上运行项目内隔离 UIKit 程序，布局代码直接提取生产源文件。修前安全区顶部 62 点，菜单顶部 0 点且 hasAmbiguousLayout 为真；连接时已有锚点正常，清理后又回到 0 点。修后等待与清理后均为 66 点且无歧义。带实际 UIStackView 和 caption1 字幕时，字幕高度 14.333 点与固有高度一致，连接菜单顶部为 80.333 点，即 WebView 顶部加 4 点。

该验证覆盖真实 UIKit 布局，不等于用户真机或完整最终签名 App 已验收。夹具、编译产物和数据保存在项目 .tmp，不进入正式资源。

## 影响

探测、连接和返回阶段的菜单保持可见可点击，聊天页面的定位规则保留。本点不处理探测等待时间或登录绑定切换。
