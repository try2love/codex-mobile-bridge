# Agent Note: 桌面更新交接只绑定其目标安装

Status: implemented

## 问题

Test 网关运行在 8788，但窗口显示了另一套数据目录和端口。手动选回原目录后窗口恢复。桌面控制器直接采用继承的更新环境变量，并在窗口打开后依照同一变量写入回执。正式版与 Test 并存时，旧更新环境会覆盖当前安装保存的目录。

## 决策

控制器只采用与当前安装目标、版本、数据目录和随机 token 一致的未完成交接。事务目录须是安装旁的更新目录，助手须已写入对应的就绪记录。助手记录了新进程 PID 时也须一致。子进程先于 PID 记录到达启动入口时，通过就绪记录和计划先绑定，快照完成后再核验事务并排他写入回执。事务失效后同时释放更新占用状态。

## 备选方案

只从 Test 启动器清理环境能覆盖一种启动方式，不能保护从系统菜单或外部程序启动的窗口。完全忽略更新数据目录会让正常更新或回滚使用错误的配置。无事务和 token 的回滚保留助手原先传入的数据目录。

## 影响

测试覆盖跨安装、已结束事务、错误 token、路径、版本和进程、PID 记录竞争、写回执前事务失效以及回滚。被拒绝的事务不得覆盖显式配置或窗口保存的目录，也不得占用更新状态或向原事务写回执。
