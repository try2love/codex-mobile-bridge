# Agent Note: 显式扫描优先当前注册安装

Status: implemented

## 问题

Windows 应用更新后可能保留旧版本目录。账号管理中的扫描先从当前 CLI 所在目录反查 GUI，只要旧 GUI 还存在，就不会查询系统当前注册的安装；因此重新扫描也可能重新保存旧路径。

## 决策

Windows 的显式桌面扫描先复用现有安装发现，再以原运行时附近的 GUI 作为没有发现安装时的兜底。发现器继续优先系统注册、解析可见 GUI，并区分桌面程序与 CLI。扫描本身不启动应用、不改原生账号文件。

扫描保存的路径标记为 scan，用户填写的路径标记为 manual。已有无标记记录保留原值，不推断为自动选择；安装跟随据此区分可以重新发现的结果与用户指定位置。

手动选择或旧记录只有在可确认同一个安装身份时才迁移：macOS 必须是同一 bundle 路径经 Bundle ID 验证后的可执行名变化；Windows 必须由原选项匹配已保存的 package family，且当前注册只有一个匹配可见 GUI，有旧 AUMID 时还必须一致。不同包、多个 GUI 或没有身份证据的自定义路径保持原选择。旧进程仍运行时先保留原路径；接管新安装并保存账号索引前，在账号锁内再次检查当前选择未被用户修改，不改变 manual 标记或资料目录。

Windows 清单失效依据补充当前用户的包注册指纹。原生 GetPackagesByPackageFamily 只查询已有 family，返回排序后的包名，不启动 PowerShell 全量扫描；实际重新发现仍复用原注册/manifest 解析。原生错误保持旧缓存，成功空集合才表示无注册。更新间隙保留 family，使已有新版目录后来被注册时也能触发刷新。

## 备选方案

删除所有旧安装路径可以迫使原逻辑回退，但会破坏用户安装与运行中的旧进程，因此不采用。按最大版本目录替代系统注册会选到尚未注册的包，仍以既有注册发现为先。

## 影响

手动路径保护和运行中旧实例保护保持。状态轮询只读取已知安装证据；证据变化才重新发现。旧安装与新安装同时存在时可以采用同一身份的当前注册 GUI，不把整个产品名称当作替换任意自定义安装的许可。

## 验证

桌面程序选择 7 项及账号扫描保存 1 项检查通过，覆盖旧运行时旁的 GUI 仍在、当前安装优先、扫描不启动进程、CLI 拒绝和账号配置保留。此提交尚未单独进行 Windows 真机扫描验收。

后续同身份跟随：安装更新 22 项、Windows 原生注册包装 8 项与发现 19 项通过，覆盖模糊身份、buffer 变化、查询失败、锁内选项变化及保留模型/账号资料之外的安装边界。Windows 实机只读查询返回 Codex、Claude 当前注册包，与 Get-AppxPackage 结果一致；没有退出或升级应用，不能视为全部商店升级流程实测。原生回执位于本轮 .tmp/recovery-20261116/windows-registration-proof.json。
