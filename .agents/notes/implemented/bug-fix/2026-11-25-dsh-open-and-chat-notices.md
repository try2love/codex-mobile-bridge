# Agent Note: 进入 DSH 会话自动连接与提示关闭

Status: implemented

## 问题

DSH 已提供原生 `resume`，但用户进入每条会话后仍需点击“继续会话”。顶部连接和离线提示也缺少关闭入口，反复占用聊天首屏；单次隐藏会被下一次状态轮询覆盖。

## 决策

用户打开 DSH 聊天并取得新鲜详情后，若原生能力声明可恢复且当前会话仍被选中，复用现有 `continueChat`。后台、离线、客户端禁用、缓存详情和已切走的请求都不触发；列表刷新仍只读。恢复请求保留原会话 ID、现有请求去重、权限和原生实例绑定，不发送消息或初始化其他客户端。恢复失败保留显式继续入口，不因后续详情轮询自动重试。Claude CLI、Codex 与 ZCode 既有激活规则不受此变更影响。

Codex 主聊天、其他 Agent 的共享聊天及离线顶部提示共用可关闭行为。关闭状态绑定当前接入、会话与提示正文，相同提示重绘后继续收起；不同会话、不同提示或连接恢复后的新提示重新显示。关闭只改变展示，不修改连接、任务、只读状态或输入权限，不持久写入账号与草稿。关闭按钮有独立可访问名称和32px点击区域，位于提示右侧。

[DSH 通用插件绑定](../feature/2026-10-28-dsh-generic-plugin-binding.md)的原实例核验、未知回执不重放规则继续适用。提示位置仍遵循[顶部只读提示](2026-11-25-process-metadata-and-readonly-banner.md)，本次不改变离线草稿与消息展示范围。

## 备选方案

在列表接口自动恢复所有 DSH 聊天会让后台读取产生原生激活动作，因此仅在主动打开聊天后执行。把自动恢复放入每次详情刷新会反复请求失败目标，因此复用打开动作与现有单次写流程。仅将提示设为隐藏会被轮询重绘覆盖；永久关闭全部警告又会掩盖新错误，因此按会话与提示正文收起。

## 影响

打开尚未载入的 DSH 聊天时会在原实例恢复该聊天，原历史和草稿先保留显示。恢复不会替用户提交模型任务。用户可以收起占位提示，实际状态仍显示在聊天顶部；新状态不会被先前的关闭动作静默吞掉。

## 验证

Node 用例先复现缺少自动恢复，再覆盖打开一次、列表只读、缓存/离线/隐藏/禁用/旧响应/原生后台不触发、失败后轮询不重复，以及既有 ZCode 与 Claude CLI 边界。Chrome/WebKit 宽窄屏验证 DSH 自动恢复、提示关闭、同文案重绘不重弹、新文案与新会话重显；Codex 离线提示关闭后仍保持离线权限。窄屏截图核对关闭按钮未覆盖正文或恢复入口。浏览器夹具不等同于真实 DSH 客户端联调。
