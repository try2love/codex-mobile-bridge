# Agent Note: macOS 更新交接暂缓待迁移的旧连接凭据

Status: implemented

## 问题

Preview 3 更新助手要求新版 GUI 写入 ACK，并恢复此前运行中的网关。Preview 4 的连接凭据改为显式迁移后，旧 bool 索引会抛出 `LegacyCredentialsRequired`。GUI 在网关恢复前不写 ACK，原异常又被吞掉，旧助手最终只报告没有输出和确认并回滚。

隔离的已发布 Preview 4 成品复现中，启用合成旧连接得到同样的 30 秒 ACK 超时；关闭同一连接，其他条件相同，约 2.3 秒完成 ACK。因此延长等待不能解决该确定性启动门禁。

## 决策

只有已验证的 macOS 更新交接向本机 worker 传入 `deferLegacyCredentials`。启动检查及实际网关进程仅对 `LegacyCredentialsRequired` 暂缓对应连接，保留它的 enabled 设置与原索引，记录当前网关 PID 和 `credentials-required` 状态。网关及其他可用连接正常启动后，GUI 才写真实 ACK；旧助手随后再次 start 会附着已运行网关。

普通启动、其他平台、损坏密文、缺失密钥和其他启动失败保持原行为。更新交接不读取旧钥匙串、不自动迁移、不把待迁移连接报告为就绪。桌面持续显示迁移提示，连接设置复用既有“迁移旧连接凭据”入口，用户显式迁移后重启网关。真正启动失败不写 ACK，并将具体错误留在本地事务日志供旧助手诊断；回滚判据不放宽。

## 备选方案

- 自动读取旧钥匙串可以恢复隧道，但会重新触发系统授权，违背已有显式迁移边界。
- 提前写 ACK 可以避免 GUI 超时，却不能恢复网关，旧助手后续 start 仍会失败，因此不采用。
- 自动关闭保存的连接可以绕过启动，但改变用户的网络配置，也会隐藏未恢复的入口，因此保留配置并展示明确状态。
- 延长超时保留原流程，但凭据门禁不会随时间解除，只会延迟回滚。

## 影响

旧资料可以完成更新并保留可用的本地访问；依赖旧凭据的远程入口在迁移完成前不可用，需要在电脑端处理一次。补丁不是对用户现有凭据的自动迁移。配置、账号、手机绑定与草稿仍由原资料目录承接，更新不会恢复旧快照覆盖当前数据。

## 验证

源码回归覆盖普通启动拒绝、仅 Mac 显式更新启动放行、其他凭据错误继续失败、当前 PID 连接状态、零 backend 调用和旧助手重复 start。Mac 实际源码子进程验证真实网关启动、待迁移状态、配置与凭据索引字节保留和正常停止。Node 回归验证真实控制器失败不写 ACK且保存原错误，及中英文迁移提示随当前运行状态显示。

[成品验收](https://github.com/try2love/codex-mobile-bridge/actions/runs/45655924556)在 Mac ARM64 与 Intel 上使用实际 Preview 3 更新器安装修订 Preview 4：新版 GUI ACK、真实网关运行、可见待迁移提示、旧索引字节不变及最终备份均通过。原 Preview 4 刷新历史列表后同版安装补丁也通过。账号、绑定、浏览器 Cookie 和草稿在升级、取消、故障恢复及返回稳定版各阶段均保留；待迁移连接夹具仅在正向升级验收后移除，回稳定版不代表旧版可读取新凭据。所有数据为托管执行机上的合成数据；不代替用户真实钥匙串迁移验收。
