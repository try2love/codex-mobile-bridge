# Agent Note: 自有服务器 HTTPS 端口

Status: implemented

## 问题

自有服务器 SSH 接入只接受默认 HTTPS 端口，无法通过同一公网 IP 的不同 HTTPS 入口连接多台电脑。原 SSH 检查也将公开地址端口写死为 443。

## 决策

自有服务器 + SSH 接入接受完整 HTTPS 地址中的有效自定义端口。同一公网 IP 的多个入口分别映射到各电脑独立的 SSH 回环端口。保存、Origin 白名单、SSH 检查和导出的部署说明沿用该地址中的端口。

HTTPS 证书校验、精确 Origin 校验和 SSH 回环监听继续生效。省略端口时使用 443；Cloudflare 与 Tailscale 保持各自端口约束。域名入口的证书验证仍需要相应的标准验证端口，IP 入口继续使用外部提供的有效证书。

本改动采纳 [heiqiu47 的 PR #146](https://github.com/try2love/codex-mobile-bridge/pull/146)，对应提交 `29b2c3f646122bc97550856d06a33b186df54943`；本地集成补充域名、IPv6、默认检查端口及非法端口回归，并按仓库格式整理本记录。

## 备选方案

保持服务器方式只支持 443、要求用户改选已有反向代理方式，可以使用非标准入口，但不能沿用自有服务器方式管理的 SSH 回程连接。复用已有 HTTPS 地址规范化和端口校验，可保留原连接流程，不需要新增配置项。

## 影响

多个独立网关可以共用公网 IP 并通过端口区分入口，部署说明和检查端口与用户保存地址一致。用户须为各 HTTPS 端口放行服务器防火墙与云安全组，并为各电脑分配独立 SSH 回环端口。

各网关使用独立 Cookie 名称区分登录。浏览器按主机向各 HTTPS 端口发送 Cookie，同一主机上的服务保持相互信任；端口不是 Cookie 的隔离边界。

## 验证

回归覆盖 IPv4、IPv6 和域名自定义端口保存、Origin 白名单、部署导出、SSH 检查指定端口与默认 443，以及非法端口保存失败。认证、精确 Origin/CSRF、TLS 错误无 HTTP 回退的规则使用相关现有回归验证。未在本轮部署真实服务器或执行手机登录、聊天收发；PR 作者描述的 Windows/macOS 连通结果属于贡献者提供的证据。
