# Agent Note: DSH 坏接入不阻断退出身份预览

Status: implemented

## 问题

旧插件插入仍指向已删除的构建目录时，完整退出预览先调用 discover_existing，因接入三文件不可验证而抛错，尚未读取目标进程身份。保存的接入目录失效时，lazy adapter 工厂也会在进入恢复模块前失败。接入完整性是恢复连接的前提，但不能代替对所选程序和资料目录的进程核验。

## 决策

恢复模块先获取所选安装的进程快照，保留出生时间、命令摘要、资料目录和无法识别角色检查。manager 仅在恢复入口将 lazy adapter 的 BridgeUnavailable 转为“无可信适配器”；普通连接工厂及安装验证不放宽。接入发现失败、插件缺失或适配器不可用时，不使用该接入的凭据发送任务 RPC，返回任务 unknown、可核验的进程数量和明确提示；不把未知状态当空闲，也不提供普通恢复确认。

确认前仍重新核验原进程与接入证据。预览时接入不可用，后来变为可用也必须重新预览；身份变化不能被配置错误隐藏。原有可信旧接入的任务核验和显式未知确认保持；明确 busy 继续阻止普通退出。进入原生派发前消耗本次恢复 token，失败或未知结果不复用它重发。

Windows 完整恢复复用现有 stop_deepseek：只接受同 profile、端点代次和受支持版本的原生 Quit/installer 退出通路，保留其任务与身份守卫。不再关闭窗口后调用 taskkill 清理后台；缺少正常通路不自动改成强制，确认原作用域已无任何进程时直接完成，不要求额外 Host 或退出 RPC；只有明确选择重启才进入既有启动流程。Mac/Linux 原有恢复规则不改。

显式 force 继续使用共享 toggle 的独立确认和原生身份 binder；它不读取坏接入或依赖任务可查，允许用户明确中断 busy/unknown，但仍受当前安装、进程身份、作用域及受保护进程规则约束。不增加第二套 DSH force 状态机，不把恢复 token 当 force 确认。实际已识别的 0.2.2-rc.1 尚无已验证 installer flag；本点不声称该版本已经支持无焦点普通退出，也不声称已经归因或修好此前实机 force 失败。

## 既有笔记审计

[独立客户端实例](../architecture/2026-11-05-independent-client-instances.md)的资料目录隔离和经验证退出通路保留；[DSH 接入兼容](../feature/2026-10-29-dsh-mobile-and-plugin-compatibility.md)的插件来源与任务证据规则保留。本点只拆分退出身份和接入完整性，不取得旧插件所有权，不备份或替换 patch，不清保存目录，不创建新 token 或重接另一个账号。

## 备选方案

清除旧绑定或放宽 verified_directory 能让连接流程继续，但会绕过来源、账号和未知配置保护。保持插件校验在身份预览之前可减少未知状态，却让用户无法查看已选程序的退出范围。将普通退出失败自动转为 CloseMainWindow、taskkill 或 RM 只能证明进程或窗口消失，不能证明正常保存，因此不采用。

## 验证

合成旧插入目录缺失的原始复现证明：旧代码未到进程身份查询即抛错，patch 不变、零原生动作。修后真实 DeepSeek 适配器夹具验证身份可见、任务 unknown、无不可信 RPC、原配置不变和不创建源文件。直接回归覆盖 lazy 工厂失败、确认前进程变化、接入状态变化、busy/unknown、失败 token 不重放、Windows 无系统关闭后备，以及显式 force 路由不加载坏适配器、不检查任务。本地40项相关恢复/管理检查与6项现有 Windows 原生协议检查通过，共46项；停止状态在同一用例中分别覆盖只完成退出和明确重启。

以上均为本地合成或 mock 路由测试，没有操作真实 DSH、旧 Test 或账号配置，也不替代目标 Windows 版本的原生退出/force 验收。

## 影响

坏接入仍不能正常连接、修改或冒充空闲，但不再隐藏所选程序的退出身份与数量。用户可在电脑端正常退出，或独立预览并明确选择强制关闭；成功之前不持久改变原开启偏好。旧孤儿插入的完整备份与受控替换仍属于后续独立修复。
