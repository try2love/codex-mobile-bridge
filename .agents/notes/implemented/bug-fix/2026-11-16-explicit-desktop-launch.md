# Agent Note: 显式开启与后台侧聊准备分开

Status: implemented

## 问题

远程明确开启 Codex 时，客户端开关仅启动侧聊准备线程，随后保存 enabled。准备遇到任务未知、账号门锁或 pending 回执便等待/失败；用户看到已启用，桌面却没有启动。准备是否成功没有成为显式启动的回执。

## 决策

用户明确开启先取消本实例未完成的自动准备，再在共用 initialization_lock 内使用已有 launch_client；其 DesktopApp.start 继续核验、复用当前共享运行时配置，不删除准备回执、不改账号或启动环境。启动未被观察到时返回错误，不把开关持久化为成功。网关启动仍按既有后台准备流程执行，纯 CLI 路径不变。

这部分取代[启动准备](../feature/2026-11-12-native-runtime-startup-preparation.md)中重新启用也只安排准备的决定。显式启动不会为了准备侧聊再次重启已运行 App；侧聊状态独立报告，手动准备入口保留。

## 备选方案

等待准备线程结束仍把普通启动与任务审计、侧聊能力绑定，不能解决准备受阻的冷启动。删除 pending 或忽略共享配置会重放未知写入或改变原 owner，不采用。重复调用启动直到出现窗口会带来重复实例，因此仍只调用已有一次启动与有界观测。

## 影响

显式启动成功与实际进程观测绑定，不承诺原生侧聊同时就绪。已有共享启动器失效仍保留明确错误，不静默切换执行者。当前 Mac 对话未退出；真实平台验收与模拟检查分开记录。

## 测试

新增冷启动回归先复现 launch_client 从未调用；修复后确认显式开启调用启动、失败不保存 enabled。17 项 Codex 生命周期定向检查通过，覆盖自动准备、取消、跨网关初始化锁、CLI-only 与退出任务保护。后续实机证据保存于 .tmp/recovery-20261116/。
