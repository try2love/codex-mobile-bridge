# Agent Note: Antigravity 新会话项目绑定核验

Status: implemented

## 问题

Issue #213 报告 Antigravity 2.33.0 创建本地项目会话时可能省略 `StartCascade` 响应的 `projectEnvInfo`。网关无法从创建响应确认项目，原客户端中留下空会话，首条消息未发送。

## 决策

显式返回的 `projectEnvInfo` 是权威证据。其目录缺失、畸形或不符时阻断首条消息。字段完全省略时，按创建返回的会话 ID 只读查询同来源的 `conversation_summaries.db`。唯一目录匹配才通过，缺目录、目录不符或多目录的已有记录均阻断。只有无记录或数据库无法提供证据时，才从同一原生进程读取一次 `GetCascadeTrajectory`。返回的各项 workspace 声明须相互一致且各自唯一，任何显式会话标识须与请求匹配。

创建、轨迹核验和首条发送共用创建进程的身份。进程世代发生变化时由现有 RPC 门禁阻断后续操作。未知回执沿用同一请求 ID 的去重规则。模型和思考强度继续遵循[原生发送契约](2026-11-16-antigravity-effort-through-native-commands.md)。

## 备选方案

- 仅使用创建响应可以减少一次读取，但原生客户端省略字段时会拦下已绑定的会话。
- 如 PR #215 所提，用轨迹补读任何未匹配的数据库查询可以兼顾落盘延迟。但查到相反证据时继续寻找可通过的结果，会放行目录有争议的会话。本地适配仅在缺少证据时补查。

## 影响

首条消息在绑定确认后提交一次。兼容路径至多增加一次数据库读取和一次轨迹 RPC。若进程退出、目录冲突或证据仍不可读，会保留原生已创建的会话供用户检查。

## 验证

macOS 上 `test_antigravity*.py` 的 145 项回归和模块边界检查通过。隔离回归覆盖显式响应、同来源摘要数据库、两种轨迹目录字段、相互矛盾的目录与会话标识，以及原生进程更换时在 RPC 派发前拦截。另验证首条消息的模型参数和未知回执不重放。本地测试使用合成 RPC，Antigravity 2.33.0 AppImage 实机结果由 PR 作者报告。
