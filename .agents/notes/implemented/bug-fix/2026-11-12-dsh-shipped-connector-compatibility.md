# Agent Note: 保留已安装 DSH 插件的源码兼容识别

Status: implemented

## 问题

Test 12 在 Mac 和 Windows 都显示“已有 Harness 接入无法验证”，重新扫描无效。实际插件、连接文件和安装记录仍完整，来源路径、归属和绑定结构均有效。

提交 `069ba77e` 为没有项目的聊天增加记录位置读取，修改 `host.mjs`，却漏掉了前版 `e608309a` 的 LF/CRLF 源码摘要。`verified_directory` 原来通过“当前源码”分支识别它；源码更新后它既不是当前版本，也不在旧版清单，因而被拒绝。测试将旧摘要固定在“当前源码”用例中，但该用例未在宿主协议修改后执行。

## 决策

把仓库可追溯的前版 LF/CRLF 摘要加入已有兼容清单。继续核验来源文件、安装记录、配置路径、文件权限和凭据结构，不自动重写插件、不旋转 token、不清除绑定或操作回执。

当前源码的测试只验证当前文件两种换行的复用；已发布前版另有固定摘要回归，明确验证两种换行都能恢复且所有文件不变。修改宿主源码时必须同时运行迁移测试，避免把旧版本误报为不可信来源。

## 备选方案

重新安装可以生成新配置，但会掩盖兼容清单遗漏并影响原绑定。取消源码校验能接受任何历史文件，却扩大旧协议接入的信任范围。采用已有的精确前版兼容机制，不改变接入所有权。

## 验证

回归先复现同一句拒绝错误，补充摘要后通过。Mac 实际已安装源码摘要与仓库 `e608309a` 完全一致；Windows 只读检查得到相同摘要。实际接入仍需正常运行中的原生 host 回应，静态校验成功不等同于已连接。

## 影响

现有修订 11 绑定可继续复用；新增记录位置能力仍取决于原生 host 版本。与[独立插件兼容契约](../feature/2026-10-29-dsh-mobile-and-plugin-compatibility.md)部分重叠：独立插件的版本握手不变，本修复只覆盖旧官方接入的源码白名单。缺文件的[连接修复](2026-11-11-dsh-missing-connector-repair.md)是另一种故障，不触发该修复。其他提案不变。
