# Agent Note: Windows Codex 退出允许打开已核验的惰性 File 菜单

Status: implemented

## 问题

Issue #206 的 Windows 实机退出流程已通过账户、待发消息、原生 owner 和进程身份审计，但仍报告没有可后台调用的退出入口。只读 UIA 证据表明：唯一可见 Codex 主窗口提供准确的 File MenuItem，子菜单仅在展开后创建；该触发器支持 `ExpandCollapsePattern`，不支持 `InvokePattern`。菜单容器可先于退出子项暴露，立即查找也可能得不到结果。

## 决策

主窗口必须已可见，且仍符合原进程、出生时间、用户会话和窗口身份。仅在准确 `application-menu-content` 不存在时，选取同 PID、唯一、可用且未离屏的 `application-menu-trigger-file-menu` MenuItem；重新比较同一触发器后，只执行一次其原生 `ExpandCollapsePattern.Expand`，没有该模式时才使用 `InvokePattern`。动作失败不改用另一种模式重试。

打开菜单不表示已经提交退出，只输出 `opening-menu`。后续在有限等待中查找原有精确 Quit 标签与 Ctrl+Q，派发前再次核对同一菜单和退出控件；退出仍只派发一次，并由系统进程消失确认完成。隐藏窗口、重复菜单或触发器、错误快捷键、取消、出生代次不符仍拒绝，不激活前台、不发送全局键盘、不强制结束进程。

打开菜单和 UIA 调用不持有取消锁。开始前与返回后都检查取消，迟到的展开回执不能继续提交 Quit。已进入 UIA 的展开本身可能在取消后才显现，不能承诺完全没有短暂菜单变化；不会为清理菜单额外注入全局输入。

这项决定部分替代[Windows Codex 安静退出](2026-11-11-windows-codex-quiet-quit.md)中“一律不展开菜单”的要求，保留其不显示隐藏窗口、同代身份与一次派发约束。旧记录保留当时理由，不改写成相反决定。检索未发现同机制活跃提案；Claude 后台退出和 ZCode 托盘退出不在本次修改范围。

## 备选方案

继续只读已暴露的菜单能避免所有主动菜单变化，却使当前官方 Windows App 的默认闭菜单状态始终无法正常退出。全局 Ctrl+Q 或强制关闭可以跳过惰性菜单，但不能保证作用于已核验的目标和正常保存，因此不采用。只尝试 Invoke 更简单，但实际子菜单提供的是 ExpandCollapse；本方案依据当前控件提供的原生模式执行一次准确动作。

## 验证

Windows 普通用户、非活动桌面的 Electron 原生夹具中，旧 helper 对关闭菜单场景失败；新 helper 的三个测试与十二种子场景全部通过、零跳过。覆盖正常与惰性退出、延迟 200ms 创建子项、隐藏窗口、原生确认、重复退出或触发器、错误快捷键、预取消、打开后取消和错误出生时间。逐场景检查前台窗口不变、菜单只打开一次、Quit 派发次数与真实正常进程退出。SelfCheck 另验证阻塞展开期间可取消、迟到返回后零 Quit，以及中文标签的独立 Unicode 编码比对。

实机读取 File 菜单模式与准确 `退出 ChatGPT Ctrl+Q` 标签；原菜单内容诊断版本删除了 Quit 派发路径，仅用于核实协议。修后普通用户的完整账户与原生任务审计通过，展开一次、Quit 一次，原进程由系统确认完全退出后恢复同一 App；账号、模型配置哈希和日常历史 ID 均保持。该次真实流程耗时约 22.6 秒，零模型请求、零强制结束，回执位于本轮 `.tmp/windows-linux-20261120/windows/menu-fix/`。

## 影响

原生正常退出可以处理默认闭菜单与惰性子项，但可能短暂展开用户已有可见窗口的 File 菜单。这是本次为正常退出接受的可见成本，不宣称完全后台无界面变化。没有增加强制退出、账号切换或模型请求权限。
