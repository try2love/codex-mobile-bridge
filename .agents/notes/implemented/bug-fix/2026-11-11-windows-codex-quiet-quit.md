# Agent Note: Windows Codex 退出不显示隐藏窗口或展开菜单

Status: implemented

## 问题

Windows Codex 正常退出助手原先会显示已有的隐藏主窗口，并展开 File 菜单寻找 Quit。即使不激活窗口、不发送鼠标键盘输入，这两步也会改变用户看到的桌面。

## 决策

仅在现有可见主窗口中查找已经暴露的应用菜单退出项。保留同一进程映像、出生时间、用户会话、窗口归属、唯一菜单项及 Ctrl+Q 标签的校验；派发前重新获取菜单和退出项，比较同一控件并检查原生确认。没有可信后台入口时立即报告尚未提交，请用户在电脑端正常退出；不显示窗口、不展开菜单。

沿用一次派发、取消锁和 submitted/pending 回执。已经派发但返回失败时不重发，由既有调用方观察原代退出。删除仅服务于隐藏窗口恢复的记录和回滚代码。ZCode 托盘分支及其私有退出协议保持原行为，CLI daemon 释放与此桌面退出互不替代。

## 备选方案

保留显示但不激活的窗口调用可提高退出入口发现率，仍会打断视野。保留菜单展开也不符合要求。系统结束会话或终止进程虽然能让进程消失，却不能证明客户端正常保存，因此不能作为正常 Quit 后备。

## 验证

更新既有 Windows 原生 Electron 夹具：退出项事先可用时仍调用实际 UIA；默认菜单未展开或主窗口隐藏时不得显示窗口或展开菜单，必须零派发并保留进程。重复退出项、错误快捷键、取消和出生代次不符仍拒绝；原生待确认保持 pending；提交成功需独立观察实际正常退出。夹具只在新建的非活动桌面中运行，留有自身正常退出通道。

Windows 实机用已有 .NET 编译器编译助手，三个原生测试通过、零跳过，耗时约 25.6 秒；其中 Electron 测试包含上述八种场景，检查零菜单展开、隐藏窗口不显示、前台窗口不变、派发次数及正常退出。使用既有 Electron 分发文件，无新依赖安装，不操作真实客户端。源码包及结果位于 `.tmp/feedback-20261111-10/quiet-codex-r1/`；对真实安装客户端的能力验证另行报告，不能把自有夹具通过等同于任意版本都支持后台 Quit。

## 影响

网关不再主动改变该退出路径的窗口可见性或菜单状态，但未暴露后台 Quit 的版本可能无法由网关正常退出。UIA 提供程序仍可能弹出自己的原生确认，不能保证所有版本绝无界面变化。显式强制退出继续使用独立的身份预览和确认。
