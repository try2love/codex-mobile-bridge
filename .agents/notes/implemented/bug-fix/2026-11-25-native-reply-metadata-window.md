# Agent Note: 原生回复元信息独立于正文窗口

Status: implemented

## 问题

真实长会话在原 Codex App 中有回复时间和回合模型，网关仍显示缺失。原生 SQLite 索引的消息时钟未被读取，只用 rollout 最后2MB补时间；较早记录因此丢时钟。LiveSession 又把40条正文窗口当作全部元信息来源，已经裁掉的完成回合失去模型和时间。运行回合被排除在已记录标签合并之外，且只有模型缺失时不会触发背景补读。

## 决策

原生索引读取按列探测兼容消息 ID、开始和完成毫秒时钟，消息 ID 必须与正文原生 ID 一致。已有消息时间保持优先；缺少时使用该消息已记录的完成时间或开始时间，不使用当前时刻、文本匹配或列表位置。

正文保持原条数边界，额外的相邻消息元信息查询只取最多100个 ID、类型和时钟字段，不读取那些记录的 `item_json`。已读取正文页的元信息同样保留，展开140条以上的已读历史不会被100条相邻窗口裁掉。回合模型仍从该原生回合的 `turn_context` 读取，沿已有物理历史分段与字节边界核验，不用会话当前模型替代历史模型。

元信息以内部 `_historyMetadata` 投影交给 LiveSession，与正文缓存分离。按同一会话、回合及消息 ID 合并显示信息；不改原 owner 状态、任务状态、审批和写入权限。运行回合已记录的模型可以补入，仅模型迟到时也进入既有有界背景刷新。

[模型回复元信息范围](2026-11-25-model-reply-metadata-scope.md)规定的界面保持不变：仅模型发言显示模型和思考强度，时间位于“引用”旁；用户输入、工具执行不增加模型标签或未记录占位。[原生消息时间](../feature/2026-11-09-native-message-time.md)的唯一原生身份与不伪造时钟约束继续有效。

## 备选方案

扩大到全量 rollout 扫描可以找到旧消息时钟，却让正文越大读取越慢。增大正文窗口能暂时覆盖此前回合，同时增加工具正文解析与传输。采用原生索引的小字段查询，使元信息覆盖不依赖正文大小；旧索引缺少列时沿用现有有界 rollout 证据读取。

## 影响

每次索引历史读取增加一次有界元信息查询和少量回合头读取。没有额外读取相邻消息正文，不影响发送路径或触发原生会话启动。时间与模型晚到通过既有同步元信息更新，正文内容摘要不因仅时间变化而改变。

## 验证

新增回归先复现丢时钟和正文窗口裁剪，再验证模型单独迟到、运行回合合并、ID不匹配保护及140条历史元信息。未选择的旧正文使用不可解析的夹具，确保元信息读取不会解析它。真实同一 owner 快照由完成回合0/7时间和模型恢复到7/7，运行回合3/3；正文仍限40条，读取约85ms。1200条原生窗口中的53条模型回复，其时间、模型及思考强度均为53/53；这是当前会话证据，不代表所有版本都保存了这些原生字段。
