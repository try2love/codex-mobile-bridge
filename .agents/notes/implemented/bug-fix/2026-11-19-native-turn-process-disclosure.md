# Agent Note: 同一轮会话只显示一次用时

Status: implemented

当前 UI 的分组展示与聚合读取已由[恢复逐条中间过程展示](../simplification/2026-11-19-unfold-native-chat-process.md)取代；下文保留原决定及兼容端点背景。

## 问题

v2.2.2-preview 将每个过程游标直接渲染成独立折叠。用户在运行中看不到过程目录，同轮过程被普通补充分隔时还会重复显示用时。Issue #212 需要恢复运行预览与整轮折叠，同时保留对话首屏的分页预算。

## 决策

两个共享聊天渲染器按原生轮次共用外层展开状态。过程片段继续留在用户补充的两侧。终态只显示一个入口，用时取原生开始和结束时间，缺少时钟时只显示“执行过程”。一次展开可以看到各片段，后续刷新保留读者的选择。

可信运行状态只自动读取最新片段的最近一页。现有过程目录通过 `after=latest` 提供有界尾页，按时间顺序返回条目，并用 `hasEarlier` 标记未读的前部。已完成轮次展开时从首条开始分页，可复用已完整读到的目录。工具各自的正文和附件仍由显式操作读取。过程游标校验与历史分页继续沿用[对话与过程读取分层](../feature/2026-11-17-lazy-conversation-projection.md)。

## 备选方案

- 每个片段独立展开能复用现有游标，但重复用时，也要分别查找补充前后的过程。同轮共享折叠，保留独立片段。
- 运行时自动读取历史首段改动较小，但长任务超过一页后无法显示近期进展。尾页预览沿用现有条数和字节限制，历史界面继续顺序翻页。

## 影响与验证

运行中最多自动读取当前片段的一页目录，结束后收起；普通补充、最终答复与文件摘要始终按原序可见。定向 Node 285 项、Python 43 项通过。Chrome 与 WebKit 的宽窄屏回归共 16 个用例通过，覆盖完成、晚到答复、目录复用、分页和滚动位置。真实原生客户端交互仍需验收。
