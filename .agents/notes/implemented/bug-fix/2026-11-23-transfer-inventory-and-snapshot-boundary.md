# Agent Note: 传输清单完整性与进行中回合的快照边界

Status: implemented

## 问题

传输页只呈现全局前100条会话，后续 Agent 和读取失败的接入没有直观展示。Codex 清单还会丢弃没有 rollout 大小且没有已连接 owner 的记录。计算下载量时，无法通过原生消息身份拼接的实时尾部会使整个会话准备失败，页面等待期间没有进度。

## 决策

自动遍历清单分页，以 Agent 标签切换列表，跨标签保留选择并显示总计数。选框与标题同排；读取失败显示在对应 Agent，允许重试，记录缺少文件元信息也保留在清单，实际传输仍核验源。

已保存历史与实时尾部仍仅通过唯一原生身份拼接。无法证明尾部完整时传输固定的已保存分界，明确提示当前回合尚有未同步内容；不伪造缺失过程。没有任何已保存分段且只有部分实时内容时仍失败。准备清单发布已处理数量、当前会话和错误；警告随任务保存，不把相关会话登记为完整缓存。

## 备选方案

继续要求完整 owner 尾部会使正在运行的会话无法复制，用户已选择先保存可验证内容。按文本相似度或位置拼接可能重复或遗漏过程，因此保留身份核验。一次返回全部清单会扩大响应，继续使用现有分页接口并自动读取后续页。

## 影响

清单会显示此前被隐藏、实际源可能暂不可用的会话；准备时逐会话报告失败。新增进度与警告均为清单元数据，不改变聊天原始内容，也不触发激活、发送或重放。

源码夹具复现相同 ValueError，验证保留已保存正文、拒绝混入无法核验的实时尾部；清单覆盖其他 Agent 和读取失败；任务验证警告会话不被标记完整。Chrome/WebKit 宽窄视口验证跨页、跨 Agent 选择计数和行布局。
