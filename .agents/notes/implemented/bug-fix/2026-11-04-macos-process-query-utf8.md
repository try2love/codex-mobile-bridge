# Agent Note: macOS 进程身份查询固定 UTF-8 子进程环境

Status: implemented

## 问题

从桌面启动的 Test 没有 LANG、LC_CTYPE、LC_ALL。默认 C 区域下，macOS `ps` 将中文目录输出为 `M-...` 转义文字，而内核身份返回真实路径。私有管道的签名与 PID 校验通过后，命令角色比对仍失败，表现为 `Wrong private ZCode service role`。这与旧管道属于另一网关可执行路径而被拒绝是两个不同原因。

## 决策

`bridge/platforms/macos/desktop.py` 的进程清单与精确 PID 命令查询，都仅对子进程设置 `LC_ALL=en_US.UTF-8`，并显式按 UTF-8 解码。保留其他环境项，不修改系统或调用进程的区域设置。继续逐字比对完整路径与参数，保留内核身份、用户、PID 世代、签名和角色检查，不把拒绝视为可占用的空闲通道。

## 备选方案

把 `ps` 的转义文字还原为字节需要处理歧义，可能将不同路径误判为同一目标，因此不采用。忽略角色比对能消除表面错误，但削弱访问边界，不能采用。只给打包脚本设置 LANG 无法保证用户从 Finder、登录启动或不同地区环境启动的结果，因此在共享查询边界固定子进程环境。

## 验证

同一个真实验收组件 PID 的内核路径与 UTF-8 `ps` 参数完全一致；在 `LC_ALL=C` 下，同路径被转义。已核对运行中的网关没有三项区域变量。四项进程查询回归通过；另用两秒自动结束的独立进程，在 C 环境下验证中文参数原样保留、调用方环境未变。该检查不操作真实 Agent，也不发送模型消息。

最终签名 Test 128.10 的冻结查询模块通过同样的中文探针，独立 8790 网关正常启停。真实 8788 冷启动原 ZCode 成功，私有管道和会话身份检查通过，同一 Fork 可读且返回发送权限；随后官方远控与 HTTPS 验收也通过。未改系统区域设置、未开启 TCP 端口、未放宽角色或签名匹配。

## 影响

所有复用此 macOS 查询的客户端获得一致的路径文本，不新增平台分叉或系统设置。只改变进程查询的文本表示，不改变如何发现、授权或退出应用。最终打包私有管道验收与源码级验证分别记录。
