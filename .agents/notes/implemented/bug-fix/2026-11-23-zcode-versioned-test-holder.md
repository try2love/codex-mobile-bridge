# Agent Note: ZCode 跨 Test 版本目录的持有进程核验

Status: implemented

## 问题

Test 包按版本保存在不同目录。仍维持原 ZCode 匿名管道的旧持有进程位于前一目录，新网关先因同目录限制拒绝它；通过这一步后，客户端还会错误地要求旧持有进程使用新包路径。持有进程对新网关的校验也有相同路径限制。

## 决策

已发布组件允许按签名证明核验跨目录的同一产品，仍要求准确的运行中 broker 摘要、独立 starter 授权和有效签名。未发布身份继续要求同一安装目录。网关验证原持有进程的当前 PID、代际、UID、资料目录的精确锁 inode 与实际服务命令；持有进程验证当前资料目录登记的网关 PID 和精确服务命令。角色检查使用已通过内核和签名核验的真实映像路径。

旧持有进程不能热替换。此次迁移在用户确认 ZCode 空闲、授权正常重启一次后进行；新协议用于后续跨版本更新。不会通过关闭签名检查或直接杀死持有进程处理该错误，也不重启 Codex。

## 备选方案

把所有 Test 永远覆盖在同一路径可绕开此症状，却继续将接入授权依赖部署目录。允许任意同名或同证书程序会丢掉具体产品、broker、资料和进程代际边界。保留已发布身份的精确证明，调整目录假设。

## 影响

组件证明包含文件摘要，首次接管仍有核验开销；同一不可变进程复用已验证证明，每次连接仍检查内核身份和服务角色。单次旧协议迁移需要正常退出原 ZCode，后续无需为目录变化中断原管道。

源码回归覆盖跨版本同产品、错误发布证明、非发布程序的目录限制、错误资料目录和额外命令参数拒绝，共25项相关检查通过。真实包接管与此次重启的结果单独记录在本轮交付凭据中。
