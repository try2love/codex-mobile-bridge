# Agent Note: Codex 历史文件缺失后的原生保存记录读取

Status: implemented

## 问题

传输准备把缺少 rollout 文件统称“原会话暂不可读取”；首屏历史也先对该文件取 stat。原 App 仍能使用原生消息索引，但网关不进入这个读取路径。现场只读核对114条记录：76条原文件缺失，其中71条仍有原生索引消息，另7条的父分段定位失败。

## 决策

在当前已授权 Codex home 内，原历史文件缺失时读取原生 `thread_history_1.sqlite` 中该线程保存的消息。首屏限制最近40项并补上同回合的首条用户输入；声明原生运行态未加载、不带审批请求，不以旧状态授予发送或停止权限。保留显示来源标记，未知模型不借用当前配置作录制标签。

传输固定原生索引的文件身份、消息 ordinal 上界、数量、更新 ordinal 和最后回合元数据。每次最多读取128项，短只读事务结束后才投影内容，避免投影工作持有数据库读锁。新追加内容不混入快照；已固定消息发生变化则拒绝该来源。实时读取版本同时包含最后回合状态、时间和错误，使只有完成状态发生变化时也能刷新；传输快照仍保留捕获时的状态。SSH 注入同一源模块，通过现有只读调用按回合取页，不要求远端安装 Bridge。

`history_base` 指向物理分段，分支祖先可能保留原逻辑聊天ID。只接受当前home内唯一、无符号链接、文件名与header身份一致且被原生base明确引用的分段。无法找到更早分段时保留当前可验证部分，明确不完整；没有原始正文和原生保存消息时仍报告错误。准备阶段区分记录缺失、权限、数据库和接入错误并记录私有网关日志，单会话错误不影响其他来源。

缺失原文件或祖先时的警告沿既有任务协议保存，该会话不被登记为完整离线缓存。原文、索引、账号与运行器不被改写，不激活历史会话。

## 备选方案

只改错误文案能让用户知道失败原因，却无法读取原App仍保留的内容。要求原App逐条激活可以获得内存视图，但会打断原生使用并扩大实时控制范围。复制整个SQLite及WAL不能证明一致性，也增加存储开销。当前采用已有的原生保存索引及有界、绑定证据的只读查询。

## 影响

保留索引缺失或损坏时的失败，不把空结果当成功。索引快照仍可能缺少已经清除的更早历史，用户收到明确提示。源变动会使当前来源准备失败并允许重试；不会自动重放写操作。

[传输快照边界](2026-11-23-transfer-inventory-and-snapshot-boundary.md)的身份拼接、未落盘尾部和不完整标记继续适用；本篇补充原生索引来源和物理分段身份。[消息级手机存档](../architecture/2026-11-23-message-level-native-history.md)管理接收端，是独立存储层，保留原决策。检索未发现同题未决提案。

## 验证

源码夹具覆盖原文件缺失但索引可读、首屏有界、已有消息变更拒绝、追加排除、回合完成状态固定、分支祖先身份、缺祖先时部分保存以及无安装包的SSH源码注入。历史、同步、路径和远程回归通过。真实来源只读核对从31条可pin增加至109条有可读取记录，其中77条带不完整提示；另5条当前未找到落盘消息。没有运行真实模型请求，未修改原生数据库。
