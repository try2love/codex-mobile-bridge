# Agent Note: 前台会话恢复与运行计时

Status: implemented

## 问题

Android 用户反馈运行状态已更新，正文和过程仍停留在旧内容，整页刷新才恢复。已复现的缺口是过程分页游标失效只留下重试按钮，不能触发最近内容校准；已加载过的过程读取失败后，也可能因版本未变而不再自动补齐。运行时长另外使用最后答复时间，缺少持续更新，持续运行的任务因此显示固定数值。

## 决策

同步过程的失效游标和已消失正文通过 `sync_cursor_changed` 返回可辨识的只读冲突。前端保留当前已显示内容，重读最近窗口、校准已展开范围，并从当前过程的有效起点补齐。一次相同来源版本恢复仍失败时保留重试入口，不无限发起自动恢复。显式重试或真正回前台后可以重新校准。正文读取发现返回版本变化时也校准元数据，不把旧版本与新正文拼接。

正文传输层在安排缓存写入之前核对请求的记录键、版本和偏移。原内容更新时服务端可能返回新版本的第零块；该回复可以触发界面更新，却不能与磁盘旧行预览一起持久化。这个边界位于异步缓存写入之前，避免只在渲染器拒绝之后才发现旧预览已经被标成新版本。

前后台恢复按实际从不可读取到可读取的转换处理；重复的原生 foreground=true 状态通知不反复中断轮询。首次联网恢复、页面恢复同时重新核验最近窗口。所有读取沿用当前授权作用域、清理版本、原请求身份和取消边界；发送、停止及审批不重放。

只有当前在线并已核验的运行回合启用共享显示计时器，起点必须来自原生回合时间。前台每秒计算当前时间与原生起点的差，回前台立即校正，后台停止刷新，已移除节点退出调度。离线和缓存展示不推进计时；完成耗时仍由原生起止时间计算。时钟不读取网络，不替代任务状态证据。

## 备选方案

遇到任何读取失败都整页刷新会破坏草稿、阅读位置和当前交互；周期性全量重载还会增加流量。无限重试失效游标不能恢复已经变化的分页边界。以进入页面的时间重新开始计时会使重开 App 后的耗时归零，因此采用当前版本校准和真实原生起点。

## 影响

过程恢复可能多一次最近窗口读取；相同版本重试有界，普通网络失败继续保留错误与用户重试，不伪造成功。源码回归覆盖失效游标、展开过程恢复、历史内容保留、运行和完成时钟、后台暂停及回前台校正。浏览器回归使用生产 HTTP 网关与合成会话，模拟 Android 宿主；它不等于 Android 实机安装验收，也不单凭该缺口断定用户现场所有失败都由同一原因导致。
