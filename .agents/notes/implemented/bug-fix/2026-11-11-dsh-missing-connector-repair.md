# Agent Note: 明确确认后修复 DSH 已删除的接入目录

Status: implemented

## 问题

Windows 旧 Test 的 DSH 配置仍包含网关插件，但引用的旧构建目录及接入文件均已删除。配置没有保存可验证的原目录所有权。普通 discover_existing 必须拒绝它；重复扫描或正常退出也不能重建缺失的接入。仅根据 marker 认定插件可信会把外观与所有权混淆。

## 决策

只在用户点击“恢复并重新接入”、所选 Harness 资料目录和安装身份已确定且无进程时，提供独立的配置修复确认。只接受唯一完整插入、固定插件 ID、严格字段、本地 file URI、同目录的 mobile-host.mjs/connection.json、desktop-sessions/deepseek 后缀及整个旧目录确实缺失。链接、重解析点、访问失败、重复或额外插件字段、仍存在的旧目录及未知新目录均拒绝。

预览展示旧目录和持久目标目录。确认明确表示备份完整配置并替换这一条失效插入，不表示接管旧插件所有权。确认绑定原 patch 字节摘要、目标已准备文件摘要和原进程快照；没有额外确认标志不修改。新 token、端点和 installation 记录按现有协议生成，完整备份在持久目标目录以私有权限保留。只替换原插入字符区间，保留其他文本和换行；不执行 YAML，不删除旧路径或改账号、聊天。

写入前再次核验进程退出、旧目录缺失与 patch 未变。token 在修改前消耗，失败不自动重放。已完整准备、且原生记录与当前目标及资料目录相符的文件可经新预览继续；不轮换其 token。部分准备失败保留备份并拒绝隐式采用，需要在电脑端检查。manager 保存新接入目录后才重新启动，启动失败仍可找到恢复后的连接文件。

正在运行但插件不可用的客户端仍不能普通恢复：先正常退出，或另行使用已存在的明确强制确认；不把 unknown 当 idle，也不增加后台强杀。

## 备选方案

自动删除 marker 后重新扫描操作更少，但未经用户审阅会覆盖未知来源配置。只让用户手工编辑 YAML 能保守恢复，但不能完成已有“恢复并重新接入”入口。复活旧临时构建目录会继续把运行依赖绑在可删除安装目录，因此迁入当前网关持久目录。

## 影响

已停止的坏接入可通过同一管理页面恢复，其他配置字节及原生账号/历史保留。无法证明形态或仍有进程时继续拒绝；没有正常退出通路的版本仍需用户选择退出方式。文件与进程核验是写入前的即时检查，不宣称能锁住外部编辑器或其他进程的所有并发变化。

## 验证

9 项隔离文件/状态检查覆盖成功备份与 CRLF 保留、额外确认、活动或新进程、配置变更、重复/额外字段、旧目录仍存在、未知目标、符号链接、替换失败后新预览、准备时编辑和目标凭据变化。原恢复模块 31 项、manager 4 项定向及 UI 5 项通过；未调用真实 DSH、模型或付费服务。目标 Windows 的真实配置修复与最终安装包仍需独立验收，不能把模拟进程快照当实机退出。
