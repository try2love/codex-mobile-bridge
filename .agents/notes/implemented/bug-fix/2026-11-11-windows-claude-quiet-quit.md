# Agent Note: Windows Claude 普通退出不恢复窗口或展开菜单

Status: implemented

## 问题

Windows Claude 的普通退出先通过 UI Automation 寻找原生菜单，缺少主窗口时会恢复托盘窗口，菜单查找失败后还可能激活 Claude。File 菜单展开本身也会显示界面；没有键鼠注入不代表没有打断用户。

## 决策

Quit 路径只读取当前可用的主窗口和已经存在的原生 Exit/退出/結束菜单项，不恢复窗口、不调用 Activate，也不打开或展开菜单。仅接受同进程、启用且非离屏、唯一且支持 InvokePattern 的原生 Quit；派发前再次查找并比较同一控件，同时复核原进程出生时间、映像、会话及窗口归属。缺少窗口或可核验入口时返回 failed，明确尚未提交退出，并提示在电脑端正常退出或另行确认强制退出。

后台 UIA 工作线程最多提交一次，派发前刷新原有 dispatching 回执。派发锁内即时核对取消文件和内存取消状态；主线程在等待时出错先原子取消尚未派发的工作，已经派发则保留 submitted。取消或超时只取消尚未派发的工作；派发之后的错误或丢失回执保持 submitted/pending，由原有流程观察原代退出，不重试、不自动升级为强制。直接 helper 的可选取消文件参数同样受该锁保护；常规 stop_claude 当前不传此参数，不把这项直接合同修正称为已复现的常规退出故障。既有任务核验、独立 force 确认和其他 Claude 操作不变。没有实际退出证据时不报告 exited。

## 能力与证据边界

[UIA Invoke 官方指南](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/implementing-the-ui-automation-invoke-control-pattern)说明提供程序可能带来选择等副作用，模态处理还可能阻塞调用；这里消除的是 Bridge 自己的恢复、激活和菜单展开。已存在控件的 Invoke 不构成所有 Claude 版本都可后台正常退出或绝不显示原生确认的保证。实际安装源的有界检查尚未证明独立后台 Quit 命令，真实客户端能力仍需针对版本和空闲原代验证；测试替身不代替该验收。

Restart Manager 私有原型中，零 force 返回成功和进程退出没有提供保存回执；另一个拒绝场景未派发。Electron 的 session-end 也不等价 app.quit，因此不增加 RM、结束会话、关闭窗口或强杀作为正常退出后备。

## 既有笔记审计

[桌面任务退出证据](2026-10-16-claude-desktop-quit-evidence.md)约束任务清单和即时身份，本次不改变这些守卫；[本机 CLI 显式释放](../feature/2026-11-11-mac-claude-owned-cli-release.md)操作网关持有的独占 CLI，本次只收紧 Windows Desktop GUI 的 Quit，互不替代。两篇仍有独立范围。

## 备选方案

保留前台回退能提高部分菜单不可访问时的成功率，但会恢复窗口、抢前台或显示菜单，不满足本次要求。只删除 Activate 仍会保留窗口恢复和菜单展开，同样不能采用。系统结束会话或终止进程容易看到进程消失，却不能证明应用正常保存，所以不伪装为普通退出。

## 验证

直接回归覆盖“无后台入口”的失败映射、单次 helper 调用和不自动强制，以及已派发回执丢失、超时和取消后的不重发。C# 自检覆盖既有入口、取消、缺失、隐藏、替换或消失和 Invoke 回执不确定，并以有界屏障覆盖末次身份核验后的取消、派发锁内的取消文件检查，以及派发赢得竞态后的不重发；Windows 自有 WPF 夹具覆盖隐藏窗口、缺失 Quit 和原生 popup 不展开、不恢复，以及已有可调用 Quit 的提交、原生确认和丢回执。本机10项直接回归通过；Windows C#自检和自有WPF检查在macOS上明确跳过，未计通过。本机没有.NET/C#编译器，不据此宣称Windows原生已验收。

## 影响

普通退出可能更早报告没有后台入口，而不会为提高成功率打断当前桌面。用户仍能在电脑端正常退出，或通过共享界面重新预览身份和影响后明确选择强制退出。Codex、ZCode、DSH 和其他 Claude 连接/初始化路径保持原行为，本点不修改其退出协议。
