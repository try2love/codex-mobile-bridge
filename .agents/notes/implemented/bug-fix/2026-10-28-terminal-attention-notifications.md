# Agent Note: 原生运行失败与阻塞的待处理通知

Status: implemented

未显式接入的 CLI 现通过[只读原生观察](../feature/2026-11-11-codex-cli-passive-notifications.md)复用本篇终态与去重规则；真实 RPC 审批仍由执行连接处理。

## 问题

通知扫描已有审批请求与成功完成两条路径。Codex 的模型容量不足、Claude 原生错误结果、DSH 的阻塞或错误终止不属于其中任何一种，用户必须主动打开聊天才知道需要继续处理。不能把普通网络沉默或自动重试提示当作一次最终失败。

## 决策

新增收件箱事件 `kind: attention` 与 Webhook 事件 `task.attention`。它们复用现有 `notifyOnRequest` 待处理提醒设置、每个第三方目的地账本和手机逐连接通知开关，不新增默认开启的独立渠道。系统提醒显示客户端名称与“需要你处理”，正文只提示打开原聊天手动继续或调整模型；不外发原始错误、提示词或凭据，不执行自动继续、改模型或重发任务。

Codex CLI 消费原生 `error` 通知的 `turnId` 和布尔 `willRetry`：自动重试仍为 `inProgress`，明确不再重试才标为 `failed`；缺失重试判定或未知轮次不推测终态。`turn/started`、`turn/completed` 继续采用原生状态并清除先前的重试标记。Codex Desktop 已有快照中的明确失败状态沿用相同扫描规则。Claude 只用已有原生根级 `result` 的错误结果，跳过中间 assistant 错误及合成结果。DSH 使用原生 `turn/end`，对 `blocked`、`error`、`max-tokens` 提醒，主动中止、中断、分叉不作为待处理故障。

每个会话和通知目的地保存独立的首次历史基线、最近轮次状态及阻塞次数。首次读到的旧失败不补发；观察到运行恢复后再次失败可以再次提醒。DSH 的递增原生终止序号还能识别发生在两次轮询之间的再次阻塞。相同原生失败不会因重连或网关重启重复发送，旧分页不会成为新失败。最新轮次已经恢复时撤销尚未发送的失败提醒，失败重试继续核验当前策略和目的地。手机落盘失败的补写放在新快照检查之后，避免先重放已恢复状态。

读取仍经过原有被动通知订阅及桌面列表/详情路径，不激活或切换会话；桌面详情继续每轮最多八次读取，启用待处理提醒也建立终态基线。手机接收器已有通用标题、正文和原会话路由，无需改动产品界面或原生通知配置。iOS 原有前台能力和 APNs 配置限制不变。

### 既有记录核对

- [通知交付隔离](2026-10-28-notification-delivery-isolation.md)部分重叠：保留独立扫描和发送、目的地账本、阶段耗时及原生证据要求；本篇补充第三类事件及恢复后撤销。
- [手机通知来源选择](../feature/2026-10-28-mobile-notification-sources.md)互补：关闭的地址仍不弹出任务提醒，重新开启仍先建立手机游标基线；不按主机名自动合并连接。
- [Android 后台通知](../feature/2026-10-27-android-background-notifications.md)与 [iOS 前台通知](../feature/2026-10-28-ios-theme-and-foreground-notifications.md)保留各平台接收及后台限制。
- 列表首屏、测试门禁和飞书成功判定只是机制或关键词关联，没有被本篇替代。检索未发现需要删除、驳回或归档的重叠提案。

## 备选方案

用“长时间没有输出”推断阻塞可以覆盖缺少原生事件的客户端，但正常思考、慢网络、后台调度同样会沉默，容易误报，因此只消费明确原生失败证据。

把失败并入完成通知可以少一个事件种类，但成功和需要人工处理的含义相反，且关闭完成通知的用户仍需要处理故障，因此采用独立事件并复用待处理策略。

直接发送错误文本能帮助手机快速判断原因，但原始文本可能含服务响应、请求内容和内部路径。保留通用提醒，详情仍在已认证的原聊天查看。

## 影响

手机和第三方现在能收到同源待处理提醒；代价是一个小型 `notification-attention.json` 状态文件，以及仅开启待处理提醒时也读取有变化的桌面历史。没有最终结果或明确状态的接入仍不会通过猜测触发通知；扫描间隔、网络延迟和系统后台限制继续存在。取消发送不能撤回已经发出的第三方 HTTP。

## 验证

合成容量错误使用已安装 Codex 协议 schema 的 `error`、`willRetry` 和 `serverOverloaded` 结构，验证自动重试静默、终态报警、恢复及没有主动重发。通知专属十项覆盖手机与第三方、首次旧历史、恢复后再失败、重启去重、目的地变更、策略关闭、DSH 旧页及新终止序号、Claude 中间错误和原生最终结果、推送载荷以及手机落盘重试。原有桌面通知十项、Codex CLI 六十项、推送十一项通过；通知相关八十二项回归在新增第十项前通过，最终共同回归由本轮集成验收执行。

Android 真实 Java/HTTP 和 iOS 真实 Swift/HTTP 消费夹具均接收到 `attention` 文案，并保留来源选择、游标去重、身份变化与生命周期检查；iOS 后台请求数为零。iOS 夹具的源码抽取范围误包含新设置页面，已收窄到消费者及来源判断函数，不改产品代码。上述结果是隔离协议与消费者验证，不宣称真实原生模型容量故障、手机锁屏或 APNs 已完成端到端验收。
