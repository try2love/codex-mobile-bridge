# Agent Note: 桌面客户端列表复用非阻塞状态快照

Status: implemented

## 问题

Web 的客户端状态读取已有缓存与后台合并刷新；桌面控制面板的 clients 命令仍直接调用同步读取。生命周期持锁或原生探测较慢时，面板等待十秒后报客户端状态读取超时。

## 决策

运行中的网关对桌面 clients 命令复用 clients_status，显式 refresh 只请求一次后台刷新，立即返回上次快照与 pending。未启动网关的本机管理仍同步读取，保留首次发现与短生命周期调用结果。

面板在 pending 时保留已有行并使用既有两秒轮询，就绪后恢复普通周期。失败保留缓存并显示已有错误区域；手动刷新仍可重试。缓存不能用于确认未知写结果：pending 或刷新失败时不调用 reconcile；已有未知操作期间，只允许继续这次状态读取，不重放操作。

## 备选方案

延长桌面十秒超时不能避免慢锁拖住界面。另建桌面缓存或后台队列会重复 Web 已有的快照与去重机制，不采用。把未运行网关的短生命周期命令也改成异步会丢失首次读取，因此保留同步路径。

## 影响

界面显示可能短暂落后于原生状态，但安全操作仍实时核验。源码与 API 共用同一缓存；没有增加周期扫描，也不将缓存解释为实时安全证据。

## 测试

真实线程持有客户端锁时，旧桌面控制调用超时；修复后立即返回缓存，锁释放后后台刷新就绪。2 项控制路由及4项既有状态缓存回归通过。110 项 UI/生命周期检查通过，包括空快照不清屏、pending 到 ready 轮询、失败重试与未知写入保护。尚未以冻结桌面面板实机替代这些检查。
