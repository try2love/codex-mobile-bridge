# Agent Note: 手机收件箱与第三方发送隔离及多客户端通知补漏

Status: implemented

## 问题

用户在 PR #85 本地 Test 中观察到手机通知晚于第三方通知，HTTPS 比局域网更晚，并反馈 Claude、DSH 没有提醒。既有代码实际已有两个客户端的通知路径，但隔离复现确认三个缺陷：Claude 扫描把桌面连接当成 CLI 通知的前提；DSH 最新历史分页丢掉上一轮锚点后，新完成记录被忽略；第三方 HTTP 与手机入箱串行，同一次发送及之后的扫描都可能等待外部请求。

当前 Mac Test 的界面和磁盘配置一致：Webhook 开启，ntfy 与手机接力关闭，尚无手机收件箱文件。固定 HTTPS 实例身份与 Test 一致。Android 接收器监听所有已保存且已认证地址，因此当前浏览的电脑不能单独证明系统通知来自它。不能把这次配置快照当成用户此前操作的完整记录。

## 决策

手机入箱在扫描线程直接完成；第三方任务发送与安全通知扫描使用独立工作线程。外部 HTTP 不持有通知状态锁，手机后续事件无需等待前一次外部请求。单次手动 `scan()` 保留扫描后排空发送的契约；生产循环使用 `scan(deliver=False)` 与同一发送器。队列按会话、通道和通知种类合并；完成通知仍依靠原有持久化完成记录及目的地账本重试。待确认通知只按最新一次对应客户端扫描保留，桌面两次扫描之间不提前删除；停用、目的地替换、策略变化及关闭在真正发送前重新核验。已经发出的 HTTP 无法撤回，超时仍可能存在接收方已处理的情况。

Claude 在桌面连接或 CLI 可用时读取既有只读列表，仍遵守客户端启用开关，不连接或激活会话。DSH 使用原生单会话事件序号作为额外完成水位，只有更大的序号及明确 `completed` 终止记录可触发；旧页、错误和中止不因界面显示 idle 被当作成功。旧完成状态没有水位时沿用锚点规则，在下一次读到有效序号后建立水位，不追补未知历史。

日志分为扫描、入箱、第三方队列/发送、手机读请求与系统通知提交。事件使用已有去重摘要的短标识关联，不记录标题、正文、令牌或完整接收 URL。HTTP 响应的 `timing.waitMs` 是网关此次快照/长轮询处理时长；事件 `ageMs` 在网关内计算入箱到响应的年龄。二者不参与稳定 revision，也不回写持久化事件。Android 使用单调时钟记录请求及接收后提交时长；请求耗时减网关等待只是额外开销估计，包含网络及未覆盖的 HTTP 处理，不是精确单向时延。提交系统通知不代表屏幕已显示。

真实 Test 安装后日志另记录到 175 秒及 102 秒的整轮扫描。定向测试确认 `notification_session(timeout=0)` 仍同步等待 CLI owner RPC；零超时只作用于后续快照等待。通知 owner 探测改为每个 Bridge 最多四个后台只读任务，每个会话至多一个在途探测，空槽不足时留待下一轮；不提前把尚未探测的会话标记为休眠。完成后唤醒通知扫描，关闭后不再启动新探测。保留原 owner、连接锁、退避和不激活约束；发现、探测、桌面列表及详情分别计时，用于继续区分 SSH 与原生读取延迟。

## 备选方案

只把手机通道排到第一个，代码变动更少，也能让同一轮的第一条通知先入箱；但外部发送会继续挡住第二条事件及下一轮扫描，阻塞测试明确覆盖了这个区别，因此同时拆出发送线程。

在扫描线程缩短 owner RPC 超时可以限制单个等待，但多个未连接会话仍会串行累加，而且过短超时会漏掉健康但较慢的响应。保留原只读 RPC 时限，改为有并发上限的后台探测。

每个第三方目标单独建线程可以避免第三方通道之间互相等待，但扩大并发、关闭及重试协调范围。本次目标是手机收件箱独立，第三方之间继续串行并共用既有账本；若实测第三方之间的排队成为问题，再单独评估。

从 idle 推断完成能覆盖缺少终止记录的接入，但 idle 也可能是中止、错误或不完整状态。保持原生终止证据要求；不把未受网关管理的 Claude CLI 历史当成实时审批或成功证明。

## 影响

手机入箱不再承担第三方网络等待，Claude CLI 与 DSH 分页路径得到定向覆盖。代价是额外发送线程和内存待发队列、每次发送后的持久化账本写入以及有限诊断日志。完成记录可跨重启恢复；待确认队列不持久化，重启后重新读取仍存在的请求。桌面扫描仍保留原来的 10 秒间隔及每轮 8 次历史读取预算，发现延迟与网络延迟必须分别评估。手机 Doze、厂商后台调度及屏幕最终显示仍需设备实操，不能用本机 HTTP 或编译结果代替。

UI、第三方接收地址、认证和用户原会话 owner/provider/auth/cwd 不因源码修改变化。此改动只在本地 PR85 评审分支；作者原始提交保持完整，不推送远程，也不推进 main。

## 验证

隔离旧代码的三个缺陷全部失败，修复后通过。新增测试经过真实后台工作循环，阻塞第三方发布器后仍接收第二条手机事件；使用真实客户端适配器和 DesktopSessions，验证 Claude/DSH 原生待确认与完成事件进入手机和第三方两种通道，并检验去重、目的地变化、关闭和请求消失。真实 DSH 只读核验确认接入可用、返回原生终止记录且存在分页；不发送模型任务。

后端源码回归 2697 项执行、82 项平台跳过；Node 1236 项通过、1 项 Windows 跳过；通知专项 97 项及手机 HTTP/长轮询 17 项通过，新增投递隔离 6 项通过。Android 真实 HTTP 接收器夹具覆盖日志字段和内容脱敏；模块边界与 70 篇 Agent note 校验通过。界面资源 diff 为空。

本轮验证日志位于本地 `.tmp/notifications-20261028/`。实际设备上的局域网/HTTPS 到达时间与厂商后台行为仍由新 Test 的分段日志及实操继续核对，未据基础请求耗时宣称手机端延迟已完全解决。
