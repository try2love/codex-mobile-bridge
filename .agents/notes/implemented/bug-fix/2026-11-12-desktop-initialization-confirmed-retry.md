# Agent Note: 核验不可用时明确确认原生连接初始化

Status: implemented

## 问题

有界并行核验减少了长历史的逐项等待，但原生 IPC 不响应时仍会超时。初始化页面只有同一种重试，用户无法按已经明确提出的要求，在接受未知任务可能被中断的前提下继续正常重启。

## 决策

首次初始化仍完整核验任务。仅当本次操作失败于任务状态不可用或核验期限耗尽，返回 `taskStateUnavailable`，共享账号面板才显示“强制继续初始化”。再次确认后使用新的请求标识，后台重新核验原生任务及进程；确认只覆盖仍然不可用的任务状态，不覆盖已知忙碌、未知/排队写入、进程代次或配置目录变化。

期限耗尽使用单独的 `TaskAuditIncomplete`，继续继承 `ValueError`，不继承普通退出已接受的 `TaskStateUnavailable`。因此普通关闭、账号切换等调用者的既有严格规则不变。核验超时时再次查看本次已收到的快照及提交，防止静默候选遮住另一 owner 已送达的忙碌证据。

“强制继续”只跳过用户已确认承担风险的不可用任务判断，仍调用正常退出，不使用强杀，也不自动重复初始化。权限、账号、历史和写入回执保持原契约。

HTTP 初始化入口与桌面直连使用同一请求契约，允许可选且只能为 `true` 的 `acknowledgeUnavailable`。入口继续拒绝任意额外字段，保留登录、CSRF、默认桌面范围和免密访问限制；实际是否有失败核验及是否可继续仍由账号管理逻辑判断。

## 备选方案

延长等待仍无法解决不响应的原生 IPC；依据历史缓存直接判空闲会把展示数据当成退出凭据。统一把超时改成可恢复退出错误则会扩大其他生命周期调用者的权限。采用初始化专属的明确确认，保留严格默认。

## 验证

新增账号回归在修改前复现缺少明确继续状态与请求拒绝。修改后账号初始化、任务核验共 58 项通过；新增超时仍保留已送达忙碌状态及期限异常类型两项通过。共享 Web/桌面账号面板 5 项定向测试通过，包含取消、确认、进行中、免密访问和外部账号管理边界。真实 Chromium 使用生产 AccountsPanel 和合成状态验证按钮、取消零请求、确认发送唯一请求、进行中隐藏并禁用。

本轮没有重启正在承载开发任务的正式 Codex App。上述证据验证确认流程和退出调用契约，不能代替正式 App 初始化后的原生侧边聊天验收。

Test 12 实操暴露了此前测试缺口：共享面板测试直接调用账号管理替身，没有经过 HTTP 路由，旧路由严格限定三个字段，导致手机/Web 的明确继续请求始终返回 400。补充真实 GatewayServer 请求回归，先复现 400，再验证 202 和参数完整转交；无认证、缺 CSRF、独立配置、免密模式、额外字段以及非 `true` 的确认值仍被拒绝。

## 影响

只改变原生连接初始化失败后的选择，尚未配置时不会自动重启，也未增加轮询。其他系统的原生 transport 支持仍按各自已验证能力判断。
