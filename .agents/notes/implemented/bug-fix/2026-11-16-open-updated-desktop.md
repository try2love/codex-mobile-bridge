# Agent Note: 旧共享接入不阻挡显式打开新版桌面

Status: implemented

## 问题

Windows 实机从 8788 强制退出成功后，再次开启返回“Codex 程序已变化”。共享 records/settings.json 保存的是旧 MSIX 应用路径及旧 Test 启动器；升级后的桌面已被正确发现，旧运行时也已退出，但普通打开仍被共享侧聊配置拦住。

## 决策

将应用路径或 Windows 网关启动器变化区分为 DesktopRuntimeOutdated。只有用户明确打开桌面时，允许在既有初始化锁内核验旧共享运行时已退出，然后用原配置目录打开当前原生桌面。移除此次子进程继承的共享接入注入变量，保留账号、代理及其他环境。Windows 仍要求能保留环境的已核验启动方式。

原共享设置、历史、待核对回执均不删除或重写。记录权限异常、配置损坏、旧运行时仍存活或退出结果未知继续报错；后台准备与账号切换不采用此回退。原生侧聊能力与普通桌面可用性分别判定。

## 备选方案

自动重写共享设置会改变其他网关的运行入口；遇到任意异常都回退可能产生第二个写入者；继续要求用户先初始化会阻断升级后的基本打开功能。以上方案不采用。

## 影响

补充[显式开启](2026-11-16-explicit-desktop-launch.md)的过期启动器边界：明确打开可恢复普通桌面，原生侧聊仍须单独就绪。不修改正式网关配置，不退出当前 Mac 对话。

## 测试

修复前 Windows 真实浏览器记录：强制退出 HTTP 200、4.689 秒且 App 进程消失；重新开启 HTTP 400、1.676 秒，错误为旧应用路径不匹配。只读核验共享运行时已退出。新增及受影响的 7 项定向检查通过，覆盖未知/活跃 writer、损坏权限、隐式拒绝、环境清理与设置原样保留；复审无阻断。修复后同一 Windows 页面显式开启 HTTP 200、5.850 秒，唯一主进程启动，随后原验收会话恢复已连接、历史和交互控件可用；没有发送付费请求。正式网关 PID 未变，原 Test 配置和 auth.json 哈希未变。原生 App 启动后 config.toml 哈希变化，未保存此前内容，不能确认具体差异，未擅自覆盖或宣称该文件完全不变。模块边界检查通过。
