# Agent Note: Codex 宿主进程接入与旧桌面 IPC 并存

Status: implemented

后续的账号独立准备、持续恢复、有界实时同步与编辑支持见[原生连接恢复](2026-11-21-desktop-connection-recovery.md)；本篇保留原决定及其约束。

## 问题

新版 Codex 将桌面会话管理移入 utility host，不再参加原有的聊天 owner 发现和状态订阅。旧 IPC 端点仍可能由 VS Code 持有，因此套接字存在和初始化成功都不能证明 Codex Desktop 已接入。发布提交 `ad5e929d` 的原始 owner 查询在该环境中超时。

这与[桌面状态结构兼容](2026-11-14-desktop-stream-v13.md)处理的 v11/v13 快照门禁不同：本次尚未收到桌面快照，增加版本白名单无法修复。原[共享运行时](../architecture/2026-11-08-codex-shared-runtime-data-deletion.md)和[自动准备](../feature/2026-11-12-native-runtime-startup-preparation.md)继续负责初始化、生命周期互斥及未知任务保护。

## 决策

旧版由主 App 直接启动的连接继续使用原有 IPC 和共享元数据路径。新版经同一 App 的 utility host 启动时，透明适配器保留原始 stdio 参数、初始化、通知和服务端请求，在 App 持有的同一个原生执行连接旁提供私有的 Bridge 控制端点。接入选择依据实时进程归属和运行记录，代码不比较或白名单化 Codex App 版本号，不改 App 安装包。

macOS 只接受主 App 或其应用包 Frameworks 内、直接隶属于该主 App 的宿主进程；Windows 使用同一可执行文件的父子身份。记录绑定 App、可选 host、适配器、原生进程及其世代、配置目录、端点和随机令牌。原生 shell launcher 的 exec 可以改变镜像及 exec 版本，不能改变 PID、起始时间、同用户身份和进程唯一 ID。握手完成后固定真实原生镜像。每个控制请求重新核验记录与进程身份。

端点复用 Bridge 内部长度帧与状态投影，以免复制 HTTP、认证、账本、审批或页面逻辑。投影中使用的版本号描述 Bridge 自身已规范化的状态，不是上游 App 版本探测。旧版 v11、v13 和未来附加字段的结构校验继续独立生效。

被动跟随只查询已加载列表和历史，不发送 `thread/start`、`thread/resume` 或 `turn/start`。读到历史不授予执行权限；操作仍核验同一原生线程的 provider、cwd、已加载状态与控制关键结构。新版 `historyMode=paginated` 分别读取回合和消息项，并检查游标、归属和容量；首次输入前尚未落盘的空聊天保持可读。

同一配置目录中的 VS Code 等旧 owner 保持可用：只有新版端点明确返回 `no-client-found` 的只读发现才查询旧路由，并将后续操作固定到实际发现的 owner。超时、未知结果及写操作不尝试另一路由。新版暂不提供原地编辑，能力字段隐藏该入口，避免把未实现的操作暴露为可用。

发送、中断、设置与审批复用既有原生操作适配。原 App 始终收到上游事件；Bridge 读取和写入的独立请求 ID 不泄漏给 App。桌面和手机的审批回复共享一次性消费状态，已解决或已经回答的请求不能再次发送。未知结果不重放，明确未发送的失败及原生错误结构保留给既有事务调用者。Bridge 断线仅释放 follower，不关闭原执行器。


新版分页刷新读取最多 40 条轻量回合 header，只水合当前轮正文。同一连接此前已观察的正文，只有仍在原生确认的连续尾部内才复用；数量和总字节受既有容量限制。未观察的间隙、回退、完整快照和连接失效停止沿用缓存；未水合到最早正文时仍保持历史不完整，旧轮大正文不重新下载。保存历史只参与展示，不进入此原生状态投影。

读取开始时记录本连接各轮的事件修订。读取期间到达的新轮、状态变化或同状态正文增量优先于旧读取结果；没有新事件的轮次继续以原生快照为准。修订只在内存中保留当前轮次，连接断开或失效时清除。

## 验证

- Issue #258 的合成回归先复现新输入后只剩新轮，以及读取期间同状态正文增量被覆盖。回归覆盖连续 45 轮、40 轮数量界限、字节截断、回退/完整快照、连接重建、原生状态更新和迟到事件；不读取旧轮 items，不调用真实账号或模型。

- 后续 8788 实测暴露了未覆盖的大回执与并发读取：原生子进程保持 `bufsize=0`，其原始 stdout 的 `readline()` 会逐字节调用底层读取。实机采样主要落在该路径；4 MiB 受控回执原先需要约 419 万次读取。现在只对 stdout 使用缓冲读取，stdin 继续保留原有即时写入和原始请求顺序。块读取、分片 UTF-8、EOF 与尺寸限制有回归，不增加版本、账号或供应商分支。
- 列表只同步展示标题，遇到会话状态锁繁忙时跳过本次标题观察，后续读取继续同步；保存历史中的列表标题可直接返回。真实 `Bridge.list()` 回归在另一线程持有会话锁时先复现阻塞，再验证列表即时完成及随后标题更新。发送、审批、停止等操作仍使用原有锁与即时校验。
- 初次单会话读写通过不能覆盖长历史和并发用户访问。`scripts/smoke-hosted-desktop.py --response-bytes 4194304` 使用同一个 loopback 原生写入者测试 4 MiB 历史、重连、发送、中断与审批；中断后等待 Bridge 确实观察到同一回合结束，不能把桌面已收到事件当成所有 follower 都已同步。
- 新增回归覆盖生产 IPC 初始化、owner 发现和跟随、分页及空历史、原始配置保留、状态未知拒绝写入、发送超时不重放、审批归属、重复审批、已解决审批、原生元数据拒绝语义，以及新旧主进程拓扑。
- 延迟修复定向回归：`test_hosted_desktop_output.py` 3 项、`test_hosted_desktop.py` 18 项、`test_desktop_stdio.py` 10 项、`test_stream_compatibility.py` 9 项、`test_bridge.py` 123 项均通过，其中 Bridge 按平台跳过 2 项。本地 preview3 Test 成品完成签名校验，并由独立 Codex App 真实启动、读取元数据和握手后正常退出；这些隔离回归不替代用户实际浏览器或手机验收。

## 备选方案

扩展旧 IPC 版本白名单改动最小，但新版没有发布该 owner/stream 通道，不能解决握手后无 owner 的故障。直接连接内部 MessagePort 能复用 App 管理器的全部界面行为，但其入口绑定 Electron 窗口及运行代次，未发现可直接交给外部进程的公开入口。另起 CLI 再恢复相同 ID 易于实现，却无法证明使用原 App 的执行连接，因此不采用。

全局 WebSocket 重定向可以共享原生执行器，但会改变 App 的传输选择和协调方式；保留原始 stdio 可复用现有透明适配器及生命周期约束。

## 影响

新版获得本机桌面聊天的基本读取、发送、实时状态、中断与审批路径，旧版仍沿用原路径。新增端点、状态归一化和分页读取带来内存及序列化开销；单连接待发布快照合并，不在原生输出线程等待慢 follower。原生事件结构未知时拒绝继续派发控制请求。

首次接入仍需通过现有原生连接准备流程正常重启一次；任务状态未知时沿用现有的人工确认入口，不能为恢复连接自动绕过任务保护。已经普通启动且未使用适配器的主 App 不会被悄悄接管。新路径针对本机默认 Codex Desktop；远端桌面 owner、完整界面操作（包括原地编辑）及 Windows 成品/真机仍需各自适配与验收，不能由 macOS 本机链路通过推断。
