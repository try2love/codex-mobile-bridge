# Agent Note: 已授权云设备复用直连账号和会话入口

Status: implemented

## 问题

132.2 的云手机可以看到 Claude 和 DSH 原会话列表，点进聊天却可能只有历史可读。ZCode 连列表都会被拒绝。实际安卓 WebView 在同一个 8796 上读取 Codex 账号、CLI 配置、其他三个 Agent 的账号和 ZCode 列表均收到权限拒绝。桌面中继使用了按旧客户端编写的共享中继路径清单，手机又把拒绝误报为网络不可用。Codex 的专用只读摘要只解决了一个面板的展示。

## 决策

手机使用与直连相同的 Web 资源、账号面板和会话控件。由网关将已配对设备的请求交给相同的账号、客户端和会话管理器。默认账号、独立配置、宿主及 WSL 入口分别校验；云连接使用独立认证会话和 CSRF，同时继承原网关对业务操作的密码保护要求。连接权限可以撤销，结果未知的写请求不自动重放。登录资料、私有 IPC、任意转发目的地和共享中继的访问权限仍由原边界管理。手机收到明确拒绝时返回 HTTP 403。

Mac 升级验收还发现，ZCode 的私有管道宿主可以继续运行，但内核记录的可执行文件路径会随旧网关包改名。接回这种宿主时，在原进程身份检查外，还核对同一安装目录下旧签名包、该构建启动器记录的精确签名摘要、原启动参数以及资料目录的私有锁。旧宿主对新网关的反向认证继续生效。

## 备选方案

继续为每个 Agent 各写一套云端账号摘要，会漏掉直连已有的写操作，也会让同一账号面板长期分叉。完全放开代理路径则会让设备调用超出工作台范围的接口。采用桌面会话共用的操作目录及有边界的账号路由，原有业务层继续判断是否允许执行。

## 验证

使用隔离宿主核对原生和独立入口的接续、发送、停止和审批。私有 HTTP 监听器测试覆盖指定 SSH 主机、API 配置写入和响应脱敏、拒绝失效 CSRF 与设备撤权、禁用入口、宿主密码策略和 WSL 归属。真实安卓云工作台的四种账号读取均返回 200；iOS 的 Codex 面板显示 API 接入和 SSH 区域。Claude 的独立 Desktop 聊天可写，未使用其上游模型。DSH Flash/low 从安卓收到一条 OK，同一结果在 iOS 的原会话可见。Codex 选中原会话后已连接，输入框可写。四种客户端均从安卓的正常入口打开了账号面板。

ZCode 成品切换前后是同一个 App 和管道宿主进程。手机重新连接到原聊天，状态为 ready，操作可写，模型为 GLM-5.3-Flash、思考为 low。一次真实发送被 ZCode 在模型执行启动前拒绝，消息未写入原生历史。ZCode 原 App 显示已登录，刷新模型设置后 Start Plan 显示「未就绪」「暂无可用体验套餐」，原生目录返回零个可用模型。没有重放消息或改动账号。

## 影响

云服务仅提供连接途径；产品操作仍按对应 Agent、平台、登录状态和已启用的原生能力展示。已有手机构建内嵌 Web 资源，账号操作更新需要匹配的新手机版本和网关。云原型的终端 WebSocket 和全类型附件尚未作为这次验收结论。
