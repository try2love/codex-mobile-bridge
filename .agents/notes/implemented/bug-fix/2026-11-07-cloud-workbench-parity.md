# Agent Note: 已授权云设备复用直连账号和会话入口

Status: implemented

## 问题

132.2 的云手机可以看到 Claude 和 DSH 原会话列表，点进聊天却可能只有历史可读。ZCode 连列表都会被拒绝。实际安卓 WebView 在同一个 8796 上读取 Codex 账号、CLI 配置、其他三个 Agent 的账号和 ZCode 列表均收到权限拒绝。桌面中继使用了按旧客户端编写的共享中继路径清单，手机又把拒绝误报为网络不可用。Codex 的专用只读摘要只解决了一个面板的展示。

## 决策

手机使用与直连相同的 Web 资源、账号面板和会话控件。由网关将已配对设备的请求交给相同的账号、客户端和会话管理器。默认账号、独立配置、宿主及 WSL 入口分别校验；云连接使用独立认证会话和 CSRF，同时继承原网关对业务操作的密码保护要求。连接权限可以撤销，结果未知的写请求不自动重放。登录资料、私有 IPC、任意转发目的地和共享中继的访问权限仍由原边界管理。手机收到明确拒绝时返回 HTTP 403。

Mac 升级验收还发现，ZCode 的私有管道宿主可以继续运行，但内核记录的可执行文件路径会随旧网关包改名。接回这种宿主时，在原进程身份检查外，还核对同一安装目录下旧签名包、该构建启动器记录的精确签名摘要、原启动参数以及资料目录的私有锁。旧宿主对新网关的反向认证继续生效。

## 手机本地状态

云工作台每次进入分配新的私有回环端口，iOS 使用临时网站数据存储。因此普通 `localStorage` 的草稿及完成未读记录无法跨次进入保留。移动端通过同一 `BridgeLocalStateStorage` 保存现有 ComposerDrafts 与 SessionActivity 的状态，Android/iOS 共用 Rust 存储实现。目录由原生壳提供，按云账号、网关 ID、已验证桌面公钥隔离；删除云配置同时移除该配置的本机状态。仅允许三类 composer 键及两个既有活动记录键，限制单值、总量及条目数。草稿、引用文本和发送结果未知的记录保留原业务结构，不向云服务发送，不自动补发。

读写复用已分配的回环监听器，继续校验当前页面凭据、Host 和 Origin。只对本机文件同步确认，避免页面声称已保存但尚未落盘；相同内容不重复写文件，也不新增轮询。云 `/api/auth` 的草稿身份来自原网关的持久身份，重启不会改变；独立云认证会话和撤权边界保持不变。

## 云文件下载

原生壳已有的下载按钮在直连下由 WebView 导航交给下载器。云页面只有 fetch 包装器携带视图授权，链接导航没有授权，会在到达原生下载监听器之前被拒绝；iOS 下载器还要求直连 Cookie。云传输同时丢失了 Range、If-Range 和 Content-Disposition，导致续传及原文件名无法保留。

两端复用共享点击适配器，将云页面中用户实际点击、且通过既有附件白名单的链接交给原生下载器。直连路径保持原行为。原生壳按当前视图、地址和代际取得仅存内存的云授权，每段下载重新核验，离开云视图即失效；不使用或转发直连 Cookie。手机与网关只补齐分段请求头和下载响应头，沿用 1 MiB 分段、流量窗口、暂停续传、系统保存及单响应大小上限。文件不会一次性装进内存，也不增加后台监听。

## 备选方案

继续为每个 Agent 各写一套云端账号摘要，会漏掉直连已有的写操作，也会让同一账号面板长期分叉。完全放开代理路径则会让设备调用超出工作台范围的接口。采用桌面会话共用的操作目录及有边界的账号路由，原有业务层继续判断是否允许执行。

固定回环端口或仅改 iOS 网站数据存储可以保留部分浏览器数据，但端口可能被其他进程占用，也无法解决网关身份变化。采用有明确键目录的原生本机存储，保持原 Web 组件的语义，避免把整份网站存储或登录资料复制到云上。

在 URL 中附加云授权可以让链接直接导航，但会把凭据写入导航记录及下载地址；将文件整体 fetch 为 Blob 则会复制大文件并绕开已有原生下载卡。采用有令牌及来源校验的原生下载入口，保留现有操作和权限边界。

## 验证

使用隔离宿主核对原生和独立入口的接续、发送、停止和审批。私有 HTTP 监听器测试覆盖指定 SSH 主机、API 配置写入和响应脱敏、拒绝失效 CSRF 与设备撤权、禁用入口、宿主密码策略和 WSL 归属。真实安卓云工作台的四种账号读取均返回 200；iOS 的 Codex 面板显示 API 接入和 SSH 区域。Claude 的独立 Desktop 聊天可写，未使用其上游模型。DSH Flash/low 从安卓收到一条 OK，同一结果在 iOS 的原会话可见。Codex 选中原会话后已连接，输入框可写。四种客户端均从安卓的正常入口打开了账号面板。

ZCode 成品切换前后是同一个 App 和管道宿主进程。手机重新连接到原聊天，状态为 ready，操作可写，模型为 GLM-5.3-Flash、思考为 low。一次真实发送被 ZCode 在模型执行启动前拒绝，消息未写入原生历史。ZCode 原 App 显示已登录，刷新模型设置后 Start Plan 显示「未就绪」「暂无可用体验套餐」，原生目录返回零个可用模型。没有重放消息或改动账号。

新增定向回归覆盖换端口后四种 Agent 草稿、未知发送记录、完成未读蓝点及阅读清除；原生存储验证跨账号和公钥隔离。私有 HTTP 测试验证网关重启后草稿身份稳定，云 cookie 与直连登录权限仍独立。实际安卓云工作台的运行中标记与聊天内状态可见；用户澄清缺失的是完成未读标记，该状态由上述本机存储修复覆盖。

Mac 8796 已正常更新为 132.4，安装包对应本地提交 `aac4767`，未退出原 Agent。iOS 模拟器 build 51 在独立旧会话输入未发送标记后，返回电脑列表并重新进入云设备，原会话草稿完整恢复；随后只清空该测试草稿，没有发送消息。真实 iPhone 未在本轮更新。

Android 模拟器 build 51 在最终网关身份下验证：返回电脑列表重进云连接以及仅终止并重启 Test 进程后，534 字未发送草稿和虚拟 SessionActivity 的 completed 蓝点均保留。33 字与 534 字的本机同步保存分别约 9.2 ms、6.9 ms；蓝点测试没有改动真实聊天运行状态，也没有调用模型。证据保存在 `.tmp/cloud-state-20261107/`，真实 Android 手机仍待安装最终 APK 实操。

升级前已打开的页面可能仍持有旧随机网关身份；更新手机 Test 后先返回电脑列表再重新进入。旧身份的草稿不做通配迁移，以免跨配置误恢复。修复前已丢失的完成未读状态无法凭历史结果还原，不能声称会补出所有旧蓝点。

## 影响

云下载定向夹具已覆盖四种 Agent 的工作区路由、原文件名、分段字节一致、If-Range 源文件变化和撤销配对；Android/iOS 生产下载器的 HTTP 夹具覆盖逐段授权、无 Cookie、拒绝跨域及重定向、视图退出后停止后续请求。共享点击适配器覆盖真实点击、旧手机能力、直连、图片预览和四种 Agent 路由。成品模拟器的实际点击及系统保存待完成，不能以夹具替代。

云服务仅提供连接途径；产品操作仍按对应 Agent、平台、登录状态和已启用的原生能力展示。已有手机构建内嵌 Web 资源，账号操作更新需要匹配的新手机版本和网关。云原型的终端 WebSocket 和全类型附件尚未作为这次验收结论。
