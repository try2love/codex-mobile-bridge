# Agent Note: 模型回复元信息范围

Status: implemented

## 问题

Test build88 将模型与思考强度标签加到了人的补充、工具执行及思考卡片，缺少字段时还反复显示未记录占位；时间被移动到顶部，破坏了普通消息在“引用”旁展示时间的既有布局。用户实测明确要求仅模型发言使用模型元信息，其他过程维持原样。

## 决策

模型最终答复和中间回复复用现有消息标题及底部操作栏，显示实际记录的模型、思考强度和时间。时间保留在“引用”旁边。人的补充、工具执行和思考卡片恢复现有展示，不增加模型标签或时间占位。缺失原生字段时沿用原有省略规则，不制造当前模型或读取时间。

移除为全类过程新增的展示辅助器、专用样式及未记录文案。历史投影继续保留来源时间；用户与工具记录不再套用回合模型。原生推理记录已有的元数据仍可保留在协议中，不因此强制展示。

此决定替换[中间过程元信息与顶部只读提示](2026-11-25-process-metadata-and-readonly-banner.md)中的广泛标签与占位方案；自动续页、缓存正文复用、顶部只读状态和原生时钟边界继续有效。

原生记录已有字段被正文窗口裁掉的缺陷由[原生回复元信息独立于正文窗口](2026-11-25-native-reply-metadata-window.md)修复；本篇界面范围保持不变。

## 备选方案

只把时间移回底部仍会给用户输入及每条执行记录添加模型占位，不能解决范围错误。为不同过程新增一套紧凑标签依然改变现有交互，因此恢复共享消息渲染器，只保留原生信息的正确传递。

## 影响

中间回复与最终回复采用同一布局，减少执行记录噪声。历史缺失字段不会被补造；此类消息显示的信息数量取决于原始记录。自动读取和只读访问权限不受此范围收窄影响。

## 验证

浏览器回归区分模型回复、人的补充、思考与执行记录，校验标题不包含时间，时间紧邻“引用”，用户消息标题隐藏，工具摘要无模型标签，页面无未记录占位。后台用例校验用户及工具不获得回合模型，同时保留原生消息时间。
