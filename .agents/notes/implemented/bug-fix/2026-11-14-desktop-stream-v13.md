# Agent Note: 桌面会话同步按结构兼容新版本

Status: implemented

## 问题

原接入只接受 v11，原生升级到 v13 后有效状态也被拒绝。重建连接不能改变这个门禁；旧提示却要求用户更新原客户端。

## 决策

会话状态同步以 v11 为基线。v11 保持原有部分快照解析；v13 和其他较新整数版本通过同一控制关键结构检查后继续同步，附加字段原样保留。已知新版本号也不能豁免结构检查，版本提升与新增普通字段无需维护接收白名单。

新版本必须保留可识别的会话 ID、provider、cwd、任务状态、审批集合、历史及工具项容器。canonical 历史的索引引用必须有效，任务状态必须可识别。实时同步与退出前任务审计共用该检查；审计遇到缺失或未知结构视为状态未知。

关键结构改变时保留历史展示，暂停控制并明确提示更新 Bridge。原生发送前再次检查格式异常，避免异步状态变更后派发操作。收到兼容快照后自动恢复。owner、host、thread、补丁 revision 和 CLI provider/cwd 归属检查继续生效；发送、审批、停止等出站消息保持各自明确版本与原有结果未知处理。

增量消息先在候选状态上应用并校验，再替换最后可信状态；操作失败或校验拒绝都不改变历史缓存。共享补丁函数只复制修改路径上的容器，未修改的历史继续复用，避免每个增量都深拷贝整段聊天。实时同步和退出审计沿用同一实现。

## 依据

官方发布包 26605（26.1106.51428）与本机 27194（26.1111.21308）的 JavaScript 源码对照：26 种声明消息仅 thread-stream-state-changed 从 v11 升为 v13；快照、补丁、订阅发送函数结构一致，其他 25 种消息版本一致。会话新增 attachedToThreadId；工具项新增 deferredOutputTurnId。canonical 历史在 v11 已存在。延迟工具正文的按需补取另有适配范围，此处处理同步兼容。

## 验证

PR169 原验证包含真实桌面快照以模拟 v99 运行结构检查。本地集成先以同一有效消息仅切换 v11→v13 复现断连，再验证 v13 的异常审批、任务及历史结构不能获得已知版本豁免。222 项定向测试通过，2 项 Windows 路径用例按平台跳过。覆盖附加字段、canonical 历史、错误 owner、格式变化后控制禁用与恢复及退出任务审计；本轮实机验收另行记录。

后续跨平台最小实测使用冻结源码 `4a2c31cb`：Windows Codex App `26.1111.2228.0` 的现有 IPC 握手、owner 发现、指定 owner/会话的 v13 快照及完整历史读取通过，活动会话的历史实体由 13 增至 18、22，控制结构均有效。结束后取消订阅，未激活或发送聊天。App 内置运行时 `0.169.0-alpha.11.1` 返回 8 个模型，临时元数据进程关闭标准输入后正常退出。该结果证明真实新版桌面连接和读取可用，不代替发送、审批或侧边聊天验收。

Ubuntu 22.04 现有安装为纯 CLI `0.167.1`，没有 Codex Desktop。本轮用同一冻结提交的 `app_server.py` 和 `websocket.py` 连接临时原生端点，握手与 home 归属通过，读取 3 条会话列表、目标历史 4 个回合及 9 个模型；读取后已加载会话仍为 0，代理与临时服务正常退出，账号和配置文件哈希不变。没有模型调用、会话恢复或正式 daemon 重启。此证据只覆盖该版本的纯 CLI，不能标成 Linux Desktop v13 或 CLI 0.169 已验证。

## 备选方案

仅将白名单增加 v13 改动最小，但下一次兼容升级仍会重复断连；放开全部版本而不检查结构则可能把未知任务或审批当成空闲。保留既有 v11 契约，新协议共用结构校验，可以兼顾旧客户端与新增版本。

## 影响

接收兼容性与出站命令版本分别处理，不改变后者。新增 attachedToThreadId 的归属展示和 deferredOutputTurnId 的正文补取仍需专项适配，不能把恢复同步称为完整实现所有 v13 能力。PR 作者原始提交保留，本地补充作为独立提交。
