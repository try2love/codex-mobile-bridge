# Agent Note: 远端 Claude 详情提前核对原工作目录

Status: implemented

## 问题

SSH 与 WSL Claude 详情原先只查询登录状态来判断能否继续。历史仍存在而原 `cwd` 已删除时，界面仍开放继续入口；真正恢复工作进程才在 `Path.resolve(strict=True)` 抛出原始文件错误。历史中的权限模式缺失是另一个独立阻断条件，不能借目录恢复替用户补齐权限。

## 决策

远端详情通过只读 `resume-preflight` 按原配置身份、原生会话 ID、`cwd`、模型和权限模式重新核对会话。原目录不存在、不是目录或不可访问时，返回带原路径的中文原因并关闭继续能力。执行恢复前复用同一目录检查，覆盖详情之后目录再次变化的情况。预检不创建目录、不替换 `cwd`、不启动或恢复聊天、不启动桌面 App、不发送模型请求，也不写原会话或配置。既有 profile/auth 核验仍可运行 `auth status --json`，版本能力诊断仍可运行 `--version`；这些只读 CLI 子进程不等同于激活聊天。未知权限仍要求用户在原终端继续。

## 关联记录审计

[合成模型恢复](2026-10-16-claude-cli-synthetic-model-reconnect.md)部分重叠，继续保留模型与未知回执边界；本篇只处理远端目录预检。活跃笔记中未发现其他持有同一目录预检决定的记录。既有未跟踪 TCC 提案不属于本变更。

## 备选方案

继续到执行阶段才检查目录最省请求，但会让详情错误地开放恢复入口，并返回难理解的原始系统错误。自动重建原目录可以绕过缺失路径，却会制造空项目并改变用户的执行条件，因此采用只读预检和明确阻断。

## 影响

未连接的可恢复会话详情增加一次远端预检，替代原来的登录查询；预检还需读取该会话的原元数据。历史仍可阅读，已有实时连接不增加此查询。登录、账号、权限和进程写入者检查保持各自职责；预检通过不能保证随后执行时目录仍存在。
