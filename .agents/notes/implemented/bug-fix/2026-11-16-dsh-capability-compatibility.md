# Agent Note: Harness 接入按协议而非发布系列判断兼容

Status: implemented

## 问题

内置通用插件的 engines.dsh 精确限定一个核心版本，网关手动绑定又仅接受 0.2.x 插件。即使更新后的服务接口、认证身份和线协议未变，也会在执行前被发布版本挡住。

## 决策

插件安装声明使用通配范围，实际必需服务继续由原 inject、profileContext 校验及各功能能力检查约束。手动绑定允许正常版本标识，不以发布系列判断协议兼容；名称、protocol、受支持 revision、安装声明与绑定一致性、认证后的运行插件身份均保持原校验。未知协议或运行代码不匹配仍在写入前拒绝，不自动降级或重放。

官方核心的 plugin-compatibility.ts 使用 includePrerelease，通配范围包含预发行版本。本次修改自己的插件声明，不向用户档案添加版本豁免，不安装或重载真实插件。兼容规则不代表所有未来核心均已实测。

源码来源清单保留原提交，显式记录 engines 的原值与打包覆盖值；检查脚本同时验证两端，不删除该字段的溯源校验。除这个已审查覆盖外，原文件与 manifest 检查不变。

## 备选方案

列更多精确版本只能延后再次失效；直接忽略全部握手会把协议变化误判成兼容。保留协议与身份检查，移除与协议无关的发布版本门槛。

## 影响与验证

新增版本系列与导出声明测试先复现失败，修复后手动绑定及来源检查夹具共 15 项通过。合成认证回环服务覆盖新版声明可读、未知修订拒绝、运行声明变化拒绝写入；来源覆盖漂移被拒绝。没有实测升级后的真实 Harness 收发。

实际本地源仓库对照另发现既存 host.mjs 与顶层 LICENSE 已偏离原 pin，二者本次工作区均与 HEAD 相同；完整来源检查因此仍失败。本次不把这项旧差异写成通过，也不顺手覆盖现有功能或协议文件。
