# Agent Note: 增量记录过多不再清空阅读窗口

Status: implemented

## 问题与决策

旧时间线在变化超过100行/192KiB或16份增量版本过期时，返回最近20行并要求前端reset，导致用户已展开的历史与过程被清空。这是传输预算触发的重同步，不等于原生历史被删除。

新Web显式选择paged增量协议：仍保持单次100行/192KiB预算，通过epoch内游标继续补齐；版本过期从已加载起点分批校对，保留节点、历史游标和阅读锚点。仅epoch变化/游标失效才重置。多页期间产生的编辑以第一批sequence为下一轮起点再核对；历史窗口扩展则重新分批校对。旧调用保留原协议，临时聊天与WSL复用同一个Timeline。

## 备选与边界

拒绝简单提高上限或收到reset直接拼接最后20行：前者重新引入大响应，后者丢失中间变化。没有修改原生IPC整快照协议、账号、任务状态或写操作。

## 验证

Python时间线24项通过，新增300条变化+过期快照分批收齐、无重复、预算和真实历史替换重置回归。Node更新循环2项通过，验证多页期间编辑补检和并发历史扩展；首次新增断言在旧实现失败。
