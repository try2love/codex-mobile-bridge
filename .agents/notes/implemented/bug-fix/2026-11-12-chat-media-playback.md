# Agent Note: 聊天音视频复用授权文件下载

Status: implemented

## 问题

原生聊天中的音频 Markdown 附件已被文件索引授权，但 Markdown 渲染器只为图片创建预览，其余附件都变成普通链接。真实 WAV 的 Range 请求可返回 206，响应却是通用二进制附件，聊天也没有播放控件。仅增加文件链接不能满足 #158。

## 决策

共享 Markdown 和附件组件调用同一音视频控件。只有现有授权文件 URL 可以创建播放器；外部链接和未授权本机路径不主动读取。播放器使用浏览器原生控件、`preload=none`、视频 `playsInline`，不自动播放。现有文件链接继续触发定位、预览和下载菜单，控件独立于链接。

播放器给原文件 URL 增加 `preview=1`，保留 relay 前缀、主机和会话参数。HTTP 入口仅对明确列出的音视频后缀返回媒体 MIME 和 inline；HTML 等主动内容仍为附件。普通下载行为不变。认证、文件身份和路径检查、大小阈值、Range、If-Range 和流式传输继续复用现有实现。工作区预览沿用 PDF 的预览大小上限，聊天文件沿用聊天下载上限。

格式或编解码器无法播放时显示下载提示；不安装转码器，也不把整个文件转成内存数据 URL。未变化的消息继续使用时间线原有 DOM 缓存。

## 备选方案

按客户端分别加入播放器容易接入，但会重复 UI 和下载边界，故使用共享组件。将任意远程链接自动变成媒体会产生未请求的外部访问，因此仅保留链接。下载完整文件再转码可扩展格式支持，但增加依赖、内存和延迟，当前保留原文件下载作为兼容路径。

## 影响

后端 18 项 Range/认证/大小/符号链接测试通过；新增认证和大小断言所在单项再次通过。前端资源、附件和文案相关 20 项通过。真实 Chromium 的 12 项共享 DOM 检查覆盖窄屏、正文两种链接、附件视频、错误回退及外链不加载。

生产 HTTP 处理器在隔离认证下读取用户反馈的原 WAV，浏览器收到播放结束和 seek 完成；合成 WebM 也实际解码播放结束，两者均为 206。此验证不发送模型请求、不修改会话。最终打包程序和手机宿主仍需安装后验收，不将浏览器结果当成三端交付完成。
