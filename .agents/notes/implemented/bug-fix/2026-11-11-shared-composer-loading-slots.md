# Agent Note: 共享输入区在加载与离线时保留完整槽位

Status: implemented

## 问题

共享客户端输入区此前只有带 `composerCapabilities` 的历史记录能保留 Skill、权限、附件和工作模式。Claude 等尚未返回能力的会话会先显示残缺输入区，真实能力到达后再插入控件。附件隐藏时，CSS Grid 自动排位还会把发送方式放进首列 30 / 26 px，窄屏只剩少量文字。

## 决策

`DesktopSessionsView` 为所有客户端保留同一组模型、Skill、权限、上下文、附件、发送方式、工作模式、输入与发送控件。首屏模型名可从已保存列表读取；列表元数据一律只读，不能授予写权限。尚未确认和明确不支持的能力分别标记为 `unknown` 与 `unsupported`，两者都保留禁用槽位；真实能力与实时连接共同决定能否操作。仅可读模型目录的既有兼容入口保持原有能力核验，不以展示元数据授权写入。

`manager._read(detail)` 将既有内建适配器的原生输入合同明确投影到共享能力：只有原生 `attachments` 为布尔值时才补缺失的 `send` 与 `projectReferences`，已有显式限制优先。Claude 的该值来自已观测 `sendMessage` 方法，DSH 来自已观测 `sessionController.prompt`，其余接入已有真实发送声明；所有内建适配器均通过同一原生输入路径处理经网关验证的 `resolvedReferences`。这不是从目录或在线状态猜能力；字段缺失或非布尔值保持未知，不生成支持声明。队列和补充当前任务保留各适配器已有明确值，不由共享层补真值。UI 对发送、队列和补充当前任务均要求明确支持，程序化提交同样核验，未知详情不会派发请求。

离线时输入框继续接受草稿；已有草稿、附件对象和阅读状态不因能力切换而重建。历史或缓存中的展示能力不能开启发送、模型、Skill、权限或工作模式。附件上传仅使用明确的 `attachments: true`；项目引用仅使用明确的 `projectReferences: true`，`cwd` 存在不是支持引用的证据。引用选择、工作台加入和发送使用同一能力门禁；已有引用在能力未知时保留草稿且阻止提交，不擅自省略或清除。上传与引用、计划与目标的合并状态均为：任一明确支持则支持，全部明确否定才为不支持，其余为未知。

共享发送行将附件、发送方式、工作模式和动作区显式固定为第一至第四列，兼容 Codex 主页面 `#work-mode` 与其他客户端的 `.work-mode-select`。附件或模式被其他入口隐藏时，其余控件仍留在原列，320 px 的 26 px 附件槽不会被发送方式占用。

## 备选方案

在各适配器补齐 `composerCapabilities` 可以减少现有客户端的跳变，但新接入或尚未收到历史时仍有同样问题，因此完整槽位由共享组件负责。把展示能力当执行能力可让控件提前可用，却会跳过真实权限确认，因此展示与操作继续分开。仅补一个隐藏附件的 CSS 分支可以修正当前首列症状，但其他隐藏控件仍依赖自动排位，因此采用四个既有槽位的显式列号。

## 验证

`tests/desktop-sessions-ui.test.cjs` 新增四客户端同一状态矩阵，覆盖无展示元数据的加载、能力明确不支持、能力就绪和断线；验证原控件、草稿和附件对象不重建，且没有客户端请求。既有不支持能力的断言更新为可见且禁用。首次草稿与 `tests/layouts.test.cjs` 合跑 204 项：203 项通过；一项已有返回文件标签测试失败，使用当时 HEAD 原版共享脚本的精确同用例仍复现相同失败，未将其归因于本改动。复审增量新增三项定向用例通过：有 `cwd` 但缺失引用能力时不能选择、加入或发送引用，已有草稿不丢失；计划 / 目标九种三态组合保持正确；已连接但未知的发送、队列和补充能力不能派发。发送合同变化后运行关联用例，并将旧合成详情补成真实网关的显式发送响应；受影响的七项重查通过，已知返回文件标签失败保留。未重复运行未变的原矩阵。

`tests/test_desktop_sessions.py` 的真实 `Claude.dispatch(detail)` → `manager.call(detail)` 合同测试以原生方法存在和移除两种响应验证发送、引用声明，并保持原队列与补充能力。未知或非布尔元数据、显式禁止能力另有定向覆盖；连同既有引用目录验证、原生分派及同 ID 不重放，共三项通过。测试仅模拟原生元数据，不启动客户端或模型。

生产资源与隔离 loopback 夹具在实际 Ego Chromium 中通过 320 / 350 / 390 / 1280 px、中英八组检查，每组 97 个断言，客户端与模型写入均为零。检查包括四客户端全部槽位、未知与不支持的区分、草稿附件保留、显式隐藏附件后的发送列宽和发送按钮边界。320 px 英文截图已目检；工具条保持横向滚动与可达收起按钮，发送行无横向溢出。该证据不等于手机原生 WebView 或实际模型收发验收。

复审后最终增量在 macOS 的实际 Ego Chromium 中仅跑 Codex 主页面生产输入区克隆和变化的能力合同：320 / 390 px、中英四组，每组 22 项通过且零客户端 / 模型请求。其中两份输入直接来自上述实际 manager 详情响应，不只手工注入 `true`；有无原生方法分别启用与禁用原控件。主页面两个下拉框分别位于第二、第三列，附件显示或隐藏均不重叠、不换行。320 px 英文主页面附件可见截图和真实共享 `prepareChat` 未知加载态截图均已目检，附件在加载态可见且禁用。新增夹具单独注册为浏览器用例，后续 CI 可独立选择。Windows 与 Linux 远端按用户要求暂停，本点不使用远端验证。

## 影响

加载和断线的输入区结构稳定，未知与不支持的能力可区分。明确不支持的功能仍占一个禁用槽位，窄屏工具条沿用现有横向滚动；本次不增加新功能、客户端专用输入区或权限推断。已有模型目录、发送回执、离线草稿和文件访问边界保持。
