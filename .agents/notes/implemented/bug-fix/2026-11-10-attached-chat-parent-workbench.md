# Agent Note: 原生侧边聊天共用父工作台

Status: implemented

## 问题

Issue #149 的原生子聊天使用完整聊天控制器时，同时创建了独立工作台。通知直接进入子聊天和返回父聊天会切换两套文件、Git、终端及标签状态。

## 决策

原生聊天执行仍采用子聊天 ID 和标准控制器；工作台仅按当前 provider、host 与根父 ID 保存一份。子聊天作为可关闭标签加入根父工作台，点击“聊天”切回父聊天；关闭子标签只改变视图，不请求停止、归档或删除。侧边聊天目录及新建入口始终属于根父聊天，不提供从子工作台继续嵌套创建的入口。已有原生嵌套关系保留，导航沿服务端附属父链解析根父，不改原生关系。

未知通知及子聊天入口先通过当前 Codex host 的分页时间线元数据解析父链，再切换工作台；已知普通列表聊天保留先展示缓存的原流程，不增加元数据等待。每次选择聊天都使旧路由请求失效，包括重新选择当前聊天；等待期间切换 provider 同样丢弃旧结果。父不可用、跨 host 或循环关系明确失败，不根据不可信通知字段构造另一个作用域。草稿、模型、附件、审批及历史继续按实际子 ID 保存；聊天滚动按 ID 单独记录。文件、终端和 Git 保留根父工作台归属，聊天中的文件定位先按实际聊天 cwd 解析，再校验是否落在父工作区内。

## 备选方案

每个子聊天保留独立工作台可以直接复用旧页面，但导致此次双层标签和父工具状态切换问题。另写子聊天输入、审批和附件面板能够完全独立挂载，却复制标准聊天能力；当前保留单一控制器，仅分开聊天身份与工作台身份。

## 验证

定向 Node 检查父工具对象保持、子标签关闭无原生操作、host/provider 隔离、通知父链解析及不可用/循环父链拒绝。浏览器合成目录夹具覆盖原生菜单、创建操作 ID、根父工作台与子标签关闭。浏览器结果记录在本轮临时证据，不能等同手机原生通知或真实模型收发验收。

## 影响

未知入口或子聊天增加只读分页元数据请求；嵌套关系额外读取祖先。不会启动新的 writer 或改变 owner、provider、认证、cwd。父不可用时不能以独立子工作台继续进入，原生历史和关系仍保留。

## 历史决策核对

[原生持久侧边聊天](../feature/2026-11-07-native-attached-side-chats.md)部分重叠，本决定替代其“子聊天独立工作台和返回主聊天按钮”表现，保留标准控制器、原生关系及关闭不删除的约束。[共享运行时](../architecture/2026-11-08-codex-shared-runtime-data-deletion.md)及其提案只涉及原生数据和原 App 标签同步，保留，不以本次网页标签修复宣称已修复原 App 标签同步。[VS Code owner](2026-11-03-vscode-shared-owner.md)、WSL 和原生删除记录保留其执行、平台和事务边界。
