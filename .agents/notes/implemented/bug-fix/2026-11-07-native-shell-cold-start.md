# Agent Note: 原生手机冷加载先登记宿主再等待样式

Status: implemented

## 问题

iOS 的 document-end 注入可能早于样式表可读取的时刻。原脚本在缺少样式时直接返回，导致首次进入同时出现网页和原生的“更多”入口，也未完成返回电脑列表的宿主布局。

## 决策

Android 与 iOS 继续使用同一份 `mobile/shared/web/mobile-ui.js`。应用节点就绪后先登记原生布局标记，再尝试读取同源样式表；样式未到时监听资源加载，成功写入后撤销监听。不为此新增轮询或重建页面。重复注入不重复注册原生交互。

本修复从云服务实验提交 `f49f31b` 中提取，仅改变共享布局初始化。普通直连同样使用它，不引入云账号、转发或存储。既有随机 token、主框架及原生授权校验保持不变。

## 备选方案

等待所有资源加载后才注入布局可以减少时序分支，但会延迟宿主识别，期间仍会出现两套导航。分别修改 Swift 与 Java 能处理单个平台，却会复制相同逻辑。因此在共享脚本中保留一次事件驱动的初始化。

## 验证

针对性 Node 回归 38 项通过，覆盖无样式冷加载、无关资源先返回、样式迟到后仅插入一次规则，以及菜单、原生主题、资源清单与宿主识别。UU 入口与该共享脚本的组合纳入本轮候选；Node 结果不代替成品 WebView 与真机验收。

## 影响

冷加载时宿主布局可及时识别，样式可读后恢复统一导航，没有新增后台计时器。暂时无样式的页面仍需等待资源恢复才能呈现完整视觉样式。

检索活跃笔记后，[iOS 主题与通知](../feature/2026-10-28-ios-theme-and-foreground-notifications.md)仅在共享注入脚本职责上部分重叠，保留其主题及通知决定；[UU 远控](../feature/2026-11-06-mobile-uu-remote.md)继续负责电脑绑定和原生调用，不由本修复改变权限。
