# Agent Note: Windows 取消 CLI 恢复时保护正在读取的回执

Status: implemented

## 问题

Windows Python 3.13 的发布回归在取消等待中的 CLI 恢复时，`private_json` 替换 `cli-daemon-recovery.json` 返回 `WinError 5`。后台维护正在读取同一记录；`Path.read_text` 会关闭文件，但读取尚未结束时，Windows 的读取句柄不共享删除权限，原子替换可能被拒绝。这是合法取消与后台短读的重叠，不是测试遗漏关闭连接。

受控夹具先让真实维护 worker 打开记录，再从取消线程调用实际 `cli_network`，在句柄仍开放时模拟 Windows 的替换拒绝，稳定复现相同错误。证据存于 `.tmp/v222-preview2-release-20261120/ci/cancel-read-overlap-evidence.log`，不包含账号或聊天资料。

## 决策

`Bridge._cli_recovery_record` 在既有 `cli_maintenance.lock` 内完成存在检查与 JSON 读取，关闭读取句柄后释放锁。取消路径原本就在同一可重入锁中读取、写入取消状态，再设置等待线程的取消事件。两者现在串行化这段文件访问；锁范围不包含原生 RPC、共享任务检查、账号恢复或进程控制。

既有维护流程按 `accounts.gate → cli.start_lock → cli_maintenance.lock` 取得锁。取消路径只取得最后一个锁，不反向等待前两个锁；记录读取也不在获得维护锁后取得账号锁或启动锁。原来已经持有维护锁的调用者通过 `RLock` 重入。

## 验证

新增回归先保持记录读取句柄开放，再开始实际取消。旧实现因读取未持有维护锁而失败；修复后记录关闭先于替换，取消状态落盘，未知提交保持原状，退出、启动与会话接续均未调用。额外线程保持账号锁与启动锁，取消仍可在它们释放前完成，验证没有引入反向依赖。

CLI 网络恢复、共享释放、强制退出、接续与目标范围相关 180 项本地回归通过，受控并发回归连续运行 30 次通过。受控测试在本机模拟 Windows 删除共享规则，Windows 原生 CI 仍负责验证目标系统的真实句柄行为。

## 备选方案

在通用 `private_json` 内重试权限错误可以覆盖其他短暂占用，但会扩大全部持久化调用的行为，并且无法区分实际权限失败与并发短读。本次只修复已证明的 CLI 恢复记录重叠。让取消等待账号锁或启动锁也能减少重叠，但后台原生检查可能长时间持有这些锁，违背取消不等待原生检查的契约。

## 关联记录

[已确认的 CLI 恢复等待共享任务结束](../feature/2026-11-11-cli-recovery-waits-for-idle.md)与本次部分重叠，继续定义显式确认、任务保护、取消失效与未知写入不重放；本次补充记录读句柄与取消替换之间的互斥。现有 Windows 原生排空能力不由本次改变。

## 影响

取消最多等待同一进程的一次短 JSON 读取结束，保留取消的实际持久结果和既有安全检查。通用原子写入、跨进程锁及 Windows 文件权限策略保持原有实现；本次不声称消除其他进程或系统扫描程序占用文件造成的全部错误。
