# Agent Note: 准备任务可恢复与下载悬浮页复用

Status: implemented

## 问题

准备清单仅由选择弹窗等待。用户关闭弹窗后不能直观看到准备进度，重新进入可能再次创建任务。原传输浮窗另有一套样式，也缺少实际速率和输入框避让。

## 决策

准备、就绪和错误均进入原生持久任务状态。取得清单ID后保存，恢复只读同一清单，不重复提交准备请求；没有取得ID的中断请求要求重新选择。弹窗在有任务时提供最小化，准备过程继续。悬浮页显示当前会话、已准备会话数，完成后显示待开始入口，可重新打开确认页。

传输阶段复用已有下载悬浮页样式与同一定位函数，包括窄屏、可视视口和输入框避让。定位与拖动共用下载卡片实现，桌面和窄屏均可拖动标题，键盘方向键可微调，切换展开状态仍限制在可视视口。标题底纹随已处理进度填充。Agent选择沿用工作台标签样式，关闭与其他动作沿用现有子页按钮；独立的CLI连接、传输、用量和消息管理移至设置顶部的统一操作区。

显示实际网络下载字节的速率及已处理内容进度；空闲、暂停和准备阶段不伪造传输速率。完成或准备失败卡片的关闭动作写入原生任务dismissed状态，重进后不再显示；新任务明确复位。旧版没有该字段的已完成任务恢复时默认收起，只迁移展示状态，不清除下载记录。窗口关闭和聊天切换不取消仍在进行的已保存任务，账号变化继续隐藏旧任务并绑定原生归档授权。

确认页只显示预计最大下载量，并说明完整内容会自动跳过，不再并列展示相同的会话全量与下载上限。

## 备选方案

关闭弹窗就取消准备会浪费已经完成的快照工作。把所有进度留在模态弹窗会阻碍继续聊天。复制另一套下载定位规则容易再次遮挡输入框，因此共用现有函数，任务状态仍由历史传输模块维护。

## 影响

任务可以独立于弹窗存在，准备失败也有可见入口。下载上限不再承诺精算后的缺失字节；实际网络速率和处理进度分别计算，已缓存内容跳过时仍能推进进度。旧任务保持兼容，新格式提速需要重新准备清单。

Chrome/WebKit宽窄四种组合验证最小化、重开、准备完成后重开、不重复POST、跨Agent选择和空间不足续传；与发送反馈共20项浏览器检查通过。单元回归覆盖准备状态恢复和双端能力协商。

后续Chrome/WebKit宽窄检查包含拖动后位置、拖动不误折叠、58%底纹和顶部独立入口。现有文件下载也使用同一拖动函数，避免两套手势分叉。
