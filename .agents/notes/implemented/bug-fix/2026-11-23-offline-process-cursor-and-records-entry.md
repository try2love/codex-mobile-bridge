# Agent Note: 离线过程读取与正常登录归档入口

Status: implemented

## 问题

手机设置的保留记录入口只查询已退出或解绑后标记retained的账号，仍有效登录的已传输归档被过滤。在线Timeline与导出Timeline各有epoch，断网页面保留在线过程游标，而离线阅读器只认导出游标，错误地返回空过程。阅读器没有正文分段入口；去除写能力时还丢失通过forkable标识的最终回答身份。

## 决策

设置入口列出所有有实际可读内容的归档，包含当前登录与以前保留的账号；状态锁定与设备验证仍由原生阅读入口执行，不改变认证。部分任务尚无实际回合时不列为空归档。

过程和正文仅在当前账号、会话、已装载回合的本地映射中按稳定记录key定位，允许在线epoch前缀映射到同一key。正文核验原版本和原分段偏移，不存在的过程或正文明确报未保存，不再伪装完整空结果。离线过程可从cached屏幕展开；已在屏幕上更新的不同版本不被旧归档覆盖。同版本可使用已保存全文。读取始终经过已有本地授权与离线桥，不发网络请求。

离线最终回答保留其显示phase，写能力继续关闭；已回答选择与进度、工具结果归入过程。当前待回答请求仍由实时请求区域显示。

## 备选方案

断网后重建整个聊天可换掉游标，但会丢掉当前屏幕的新内容和阅读位置。仅提示用户重进聊天无法修复本地正文读取。用空数组吞掉未知游标虽然不会报错，却把读取失败误认为没有中间过程，因此采用当前授权范围内的稳定记录身份。

## 影响

型号或网络变化不扩大离线权限；被撤销账号仍需原有验证。未保存内容明确保留缺口。大回合仍由原生分回合分页，过程展开沿用共享时间线与独立思考摘要折叠。

四项离线单元复现先全部失败，再通过；同步器覆盖cached离线展开与保留更新行。Chrome/WebKit宽窄屏真实渲染验证已保存的完整正文、思考摘要、选择答案、进度与工具结果且无API网络请求。Swift归档仍通过持久化、传输、清理与锁定检查。
