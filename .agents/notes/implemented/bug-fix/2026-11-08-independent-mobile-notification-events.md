# Agent Note: 手机通知按事件独立保留

Status: implemented

## 问题

Android 的通知接收器已按事件去重，但系统展示层对同一会话复用 `chat|gateway|host|thread` 标识。先到的待确认提醒会被后到的完成提醒替换；再次要求确认也会覆盖同一张卡片。它们表征不同的行为，不能以会话为单位互相替换。

## 决策

普通 Android 收件箱和可选 FCM 共用 `TaskNotifications`。系统通知的 tag 由已认证网关身份、事件流和流内唯一序号组成；无序号的本机测试事件使用自身 ID。相同事件经收件箱或 FCM 重试只更新自己的卡片，不再次响铃。不同事件即使属于同一会话、同一提醒类型也各自保留。地址切换沿用网关身份，不增加重复卡片。点击使用对应事件的独立 Intent data，保留原会话及完整 host 路由。

查看聊天不清理新事件卡片；只有点击该条、手动划走或显式清空收件箱才移除。旧 `clearChat` 回调仅清理升级前的会话级卡片，不遍历并清除新事件。此规则不改变系统/厂商的通知分组方式，也不改变后台服务常驻通知、接收频率、权限或通知来源开关。

网关未保存的 `mobileEnabled` 和 `includeTitle` 默认开启；已有配置中明确保存的 `false` 继续优先。它们只控制网关入箱与标题呈现，不自动开启手机后台服务，不代替操作系统权限，也不启用未配置的第三方通知通道或 Agent。

### 既有记录核对

- [Android 后台通知](../feature/2026-10-27-android-background-notifications.md)部分重叠：本篇替代其中“打开聊天清理该聊天系统卡片”的规则，保留其后台服务、权限、接收基线和导航决定。
- [通知投递隔离](2026-10-28-notification-delivery-isolation.md)互补：本篇只改变 Android 系统呈现身份，不修改网关投递队列及第三方重试规则。
- [手机第三方通知设置](../feature/2026-10-13-third-party-notification-settings.md)部分重叠：通用配置仍使用同一份设置和认证边界，仅补充未保存字段的默认值。
- 其他活跃通知笔记描述来源筛选、主题或客户端适配，不被本篇取代；没有需要归档或删除的提案。

## 备选方案

按会话保留最新通知占用更少的通知空间，也可以自动消除已过时的待处理提示，但会丢失用户要求保留的行为记录。按“会话＋事件类型”分配卡片仍会覆盖后续同类型事件，因而均不采用。

所有已安装配置强制打开收件箱和标题能立刻统一默认体验，但会覆盖用户此前的关闭选择。读取时只为缺失字段补默认值，保留用户已有决定。

## 验证

`scripts/test-android-task-notifications.py` 编译生产 `TaskNotifications.java`，用 NotificationManager 与 PendingIntent 系统服务替身重现同会话的“决策 A → 完成 B → 决策 C”只剩一条；修复后独立卡片、同事件跨地址重试、网关及事件流隔离、四客户端路由、点击身份、可见聊天与旧卡清理均通过。该夹具不模拟厂商分组布局。

后端 `test_mobile_events.py` 的 19 项通过，覆盖新配置默认入箱及标题、旧配置关闭值和部分旧字段迁移、游标、鉴权、撤销及长轮询。`test_notifications.py` 首轮 52 项通过，2 项因第三方通知夹具未明确关闭新默认收件箱而失败；补齐夹具前提后，这 2 项定向复测通过。没有真实模型请求或外部通知发送。

## 影响

同一聊天可保留多张事件通知，代价是通知栏条目更多，受 Android 系统通知数量上限与厂商分组策略约束。没有新增监听器、定时器、轮询或事件存储。iOS 已按事件分配通知标识，本轮不改其呈现。Android 真机的连续提醒和逐条点击效果仍需新 APK 实测，源码夹具不能替代系统验收。
