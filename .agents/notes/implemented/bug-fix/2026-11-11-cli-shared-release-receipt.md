# Agent Note: 旧 CLI 共享服务释放回执跨会话协调

Status: implemented

## 问题

旧版共享 daemon 已正常退出时，私有恢复账本仍保存 `phase=stopped`。窄兼容通过成功 unload 回执判断这是已完成释放，却额外要求回执的 sessionId 等于本次继续的线程。退出影响整个 home 的服务，因此同配置另一线程会被误当成未完成维护而长期阻挡。

## 决策

旧 stopped 的兼容仍只接受 generation/phase/configuration/connections 四字段、单连接，以及精确匹配的原 unload 成功回执。匹配范围是该 Bridge 私有目录和 host、Codex provider、连接 token、操作 UUID、成功状态与旧版专用正常退出 notice。回执的原线程必须仍能从当前 home 的原生元数据读取；本次请求可以是同一 home 的另一 CLI 线程。

补全 `purpose=release`、`phase=released` 和原释放操作身份时，`releasedThread` 保留回执原线程的 ID/cwd/provider，generation、配置摘要及连接集合保持不变，不改成当前请求线程。后续显式继续仍核验配置、原释放线程身份、当前目标线程和 daemon 代次；同代仍存活、无法重新核验环境或配置变化时不启动或恢复。没有释放成功证据的 stopped、未知回执和其他网络维护仍保持阻挡。

PATH 中有完整 CLI 也不能绕过未决账本：home 管理组件缺失时，待核验的退出、启动、恢复或未知设置写入明确阻挡，不将检查缺失当作允许冷启动。已证实释放则可使用已有 PATH CLI，在原身份和配置核验后正常启动；原生准备出该 home 的 daemon 包时，启动后重新选择实际包路径核验进程代次，不能把最初的 PATH 启动器路径当成新 daemon 身份。

旧回执没有独立 home 或 generation 字段，本实现不补造历史证据，也不把 notice 单独视为成功。原生线程所属 home、精确连接关联与后续进程/配置核验共同约束兼容；这不是对任意恶意改写私有历史文件的签名认证。

## 备选方案

继续要求当前线程等于释放线程能避免跨线程推断，但把共享服务的退出错误归为单线程状态，无法恢复同 home 的其他聊天。删除 stopped 账本或接受任意 released 回执可直接绕过阻挡，却会丢失未完成维护和未知结果保护，因此保留原窄兼容，只校正线程关联。

## 验证

将当前已提交的旧 `_completed_cli_release` 方法只在测试进程内装回后，新的跨线程 SQLite 用例重现未完成维护错误；没有修改仓库源码或任何真实账本。修后 9 项定向回归通过，其中新增 6 项覆盖两个真实 SQLite 线程、网关重启、另一个 home 缺失原回执线程、9 种错误/未知回执、仍在运行的原代次、不同代次环境及配置变化。成功分支只启动一次并接入当前线程，保留原代次和回执线程，操作账本字节不变；反例不 start、不 attach、不 stop。

用例仅使用 `.tmp` 合成元数据和原生协议 stub，没有模型请求、真实服务操作或固定评估样本。复现记录位于 `.tmp/feedback-20261111-10/legacy-cross-thread-red.json`。

与 PATH 冷启动的交互另先复现两个相反失败：无管理包时未知旧回执被跳过；正确已释放回执却被缺管理组件挡住。修后新增 4 项与受影响的既有 3 项回归共 7 项通过，覆盖未知/失败/缺失回执、4 种待核验维护阶段，以及新旧成功释放经 PATH 启动后核验准备出的包路径。此处仍是受控夹具，不扩展真实生命周期或强制操作验收。

## 影响

共享服务的既有成功释放可用于同配置其他 CLI 线程的显式继续，旧回执仍可追溯到原操作。不能重新证明的环境或互相矛盾的运行状态继续要求核验，不借本次兼容改变账号、提供商或服务生命周期策略。
