# Agent Note: 对话补页与缓存过程展开分开

Status: implemented

## 问题

一次“更早内容”被纯工具页消耗，连续每页渲染造成频繁移动；折叠组即使收起也挂载大量正文。普通任务补充不能按“user”之外的模糊规则吞进过程。

## 决策

两个聊天渲染器复用readChatHistoryBatch：每个阅读意图最多读取四个现有有界原生页，直到出现未缓存的普通对话，再一次合并。纯过程最近页也做一次有界补读；无进展游标、网络失败保留已有内容与手动重试。切换会话后成功或失败回执都不能回填旧内容。

操作组单独从已接收缓存挂载近期20条，“加载更早过程”每次补20条，保留锚点，不重复请求外层历史。Codex正文仍用既有detail按需接口；其他客户端原生页已携带的文本保留缓存，只在展开时挂载正文。这个改动分离阅读操作与DOM加载，没有声称各原生协议已统一为独立的activity网络接口。

## 备选方案

- 调高一次全量加载上限：会放大传输/布局阻塞，拒绝。
- 对每个工具页立即渲染或反复清屏：不能稳定上翻，拒绝。
- 为各Agent重写历史读取协议：超过这次中间展示修复范围；复用已有游标与缓存。

## 影响与验证

普通补充、说明与最终回答仍是外层；显式已处理响应属于过程，待处理审批不进入历史页的权限/状态回填。单次补读到预算后仍允许手动继续，不无限追读。单元回归验证200工具跨页、已回答与补充区分、重复游标、失败保留和跨会话丢弃；生产渲染器宽窄屏证据在本轮.tmp验收目录。
