# Agent Note: 补齐飞鸟终端代理的当前端口来源

Status: implemented

## 问题

用户的 `.zshrc` 在终端启动时从飞鸟配置读取 `mixed-port`，再导出代理环境。常驻 CLI 保留旧端口；原自动恢复只读取系统静态代理，不能覆盖没有启用系统代理的终端用法。网关自己的启动环境同样可能过期。

## 决策

保持现有系统静态代理优先。只有 macOS 系统设置成功读取、没有 HTTP/HTTPS 静态代理且没有 PAC、自动发现或已启用的 SOCKS 路由时，才尝试当前用户的飞鸟配置。只提取唯一有效的顶层 `mixed-port`，核对文件属主、变化、应用标识、核心实际映像、所用配置参数和监听端口归属，并做不携带目标地址的 SOCKS5 协商。配置正文、订阅和认证不进入日志。

返回现有代理元组，继续复用同主配置、旧代理失效、目标绕过规则、等待空闲、派发前复核及未知操作不重放的恢复流程。这里只扩展已知来源，不执行用户 shell、不改变系统设置、不新增恢复状态机，也不承诺识别任意 shell 脚本或其他代理产品。

## 备选方案

重新运行交互 shell 可得到用户脚本导出的变量，但同时会执行其他启动命令；输出白名单不能消除副作用，因此没有采用。直接沿用网关环境不能证明它是当前端口。读取任意同名配置或仅探测 TCP 也不能证明该端口由对应程序提供。

## 验证

15 项定向回归覆盖既有路由规则、系统源优先、PAC/SOCKS 不回退、错误和重复端口、文件或进程变化及其他监听者。真实 Mac 上单独调用飞鸟来源，已返回当前端口 `http://127.0.0.1:15937`；本轮最新系统静态源也返回该端口，两者分别核验，未互相冒充。

基于此源码打包的 Mac Test 已经由真实浏览器和原生 0.167 CLI 验证：隔离主配置的 CLI 最初持有已关闭的代理端口，点击原会话“继续”后约 1.8 秒连接，已核验旧代退出、新代采用当前代理。第二条原会话也能继续。通过单会话入口查看共享配置影响范围并确认正常释放后，原生进程确实退出；再次继续约 1.4 秒连接，两条原会话均保持 ID、provider 和工作目录，代理未退回旧值。网关、CLI 正常退出，临时配置恢复，无模型请求。原始证据保存在 `.tmp/feedback-20261111-10/mac-cli-direct-live/`。该完整恢复使用当时可用的系统静态源，不能据此宣称完整验证了“系统源为空”的打包回退；飞鸟回退来源由独立实机读取及定向测试覆盖。固定用户会话、Windows SSH 和正式 App 图形接管仍需单独验收。

实机发现并修正了模拟测试遗漏：`ps` 在 `LC_ALL=C` 下把中文应用路径转义，草稿无法匹配“飞鸟加速”。改用项目既有的 `en_US.UTF-8` 查询约定后，实际核心路径匹配通过。核心以 root 运行时强进程身份接口返回 EPERM；此处只观察代理来源，使用可读的进程路径、出生时间和监听关系，不把它当作发送停止信号的身份凭证。CLI 自身的停启核验没有放宽。

## 影响

补齐已确认的飞鸟配置来源。原静态代理、Windows 和不支持的来源保持既有边界；无法核验时不猜测替代端口。没有修改账号、聊天、原生权限或飞鸟配置。
