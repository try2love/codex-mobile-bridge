# Agent Note: Android 预览安装与签名边界

Status: implemented

## 问题

构建时自动生成签名可能产出同应用标识、不同签名的 APK，无法覆盖已安装版本。预览分发需要明确与原 App 的安装和数据边界。

## 决策

Android 构建要求显式提供已有密钥及密码环境变量，缺失即停止，不生成替代密钥。密钥和备份由发布者保存在非临时、未跟踪目录，普通产物清理不得删除。

本轮 Android 预览采用独立应用标识 `io.github.try2love.codexbridge.previewchannel`，名称为 Bridge Preview；仅构建暂存清单改变标识、下载 provider 和 UU 回调，Java 入口保持原值。原 App 与数据保留；预览版重新添加连接，不自动迁移绑定和草稿。CI 使用明确生成的短期夹具密钥，不能将其当成发布密钥。

## 备选方案

沿用原应用标识便于覆盖升级，但要求相同签名或有效轮换链，不能以新密钥代替。卸载再安装会丢失原 App 数据，不符合保留要求。本轮采用独立预览安装。

## 影响

预览用户可保留原 App；代价是首次重新连接电脑。后续同预览标识的更新仍需保留本轮签名。签名和安装共存应分别验收，编译成功不能代替覆盖升级检查。
