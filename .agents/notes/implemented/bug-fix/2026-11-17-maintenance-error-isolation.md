# Agent Note: 后台维护按会话和轮次隔离异常

Status: implemented

## 问题

[元数据读取边界修复](2026-11-16-passive-metadata-retry.md)覆盖 `_attach` 中已知的存储和传输失败，但 `_settle_scope_queued`、其他会话维护步骤及远端 `retry_ssh` 仍可能抛出异常并结束整个维护线程。单会话失败也会阻止同轮健康会话得到维护。

## 决策

PR195 保留作者提交 `05e672048ce03730bd67ef2c1c69be41dd1ec623`，将原单会话流程抽取为 `_maintain_session`。每个会话异常写入带会话 ID 的异常日志后继续下一个会话；轮次外围异常记录堆栈后返回原 `closed.wait(delay)`，不退出线程。异常日志保留故障可见性，不把失败记作连接成功。

单会话仍在既有提交锁内复制队列，锁外调用发送及跟随；元数据边界的原错误处理保留。待发送消息仍先持久化为 unknown，派发异常不改回 queued、不自动重放。activity-only 的 15 秒预算和恢复期预算保持，成功轮次继续采用原 3 至 30 秒退避；整轮异常保留已有 delay。

历史笔记审计：元数据读取笔记部分重叠，其局部错误说明与返回契约继续有效；本篇补充此前未采用的外围异常隔离，并以记录异常替代无记录吞错。SSH 离线隔离与退避笔记继续决定主机级探测预算，本篇不替代其机制。未发现被完全取代的记录。

## 备选方案

仅保留 `_attach` 中的已知异常处理，能使故障类型保持集中，但无法覆盖维护其他步骤及远端预检的异常。无记录地捕获整个循环最简单，却掩盖故障且不能保证同轮其他会话继续执行；采用有日志的单会话隔离与外层兜底，仍保留局部处理。

## 影响

单会话和瞬时整轮故障不再终止被动维护；代价是持续错误会在既有退避周期重复记录日志。此隔离不修复错误本身，不保证 SSH 可达，不扩大启用观察、激活或发送权限，不改变原 owner/provider/auth/cwd。

## 测试

集成后 `test_disabled_observers.py` 13 项通过，包含隔离 Unix socket 的原 owner 恢复夹具。额外直接调用生产 `_maintain`、`_maintain_session`、`_send_queued` 的合成检查覆盖同轮健康会话继续、15 秒预算、锁释放、整轮恢复及持续错误等待、远端预检异常恢复、停用不派发和 unknown 不重放；其中维护相关 6 项通过。未启停或连接真实 Agent，未操作当前 Codex App。
