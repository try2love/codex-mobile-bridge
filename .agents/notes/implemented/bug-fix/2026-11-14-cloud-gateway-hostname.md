# Agent Note: 云网关登记默认使用本机名称

Status: implemented

## Problem

桌面云登录未填写可选 name 时，网关登记固定发送 Desktop，同账号的多台电脑在手机上无法区分。网关现有认证和局域网发现接口已使用 `socket.gethostname()` 描述本机。

## Decision

登录时无显式名称便读取同一网关宿主机的 hostname；默认名去空白、过滤控制字符并限制为服务端允许的 100 个 UTF-8 字节。系统名不可用时使用带当前 gateway ID 前缀的兜底名称。显式名称仍优先，不更换 gateway ID、公钥、账号或授权流程。

已有登录不为了修改展示名重新登记或退出；手机可从已授权网关的现有 `/api/auth` 补齐旧默认名。此次不新增服务端 API，也不部署远端或重启现有网关。

## 记录审计

- [云登录表单](../feature/2026-11-01-cloud-login-dialog.md)：部分重叠，仍是显式登录与原表单契约，仅默认登记名来源变化。
- [手机多信道](../architecture/2026-11-02-mobile-gateway-channels.md)：无关，名称不作为身份或信道合并依据。
- 已搜索活跃名称、hostname、云登录和目录笔记，无重复默认命名提案。

## Alternatives considered

- 从 Electron UI 提供系统名能满足桌面壳，但遗漏其他 Controller 入口且重复已有 Python 取名能力；在注册拥有者处设默认值。
- 自动重新登记现有设备能更新服务器目录，但会旋转设备令牌并关闭现有连接；不为展示变化触发此操作。

## Testing

42 项云账号测试和 4 项模块边界测试通过，新增用例验证 Windows/macOS/Linux 形式的 hostname、UTF-8 长度边界、控制字符过滤、系统读取失败的稳定兜底，以及实际登录登记 payload 的显式名字优先和原 gateway ID/公钥保留。初次使用系统 Python 缺少 aiohttp/cryptography，改用本机已有测试虚拟环境执行，没有修改依赖版本或全局环境。

配套 App 在已授权连接上读取现有 `/api/auth`，模拟器两张旧 Desktop 卡片已显示不同的实际系统名。桌面源码的默认登记值修复未重新打包安装，未代用户登录、重新登记、部署服务器或重启现有网关。

## Consequences

新登记的电脑默认可以区分，继续复用现有身份和服务端字段。代价是默认名需要系统调用并遵守字节长度限制。该默认值在更新后的登录登记生效，既有云目录不会立即被桌面改写。hostname 可能是 `.local` 名称而非用户自定义的产品昵称；手机本机别名仍可覆盖展示。
