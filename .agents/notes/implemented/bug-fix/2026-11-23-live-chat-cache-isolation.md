# Agent Note: 实时聊天展示与缓存持久化分离

Status: implemented

## 问题

其他 Agent 的在线同步结果无条件调用离线阅读器状态，产生“离线、只读”假提示，实际仍可交互。缓存验证还等待上次持久化完成；手机 recent 页面被排除在提前展示路径外，缓存慢写能阻塞实时结果显示。

## 决策

只在真实离线阅读模式显示离线提示；缓存预览仍不能授予交互能力。运行中的浏览器与原生手机壳使用当前内存版本提示，不等待磁盘、原生归档或先前持久化任务。浏览器手动打开首屏、历史与正文，或首次恢复当前页过程时给本地缓存最多50毫秒的读取机会，快速命中继续复用已有正文；超时或失败立即用内存提示请求网络，不等待迟到查询。缓存索引探测后的本地还原同样有界，失败重新读取完整服务端页。预取仍按持久化缓存执行。正文分块在当前授权作用域的有界内存页中复用，清理、账号变化或代际变化会使其失效。

最新前台结果独立验证当前身份、作用域、代际、清理版本以及完整行版本后即可展示，缓存写入保持串行。不能可靠还原完整页面、发生删除或清理版本变化时不提前展示。最新服务端控制元数据继续覆盖展示缓存，不以缓存推断发送授权。

范围回填的缺失判断同时检查扁平原始行与折叠会话投影。仍存在的过程子行不会因被折叠而被删除；原始源与会话投影都已不存在的对象继续清理。浏览器回归定位到旧判断会误删已下载的末尾5条过程，导致再次展开重复传输。

原生发送成功回执文案表达会话已接收、等待显示；未知发送继续保持原请求身份与防重放规则。日志中最近发送请求约22至46毫秒，但不能据此证明用户报告的两端几十秒显示延迟已被完整定位。

内存中的过程版本提示只来自当前过程组，不能把聊天正文或其他组的键交给过程接口，否则服务端会将不属于该组的键报告为删除，进而误清理缓存。过程检索同时合并尚未落盘的内存页索引，索引探测优先复用与服务端版本相符的内存正文，避免异步持久化使后续分页漏掉已经展示的记录。

页面导航取消本页的只读请求，并合并调用者提供的取消信号。`/api/activity` 虽使用 POST 传递查询范围，仍属于只读轮询；导航取消不提升缓存校验代次。真实网络失败继续要求重新校验；发送、停止和审批等写入不加入导航取消或自动重放。

## 备选方案

等待所有磁盘与原生归档写入能简化读后写顺序，却让缓存性能决定实时界面延迟。直接关闭缓存会丢失增量复用。跳过鉴权或清理校验虽然更快，却可能重新展示已清理的内容，因此分离展示与持久化，并保留这些验证。浏览器手动读取若完全不查询旧缓存，会在重开页面时重复传输；无限等待又恢复原缺陷，所以仅手动读取采用50毫秒预算，实时刷新与原生壳不等待。

## 影响

持久化可能晚于可见页面，下一次读取可使用已提交的较旧版本并让服务端补齐差异。写操作不加入缓存请求合并，不因未知结果重试。缓存持续失败不应被当作会话离线。

浏览器回归同时挂起 IndexedDB 读取与写入，验证真实会话仍能显示网络返回的首屏。源码回归覆盖正文分块在磁盘挂起时首次读取及内存复用、内存版本增量和清理后迟到结果丢弃。回归用例还故意挂起持久化，分别验证后续在线校验、手机页面和已有缓存任务尚未完成时的最新展示；旧代码均出现阻塞，修改后通过。在线 Agent 用例同时验证可交互状态与提示一致。
