# Agent Note: 实时聊天展示与缓存持久化分离

Status: implemented

## 问题

其他 Agent 的在线同步结果无条件调用离线阅读器状态，产生“离线、只读”假提示，实际仍可交互。缓存验证还等待上次持久化完成；手机 recent 页面被排除在提前展示路径外，缓存慢写能阻塞实时结果显示。

## 决策

只在真实离线阅读模式显示离线提示；缓存预览仍不能授予交互能力。在线校验读取已提交的缓存状态，不等待先前持久化任务。

最新 recent 结果独立验证当前身份、作用域、代际、清理版本以及完整行版本后即可展示，缓存写入保持串行。不能可靠还原完整页面、发生删除或清理版本变化时不提前展示。最新服务端控制元数据继续覆盖展示缓存，不以缓存推断发送授权。

范围回填的缺失判断同时检查扁平原始行与折叠会话投影。仍存在的过程子行不会因被折叠而被删除；原始源与会话投影都已不存在的对象继续清理。浏览器回归定位到旧判断会误删已下载的末尾5条过程，导致再次展开重复传输。

原生发送成功回执文案表达会话已接收、等待显示；未知发送继续保持原请求身份与防重放规则。日志中最近发送请求约22至46毫秒，但不能据此证明用户报告的两端几十秒显示延迟已被完整定位。

## 备选方案

等待所有磁盘与原生归档写入能简化读后写顺序，却让缓存性能决定实时界面延迟。直接关闭缓存会丢失增量复用。跳过鉴权或清理校验虽然更快，却可能重新展示已清理的内容，因此只分离展示与持久化，并保留这些验证。

## 影响

持久化可能晚于可见页面，下一次读取可使用已提交的较旧版本并让服务端补齐差异。写操作不加入缓存请求合并，不因未知结果重试。缓存持续失败不应被当作会话离线。

回归用例故意挂起持久化，分别验证后续在线校验、手机页面和已有缓存任务尚未完成时的最新展示；旧代码均出现阻塞，修改后通过。在线 Agent 用例同时验证可交互状态与提示一致。
