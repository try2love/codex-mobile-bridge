# Agent Note: 原生连接独立准备与有界实时同步

Status: implemented

后续[普通 GUI 启动自动接入](../feature/2026-11-22-codex-ordinary-launch.md)为 macOS 初始化登记启动分派器，补齐普通打开原 App 时的环境缺口；本篇的执行归属、任务保护和恢复事务继续适用。

## 问题

[新版宿主接入](2026-11-21-hosted-codex-desktop.md)复用原 App 的 stdio 执行器，但连接准备错误复用了外部账号管理禁写检查，Magpie 用户因此被拒绝。准备成功后监视线程退出，后来普通启动的 App 或新出现的 hosted 端点不能自动恢复。最新回合全部消息项与逐增量快照复制还会拖慢原生输出，取消订阅也没有释放观察状态。

## 决策

连接准备独立于账号、供应商配置管理；保留原认证、provider、cwd 和执行 owner。UI 依赖已有 `canManageDesktop` 权限，HTTP 登录、CSRF 与无密码模式边界不变。账号写入继续受外部管理限制。

[启动准备](../feature/2026-11-12-native-runtime-startup-preparation.md)的单次准备事务保持不变，调度器在准备成功后继续每 30 秒检查。只有网关初次启动允许冷启动，后续监视只处理已经运行的 App，用户主动退出后不会被重新打开。共享 pending 回执、即时任务与进程身份核验、取消和未知启动不重放继续生效。普通启动缺少适配器且任务未知时仍需明确恢复，不隐式绕过任务保护。

已验证 hosted 端点出现或代次变化时，后台在操作门锁空闲时重建 follower；不会中断在途写入，不启动替代执行器，不重复发送。旧 IPC 继续使用原协议，选择依据运行中的端点与协议能力，不比较 App 版本号。

本地 Desktop 使用 hosted 端点时，先核验该线程是否由原生运行时加载，再订阅；负面的 Desktop 查找不会回退扫描旧 IPC。IDE 的旧 owner 查找仍保留。失败订阅和最后一个观察者离开只清理本地观察状态，不发送原生断线；真实的单聊天卸载只使对应聊天失效，不关闭其他聊天共用的 follower 套接字。已核验且未换代的 hosted 连接下，进入冷聊天或点击重建只重新寻找目标 owner 并按显式意图激活，不重置整个共享连接；旧路由替换和真实端点换代仍重建 transport。任务审计从原始端点重新选择路由，不把上次选中的 hosted 套接字当作旧版备用端点。

分页接入只读最新回合的最近 100 个消息项，其余历史沿用保存历史分页。实时状态最多保留两个回合，每个回合 100 项；截断标记为不完整，不能据此声称历史已读完。顺序增量在有界状态上应用，25 ms 合并发布；复制后的快照只由一个发布线程校验和发送，刷新也通过同一发布入口，避免旧快照晚于新状态发布。最后一个 follower 释放时清除观察状态，不卸载原生线程。

新版编辑操作读取并核验最近回合及原输入，再用原生 `thread/revert`（分页）或 `thread/rollback`（非分页）与 `turn/start` 完成。保留输入附件和文件提示包装。回退成功后的发送失败属于整个编辑结果未知，不能报成全部未发送或自动重放。回退中原生短暂 `notLoaded` 不关闭当前 follower，正常卸载仍使连接失效。追问使用已有输入转换保留图片和文件上下文。

## 展示时间与重试错误

自动重试通知中的错误会保留到原生回合结束。若每次投影都把它追加为整轮错误，即使已经继续输出，远程末尾仍反复出现“执行错误”。共享规范化仅在原生明确给出 `willRetry: true` 且回合仍为 `inProgress` 时，不投影该整轮失败提示；保留原始错误与重试证据，不触发额外发送或重试。终止失败、未声明重试的旧接口错误以及消息项中的工具错误继续展示。过滤在网关读取侧生效，无需重启已经运行的原生适配器。

历史索引的开始时间另按其原生秒单位转换，沿用[完成时间证据规则](2026-11-16-task-duration-disclosure.md)。缺失时间不补网页时钟，也不设置时长上限来掩盖单位错误。

## 验证

定向回归覆盖外部账号管理下的准备与配置不变、用户退出不重开、准备成功后继续观察、在途写入延后换路、长回合单页读取、慢发布不阻塞原生输出、多 follower 释放、有界状态、编辑身份变化及未知回执。原生隔离烟测使用安装的执行器和 loopback 模型，验证读取、发送、重连、编辑、中断和审批取消；另用 2 MiB 回复验证原有发送与中断路径。实际 Test 部署与目标会话验收证据保存在私有 `.local/installations/20261121-experience-fix/`，不提交聊天内容或安装包。

实际 8788 Test 网关最终复查的列表读取约 49 ms，已加载会话重连约 6 ms。原生 App 重启后首次打开未加载的长聊天约 5.9 s，保存历史与此过程并行；390 px 浏览器视口上翻成功，单次补页约 21 ms。普通发送的 HTTP 回执约 41 ms；编辑重发的 HTTP 回执约 190 ms，原生回复快照到网页 DOM 更新约 136 ms，编辑前历史仍可读取。新适配器下冷会话订阅失败不影响已有连接，连续 60 秒跨两个监视周期无断线，七页共 620 条不重复历史每页约 5–36 ms。模型生成用时独立于上述网关传输用时。窄屏 Chromium 不等于手机真机。

本轮部署发现，原位替换仍被原生适配器使用的 PyInstaller 可执行文件不能当作热更新：旧进程保留旧 PYZ 目录，后续按旧偏移读取新文件时会解压失败。最小只读复现使用旧目录读取新归档，`model`、`tool_images` 模块均失败；实际编辑请求因此断线，未自动重放。最终按既有授权正常重启原生 App，加载已安装的新适配器后编辑实测通过，认证与配置文件摘要不变。仅验证进程路径、PID 或代码签名不足以证明这种替换可用；后续部署不得复用本轮被否定的原位替换步骤。

随后补充的网关恢复修复使用另一个完整 Test 包启动同一数据目录的 8788 网关，原适配器所属的旧包原路径完整保留；只停止并启动网关和控制面板。三个真实已加载会话分别重建用时约 5–10 ms，其他会话均保持连接，日志没有共享 transport 断线。21 项恢复回归和 127 项 Bridge 回归（2 项跳过）通过，打包后的七个改动模块与工作区内容核对一致。这个私有部署方式允许本轮追加的网关改动生效，不再修改仍运行的适配器归档，不代表原位热替换已经获得支持。

展示修复的定向后端回归共 290 项，287 项通过、3 项平台跳过；23 项 Node 回归与模块边界检查通过。浏览器实际执行既有用时/阅读夹具共 109 项断言，并在 1280 px、390 px 分别回放 7 个后端投影快照，各通过 12 项断言，覆盖缺失与晚到时钟、连续重试后的输出、阅读位置和真实终止错误。8788 新 Test 包自动启动后，三条目标聊天保持连接，历史读取约 5–7 ms，错误的 1970 年日期恢复为原生日期；Codex、适配器与执行器 PID 不变，原适配器文件摘要不变，8787 保持原实例。重试故障使用合成通知，不人为中断真实模型服务；手机真机未验收。证据位于私有 `.local/installations/20261121-timing-retry-fix/`。

## 备选方案

每次刷新全量读取最容易保持单一快照，但长回合会阻塞接入，因此保存历史与实时窗口分别按既有职责读取。异步排队所有原生事件能缩短转发路径，却会让读取快照与已排队增量产生重复和先后歧义；当前只异步处理复制与发布，并限制同步状态规模。强制重启或设置全局启动环境能减少普通启动的准备步骤，但会改变系统配置或中断任务，不采用。

只在原生事件层收到新输出时清除重试错误可以缩短提示停留，但需要更新正在运行的适配器，且重试期间仍会把警告显示成终止失败，因此本次在只读投影中依据明确的重试标记处理。统一隐藏运行中的所有错误更简单，却会吞掉旧接口未声明重试的错误和工具失败，不采用。

## 影响

普通查看和实时追问不再随全部历史规模复制；发布增加至多约 25 ms 的合并等待。旧版 App 保留旧 IPC，未改认证、账号切换、文件边界或未确认写入规则。监视不能在任务状态未知时安全地改造已经启动的 App，故不能承诺任何启动方式都无需一次准备；未来协议变化仍需要核验，未以不写死版本号等同无限兼容。手机真机与其他系统实际包的验证不由 macOS 协议测试替代。
