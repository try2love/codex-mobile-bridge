# Agent Note: 中间过程元信息与顶部只读提示

Status: implemented

元信息展示范围、时间位置与缺失占位已由[模型回复元信息范围](2026-11-25-model-reply-metadata-scope.md)收窄；自动续读和顶部只读提示的决定继续有效。

## 问题

运行完毕后的中间答复和用户补充没有统一的时间、模型及思考强度；运行中的尾页也未进入展开过程的自动续读状态。原生缓存只读模式另外将黄色提示移入输入框并遮住原控件，用户无法判断聊天状态与输入区域的关系。

## 决策

历史投影保留各类过程的原生时间，模型与思考强度只使用消息自身或所在原生回合已记录的值。用户补充和 Agent 中间回复、思考与工具卡片共用元信息展示；缺失字段明确标注未记录，不使用当前全局配置或读取时刻补造历史。过程目录与 watch 的版本包含元信息，使晚到时间可以更新，正文内容版本保持独立，缓存正文无需重传。

运行中的过程自动进入展开态，先显示已读页，再沿有界游标补齐。已有缓存按稳定行身份复用；真正失败保留重试，切换、折叠或失效仍取消后续读取。该行为补全[展开过程自动读完](2026-11-23-expanded-process-and-attachment-labels.md)，前台恢复与计时继续沿用[来源校准与原生时钟](2026-11-24-live-chat-resume-and-clock.md)。

只读状态提示留在工作台“聊天”标签下方。输入框保留布局但禁用写操作，不移动提示覆盖输入框；联网恢复仍通过原有身份与请求代际核验。

## 备选方案

用当前模型及本次读取时间填空会把未记录的历史标成真实来源，因此保留缺失说明。扩大为单次全量过程请求会增加首屏和实时读取负担，继续逐页渐进展示。保留输入框黄色覆盖层节省顶部空间，却掩盖聊天状态与输入控件，采用独立顶部提示。

## 影响

长运行回合会自动产生更多有界读取，现有缓存减少重复正文传输。元信息增加每条过程的可辨识性，同时占用少量垂直空间；工具正文仍按需展开，不自动读取大型附件。共享渲染器使 Codex 和其他 Agent 复用同一展示，不改变发送、停止及审批权限。

## 验证

Timeline 与同步用例覆盖原生过程时间、用户补充、已记录模型、晚到元信息及正文复用。Chrome/WebKit 在宽屏和390px窄屏共12项通过，覆盖元信息、顶部只读提示、失效过程恢复，以及100条缓存跨新增过程自动补齐和阅读锚点保留。截图确认黄色提示位于聊天标签下、输入框仍可见。浏览器宿主模拟不替代 Android 或 iOS 真机验收。
