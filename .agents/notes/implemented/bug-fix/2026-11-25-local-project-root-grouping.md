# Agent Note: 缺少显式归属的会话按已登记项目根分组

Status: implemented

## 问题

Codex App 可以为会话保留项目工作目录，同时让 `threads.project_id` 为空。远程列表此前将这种本机会话放入「未归类」，而文件页仍按会话的 `cwd` 打开项目。

## 决策

列表先采用原生归属，尊重已确认的移出和显式无项目标记，再核对同一配置的旧成员关系。当这些信息都没有指定归属时，仅在工作目录完整匹配唯一的已登记项目根时显示项目名称。登记来源包括原生 `project_roots` 和 App 旧注册表的全部根。迁移映射在对应主机和 Codex 数据目录内将同一项目合并。

路径比较处理末尾分隔符与 Windows 常见等价写法。纯 `//` 前缀在 Windows 上按 UNC 比较，在 Mac/Linux 上保留 POSIX 大小写；显式反斜杠 UNC、扩展 UNC 和盘符仍按路径语法识别。SSH 在同一次列表读取中附带实际目标平台，归类后移除内部标记；没有目标平台的旧结果保留原精确字符串匹配，不能借用网关系统推断。列表结果只影响显示；文件页按原会话的工作目录授权，显式项目移动和移出仍使用[原生分类命令](../feature/2026-10-28-shared-session-menu.md)。

## 备选方案

仅展示数据库显式归属可以直接反映成员字段，却遗漏了桌面按登记根分组的会话。按父目录或文件夹名归组能覆盖更多会话，同时会把同名目录、子目录和多项目共用目录归错。写回推断出的项目 ID 则会永久改变用户在桌面端的归属。所有双斜杠都按 UNC 处理更简单，但会合并 POSIX 上大小写不同的目录；只看网关平台又会误判另一操作系统上的 SSH 会话。

## 影响

原生根匹配按已读取的列表页合并查询。目录未登记、匹配多个项目或已有移出记录时，列表继续显示「未归类」。用户可以通过原生项目操作明确归属。

## 验证

使用含多个根的 SQLite 夹具覆盖精确匹配、歧义、显式归属和移出。另行核对本机独立配置、Windows 路径等价形式及 SSH 迁移键。对用户报告的桌面会话只读重放后，列表显示与工作目录对应的项目，原始 `project_id` 仍为空。

双斜杠回归分别模拟 Mac、Linux 和 Windows，覆盖旧注册表与原生 SQLite 根匹配，并执行实际 SSH 源码载荷验证目标平台随同列表返回。Windows 网关连接 Linux 目标及反向组合分别核对，不修改原始 cwd；这些是隔离平台模拟，不代替远端实机验收。
