# Agent Note: 已读缓存不按全局固定容量互相淘汰

Status: implemented

## 问题

原有 32 MiB、256 页和单页 2 MiB 限制会让其他聊天及较大的已读页挤掉有效历史，重进时再次从网络加载。

## 决策

取消这三项持久缓存拒存或全局淘汰阈值。保留七天有效期、身份隔离、主动清除和系统配额失败的内存/网络兜底。传输分页与页面渲染窗口继续独立受控，取消存储阈值不意味着请求完整原生历史。

## 备选方案

仅提高全局上限改动更少，但总量到达新上限后仍会让不同聊天互相挤占，不能解决本次反馈。

## 影响与验证

浏览器回归场景改为超过旧总容量、页数和单页容量后仍保留有效页；原生缓存继续使用相同七天校验。磁盘不足时写失败不会清除已显示内容，也不会通过加载完整历史补偿。

本次选择性集成保留当前 Timeline 的 conversation-recent-v1 缓存槽及过程内存边界；旧分支的 loaded-history-cache 笔记依赖旧页持久化与完整已读范围保存，本次未移植，因此不恢复该笔记。当前对话缓存规则继续归[共享历史缓存](../../implemented/feature/2026-11-16-shared-history-cache.md)，过程读取归[对话与过程分层](../../implemented/feature/2026-11-17-lazy-conversation-projection.md)。

本次 266 项历史、Timeline 和共享桌面源码回归通过。已有 Google Chrome 与 WebKit 的宽窄视口共 8 组缓存浏览器检查通过，覆盖 17 个超过 2 MiB 的页累计超过 32 MiB、260 个其他会话页、身份隔离、七天过期、拒存/阻塞及跨页面清理竞态。锁定 Chromium 运行时本机缺失，使用已有 Chrome 完成对应场景，未安装新浏览器；没有编译 App 或连接真实客户端。
