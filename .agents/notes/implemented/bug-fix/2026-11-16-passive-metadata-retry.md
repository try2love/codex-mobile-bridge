# Agent Note: 元数据读取失败保留被动重连循环

Status: implemented

## 问题

真实网关日志显示 SSH 可用性预检之后，读取会话元数据仍可能失败。异常从 _load_session_origin 穿过 _attach，结束 _maintain 线程；后续网络恢复也不会恢复该线程的被动观察。

## 决策

_attach 在原有元数据读取边界捕获已有存储、传输及数据错误，写入当前会话错误并返回。失败不标记 origin_verified，不改变 origin/provider/cwd，不启动另一执行者。既有维护循环的重试预算保留，下一轮重新读取；其他会话仍能处理。

[维护异常隔离](2026-11-17-maintenance-error-isolation.md)另行覆盖单会话其他步骤和远端预检的异常；本篇的局部读取边界与错误语义保留。

## 备选方案

只给预检增加重试无法覆盖预检之后的断网。整个维护循环吞掉所有异常会掩盖编程错误和影响未知写入语义；因此仅处理被动元数据读取的已有失败类型。增加高频循环会放大断网请求，不采用。

## 影响

暂时不可读的会话仍报告原错误，不伪称已连接。恢复后可以继续核验原始来源，既有手动发送、授权和未知回执规则不变。该修复对应已观察到的 SSH 维护线程退出，不据此宣称本机所有只读情况均已解决。

## 测试

测试调用真实 _maintain、_attach 与 _load_session_origin，注入一次 SSH 读取失败；修复前在与日志相同的位置退出，修复后同轮处理另一会话、下一轮读取失败会话，保留 provider/cwd 且不调用原生激活请求。完整 IPC 定向回归 19 项通过（含真实隔离 Unix socket）；只读复审将 HEAD 旧函数放回内存重跑同一测试，再次复现原异常。未操作正在运行的 Mac App。
