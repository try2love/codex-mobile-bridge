# Agent Note: macOS 网关凭据跟随资料目录保存

Status: implemented

## 问题

用户反馈更新网关、尤其重新编译 Test App 后反复出现钥匙串授权，妨碍自动化。源码确认网关连接密码使用 Python keyring，ZCode 官方登录使用 Electron safeStorage；这两处均会依赖系统钥匙串。用户确认本次覆盖网关自身的全部凭据。

## 决策

macOS 将 SSH 密码、私钥口令、隧道令牌和 ZCode 官方登录保存在资料目录的私有加密容器。`.credential-vault/key` 是随机 256 位主密钥，目录权限为 0700，密钥与凭据文件为 0600；密钥不绑定应用包、签名或构建路径。同一资料目录由更新后的网关继续使用，正式与 Test 资料仍分别隔离。

密文采用 `CMB1 + 12 字节随机 nonce + AES-256-GCM 密文与 16 字节 tag`，用途作为附加认证数据，连接与官方登录不能互换。Python 复用现有桌面依赖已携带的 cryptography，Electron 使用 Node crypto。密钥完整写入后以独占硬链接发布，并发创建不能替换已有密钥。凭据更新保持原子替换；Python 同时核验读取时的密文、索引、密钥，ZCode 继续绑定 authGeneration、登录文件、链接文件及加解密所用密钥身份。

普通启动、状态刷新、自动连接和新格式恢复不查询旧钥匙串。连接管理提供“迁移旧连接凭据”，ZCode 提供“迁移旧登录”；只有明确触发才读取一次旧系统存储。重新填写连接凭据或重新登录也可保存到新容器。旧系统条目保留，ZCode 旧密文另存为加密备份；忘记官方登录会清除该登录及其备份，保留链接。没有读取或迁移用户本机的真实秘密。

[更新交接兼容](../bug-fix/2026-11-25-update-legacy-connection-startup.md)补充已验证 Mac 更新期间的暂缓行为：旧连接等待用户显式迁移，网关及可用连接先恢复，保存配置不变；普通启动仍保留原门禁。

缺失、截断、损坏或无法确认的本地密文/索引/密钥不会触发重新生成密钥或明文回退。第三方文件变化拒绝覆盖，未知迁移失败保留原文件和索引。迟到迁移不能删除较新的内存凭据；保存或清除成功移除迁移提示。

## 既有笔记审计

- [官方本机 RPC 与系统安全存储](2026-11-04-official-local-rpc-platforms.md)：部分替代其 Mac 存储决定；Windows DPAPI、Linux 真实密钥环、异步等待、代次与私有服务边界保留。
- [ZCode 连接选择与 API](../feature/2026-11-04-zcode-connection-choice-and-api.md)：部分替代 Mac 官方登录的 safeStorage 保存；独立链接和连接模式保持原契约。
- Claude 手动额度与 Antigravity 原生账户的受保护数据属于原客户端，手机绑定存储属于手机原生宿主；这些记录与本网关凭据存储不同，没有被本决定取代。

## 备选方案

稳定签名与钥匙串 ACL 可保留更强的同用户应用隔离，但本地 Test 重编译仍可能需要逐次授权，也依赖签名分发条件。按用户选择，采用独立于应用签名的资料目录密钥。明文 JSON 更简单，但会直接暴露单独备份的凭据文件，因此仍采用认证加密。自动首次迁移可减少手动点击，却会在更新后的启动中再次弹授权，改为明确入口。

## 影响

更新与重编译无需重新授予网关自己的钥匙串访问。密钥与密文须一起备份；能以同一系统用户权限读取整个资料目录的程序也能取得密钥，此方案不提供钥匙串的应用级隔离。原客户端账号、历史和手机绑定的归属不由本功能重定义。Windows/Linux 继续原系统存储策略。

## 验证

回归使用合成秘密，覆盖新实例恢复、零钥匙串调用、显式旧数据迁移、缺失与截断、篡改、权限与符号链接、并发保存、第三方密文/索引/密钥替换、真实主进程 IPC 分派及迟到结果。真实重签名包更新和用户旧凭据迁移尚未执行，不能由源码回归代替。

验证结果：62项相关后端通过；完整Node回归1809通过、1跳过。Electron 44.5.1两个独立进程的合成保存/恢复均为零钥匙串API调用，同profile密钥不变。Python/Node互操作检查通过。这些不是真实重签名升级或用户旧凭据迁移的验收。
