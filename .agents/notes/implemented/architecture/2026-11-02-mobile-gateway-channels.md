# Agent Note: 手机按网关绑定选择访问地址

Status: implemented

## 问题

同一网关有局域网和 HTTPS 地址。按地址保存时，用户离开 Wi-Fi 要退回电脑列表，通知也可能按两个地址重复出现。仅凭主机名合并，还可能把同一台 Mac 上的正式版和 Test 当成一个网关。

## 决策

手机按网关持久化的 cookie 命名空间识别实例。可信手机登录取得该实例允许的候选地址。首次绑定凭据留在系统凭据存储中，其他地址使用按目标派生的凭据。切换前以随机挑战证明对端属于原绑定，撤销原绑定同时使派生凭据失效。直接连接无需共享中继。

桌面概览和手机从同一函数取得固定地址、当前临时 HTTPS 和已绑定的局域网地址。手机只列出允许从手机访问的地址；回环入口仅供电脑自身使用。名称、别名和通知归属绑定到网关实例。DSH Mobile 继续通过原生独立入口进入。

网关发布按显示顺序排列的候选地址及 firstVerified 竞速策略。首页每个地址仅显示可达状态，进入电脑时同时显示耗时。对当前网络的身份验证最先成功即接入，不等慢线路超时。聊天列表左上角在原应用切换器中提供相同的地址与实测延迟；手动选择仍须验证指定来源。一台设备只有一个活动信道。活动页检查当前通道，网络稳定时不对全部地址持续测速。

旧绑定从已经验证的备用地址同步新清单。绑定新域名需要已认证会话、原 CSRF 和由手机根凭据导出的授权证明，限定实例、目标 URL 与新凭据摘要。旧版本配对可使用原始地址预登记的独立摘要升级。网关不把根登录凭据发送至其他地址。去除的临时域名不继续出现在清单中，撤销手机绑定会使整组授权失效。

活动聊天的页面来源与当前访问地址分开保存。网关提供一个只含静态空文档的顶层入口。只有手机在验证备用信道后，才为指定目标和一次性随机值创建辅助 WebView。辅助页在自己的来源下核验绑定和 CSRF，主页面核验窗口、来源、随机值和绑定，再使用消息端口按需读取 API 响应。凭据留在原生 Cookie 存储中。切换无需搬运聊天历史、草稿、上传字节或时间线 DOM。已发出的写入可以完成，换线本身不会重放它。

进入电脑时只对已启用地址竞速。连接后，网络变化首先验证当前信道，两次失败才进入断线状态。自动模式以退避间隔寻找可用入口，手动模式对当次断线提示一次。管理页只在保存时提交修改，选择随电脑绑定持久化。临时 HTTPS 以信道类型标识，换域名后继承开关。关闭全部信道后，下次点电脑进入管理页。

原生探测失败时，活动页面通过当前已登录的请求通道读取 `/api/auth`，仅在可信设备与当前 CSRF 均匹配时确认仍可达。核验限制在前台，最长 5 秒、正文最多 32 KiB；切换来源或登录后到达的旧结果不能恢复状态。手动刷新同时测量这条请求通道，显示真实往返延迟。备用地址仍须独立完成身份挑战，不能复用当前地址的成功结果。信道交接取消旧长轮询时直接重试读取，不显示断线；真实网络错误仍显示重新连接并重试。

## 备选方案

原先通过销毁 WebView 并在新页面恢复草稿和阅读锚点来换线。手机实测发现已上传附件的待发引用会被丢弃，聊天列表与历史也会重新加载。保留当前页面让四种 Agent 共用同一条切换路径。

按 IP 或电脑名称合并可减少改动，但正式版与 Test 可能共用这些信息。直接移动原 HTTPS cookie 实现较短，但会向局域网传递不受地址限制的凭据。继续要求共享中继能发现新域名，却不能覆盖只开启局域网和固定 HTTPS 的用户。

只延长原生探测超时不能覆盖原生网络栈与 WebView 走不同路径的情况。把任意 HTTP 200 当作恢复又可能误认登录页或其他服务，因此当前通道的补充核验必须匹配已经持有的认证上下文；它不改变首次连接与备用地址授权。

## 验证

8788 Test 正常重启后临时 HTTPS 域名确实发生变化。使用重启前配对的专用手机绑定，从固定 HTTPS 读到与网关同序的新地址，确认旧域名消失。使用 iOS 选路组件为新地址续授权，验证网关身份后从新临时 HTTPS 实际登录，得到同一绑定。Android 的三个隔离端点中，最快的错误身份被拒绝，首个有效结果在 199 ms 到达，而另一条有效线路用时 1075 ms。用例的延迟来自本机模拟端点，不代表公网性能。最终网关再次正常重启后，Android 原生选路组件也通过固定 HTTPS 完成新版绑定续期，并在新临时 HTTPS 上实际登录。

在 iOS 18.2 的实际 WKWebView 中，对独立绑定注入当前信道的探测失败。手动模式保留 LAN，自动模式接入真实固定 HTTPS。比较换线前后的 WebView、输入框、光标、滚动位置、时间线对象和待发上传 ID，并通过新信道完成一次二进制上传。LAN 恢复后公网连接保持稳定。独立实测还覆盖保存后仅用固定 HTTPS 首连，以及从 HTTPS 主页面打开局域网信道并读取已认证响应。Mac Test 重启后的新临时 HTTPS 使用原绑定验明身份并实际登录。Android 的 JVM 检查覆盖按电脑隔离、按地址排除和临时域名轮换，签名 APK 与 IPA 中的共享脚本已逐字节核对。运营商蜂窝和 Android 原生 WebView 的实机切换待验。

## 影响

补充核验通过 17 项信道与时间线回归、Chromium/WebKit 宽窄屏 4 项浏览器用例，覆盖原生探测失败但页面仍可用、刷新实际延迟、错误认证不恢复、后台过期回调、重复刷新合并和正文停滞超时。本机 8788/8796 的只读身份探测正常，Android 模拟器可以显示延迟；用户实际手机上三种提示同时出现的完整条件尚未复现，不能把这些逻辑回归当作其真机问题已解决的证据。

后续的[局域网优先规则](../feature/2026-11-02-prefer-lan-channel.md)取代了“局域网恢复后仍停留在健康 HTTPS”及公网之间自动故障转移的行为；设备绑定、首次竞速和原页面交接沿用本设计。

未提供绑定清单的旧网关和 DSH Mobile 继续走原入口。首次打开电脑仍需加载页面。处于活动聊天时，每次成功换线只重新建立到同一网关的请求通道，聊天继续使用已有游标读取后续内容。上传中断沿用原有上传 ID 和重试规则，已完成上传的附件继续留在输入框。
