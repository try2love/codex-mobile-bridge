# Agent Note: DSH 独立插件源码与网关内置副本的边界

Status: implemented

## 问题

用户要求独立仓库维护通用 DSH 插件。现有官方一键安装和手动导出共用 host 源码，直接移除文件会改变现有安装行为。

## 决策

独立仓库 `dsh-codex-mobile-bridge` 持有完整运行时、原许可、来源清单、回环协议测试与可复现包脚本。Bridge 保留当前内置副本，通过 `plugin-source.json` 固定独立仓库提交。检查脚本只读取明确指定本地仓库的固定 Git 对象，逐字节比较运行时和许可证，并比较包版本、核心版本与协议字段，不读取浮动工作区、不连接网络、不更新真实接入。

后续插件运行时修改在独立仓库完成后，同步到 Bridge 专题分支并更新固定提交。文档和仓库元信息可以各自维护；运行时变化必须一起审查。每次变更内置 host 时，同时保留已发布/已安装的上一版原始 LF/CRLF 哈希，供现有安装记录、路径与私有凭据共同核验；识别旧源码不等于自动覆盖或跳过运行中任务检查。用户随后明确批准公开独立插件源码，已创建并推送 `try2love/dsh-codex-mobile-bridge`，远程 main 与本地提交及文件清单已核对；未发布 npm 或可安装市场。原包作者与 `coding-mobile` MIT 许可保留，独立仓库初始导入不声称继承完整作者 Git 历史。

## 备选方案

立即删除内置副本能消除物理重复，但冻结分发和原生一键安装需要它，当前不迁移加载路径。仅复制一个独立目录更简单，但无法发现日后偏离，因此增加固定提交检查。

## 验证

独立仓库的插件回环测试与可复现打包测试通过。Bridge 检查覆盖正确固定提交、工作区变化不影响固定源、内置文件漂移和版本字段漂移。2026-11-04 从 Test 128.11 升级验收时，旧 revision 9 文件与 d75c61e 的打包源码字节一致，但新兼容表遗漏这份哈希而拒绝接入。补入经固定 Git 对象与真实安装文件双重核实的两种换行摘要，并验证识别过程不改配置、原凭据和源文件；未知源码仍拒绝。插件源码协议测试与此升级识别验证分别成立，不替代各平台真实安装验收。

## 影响

插件有独立维护入口，现有安装与导出不变；代价是维护者需要显式同步。公开独立源码的授权仅覆盖该仓库；npm、市场以及 Bridge 主仓库推送和版本发布仍未授权。
