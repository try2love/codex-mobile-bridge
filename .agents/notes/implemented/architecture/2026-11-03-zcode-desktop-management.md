# Agent Note: ZCode 的应用管理、手机访问和实时连接分别核验

Status: implemented

## 问题

预览版把 ZCode 的手机开关绑定到开发时保存的聊天和调试进程。用户在电脑端停用后从手机重新开启，网关会直接恢复那条聊天。普通启动的 App 没有对应端口，启动、接入和退出均无法从应用管理完成。

## 决策

共享发现流程按程序身份登记 macOS、Windows 和 Linux 桌面安装的 ZCode。启用操作对已运行的应用保持原进程，对未运行的应用执行普通系统启动。停用手机接入只撤销网关访问。查看应用状态、读取历史和账号额度都不应激活聊天。当前普通本机实例支持读取已保存的历史；只有实际接入已验证的执行连接，才允许启用实时控制。

“重试连接”取决于当前能否重新绑定原 App。能否连接取决于已核验的原进程、控制通道与原 App 握手声明的会话能力，不能从有聊天数据库推定。协议或本机进程身份不匹配时只展示只读历史；兼容的监听存在、原会话绑定失效时才提示重试。仅取得历史不能报告实时接入成功。

两个管理界面共用正常退出、强制退出和二次确认。正常退出前检查可核验的任务，有已知活动时阻止退出；无法取得任务证据时须单独接受中断风险。强制退出另行确认并重新核验程序、进程与系统用户。Windows 的关闭窗口默认隐藏到托盘，必须请求原托盘的退出操作并等待所选安装的进程退出。

保留已有显式原型配置的旧会话能力，普通启动不设置调试参数，不自动启用厂商远控。支持私有管道的网关首选由网关启动并接回原 App。已有普通进程需要初始化时，网关、手机与 Web 共用正常重启确认。兼容端口仍可单独选择，已知活动任务阻止正常重启，无法核对任务时需另行确认。旧配置可继续重连已有监听，但不会因此让网关打开新的端口。端口只绑定回环，同机其他进程可能访问；关闭设置即可停用兼容接入，已经启动的监听随原 App 正常退出关闭。切换已保存账号先停用手机访问并退出原 App；普通启动后无法经原控制连接核验身份时，禁止在运行中修改登录配置。

显式继续聊天时优先使用能核验原会话的原生连接；兼容连接只对已选择的安装启用。重连先确认新监听身份，再核对所选会话的本机索引与原 App 工作区以及新订阅，在此之前不沿用旧写权限。可从没有旧会话绑定的网关进程恢复，无须预先在电脑点开聊天。不为被动读历史打开聊天，亦不跨连接重放发送。

Windows 与 Linux 通过同一网关持有进程管理原 App 的匿名调试管道。Windows 只继承指定的两个句柄，通过拒绝远程客户端的本机命名管道与持有进程通信。Linux 传递描述符 3 和 4，通过内核提供对端凭据的本机 Unix socket 通信，使用已登录的图形桌面。两端都核对通信进程、所属网关资料目录、角色和原 App 身份后才执行白名单操作。宿主退出前保留管道，手机掉线不会关闭桌面任务。可选的 TCP 兼容连接限于实现了监听者身份核验的平台，Linux 不提供该选项。握手失败不转换成另一种传输重放命令。

## 备选方案

继续通过带调试参数的重启恢复聊天可调用原 App 的内部服务，但改变用户正常启动方式，升级后也可能丢失原执行上下文。官方远程控制可分享同一运行任务，但需要登录并经过外部配对中继，超出本机接入范围。Windows 的关闭窗口消息最简单，但用户启用关闭到托盘时进程仍在，不能据此报告退出成功。

## 影响

Mac 普通启动的 ZCode 3.17.2 可以开启并撤销手机访问，两次检查为同一主进程。独立签名的 AppKit 夹具验证了正常退出与强制退出，被选择的程序退出，原 ZCode 仍在。回归用例覆盖旧手机的停用语义、有活动任务时禁止正常退出、未知任务的二次确认和强制退出请求验证。Windows 笔记本上以普通方式启动独立空 profile 的 ZCode 3.17.1，系统报告托盘图标位于溢出区（实际 ID 为 3）。核对属于该主进程的“打开 ZCode”和“退出”后调用原生退出，助手报告命令已提交，独立进程检查确认原 PID 已退出。此次未启用调试端口，未发送模型消息，也未强制退出。

同一 Windows 验收机还验证了自动扫描能找到 F 盘的安装；强制退出使用独立构建的同名原生测试程序，选定目录的进程退出，另一目录的同名进程和网关观察进程继续运行。

Mac 上普通启动的 3.17.2 能通过原窗口核对会话身份。两个独立测试聊天（原聊天及其 Fork）的标题菜单分别复制出与 8788 返回值一致的会话 ID。前台停在 Fork 时，从侧栏原聊天的右键菜单复制 ID，得到的是该行的 ID，前台并未切换。原生菜单会写系统剪贴板。临时草稿只在 Fork 可见，切回后仍在，清空后发送按钮重新禁用。这个实验验证了显式操作时的目标定位与输入框归属；手机发送、桌面并发切换时的提交和回执仍未验证。

进一步在 3.17.2 普通 Mac 原进程做了并发切换检查。网关通过侧栏打开指定 Fork，再从标题菜单取得完整 ID，与本机任务索引一致；不必让用户先点开聊天。在 Fork 捕获标题、草稿框和发送按钮后，桌面切到原聊天，三个 AX 对象与新聊天对应对象都仍然相等。原 App 会复用这些控件；“ID 已检查”加“向旧按钮提交”不是面向该 ID 的操作。因此未向普通聊天按钮输入或派发消息。后续应检验 ZCode 自身按会话绑定的交互面板；本机选择成功不是手机收发成功。

随后在同一版本通过原 App 插件市场临时启用一个仅允许固定测试消息的本地会话面板。宿主根据工作区、原会话、插件及面板资源分配状态键。对照聊天返回自己的键且没有发送控件；Fork 的键与独立计算的值相同。安装前已打开的空闲 Fork 首次报告 `MCP App connection is unavailable`，只重载面板无效，重载该 Fork 的运行时后恢复。实际接入不能将这个动作无条件施加到正在执行的任务。

独立网关沿用现有的登录、会话和命令接口，以验收用传输连接该面板。发送触发了原 App 的确认框。网关通过会话详情呈现对应请求，再通过审批接口确认；测试期间没有人在电脑上点击“发送”。夹具只允许一个原会话、一条固定正文和一个在途请求，并校验原进程、插件来源与完整确认文本。原确认框没有对外请求 ID，对任意并行请求不能仅按正文匹配。审批完成后才出现新的原生用户记录，距最初提交约 134.5 秒；此前的 unknown 回执不足以确认失败，固定的 30 秒匹配窗口也不足以覆盖用户审批。应将原命令保留为待确认，确认后再跟踪原消息，不能重新提交。

原生用户记录确认模型为 GLM-5.3-Flash、思考档位为 low，随后助手回复固定标记。独立 HTTP 网关和已安装 8788 Test 的局域网、固定 HTTPS 入口读取到相同的一条原生用户消息和一条助手回复；对照聊天没有标记。验证覆盖本机原会话的定向发送与远程确认，不包含手机真机点击、任意文本、自动打开面板或常规 Test 的写入。测试后已卸载插件，移除临时市场及缓存并结束两个仅属于夹具的 stdio 服务。[ZCode 插件面板原会话绑定](https://github.com/zai-org/ZCode/blob/a60ba6a7e5a06742270ca605f5d2cc2766afa7e1/packages/ui/src/plugin-ui/adapters/pluginUiSessionBinding.ts)

在真实 Mac 锁屏中核验了兼容路径。ZCode 3.17.2 正常退出后，以仅监听回环的兼容方式启动；亮屏时取得原测试 Fork 的实时订阅，Mac 锁定后从新的无绑定管理实例重新连接。同一原账号、原工作区下，以 GLM-5.3-Flash / low 发出一条固定文字，原 App 返回 accepted，同一聊天读回了对应的用户消息与助手回复。发送前和收到回复后系统均报告已锁定。测试经过网关共享命令层，没有经手机点按，不覆盖睡眠或无调试端口的面板发送。Windows 的 3.17.2 未据此加入兼容名单。

[原型连接边界](2026-11-01-zcode-bundled-transport.md) 与 [保存历史的读取约束](../feature/2026-11-03-zcode-saved-history.md) 分别描述实时兼容连接和只读数据。


Mac Test 的无端口实现复用 [3.17.2 源码同步版本](https://github.com/zai-org/ZCode/commit/a9fe401eede6e6e5e01be9048679c206fe6f02d9) 的原桌面会话。上游在[窗口 Host 接入](https://github.com/zai-org/ZCode/blob/a9fe401eede6e6e5e01be9048679c206fe6f02d9/packages/desktop/src/main/webRemoteControlSharedHostAttachments.ts#L78-L110)中传递 MessagePort，并在[远控架构](https://github.com/zai-org/ZCode/blob/a9fe401eede6e6e5e01be9048679c206fe6f02d9/docs/web-remote-control/web-remote-control-architecture.md#L1-L11)中明确移除了旧窗口控制接口。Bridge 通过原桌面的匿名调试管道取得同一个 V4 服务，复用既有会话、项目和命令回执。网关自带的持管道进程在调用方断开后保留管道，直到原进程退出；重新接入需核验当前同资料目录的网关进程、签名和原 App 世代。[启动器打包与身份校验](2026-11-03-zcode-private-launcher-packaging.md)单独记录。

锁屏冷启动时，原 App 的项目服务可能早于聊天记录库就绪。实测出现过原生握手成功而只读 SQLite ATTACH 失败。显式继续聊天时以本机任务索引、原 App 项目树和最终订阅核对同一会话及工作区；已知项目不符仍拒绝。列表读取和缓存刷新不建立会话租约。

最终签名的 Mac Test 经已登录的局域网管理接口在锁屏时正常退出旧 ZCode，由默认入口无 TCP 调试端口冷启动同一安装。在原测试 Fork 接回 V4 实时订阅，返回相同会话 ID、原生快照、ready 和可发送权限；另一次独立 HTTPS 登录重新接续同一个 App 进程，结果一致。此次没有发送模型消息。测试保留了私有连接。本次成品证据不覆盖 Windows、整机睡眠或在途模型任务中重启网关。
