# Agent Note: ZCode 的应用管理、手机访问和实时连接分别核验

Status: implemented

## 问题

预览版把 ZCode 的手机开关绑定到开发时保存的聊天和调试进程。用户在电脑端停用后从手机重新开启，网关会直接恢复那条聊天。普通启动的 App 没有对应端口，启动、接入和退出均无法从应用管理完成。

## 决策

共享发现流程按程序身份登记 macOS 与 Windows 上的 ZCode。启用操作对已运行的应用保持原进程，对未运行的应用执行普通系统启动。停用手机接入只撤销网关访问。查看应用状态、读取历史和账号额度都不应激活聊天。当前普通本机实例支持读取已保存的历史；只有实际接入已验证的执行连接，才允许启用实时控制。

“重试连接”取决于当前能否重新绑定原 App。留有原型配置的电脑升级到 3.17.2 后，仍可能有聊天数据库，但 3.17.1 的适配器并不能用于新版。版本或本机监听身份不匹配时只展示只读历史；兼容的监听存在、原会话绑定失效时才提示重试。仅取得历史不能报告实时接入成功。

两个管理界面共用正常退出、强制退出和二次确认。正常退出前检查可核验的任务，有已知活动时阻止退出；无法取得任务证据时须单独接受中断风险。强制退出另行确认并重新核验程序、进程与系统用户。Windows 的关闭窗口默认隐藏到托盘，必须请求原托盘的退出操作并等待所选安装的进程退出。

保留已有显式原型配置的旧会话能力，普通启动不设置调试参数，不自动启用厂商远控。切换已保存账号先停用手机访问并退出原 App；普通启动后无法经原控制连接核验身份时，禁止在运行中修改登录配置。

## 备选方案

继续通过带调试参数的重启恢复聊天可调用原 App 的内部服务，但改变用户正常启动方式，升级后也可能丢失原执行上下文。官方远程控制可分享同一运行任务，但需要登录并经过外部配对中继，超出本机接入范围。Windows 的关闭窗口消息最简单，但用户启用关闭到托盘时进程仍在，不能据此报告退出成功。

## 影响

Mac 普通启动的 ZCode 3.17.2 可以开启并撤销手机访问，两次检查为同一主进程。独立签名的 AppKit 夹具验证了正常退出与强制退出，被选择的程序退出，原 ZCode 仍在。回归用例覆盖旧手机的停用语义、有活动任务时禁止正常退出、未知任务的二次确认和强制退出请求验证。Windows 笔记本上以普通方式启动独立空 profile 的 ZCode 3.17.1，系统报告托盘图标位于溢出区（实际 ID 为 3）。核对属于该主进程的“打开 ZCode”和“退出”后调用原生退出，助手报告命令已提交，独立进程检查确认原 PID 已退出。此次未启用调试端口，未发送模型消息，也未强制退出。

同一 Windows 验收机还验证了自动扫描能找到 F 盘的安装；强制退出使用独立构建的同名原生测试程序，选定目录的进程退出，另一目录的同名进程和网关观察进程继续运行。

Mac 上普通启动的 3.17.2 能通过原窗口核对会话身份。两个独立测试聊天（原聊天及其 Fork）的标题菜单分别复制出与 8788 返回值一致的会话 ID。前台停在 Fork 时，从侧栏原聊天的右键菜单复制 ID，得到的是该行的 ID，前台并未切换。原生菜单会写系统剪贴板。临时草稿只在 Fork 可见，切回后仍在，清空后发送按钮重新禁用。这个实验验证了显式操作时的目标定位与输入框归属；手机发送、桌面并发切换时的提交和回执仍未验证。

进一步在 3.17.2 普通 Mac 原进程做了并发切换检查。网关通过侧栏打开指定 Fork，再从标题菜单取得完整 ID，与本机任务索引一致；不必让用户先点开聊天。在 Fork 捕获标题、草稿框和发送按钮后，桌面切到原聊天，三个 AX 对象与新聊天对应对象都仍然相等。原 App 会复用这些控件；“ID 已检查”加“向旧按钮提交”不是面向该 ID 的操作。因此未向普通聊天按钮输入或派发消息。后续应检验 ZCode 自身按会话绑定的交互面板；本机选择成功不是手机收发成功。

随后在同一版本通过原 App 插件市场临时启用一个仅允许固定测试消息的本地会话面板。宿主根据工作区、原会话、插件及面板资源分配状态键。对照聊天返回自己的键且没有发送控件；Fork 的键与独立计算的值相同。安装前已打开的空闲 Fork 首次报告 `MCP App connection is unavailable`，只重载面板无效，重载该 Fork 的运行时后恢复。实际接入不能将这个动作无条件施加到正在执行的任务。

独立网关沿用现有的登录、会话和命令接口，以验收用传输连接该面板。发送触发了原 App 的确认框。网关通过会话详情呈现对应请求，再通过审批接口确认；测试期间没有人在电脑上点击“发送”。夹具只允许一个原会话、一条固定正文和一个在途请求，并校验原进程、插件来源与完整确认文本。原确认框没有对外请求 ID，对任意并行请求不能仅按正文匹配。审批完成后才出现新的原生用户记录，距最初提交约 134.5 秒；此前的 unknown 回执不足以确认失败，固定的 30 秒匹配窗口也不足以覆盖用户审批。应将原命令保留为待确认，确认后再跟踪原消息，不能重新提交。

原生用户记录确认模型为 GLM-5.3-Flash、思考档位为 low，随后助手回复固定标记。独立 HTTP 网关和已安装 8788 Test 的局域网、固定 HTTPS 入口读取到相同的一条原生用户消息和一条助手回复；对照聊天没有标记。验证覆盖本机原会话的定向发送与远程确认，不包含手机真机点击、任意文本、自动打开面板或常规 Test 的写入。测试后已卸载插件，移除临时市场及缓存并结束两个仅属于夹具的 stdio 服务。[ZCode 插件面板原会话绑定](https://github.com/zai-org/ZCode/blob/a60ba6a7e5a06742270ca605f5d2cc2766afa7e1/packages/ui/src/plugin-ui/adapters/pluginUiSessionBinding.ts)
