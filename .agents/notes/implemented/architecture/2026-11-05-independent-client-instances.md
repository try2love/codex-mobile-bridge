# Agent Note: 独立客户端实例与默认接入共存

Status: implemented

## 问题

“添加接入”当前只有 Codex 真正登记独立配置，其余选项跳回原管理页，且没有 ZCode。用户要求新增真正独立的配置、账号、会话，并与默认接入同时使用；核验原生限制后明确排除 ZCode 的第二套配置，保留它的默认接入。外壳已有实例 ID，但非 Codex 的业务仍把平台名当作唯一身份；只增加按钮或改名称会串账号、附件、草稿和进程控制。

## 决策

保留平台 family 与稳定 instance ID 两层身份。默认入口、旧 URL 和默认资料不变；新增入口经原生配置解析器验证后登记，未核验的原生能力不能显示已连接。共有的新增表单、管理子页、账号面板、模型选择器、会话视图、排序和通知复用既有实现。Claude、DSH 新增入口仅接入对应独立 Desktop，不借用默认 CLI、WSL 或 SSH 账号；Codex 的独立 IDE/CLI 入口沿用原合同。Linux Claude 的原生自动接入仍不支持，界面按能力禁用新增可运行配置。

统一解析 `family + entry` 得到该实例的 manager、附件存储、通知身份与原生启动范围。未提供 entry 的旧调用仍对应默认入口；显式未知、停用或 family 不符的 entry 必须拒绝，不得回落默认。异步响应、草稿和待发送操作捕获原实例身份，不在返回时借用当前选中的实例。

[上游 v2.2.0 集成](../process/2026-11-08-upstream-v2.2.0-integration.md)沿用本篇的实例身份与管理回调，只在云网页图标和管理入口外组合代理路径及本机云回调；云接入不重新按旧平台名称解析实例。

实例资料根与真实网关服务根分开：派生的管理器不能改写默认 bridge 的客户端/账号守卫。ZCode 仅保留默认实例，其原生私有管道及官方远控契约保持不变，不新增第二套认证或伪造子网关控制记录。上传、预览、发送与工作区查询从同一实例上下文取得存储，不能继续只按 family + session ID 查全局上传。

新增客户端的管理子页共用“移除此客户端配置”，只移除显式登记，不删除原生目录、应用、账号、聊天或网关收据，默认入口没有移除操作。先停用手机接入，再确认移除；同一实例的写入锁内检查网关持有的排队、未知结果、CLI 工作及终端，最多等待正在处理的操作 3 秒。Codex 已停用入口仍可能因账号管理生成只用于管理的 owner，因此不能只凭缓存中存在 owner 拒绝移除；检查工作状态后关闭该 owner 并淘汰缓存，再保存登记清单。原生 App 无需退出，其他实例不受影响。读取实例身份与建立 owner 在同一锁内，已移除的 entry（包括旧页面携带的 entry）继续拒绝，不回落默认配置。目录已移动或丢失也可以取消登记。

Codex 配置目录标注“.codex 文件夹”仅帮助定位，不限制目录名，已有 `.codex-xxx` 校验和隔离规则不变。账号管理的扫描结果增加“保存配置”：单个可导入结果直接选择，多个结果须明确选择；调用原有不透明 candidate ID 导入，API 仍进入现有模型选择与保存表单。修改扫描路径后旧选择立即失效，不把扫描到的目录写入默认 CODEX_HOME。

生命周期按原生 profile/userData/runtime home 证明精确进程和子树。相同可执行文件下的另一实例不能被视为本实例，也不能被退出、切账号或释放。Linux AppImage 的持久启动文件与已挂载的运行可执行文件分开；挂载路径不作为永久安装路径，多候选须按实例/PID选择或拒绝歧义。Claude Windows 还将进程级 APPDATA/LOCALAPPDATA 指到实例根，覆盖原生第三方模式的全局目录与旧目录迁移源；不改系统环境、HOME、USERPROFILE、默认登录资料或原 App 安装包。

Mac Claude 开启开发者模式时会由原 App 自行重启，启动回执中的旧 PID 因此失效。只有用户显式连接或初始化独立 Claude 时允许重新核验：旧 PID 确实不存在，当前只有一个属于该目录的原生主进程，应用通过 Apple 锚签名校验，内核用户、可执行文件、进程代际和完整 userData 参数一致，具名读取的 `CLAUDE_CONFIG_DIR` 也与该实例的注册根相同。目录身份、进程和启动回执在更新前再次核对；取消或并发变化不改回执。被动列表、自动恢复、退出与普通启动保持严格旧身份检查，Windows/Linux 未验证的重启路径不借用 Mac 规则。不启动替代进程、不终止旧进程、不只凭相同目录改写 PID。

## 原生目录边界

默认目录保护也覆盖原生运行时的所有已知账号目的地。Windows Claude 即使当前使用 Roaming 或 MSIX 官方资料目录，仍会读取 LOCALAPPDATA/Claude-3p，并可能迁移 APPDATA/Claude-3p；这两个精确目录与当前默认资料均禁止作为新增入口。保护不扩大到整个 AppData，同级真正独立的目录仍可登记。针对经典版与 Store 资料的目录冲突用例及同级允许用例通过，不依赖启动原 App。

DSH 需要同时隔离 DSH_HOME 与 Electron userData；同一个 DSH_HOME 下的两个 profile 并不隔离账号和历史。Claude 使用已核验的标准 userData 参数、CLAUDE_CONFIG_DIR 和第三方配置派生路径；不能绕过官方签名或把其他配对功能的限制误认为当前文件桥限制。ZCode 还读取真实用户目录的 bootstrap 和 MCP/技能/命令等全局配置，不能只看到环境变量存在就承诺完全隔离；用户选择不开放 ZCode 第二配置。验证只用临时空目录，默认客户端保留。Windows 假 API 实例发出过一次本机 POST，测试服务直接返回 403；没有请求真实上游或产生模型回复。

DSH 首次准备按原 App 能力处理：有 `./profile` 导出时，由原 App 已使用的 Electron-as-Node 运行其 `ensureDesktopProfile`，先生成原生清单，再安装连接插件，最后启动 GUI。Windows 验收中的原生程序把仅有 patch、没有 package.json 的目录视作不完整目录并移走，因此只预建 patch 无法接入。原生初始化不覆盖已有 patch；共用安装器把纯空 YAML 数组 `[]` 转成插件序列，保留注释和非空配置。缺少初始化能力时不启动一个注定无法接入的新实例，用户可选择已初始化的独立目录。此路径不依赖外装 Node，也不锁定版本号。

DSH 在 POSIX 上会自行从登录 Shell 恢复 API 环境变量，因此仅清理网关子进程环境不能证明独立账号。原生插件的 `account` 响应以兼容附加字段报告 `credentialSourcesVersion`、实际 `credentialSource` 和非秘密的 `credentialRef`；独立实例触发模型前必须匹配当前原生模型及 `file` 凭据来源。默认接入不新增这一限制。不会用 `DEEPSEEK_API_KEY` 文件存在推断自定义 ref，也不会读取或传回密钥。旧运行插件的哈希保留兼容，新增来源合同不迫使默认客户端重启。原 App 在网关之外自行使用 Shell 环境仍属于原生行为。

## 备选方案

只增加四个入口或把新名字绑定到旧 manager 最省改动，但不满足用户确认的独立性。复制四份管理/会话功能会继续分叉，因此采用共享上下文注入。直接多次构造现有 DesktopSessions 会覆盖根 bridge 的守卫并借用默认 CLI 账号，不能照搬。为规避原生限制修改安装包、复制默认凭据或放宽进程身份检查均不采用。

移除时递归删除目录能顺便清理空间，但会误删用户原生资料与待核对收据，故仅取消登记。要求先退出所有原 App 虽然容易判断安全，却把“移除网关配置”变成进程控制；实际只检查并释放网关持有的工作，不退出原 App。

## 影响与验证

本轮针对独立配置移除与扫描保存的源码回归：`tests.test_client_instances`、`tests.test_client_instance_runtime` 共 40 项通过；`tests/client-connections-ui.test.cjs`、`tests/accounts-ui.test.cjs` 共 134 项通过。覆盖已停用管理 owner、未知写入与终端阻断、默认/跨 family 拒绝、旧 entry 失效、原生和收据文件保留、扫描候选保存及 API 模型选择复用。全部使用隔离目录与模拟客户端，没有启动原 App 或调用模型；成品三端验收另行确认。

1. 默认 A 与独立 B 同时存在，A 的目录、账号与会话保持原归属。
2. 同目录、路径别名和同 inode 不重复登记；读取注册记录不会启动 App。
3. 相同原生 session ID 在不同实例中也不串会话、附件、模型缓存或草稿。
4. 新建项目/会话只归当前实例；未知写入不因切换实例而重放。
5. 只退出、重连、切账号或释放指定实例，其他实例的进程和任务不受影响。
6. 通知图标按 family，点击按完整实例身份路由；默认旧链接仍兼容。
7. 新增页面三端共用，选择文件夹、扫描、手填与错误提示行为一致。
8. Ubuntu 的 Test 更新须沿用旧 rc7 实际资料并修正用户级启动入口；安装/登录持久恢复与源码验证分别记录，构建成功不能替代安装验收。

Mac 已实际经 manager 登记、开启两套空 DSH，和原有 DSH 并存，读取各自连接与空任务状态，并逐一正常退出；原有 PID 和账号/patch/package 文件哈希、修改时间未变。父状态约 4.03 秒变为已连接。Mac Claude、Windows Claude 的官方空配置/API 空配置进程与资料目录隔离已验证；这不代表双账号 OAuth 和登录后的原会话收发已经验收。

Mac 独立 Claude 的真实登录已落到专用资料根，没有复制默认账号。用户观察到官方登录回调先进入原默认 API 实例，主动关闭原默认实例后才完成新实例登录；这是原 App 的全局协议回调限制，不是网关退出了默认 App，也尚未解决为双实例同时登录。随后用户开启开发者模式，原 App 自重启产生新 PID，暴露旧启动身份拒绝恢复的问题。定向测试覆盖显式入口、具名环境、签名、旧 PID 仍存在、目录/进程漂移、并发回执和取消；真实新包初始化及目录信任仍需分别验收，不把登录完成或源码回归等同完整会话收发通过。

Windows 的此前 DSH 验收通过 manager 完成两套空配置的原生握手、父状态同步、凭据来源合同及逐一正常退出。原有 DSH 的 PID、账号文件与修改时间不变，没有发送模型消息。首次开启到握手约 33–38 秒，正常退出约 17–22 秒；不能据此宣称快速启动。Ubuntu 仅安装 DSH Web CLI，且[上游桌面打包说明](https://github.com/deepseek-ai/deepseek-harness/blob/08afd883d7d792d8a4c98fa1ec6c6148d1478319/apps/desktop/packaging/README.md#L100)明确 Linux 不是 Desktop 发行目标，因此现有 Linux 路径契约与 POSIX 子进程证据不等于官方 Desktop 产品支持或双实例实机验收。当前用户暂停 Windows/Linux，Claude 原生自重启恢复只在 Mac 修复和验证；完整初始化仍需对应独立配置的开发者模式及必要目录信任。

共享回归覆盖相同原生会话 ID 下的草稿、晚到详情、附件、工作台、HTTP 读写和通知已读/历史隔离；Java/Swift 原生路由编译检查保留完整实例 host。桌面新增表单通过浏览器视觉检查：空错误容器不占高度，有错误内容仍显示。

## 限制

上游程序可能只部分支持资料重定位；未经原生实测不能开放控制能力。系统级资源和实例私有配置的边界必须明确，无法独立的项目需在实施前说明，不能暗中共享。原 App 多进程与 AppImage 挂载变化需要守住 PID/生命周期校验。真正跨平台和手机通知跳转应与模拟回归分别记录，源码检查不能替代实机结论。
