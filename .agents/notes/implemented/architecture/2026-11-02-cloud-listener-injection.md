# Agent Note: 云监听器由应用层组装

Status: implemented

## Problem

`cloud_connector` 导入 `bridge.api.httpd.GatewayServer` 违反 `implementation-upward` 依赖边界，用户要求修复。

## Decision

`bridge.app.cloud.create_cloud_server` 创建并配置云专用监听器，运行入口把惰性工厂传给 `Connector.start`。连接器先检查 `aiohttp` 和 `noise.connection`，再分配监听器；继续管理出站传输、证明/转发策略和监听线程生命周期，不导入 HTTP 或应用层，不扩大检查规则或依赖例外。

监听器仅绑定 `127.0.0.1` 随机端口，内存密码认证、会话、Cookie 命名空间和配对权限与直连隔离，即使直连免密也一样。业务服务与接入/终端限额保持同一实例；云监听器不拥有或关闭共享移动更新服务。工厂部分失败只关闭自己新建的 socket，不激活网关、编码客户端或会话，不增加凭据路径或写入重放。

云监听器的 `sessionHours` 为 0：内部 HTTP 会话由中继连接持有，不另设浏览器到期时间。Connector 每次转发仍核验当前账号、服务有效期、显式权限记录和手机公钥；权限关闭调用 `block_binding`，中继断开调用 `clear_authority`，令牌只在内存中存在。显式注销的内部会话继续拒绝访问，不因 `Auth.get` 返回空就自动补发。直连监听器沿用其原会话策略。

## Alternatives considered

最初的监听器注入没有保存独立备选方案。桌面审查发现，原 12 小时内部会话与 Connector 的连接级缓存生命周期不一致；下面只记录这次会话修复实际比较的方案。

- 保留 12 小时并在失败时重建会话，可以沿用浏览器默认值，但 `Auth.get` 同时会删除到期记录，其他新会话也会清理到期会话；简单重建无法可靠区分超时与明确撤销，还会在 HTTP 交接时增加轮换竞态。当前会话本就由独立连接拥有，因此选择连接生命周期，不新增恢复和请求重放分支。
- 伪造 `BridgeMobile/...` User-Agent 可触发已有移动端永久会话规则，但内部转发并非原生客户端，不应靠伪造客户端类型改变认证语义；使用云监听器的显式独立配置。

## Consequences

云响应发送结束仍等待手机关闭通道，避免尾部 credit 与桌面外层 Close 交错使成功列表读取被打断；收尾限制和三端验证见[云响应关闭顺序](../bug-fix/2026-11-04-cloud-response-peer-close.md)。

应用组装与传输职责分离，原有授权隔离和线程生命周期继续成立；运行入口需要提供工厂，相关失败必须在线程启动前处理。本篇取代[自动启用记录](../feature/2026-11-02-cloud-service-auto-enable.md)中的上层导入缺口，不改变其历史测试结果。持续连接不再被独立的 12 小时内部 Cookie 截断；代价是后续增加退出路径时必须继续清理连接所有的内存令牌，不能依赖浏览器超时兜底。[桌面审查收尾](../simplification/2026-11-04-prerelease-cloud-contract-cleanup.md#桌面审查收尾)记录同批兼容残留清理。

## Testing

2026-11-02 的合成测试覆盖工厂注入、依赖/工厂失败、服务与权限隔离及生命周期。回环 HTTP 检查直连 Cookie 拒绝、Host/Origin、CSRF、本地退出和关闭，不访问真实云账号或编码会话。模块边界沿用 22 条例外；52 项云 Python（含 8 项组装）、4 项边界、66 项网络/旧中继/资源和 26 项 Node UI/IPC/i18n 回归通过，无跳过，语法和空白检查通过。当次未重启真实应用、控制浏览器、构建或部署；运行中的网关需要操作者重启以加载修改。

2026-11-04 的 `test_cloud_session_lifetime.py` 使用真实回环 HTTP、生产 Connector/监听器/权限记录与合成密钥。6 个用例中，旧实现仅超过 12 小时的持续连接用例失败，其余权限保护通过；修复后 6 项全通过，覆盖 13 小时后的重复读取、明确注销不补发、关闭后重新授权、账号退出/服务到期/公钥变化拒绝、断连清理和未知 POST 不重放。测试推进独立进程内的时钟，没有修改系统时间、真实账号或运行网关。
