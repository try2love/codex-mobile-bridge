# Agent Note: macOS 正式包的 ZCode 本机连接与发布身份

Status: implemented

## 问题

[私有启动器](2026-11-03-zcode-private-launcher-packaging.md)原先仅装入固定开发证书签名的 Test。正式包采用 ad-hoc 签名，没有证书叶节点，原对端检查拒绝它；仅复制启动器不能使正式包连通。用户要求正式版也提供本机连接。

## 决策

正式包与采用 ad-hoc 签名的 Test 在 electron-builder 的 afterSign 阶段固定顺序：签网关二进制，按最终 CodeDirectory 摘要构建启动器，签启动器，用现有更新发布密钥签署组件清单，最后只重签外层 App。最后一步不使用 deep，防止已封存的嵌套摘要再次变化。钩子只接受正式和 Test 两个明确的产品标识；两者都不能跳过启动器与清单生成。

发布清单带独立用途、实际产品标识、版本以及网关和启动器的 SHA-256、各架构 CDHash。正式产品标识为 `io.github.try2love.codexmobilebridge`，Test 为其 `.test` 变体；清单产品必须与外层 App 相同，跨构建接续还必须与当前运行网关的产品相同。正式清单不能复制到 Test 使用。运行时使用冻结进程内的固定公钥，核验发布签名、实际组件与内核当前代码身份；不能从可替换文件加载信任根。没有匹配的发布密钥，两类 ad-hoc macOS 构建均明确失败，不静默产出缺少本机功能的包。

不同 ad-hoc 构建的指定要求不同，因此跨版本接续额外核验另一构建的发布清单与实时摘要。既有同用户 audit token、PID 世代、精确安装路径、同目录旧包、资料目录及 nonce 检查仍必须通过。发布身份不能单独授权任意同名进程。启动器仍独立核验当前包的精确网关摘要与原厂 ZCode 身份。

发布私钥只进入构建钩子进程，不传入编译、codesign 或 Python 子进程，不落盘也不随安装包分发。此机制证明组件来自本项目发布者，不代替 Apple Developer ID、公证或 Gatekeeper 信任。

## 验证

源码用例覆盖错误发布者、内容篡改、产品/版本/用途不符、符号链接和伪造摘要。原生启动器夹具覆盖 Test 与正式产品身份、复制网关冒充及替换二进制。真实冻结进程夹具使用临时发布密钥和实际生产构建钩子，验证同构建双向认证及旧持有者移至升级备份目录后与新摘要网关双向接续；该检查进入 macOS 两种架构的构建流程。夹具不访问真实账号、不连接 ZCode、不发送消息。发布产物另行校验清单、签名和实际连接，不能以夹具代替真实客户端验收。

2026-11-10 实际 Test `2.2.0-test.20261110.2` 缺少 starter 与清单，原因是 afterSign 将 Test appId 提前排除。新增回归先复现 Test 未打包、独立 Test 清单被运行时拒绝两个缺口，再验证修复。冻结 peer 验收现可选择 `--product test`，本机正式与 Test 均通过真实钩子、双向认证和不同构建接续；PyInstaller 使用每夹具独立缓存，避免并发写同一全局缓存。最终分发 Test 仍需检查独立清单、最终内核身份与实际 `supported()`；上述夹具不等同真实 ZCode 接入。

## 备选方案

Developer ID 可以直接提供稳定的 Apple 发行身份，但当前只有用于 Test 的 Apple Development 证书；本次不新增付费账号或导出私钥。只匹配 bundle ID 或用户可避免签名配置，却失去精确代码身份边界，不能采用。仅保留官方远控最省构建改动，但不满足用户明确要求的正式版本机连接。

## 影响

macOS 正式包具备与 Test 相同的本机启动入口，且能核验跨版本接续。正式构建需要现有发布密钥；公钥轮换需同步网关内嵌公钥与更新器。新增组件校验只属于 macOS 管道身份，不改变 Windows/Linux、原生会话控制、账号、绑定或草稿格式。
