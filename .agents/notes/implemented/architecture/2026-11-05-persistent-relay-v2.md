# Agent Note: 桌面持久加密中继与故障隔离

Status: implemented

## Problem

每请求通道及资格轮询使短时失败反复中断桌面共享连接。用户确认三端同步切换 v2，取消客户端资格自动查询并保留已有配对。

## Decision

桌面按绑定保持 Noise 会话，逻辑流有界并发，单一公平发送器在加密前调度；响应结束等待流级确认。继续通过私有 HTTP listener 和本地可信密钥授权。运行期只响应配置与本地许可变化；官方资格由服务器检查。令牌刷新以持久 request_id 恢复同一次结果。

## 记录归属

[原响应关闭决定](../../implemented/bug-fix/2026-11-04-cloud-response-peer-close.md)部分重叠，保留失败证据；v2 将等待关闭替换为流级确认。[监听器组装](../../implemented/architecture/2026-11-02-cloud-listener-injection.md)继续持有本地 HTTP 授权边界。协议规范及跨端验收由服务端同名持久中继笔记持有。

## Alternatives considered

只延长关闭等待能降低旧竞态概率，但每个请求仍重复建连；单请求串行长连接会被 SSE 阻塞，因此采用有界多路流。

## Testing

真实三端业务阶段 1800 秒、107648 次读取复用一个业务会话；独立 fault4 验证 SSE/通知/列表并发、20 MiB 下载和上传、心跳、Rust 自动重连、监听取消与未知写入只到本地夹具一次。满大小上传帧曾被 aiohttp 的排他上限拒绝；接收阈值改为 32819，解码器仍拒绝超过 32818 字节，真实 WebSocket 回归通过。带查询参数的通知路径白名单错误也有回归。

桌面云 Python 全套 89 项通过，另新增帧边界测试；53 项定向与资源、41 项 Node 和模块边界检查通过。运行时资格轮询及面板资格轮询均移除。完整三端证据与原始失败在 `D:/github/.codex-tools/relay-v2-20261105/`，生产加载单列交付结果。

20 路突发验证发现响应已完成、尾部 ACK 尚在途时会占满 8 个活动槽位。桌面现将已发送结束标记的流有界退役，后续 ACK 只解密并忽略；新增三批各 8 流、故意不 ACK 的回归，确认没有容量误拒且会话仍可心跳。`authfixed` 真实链路同时验证 20 路认证/快照/待核实查询和上传、断线恢复。

最终桌面云 Python 91 项通过，模块边界仍为原有 22 条例外；未增加反向依赖。核验 PID/instanceId 后通过管理入口重载本机网关，最终运行 PID 3952，Connector SHA256 `f2830bdad76b7f6fd0879078ebe59e6636a2851d3c750037264cc01449eaa0a1`，云状态 connected。账号、绑定、许可和设备证明文件哈希不变，没有重启编码客户端。手机实际只读刷新/恢复及后台测试通知均通过；完整进程与数据证据保存在同一任务目录。

## Consequences

复用减少重复握手和响应关闭竞态，局部流取消不再关闭绑定；代价是公平调度及流窗口需要三端共同维护。共享 TCP 故障仍使当前会话的在途流失败，未知写入继续核实。本地许可始终由桌面控制，云资格由服务器控制；缓存和开源客户端均不能授予官方云权限。
