# Agent Note: 桌面云服务只保留标准登录流程

Status: implemented

## Problem

官方换域时曾为已登录的旧官方账号增加专用入口和锁定表单。用户明确要求移除「重新登录」按钮；继续保留单独处理会让同一个云面板出现两套账号流程。

## Decision

桌面不识别旧官方域名，也不显示专用账号视图或锁定表单。当前账号使用普通账号视图和退出入口，只有未登录状态显示标准登录入口。官方预设仍为 `https://bridge.apijr.xyz`；已有会话不改写，令牌、密钥、手机配对和网页许可仍按精确 origin 隔离。标准登录仍核对回执和当前账号、网关，迟到的回执不覆盖其他作用域，失败不自动重放。

## Existing decisions reviewed

- 上一版专用入口已撤回，实际安装和隔离测试作为历史保留，未以真实账号或手机验证旧入口切换。
- [官方默认值](../feature/2026-11-01-official-cloud-default.md)、[登录表单](../feature/2026-11-01-cloud-login-dialog.md)与[网页地址](../feature/2026-11-11-sponsor-dialog-and-web-address.md)部分重叠；保留其预设、表单和读取边界。
- 赞助、邮箱验证、云服务启用和本地签名流程不变；其他账号重登记录与本次云面板无关。

## Alternatives considered

- 给旧入口换回普通登录文案可以保留少一步的迁移路径，但并未删除用户拒绝的专用操作。
- 自动退出或改写旧地址不用增加按钮，但打开应用不应清除当前账号或等待旧站撤销会话；改写地址也不能让旧凭据和授权跨域。

## Testing

- 桌面 Node 回归通过 1,881 项、跳过 1 项；Chromium 和 WebKit 宽窄视口共 188 项通过，覆盖已登录状态没有专用按钮、旧站离线时本地退出，以及普通表单向新官方入口提交。
- 签名 Mac 包在隔离的旧账号资料中只有普通账号视图，未写配置。原签名覆盖本机只重启界面；网关 PID、资料摘要、新域账号和隧道状态均保留。构建及安装证据在 `.tmp/desktop-cloud-standard-signin-20261125/`。

## Consequences

桌面只有一套登录流程，不需要维护旧域例外。仍在旧域的用户须使用原有退出入口，再在标准登录表单选择官方服务。已经登录新地址或自建服务的用户不受影响。
