# Agent Note: 恢复逐条中间过程展示

Status: implemented

## 问题

整轮、连续活动批次及过程目录三种展示同时存在，过程摘要字段与原生详情读取边界尚未统一，运行中回看及完成态排布无法满足实际使用。用户明确要求回退到 v2.2.1 及此前的非分组版本。

## 决策

主聊天恢复普通 `timeline/changes/detail` 分页读取，不再请求 `conversation/process` 聚合。其他 Agent 恢复原生 `detail` 与历史游标，不再经共享过程投影。用户、思考、工具、助理进度和最终回答保持原始顺序，全部作为独立行。取消完成时整轮自动折叠、批次摘要、生成的折叠耗时入口及专用目录加载。v2.2.1 已有的单条长输出详情与分页继续使用，已展开单条的阅读位置在更新后保留。

缓存使用 `timeline-recent-v1`，隔离先前的 `conversation-recent-v1` 过程页；缓存仍只用于展示，原生操作仍依赖新鲜会话状态。服务端旧聚合端点保留给旧客户端，当前 UI 不再调用，不把兼容端点保留描述为仍使用折叠。

本决定取代[整轮过程折叠](../bug-fix/2026-11-19-native-turn-process-disclosure.md)、[共享活动分组](../feature/2026-11-16-shared-activity-groups.md)的外层/批次展示及[过程投影](../feature/2026-11-17-lazy-conversation-projection.md)的当前 UI 读取方式。原有只读不激活、作用域身份、未知写入不重放和有界历史读取约束继续有效。

## 备选方案

只删除摘要或默认展开所有折叠可以少改控件，但仍保留过程目录的数据转换与多层分页，无法恢复用户指定的旧行为。照搬分享的 Flutter 控件能简化外观，却仍按助理正文拆组、缺少原生获取链路且不满足本次回退目标。因此恢复既有逐条路径，不引入替代折叠方案。

## 影响

加载的工具条目逐条进入消息区，长任务较聚合页占更多纵向空间；历史仍以既有条数与字节预算读取，超长输出按单条展开，不改为全量预取。审批、编辑、复制、引用及原 owner/provider/auth/cwd 不因展示回退改变。当前单条详情展开是 v2.2.1 原有能力，与被撤销的整轮和批次折叠不同。

## 验证

新增用例先复现普通时间线、原生详情路由及无分组失败，再验证恢复后的行为。浏览器用生产渲染器与合成数据覆盖 Codex、Claude、DSH、ZCode 和 Antigravity，检查逐条顺序、用户补充、最终回答、显示偏好、完成时不强制收起单条，以及历史补页时阅读位置保留。实际结果见本轮项目 .tmp 日志，源码测试不代替真机结果。

本轮实测：Node 前端 1,713 项（1,712 通过、1 项平台跳过），Timeline Python 29 项通过；Chromium/WebKit 宽窄屏 12 项通过。五类 Agent 逐条渲染、完成态、显示偏好、历史分页与阅读位置均通过隔离浏览器检查。
