# Agent Note: 未上线云流程只保留自动目录和显式连接权限

Status: implemented

## Problem

App 架构省察后的修复仍留下桌面手动候选、批准、拒绝和撤销入口，以及 Server 的旧配对表和升级迁移。两套流程对关闭和密钥的处理不同。用户要求连同桌面一起清理，并明确尚未上线，旧数据库和已有绑定数据无需保留；继续维护旧格式会让已经移除的行为重新进入授权链路。

## Decision

三端统一采用同账号自动目录、独立加密证明和桌面带 revision 的连接开关。删除手动云配对的 IPC、HTTP、存储方法和测试夹具；PostgreSQL 从 `001_current.sql` 初始化，App SQLite 直接创建当前连接表，不提供旧配对或旧库迁移。桌面缺少显式 access 记录时拒绝业务访问，可信公钥本身不授予连接权限。App 只接受当前绑定格式，不读取旧手动请求字段。

邮箱注册只保留“验证码 → 短期注册证明 → 设置密码并创建账号”。旧 `verification/verify-code` IPC/HTTP、预建未验证账号、旧验证码表和激活旧密码的分支一起删除；任何已有账号都不能被注册流程覆盖。重置密码和 selfhost 管理员创建账号继续走各自入口。旧开发数据库明确拒绝启动，不自动改写或清空。

桌面删除没有当前手机调用方的 direct U-Push 注册、ACK、租约与供应商签名发送实现及专属测试、文档；U-Push 属于当前云服务器的推送通路。直连 APNs、FCM、Live Activities 仍使用原协议，未知保存类型被丢弃并在发送入口拒绝，不回退为 APNs。云通知 SQLite 只保留当前表定义和当前版本重启语义，不再为旧开发表补字段。已退役的云配对/注册界面删除 50 条无调用翻译、4 条 CSS 规则、无调用身份格式化函数和旧错误别名，当前协议拒绝提示继续保留。

新流程仍保留首次安全码核对、账号与 origin 隔离、关闭优先的并发栅栏和未知写入不重放。当前版本正常关闭后恢复连接继续保留本版本的已验证密钥。直连扫码登录、加密协议内的证明消息和永久设备撤销各有用途，不能根据名称含 pairing 或 revoke 就一并删除。

本轮只修改源码和本地合成夹具；数据库初始化使用独立回环测试实例，不对任何部署数据库或真实设备执行清理。

## 记录归属

- [原保留历史兼容提案](../../rejected/simplification/2026-11-04-retire-manual-cloud-pairing.md)因数据保留前提被用户撤销而 rejected，独特的保留理由留在原篇。
- [同账号目录](../../implemented/feature/2026-11-03-account-device-auto-discovery.md)部分重叠，继续持有自动发现、可逆开关和证明恢复；本篇取代其旧绑定迁移要求。
- [桌面手动批准](../../implemented/feature/2026-11-03-desktop-approved-cloud-pairing.md)部分重叠，保留加密证明、安全码与未知写入约束，手动请求和旧表由本篇取代。
- App 的云状态修复与 Server 的推送撤回笔记继续持有各自权限边界，本篇只收敛旧入口和数据格式。
- 邮箱优先注册与验证码笔记部分重叠，保留邮箱所有权、短期证明、过期和不重放的理由，旧激活及旧数据迁移由本篇取代并互链。
- 检索命中的云退出、监听器组装、依赖、默认服务和开发重载笔记继续持有各自决定；其他 provider 与直连配对无关。三项门禁发现 14 篇既有云笔记缺失标准头块/必备节，本批仅规范化其格式与中文正文、保留日期、原理由和历史验证结果，不改写旧失败为通过，也不编造备选方案。

## Alternatives considered

- 只删除界面而保留旧 IPC、HTTP 与升级迁移，可以支持已有客户端和数据库；用户明确无需这层兼容，而且隐蔽旧入口仍扩大授权面，因此协同删除。
- 连加密证明、可信密钥及关闭后的恢复一起删除，可以进一步减少状态；这些是现行信任校验和可逆开关的必要行为，删除会让账号目录直接变成授权来源，因此保留。
- 保留 direct U-Push 可为未来独立直连推送预留协议，但当前手机没有调用方，且其绑定、ACK 和载荷与云推送不兼容；未经交付的预留能力不值得继续维护。删除这套分支时保留通用参数校验，未知供应商严格拒绝，不为旧记录增加迁移。

## Consequences

云注册与授权的执行入口和保存格式明确，旧密码激活与缺权限记录默认放行的路径被移除。代价是旧开发数据库与旧云绑定需重新建立，三端源码和生成 FFI 必须一起使用；这不是升级兼容方案。当前版本内的未知写入和关闭后恢复仍保留，编译与合成测试不能证明 iOS 签名、真实账号操作或厂商推送送达。未来首次需要保留发布数据时，应另立升级契约，不能恢复隐式默认放行。
