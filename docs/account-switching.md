# 账号与接入

v1.3.0 提供多账号与 API 接入管理。账号添加仅在 Bridge 桌面端进行，已保存接入可在桌面端和 Web 切换。

## 添加与管理

启动 Bridge 网关，在 **Bridge 桌面端 → 账号与接入** 操作：

- **官方 ChatGPT 账号**：填写名称，继续后点击“打开官方登录”，在此电脑的浏览器完成授权。添加过程使用独立登录目录，不替换当前 Codex 认证。支持取消登录、重命名和重新登录。
- **自定义 API**：填写名称、API 地址、API Key 和默认模型。服务需要兼容 Responses API。远程地址使用 HTTPS，本机服务可以使用 HTTP。修改已有 API 时，密钥留空表示保留原密钥。
- 当前接入不能直接删除、修改或重新登录，先切到另一个接入再操作。
- 网页没有添加、修改、删除或恢复接口。登录链接也不发送给网页。

### 扫描已有配置

展开 **扫描本机配置**，留空使用运行配置中选定的 Codex 数据目录，也可以填写其他 Codex 配置目录。点击“扫描配置”后，选择要导入的官方账号或 API。扫描和导入不切换当前账号、不重启 Codex；导入后仍需显式选择切换。

扫描识别 `auth.json` 中的官方登录、原生 API Key，以及 `config.toml` 的 `model_providers` 和 `profiles`。API 密钥可来自直接保存的 bearer token 或 Bridge 进程已有的环境变量；缺少密钥、非 Responses 协议及额外请求头/认证配置会显示不可导入原因，避免导入不完整的接入。系统凭据库中的官方登录不直接复制，使用“官方 ChatGPT 账号”重新授权添加。重复导入相同账号/接入不会重复创建。若导入的接入就是当前接入，会自动标记并禁用切换按钮，无需再次切换。

API 配置选择后填入添加表单，保存的密钥不显示；可获取上游模型或手填模型，再点击“继续”完成导入。如果扫描后修改了源配置，请重新扫描。

### 从上游获取模型

在自定义 API 表单填写 API 地址和 Key，点击 **获取上游模型**，然后从列表选择默认模型。已有 API 修改时密钥留空可使用已保存密钥；扫描出的 API 使用后端暂存的凭据，无需把 Key 填回界面。

此操作只在手动点击时请求该 API 地址下的 `GET /models`，不发送推理请求，也不自动跟随重定向。上游不支持列表、拒绝访问或返回空列表时会显示原因，仍可手动填写模型。列表中的模型未必支持 Responses API，需要用实际对话验证。扫描、导入和填写任意地址的模型查询仅在桌面端提供；Web 可查看已保存接入的模型。

网页进入聊天后，模型选择器按当前接入读取上游 `GET /models`，与账号面板共用模型来源；API 接入不使用官方 GPT 目录。旧模型不在上游列表时会提示重新选择，点击“应用”后才修改聊天模型；读取列表本身不更改聊天设置。查询失败时显示原因，并保留手动填写模型 ID。官方账号继续使用原生模型目录，SSH 聊天在对应主机查询。

### 当前接入、额度与模型

两端会识别当前 Codex 的有效接入，并在匹配的账号旁显示不可点击的“当前接入”。尚未保存的接入会单独标明；识别失败时显示暂未识别，不沿用旧账号标记。

桌面与 Web 均将当前接入置顶，并禁用其切换按钮。官方账号名称旁显示紧凑的剩余额度进度条与重置卡数量；API 接入不显示官方额度。各账号均可展开“查看可用模型”。

首次打开账号页面会自动查询官方账号额度，无需点击；后续在页面可见时每五分钟更新。手动点击“查看剩余额度”立即查询，并从本次查询完成后重新计时五分钟。离开页面或隐藏网页后停止查询，后台账号列表读取不触发首次额度查询。桌面与 Web 自动查询共用后端五分钟缓存。额度查询与使用重置卡是不同操作。

Web 侧栏只有一个固定位置入口：官方登录显示“账号与额度”，API 显示“API 接入”，均打开账号列表；当前官方账号的重置卡详情也在同一面板内。

桌面端原“账户与额度”已并入“账号与接入”。当前官方账号的完整额度恢复时间和重置卡操作保留在折叠的“当前账号 · 重置卡与额度详情”中。v2 预览版允许为每个已保存的官方账号手动使用重置卡，无需切换当前接入，也不依赖 Desktop 的代理用量重置开关；须核对账号与到期时间，等待五秒后确认。

首次使用请在“桌面程序与恢复”点击 **扫描桌面程序**，自动识别并保存 Codex / ChatGPT 桌面程序。macOS 也可直接填写 `.app` 应用程序包路径，Bridge 会根据 `Info.plist` 解析其 `Contents/MacOS` 内的实际程序；无需手动深入应用包。内置 Codex CLI 与 shell 启动脚本不能作为桌面程序。Windows 和 Ubuntu 的非标准安装仍可能需要手动指定。

## 切换

桌面端可直接选择账号；Web 首页通过“账号与接入”选择已保存账号。两端切换的是此电脑同一份认证与默认提供商配置。

切换前结束所有桌面任务，包括没有在网页显示的任务；清理排队消息和未确认的发送。确认后会依次准备配置、退出官方桌面应用、应用接入、启动并核验。Bridge 网关保持运行，切换期间暂停聊天写操作、排队发送和主动激活。免密访问模式不能从网页切换账号。

阻止切换时会列出运行中、待确认、排队或发送结果未确认的聊天。已断开的旧状态和连接错误本身不会被当成运行任务；这不代表能检测到所有未接入网关的桌面任务，仍须在确认前检查桌面。

- **官方 A → 官方 B**：保留聊天历史，下一次消息使用重新启动后的认证。账号所属工作区和权限仍以官方运行时为准。
- **切换后继续旧聊天**：切换只替换账号认证和接入配置，不扫描聊天历史、不批量恢复聊天或访问其项目目录。继续聊天仍通过原 Desktop 的会话入口发送；网关管理的 API 接入同时更新 `bridge_api` 和 `openai_base_url` 兼容路径。
- **模型与推理强度**：模型窗口与账号“查看可用模型”使用当前接入的同一上游和缓存，支持“从上游刷新可用模型”，请求失败不回退为 GPT 列表。切换不批量改写历史聊天的模型；需要更换模型时，在模型窗口选择并由原 Desktop 应用到当前聊天。官方推理强度按模型能力列表匹配，API 未提供能力元数据时保留手动选择。
- **回复标签**：每轮助手回复显示该轮模型与推理强度。保存的 `turn_context` 优先于 Desktop 加载历史时补入的当前模型；缺失元数据的旧回复不猜测标签。
- **API → 官方**：清除 API 地址、密钥覆盖与 `openai_base_url`，恢复官方认证及默认 `openai` 提供商。历史聊天使用的 `bridge_api` 名称保留为官方认证兼容配置，由原 Desktop 在打开该聊天时使用，不批量加载或修改历史。已有 `forced_login_method` 会同步调整为目标登录方式。

如果配置启用了不能安全覆盖的 profile 或组织策略，切换会失败，需先在官方桌面端解决配置限制。macOS 首次退出应用可能需要系统允许自动化控制；桌面应用通过 LaunchServices 重新打开。Ubuntu 应在已登录的图形桌面会话中启动 Bridge。

启动网关和切换账号不再主动检查或申请文稿目录权限。用户主动打开项目文件树、预览或下载附件等既有文件功能仍可能访问对应文件，不能将取消启动探测理解为所有文件功能均不需要系统授权。

## 失败与恢复

切换前保存配置与认证快照。目标账号或桌面连接核验失败时，尝试恢复原配置、认证并重启，不读取或恢复旧聊天。自动恢复失败或进程中断时，聊天操作保持暂停；在 Bridge 桌面端选择“桌面程序与恢复 → 恢复原接入”。不要在恢复期间同时手动编辑认证文件。

兼容旧预览版：如果 r8/r9 在聊天迁移中断，仍保留其恢复记录；只有用户明确执行“恢复原接入”时，才恢复该记录中已迁移的聊天。新切换不产生此类记录，也不会自动触发旧聊天恢复。

“切换完成”表示新的本地认证、有效提供商配置和桌面 IPC 已核验；没有为此自动发送付费模型请求。真实模型响应仍需用户自行测试。

## 数据保存

账号档案位于 Bridge 数据目录的 `accounts/`，使用 Codex 原生文件认证格式。目录和文件限制本机文件访问权限；不是额外的加密保险库。OAuth 令牌、API Key 和恢复快照不会返回 Web、写入命令行参数或显示在界面中。请不要共享或提交这个目录。

当前 Codex 数据目录保持不变，仅替换 `config.toml` 和 `auth.json`；聊天数据库、历史、项目和 Skills 不搬迁。配置由官方运行时的配置接口生成。官方账号离开前保存已刷新且身份匹配的凭据。

## 本轮验证范围

已覆盖模拟切换、回滚、中断恢复、登录完成与取消、重复请求、任务/队列阻塞、HTTP 权限边界和界面竞态。r10 回归另行检查普通切换及失败回滚不列举聊天、不读取历史、不请求模型列表、不启动聊天恢复运行时。

已用桌面内置 Codex 0.160.0、合成凭据和本地模拟上游验证 API 登录、新聊天、`openai` 与 `bridge_api` 旧聊天的实际 `/responses` 地址及 Bearer 认证。仅修改认证与配置后，旧聊天在正常打开及发送时使用新 API 地址和密钥，准备配置期间历史文件保持不变。真实官方账号 A/B 切换、真实第三方 API、重置卡消费，以及 Windows / Ubuntu 真机的退出启动与系统权限，仍需用户测试；不能将模拟测试或 macOS 打包通过视为三平台实机通过。

官方兼容配置另以合成 ChatGPT 凭据和本机 TLS 模拟服务验证：实际 `Accounts.prepare()` 写入后，旧 `bridge_api` 聊天无需提供商覆盖即可恢复，请求使用与内置 `openai` 相同的官方路径、账号认证、模型和推理强度。切换准备不发聊天或推理请求，历史与测试项目文件保持不变。证书仅对该测试进程生效，请求不转发到真实上游；这不代表验证了真实 OAuth 凭据或原 Desktop 界面操作。

当前账号按钮保持禁用；升级无需为了批量迁移聊天而来回切换账号。

## Computer use 授权

Web 根据桌面请求实际支持的范围显示“始终允许”“拒绝”“允许此对话”，以原生 MCP elicitation 的 `_meta.persist` 回传。后端对照仍待处理的原请求校验范围；普通表单不能附带持续授权，已过期请求不能再次授权。允许本次不会被静默扩大为持续授权。

本地 r8 验证：原生运行时使用合成凭据向 localhost 模拟上游发送迁移前后两轮请求，确认同一线程由旧 endpoint/model 切到新 endpoint/model，保留 cwd、权限与旧轮标签；迁移本身（含带 active goal 的线程）未发送推理请求。真实 Desktop 账号切换、第三方模型回复及 macOS TCC 弹窗尚待实际评测。
