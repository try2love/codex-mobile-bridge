# 自建中继（v2 内测）

一台公网服务器可以为多位用户转发连接。每位用户安装自己的电脑网关，继续使用自己电脑上的 Codex、模型账号与项目。

```text
手机 A → 共享 HTTPS 入口 → A 的出站连接 → A 的电脑网关 → A 的 Codex
手机 B → 共享 HTTPS 入口 → B 的出站连接 → B 的电脑网关 → B 的 Codex
```

**中继服务器不需要 GUI、显示器、Electron 或 Codex，也不需要模型 API Key。** 它可以运行在只有 SSH 的 Linux 云服务器上。任务仍在用户电脑或其既有 SSH 项目主机执行；电脑、Codex 与网关需保持在线。

当前开发版可在 **网络访问 → 自建中继 · 内测** 配置自己的服务器，默认未注册、不启用。旧版本安装包可能隐藏或不包含该入口；本文对应当前源码。它不是由项目方托管的公共服务。

## 选择 SSH 固定入口还是自建中继

- 单人使用、希望沿用全部直连功能：可优先选择[固定域名 · 自有服务器 + SSH](server-ssh.md)。不需要部署中继应用，公网服务器提供 HTTPS 并接收电脑的 SSH 反向连接。
- 多台电脑或多位用户共用入口、需要邀请码与设备管理：部署本中继，电脑通过出站 WSS 连接服务器。

两条路径均可完全绕开 Cloudflare Tunnel。域名可继续在阿里云等注册商续费；注册商不决定网页流量线路。将用于接入的子域名解析到实际服务器，若仍使用 Cloudflare DNS，使用仅 DNS 解析避免再次经其代理。

选择服务器时同时测量“手机到服务器”和“电脑到服务器”的线路、丢包与带宽。国内地域可能更适合国内访问，但不能保证某个云厂商或地域一定更快。阿里云中国内地服务器使用域名提供 Web 服务需要办理相应备案，地域及要求见[阿里云官方说明](https://help.aliyun.com/zh/ecs/cross-region-usage-faqs)。

## 管理员准备服务器

准备普通服务用户 `codex-relay`、Python 3.9+（建议 3.13）、公网域名和 HTTPS 反向代理。以下路径是示例，按实际部署调整；不要复制用户的 `.codex`、电脑私有数据或模型凭据到服务器。

将此分支源码放到 `/opt/codex-mobile-bridge`，在项目目录创建独立环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-relay.txt
```

前台运行（普通用户，不需要桌面会话）：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay serve --origin https://relay.example.com
```

数据目录必须可由服务用户读写，且不对其他用户开放。服务默认仅监听 `127.0.0.1:18790`。外部 HTTPS 代理须保留原始 Host，支持 WebSocket Upgrade，读取超时至少 120 秒，上传正文上限至少 20 MiB。关闭 API 缓存和写请求自动重试；不要把 `18790` 直接暴露到公网。域名、证书和服务器配置由管理员准备。

长期运行可使用 [systemd 服务模板](../deploy/relay/codex-bridge-relay.service)。先修改域名和项目路径、确认普通服务用户存在，再由管理员安装并启动服务。模板不安装系统软件，不要求 GUI。

无凭据健康检查：`GET /health`。响应只表示中继服务存活，不代表某位用户的电脑已在线。

## Web 管理后台（与中继共用端口）

终端与 Web 后台共用同一份邀请和设备记录。Web 后台由中继服务直接提供，不需要 Node.js、单独的前端进程或服务器 GUI。管理员使用自己电脑上的浏览器操作即可。

首次使用，以同一个服务用户在服务器终端生成独立管理密钥：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay admin-token
```

妥善保存返回的 `adminToken`，打开 **`https://relay.example.com/relay/admin/`**，粘贴密钥登录。该地址与手机入口、电脑连接共用同一域名和同一后端端口 `18790`；现有 HTTPS 代理把整个域名转发到该端口即可，无需为后台另开端口。它不是直接公开的 HTTP 管理端口。

在后台可以：

- 填写用户备注与有效期，生成邀请码，复制包含中继地址的接入信息，私下发给对应用户。
- 查看邀请码的可使用、已使用、已过期状态。完整邀请码只在生成时显示一次，刷新页面后无法找回。
- 查看电脑名称、归属备注、在线状态与注册时间，点击“刷新状态”取得最新状态。
- 确认后撤销电脑访问及其全部手机授权。在线连接会关闭；已提交给 Codex 的操作不会因此撤回。

未生成管理密钥时无法登录后台，仍可使用下方终端命令管理服务。管理密钥与用户邀请码、电脑令牌、手机登录相互独立，不要把管理密钥发给接入用户。

后台登录有效 8 小时，可以主动退出。再次运行 `admin-token` 会**轮换密钥并立即使全部已有管理登录失效**，无需重启服务；它不影响正常电脑、手机授权。密钥丢失或泄露时也用此命令恢复。

## 发放邀请码与管理设备

在服务器项目目录，以同一个服务用户执行：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay invite --owner alice --hours 24
```

把返回的 `invitation` 私下交给对应用户。每个邀请码只注册一台电脑，默认 24 小时过期。`owner` 是管理员的归属标签，无需绑定模型服务商。多台电脑分别发放邀请码。

查看已注册设备（不显示设备令牌）：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay devices
```

撤销某台电脑及它的全部手机授权：

```sh
.venv/bin/python -B -m relay --data-dir /var/lib/codex-bridge-relay revoke DEVICE_ID
```

撤销后新请求立即拒绝，既有设备连接在下一次维护检查时关闭（最多约 5 秒）。已经提交给 Codex 的操作不会因此撤回。

## 用户连接电脑与手机

1. 使用包含此分支功能的电脑客户端。源码运行需先安装 `requirements-relay.txt`。
2. 在 **网络访问 → 自建中继 · 内测** 填写管理员提供的 HTTPS 地址、邀请码和电脑名称，确认信任中继运营者后注册。
3. 在 **概览** 启动或重新启动网关，再回到共享中继中刷新，确认电脑在线。
4. 点击 **生成手机配对**，用手机浏览器或 v2 手机 App 打开二维码或链接。链接有效期为 5 分钟。
5. 手机填写名称并申请连接；在电脑端核对手机名称，点击 **批准**。
6. 手机进入原 v2 工作台，可以继续聊天、处理审批、查看文件、使用终端和 Git 等已授权操作。权限沿用电脑网关与原会话。

手机只绑定批准它的电脑。修改请求里的设备 ID 不能切换到其他电脑。每台电脑有独立入口 `/d/<电脑ID>/`；同一浏览器或手机 App 可以同时保存多台电脑，登录、草稿与通知偏好相互隔离。授权闲置有效期为 180 天，活跃访问自动续期；撤销或过期后仍需重新配对。旧版根路径连接继续兼容，建议用新二维码添加多电脑入口。

在电脑端可撤销单部手机、暂停中继或撤销整台电脑。暂停无需中继在线；已注册且正在运行的网关重新启用后会自动连接，首次注册仍需重启网关。撤销电脑注册需要中继可达，失败时本机仍会先暂停连接，随后可重试撤销。注册新中继前须先撤销旧注册。

## 临时地址变化后的恢复

自建中继也提供稳定地址查询入口。电脑注册并启用中继后，手机通过原地址成功登录一次，会记住与这次配对绑定的查询凭据。电脑发现临时隧道地址更新时，会通过现有出站连接更新入口；未变化时不重复发送。

之后手机打开旧地址失败，会向中继查询新地址。手机先发送不带 Cookie 的随机挑战，验证新入口持有原电脑配对身份，再迁移原有登录；不会根据返回的 URL 直接转交 Cookie，不会从 HTTPS 自动降级到 HTTP。撤销原手机登录后，新入口也无法通过该身份验证。浏览器直接收藏旧临时地址不能依靠已失效页面自行找回，建议收藏稳定的中继电脑入口。

此恢复需要新版电脑网关、手机 App 和已配置的稳定 HTTPS 中继共同工作，无法在所有已知入口都失效时凭空发现电脑。网关重建数据目录或用户撤销配对后需要重新扫码。进入后台会取消恢复，失败不会重发聊天、授权、停止或文件写入。正常页面不会因为地址查询被重新加载；发生入口切换时恢复原会话链接，并迁移仍可读取的草稿存储。

同一局域网仍可直接使用局域网地址；远程访问可直接保存中继入口，避开 Cloudflare 的可达性问题。此版本不会自动把 HTTPS 登录凭据降级迁移到局域网 HTTP 入口。国内蜂窝网络的实际质量取决于部署线路，需要用目标运营商验收。

## 内测范围

- 本机个人访问、已有 SSH 隧道等连接方式继续保留，不启用共享中继时不加载其网络依赖。
- 中继禁止手机管理模型账号、模型凭据、额度重置和全局通知服务配置。这些操作在电脑端完成。
- 网页使用 HTTP 轮询；终端和侧边聊天保留每部手机独立的会话归属。网关重启后临时终端/侧边聊天的归属会更新。
- 支持手机 App 已有的在线通知事件读取。共享中继暂未接入原生 APNs/FCM 注册或 Web Push；后台通知可继续使用电脑上的 Bark/ntfy 等已有通道。
- 上传请求及普通 JSON 响应最多 20 MiB；新版连接器的图片和文件下载使用二进制流，单块 64 KiB、最多 8 块待确认，不再要求整个文件装进一个响应帧。文件访问边界、点击下载阈值和 Range 校验仍由电脑执行；旧连接器保留 20 MiB 响应上限。静态脚本支持压缩和 ETag 校验，登录和 API 内容不缓存。
- 默认最多 200 台在线电脑、64 个同时转发请求、每台电脑 12 个同时请求和 16 部有效手机。它们是保护上限，**不是已通过压测的承载量**。
- 出现“操作结果待确认”时先检查原聊天或文件状态。中继不会自动重发断线期间的写请求。
- 注册和申领按连接来源限流。代理后可能共用来源额度，内测期间避免集中批量注册；不信任访客自行填写的转发 IP 头。

## 数据与恢复

服务器 SQLite 只保存邀请、设备、手机授权和管理登录元数据，不持久化聊天正文、模型密钥或原始设备/手机令牌。邀请码、管理密钥与登录令牌只保存摘要。电脑设备凭据存放在原 Bridge 数据目录的私有 `shared-relay.json`。

HTTPS/WSS 提供传输加密，**不是端到端加密**。中继运营者技术上能够读取转发内容，也处于远程控制的信任边界内；仅连接可信服务器。获准手机具有对应电脑网关允许的操作能力。

停服后备份整个私有数据目录，保留权限；不要只复制活跃 SQLite 主文件而漏掉 WAL。恢复同一域名和数据库后，电脑会重新连接。丢失数据库需重新发放邀请并配对；泄露时撤销相关设备并重新注册。
