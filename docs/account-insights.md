# 账户信息与 Codex Desktop 更新

## 查询与显示

- 查询过程中保留同一账号上次成功的额度、重置卡及更新时间，旁边显示“查询中”。失败时保留旧结果并提示未更新。
- 原生账号查询结束时清理对应任务的加载状态；配置变化后丢弃旧结果，恢复登录后可重新查询。新查询的状态与结果按任务隔离。
- 服务端按账号隔离缓存。后台每五分钟至多刷新一次，手动刷新可立即查询；界面倒计时不额外调用服务。
- 账号页面空闲时按五分钟缓存节奏更新；切换、登录与查询任务进行中，每两秒读取进度，任务结束后恢复低频更新。读取失败十秒后重试，成功后恢复缓存节奏。相同数据复用已有卡片，倒计时每分钟仅更新文字，隐藏页面只保留数据快照。
- 额度批次合并列表渲染，接入变化与重置确认的身份保护即时更新。离开账号页后结束剩余查询的派发，重新进入使用新的页面访问代次。
- 只读账号查询由专用凭据锁保护，网络等待位于账号管理锁和聊天操作门禁之外；返回前再次核验账号与切换状态。重置卡使用沿用即时身份核验、操作门禁和请求去重。
- Credits 余额与重置卡数量分别显示。上游未提供的数据不会显示成零。
- 官方账号订阅日期通过 ChatGPT 的账号权益接口在线查询，日期缺失或已过去时补查订阅接口。严格匹配账号 ID，不自动挑选其他工作区；不从 JWT 到期时间或旧登录记录推算订阅是否过期。接口受限或查询失败显示“订阅有效期暂未确认”，不影响额度和重置卡。日期表示查询到的周期截止日期，续订、取消与扣费状态以 ChatGPT 订阅页面为准。这些产品后端接口可能随上游变化。
- 每个已保存的 ChatGPT 账号均有“使用重置卡”入口，无需切换当前接入或重启 Codex。人工使用不依赖 Desktop 的代理用量重置开关；不会修改该开关。确认界面显示所选账号与卡片到期时间，等待五秒后才可使用。每次使用都要确认，服务端再次核对账号和卡片状态。结果不明时沿用原请求标识，避免重复消耗。API 接入不提供官方额度和重置操作。

## 提醒

在“第三方通知”（桌面端“消息通知”）中按用途分组开启提醒。重置动态卡片的铃铛保留快捷开关，与通知页同步：

| 提醒 | 触发条件 |
| --- | --- |
| 低额度 | 某额度窗口剩余不超过 10% |
| 额度恢复 | 查询确认窗口已更换且剩余额度增加，包含提前重置 |
| 重置卡到期 | 可用卡片距到期不足 24 小时 |
| 订阅周期 | 在线查询日期前 7、3、1 天；不判断是否续订或已经扣费 |
| 重置动态 | 官方重置预告与全局重置确认，统一开关 |
| Desktop 更新 | 已安装发布渠道出现更高的公开版本 |

使用电脑端“手机通知”中配置的 Bark、ntfy 或 PushPlus。默认全部关闭；未配置通道时不在后台查询账户。电脑睡眠、离线或网关退出时无法检查和发送，恢复运行后继续检查。相同账号、周期或卡片以及接收通道的提醒会去重。通知内容不包含账号邮箱和凭据。

API 或聚合接入下，原生登录的官方账号同样参与额度与到期提醒，查询共用账号卡片的五分钟缓存；已导入的同一账号按已保存账号统一检查。

提醒按账号所属身份（含工作区）去重。导入、删除或重新导入账号档案时，继续沿用同一份发送记录与额度恢复比较基线；已有记录自动合并，保留成功状态及失败重试间隔。

网页和手机通知页中的开关即时保存，失败时恢复已保存状态。高级设置中的网关名称与通知跳转地址由独立的“保存设置”按钮提交；切换开关保留这些填写草稿。推送通道的启用开关独立保存，服务地址和密钥仍通过“保存配置”提交。桌面端账号提醒独立于网关通用配置表单保存。

通知页打开时读取设置，保存后仅同步账号页铃铛对应的提醒字段；空闲时停止轮询。版本检查或更新窗口交接进行中，每两秒查询进度，结束、失败或离开页面后停止。其他设备的设置变化通过重新打开页面获取。健康的账号快照会清理读取错误并恢复更新进度轮询；保存错误保留到显式重试。推送网络请求位于账号管理锁之外，发送前复核提醒开关、监听起点与接收渠道。

## 原版 Codex Desktop 更新

版本与更新入口位于网页和手机的“应用管理 → Codex → 版本与更新”，以及桌面端“客户端与接入 → Codex”的独立更新卡片。新版本提醒开关归入通知页。这个入口管理原版 Codex Desktop，与 Bridge 自身的“应用更新”分开。

| 安装方式 | 当前行为 |
| --- | --- |
| macOS 可识别的公开安装渠道 | 读取安装元数据与对应公开 appcast；手机确认后请求打开该桌面进程的原生更新菜单 |
| Windows 可识别的商店安装 | 校验公开清单的产品和安装包身份；手机确认后打开对应 Microsoft Store 产品页 |
| 其他渠道或无法识别的安装 | 提示在电脑端或包管理器中检查；不猜测下载地址 |

公开版本比较不等于设备更新资格。灰度发布、组织策略、账号资格和安装确认由原生更新器或商店处理。查询失败不会显示“已是最新”。

“查看 Codex 新版本”只读取公开版本信息，不操作桌面菜单、不请求辅助功能权限。“打开电脑端更新窗口”针对原版 Codex Desktop。macOS 上将该应用切到前台，触发其“检查更新 / Check for Updates…”菜单，后续检查、下载与安装需要在电脑端由 Codex 自身处理；网关 App 使用独立的更新入口。Web 和手机端会直接显示这项限制。

发起入口前，需要确认所有桌面任务已经结束，包括未在网页显示的任务。网关还会拦截已知的运行任务、待确认操作和排队消息。免密访问不能发起桌面更新。

macOS 需要已运行的目标应用、解锁的桌面、控制 System Events 的自动化权限和辅助功能权限。网关按目标进程查找“检查更新”菜单，留出最多三分钟供系统授权与菜单响应。失败时会区分权限、超时、菜单缺失或不可用，并保留重试入口；每次重试仍须重新确认桌面任务已结束。授权已开启但系统仍拒绝时，可退出并重新打开网关后再试。

菜单操作成功后界面显示“等待电脑端确认”，安装仍由原生更新器决定。不会把打开菜单、打开商店或检查成功当成安装完成。当前不提供无人值守的远程下载与安装；检测到安装版本变化后会核验结果，仍不能把入口已打开视作更新完成。
