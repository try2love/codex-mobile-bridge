# 原生侧边聊天接入调研

调研日期：2026-10-07。初次调研为只读检查；后续经用户授权，使用用户手动创建的原生侧边聊天进行了真实收发与关闭实验。没有修改 Codex 安装包或启动替代模型进程。

## 本地接管实验

已实现工作台独立子标签：连接电脑端已打开的原生侧边聊天、读取回复、发送文本，以及断开手机连接。它不创建普通持久聊天，也不启动独立 app-server。

- 桌面快照必须同时满足 `ephemeral: true`、`sideConversation: true`、`forkedFromId` 等于当前主会话。实际验证取得了这些字段。
- 发送复用原桌面 owner 的 `thread-follower-start-turn`，使用 `inheritThreadSettings: true`，不覆盖模型、提供商、工作目录或权限。真实测试消息得到正常回复。
- 每次发送前取得新快照。用户在桌面关闭测试侧边聊天后，现有连接无法再取得快照，校验拒绝继续发送，不执行 `thread/resume`。
- 内容和发送去重状态只存在内存中；断开后清理。发送回复丢失时不自动重放。不活跃的手机连接在 5 分钟后释放 follower；这只是 Bridge 连接清理时间，不是原生聊天寿命。
- 确认、审批和结束原生临时聊天仍需在电脑端操作。手机关闭子标签只断开连接，不能宣称销毁了桌面聊天。

当前发现入口是 macOS 当日日志里最近的 `thread/inject_items` 路由记录，只提取候选 ID，再用实时快照确认所属主会话和临时性质。没有匹配日志时无法自动发现；该机制依赖当前桌面版本，尚不是跨平台稳定接口。同一主会话有多条侧边聊天时，连接最近发现且可用的一条。

用户选择了通过桌面 UI 创建的实验路线，但 Computer Use 工具明确禁止控制 Codex 自身。未使用其他自动化工具绕过限制，由用户手动创建和关闭完成验证。因此本次交付是**原生侧边聊天接管预览**，自动创建和远程销毁尚未实现。

## 结论

原生侧边聊天是当前会话的临时分支，具有上下文继承、独立执行和原生销毁状态。普通历史聊天并排展示不等价。

本机桌面实现中可以定位到完整创建与关闭链路，但 Bridge 现有 follower IPC 没有创建、销毁侧边聊天的方法。本机正在运行的 app-server 使用由桌面持有的标准输入输出通道，没有发现可复用的 Unix socket 监听端点。因此，知道底层方法名还不意味着 Bridge 可以直接调用当前桌面实例。

## 已核实的原生流程

1. **创建**：从当前会话调用桌面管理器的 `forkConversationFromLatest`。参数包含父会话、当前 host/cwd/协作模式，并设置 `ephemeral: true`、`sideConversation: true` 和父导航路径。
2. **继承上下文**：管理器发送 `thread/fork`。临时分支使用 `ephemeral: true`；侧边聊天还使用 `excludeTurns: true`，避免把继承的主聊天历史作为新标签的展示内容返回。它并不表示模型没有继承父上下文。
3. **建立边界**：桌面使用 `thread/inject_items` 注入侧边会话边界，并添加专门的指令，明确继承历史仅为参考、等待侧边聊天的新问题。不能把主聊天旧任务当作需要继续执行的指令。原生文案偏向轻量探索，但不能把文案当作强制权限隔离。
4. **显示与发送**：以独立侧边标签显示，沿用该子会话的桌面管理器、模型、接入和审批状态；不能启动一个替代 owner 去恢复主会话。
5. **关闭**：桌面先在需要时中断子会话运行，再经 `discardConversationFromCache` 丢弃状态。本机普通 host 路径调用 `thread/unsubscribe`；临时会话在 durable host 的路径调用 `thread/stop`。还会清理关联的临时语音历史与标签记录。
6. **失效**：应消费桌面的卸载、关闭、找不到会话等状态，并禁用输入；不能静默恢复为持久聊天。当前构建包含约 3 小时的非活跃 owner 卸载检查，但有活跃视图、follower、运行或待处理请求时逻辑不同。这不是侧边聊天统一的绝对寿命，也不能硬编码为产品保证。退出桌面、断开 owner 等情况也可能让临时会话不可恢复。

原生关闭 UI 会提示临时聊天关闭后无法恢复。接入后的手机与 Web 也应保持这一语义。

## 可选接入路线

| 路线 | 与原生的关系 | 目前结论 |
| --- | --- | --- |
| 通过桌面受支持的管理器入口创建、发送、销毁 | 可真正保持同一桌面 owner、标签状态与失效行为 | 最符合要求；当前 follower IPC 未提供创建/销毁入口，需要找到或获得桌面扩展能力 |
| 连接已运行 app-server 的共享 transport | 可以复用该引擎；还必须同步桌面侧边标签元数据及生命周期 | 官方协议支持 Unix socket/WebSocket，但当前桌面实例没有暴露这些监听端点；不能直接接管它的 stdio |
| Bridge 单独启动 app-server，创建 ephemeral fork | 可以实现相似的临时聊天语义 | 属于 Bridge 自己管理的临时分支，不是桌面原生侧边聊天；模型接入、权限、实时父上下文和过期策略都需另行验证 |
| 修改桌面包或调试器注入内部调用 | 可能触达当前内部管理器 | 强依赖具体版本，影响签名及更新，并扩大控制面；本轮未实施，不适合默认产品接入 |
| 自动操作桌面 UI | 可以操作真实原生功能 | 依赖前台、辅助功能权限和界面结构，难以作为无人值守网关能力 |

## 建议与验证门槛

优先争取通过受支持的桌面入口接入原生管理器。在此入口确认前，不把独立 app-server 或普通聊天包装成“原生侧边聊天”。如后续决定接受 Bridge 管理的临时分支，应单独标明这一产品差异。

任何接入方案都应先用合成会话验证：

- 父会话运行、草稿、owner、模型接入、cwd 和权限保持不变；
- 子会话继承上下文，但不会自动续做历史任务；
- 创建响应丢失、重试和关闭过程中不产生孤儿会话或重复发送；
- 关闭后不出现在历史列表，不自动恢复；
- 原生失效后客户端停止发送，不自行延长或重建；
- 审批请求在正确子会话处理；
- 网关重启、桌面退出和 SSH 断开时的状态一致。

## 依据

- [Codex App Server 官方文档](https://developers.openai.com/codex/app-server)：`thread/fork`、`ephemeral`、`thread/unsubscribe` 以及 stdio/Unix socket/WebSocket transport。
- [当前 App Server 生命周期说明](https://learn.chatgpt.com/docs/app-server#unsubscribe-from-a-loaded-thread)：最后一个订阅者取消订阅后，连续 30 分钟没有订阅者和会话活动才卸载。这与桌面自己的非活跃 owner 清理不是同一个计时器，不应硬编码成侧边聊天的统一寿命。
- [Codex 桌面功能官方文档](https://developers.openai.com/codex/app/features)。公开页面未提供可直接从 Bridge 调用的原生侧边聊天 API。
- 本机桌面构建的创建、丢弃和非活跃会话清理逻辑，以及当前进程的只读 transport 检查。上述内部符号和条件是当前版本的观测，不视为稳定公开 API。
