# Windows ChatGPT 与 WSL Codex

同一个 Windows 网关可以分别接入 ChatGPT 内的 Codex/Work 和 WSL 终端里的 Codex。**Codex** 与 **WSL Codex** 是应用管理中的独立应用，历史、草稿、附件、操作记录与接入说明分别保存。其他电脑接入不属于本轮实现。

## 连接 WSL

1. 在 WSL 中安装支持原生共享服务的 Codex，并配置好原有接入。首次发现仍需让发行版运行，扫描并登记一次。
2. 使用更新后的网关，在网页或手机打开 **应用管理 → 扫描 WSL 应用**；桌面控制面板的 **重新扫描并接入** 也会发现 WSL。
3. 核对 **WSL Codex · 发行版 · 用户**，打开它的应用开关。
4. 点击 **查看聊天**，或者从底部应用图标切换。此明确动作会连接已有服务，必要时启动已安装的原生共享服务；已登记的发行版停止时也可由这一步唤醒。Codex 只显示原桌面及其 SSH 聊天，WSL Codex 只显示该 WSL 环境的聊天。
5. 从手机直接点击 **新建**，选择 WSL 已有工作目录或独立聊天；打开历史聊天会恢复同一个线程，不需要在原终端打开。

已有版本登记的 WSL 入口直接显示为独立应用，继续使用原来的身份、启用状态和数据目录，不需要重新登记。多个已发现的 WSL 配置目录各自对应一项 WSL Codex 应用。聊天顶部不再显示入口下拉框及连接/关闭按钮；应用显示偏好与底部切换沿用现有应用功能。

扫描只检查正在运行的发行版，不安装 Codex、不启动新的执行器，也不自动启用发现的入口。每次执行 WSL 辅助请求前重新核验发行版身份；被动请求不会唤醒停止的发行版。只有用户明确打开已登记应用、创建或恢复聊天，才允许启动它。

当前扫描发现的是发行版默认用户的 Codex 目录，以及该用户正在运行的共享服务使用的自定义 `CODEX_HOME`。不会把 Windows 的配置和环境变量当成 WSL 的配置。与桌面共用同一已识别数据目录的入口不能重复登记。

**历史读取和会话恢复分开。** 列表、历史读取、后台刷新不恢复线程。用户打开历史聊天或点击重新连接时，通过原生 `thread/resume` 恢复同一线程，再核验工作目录、提供商、身份和直接输入能力。发送也会重新核验当前状态，不把展示缓存当作授权。

没有共享服务时，只在用户明确操作后调用已安装 Codex 的 `app-server daemon start`，不执行 restart/update/bootstrap，不另外创建竞争的执行器。不支持共享服务的旧版本、已有独立执行器或另一个配置目录占用服务时会明确报错；不会为了连接而结束原 CLI 或迁移账号。经同用户扩展路径、参数及 VS Code 父进程核验的独立 stdio app-server 可以共存；来源不明的 vscode 历史不作为终端聊天恢复。

用户打开或操作线程时，Bridge 通过同一服务的原生订阅接收实时事件和审批。订阅不传入模型、认证、提供商、目录或权限覆盖。后台读取不调用线程恢复或启动接口。

## Magpie

- Windows 与 WSL 分别读取各自的接入。查看 WSL 接入时不会显示或切换 Windows 的账号。
- 检测到 Magpie 配置时启用外部管理保护。也可在 Bridge 桌面端的账号面板选择 **由 Magpie 等外部工具管理**。
- Bridge 不将该接入自动转换为 `bridge_api`，不替换认证，不移除 Magpie 提供商和模型目录。
- 模型列表由对应 Codex 原生运行时读取，保留 Magpie 的模型和路由组 ID。查询失败不会切回官方或改模型。
- 接入切换继续在 Magpie 或原 WSL 环境完成。聊天中的模型设置只作用于允许修改的原线程，不重写全局提供商。
- 如果切换或恢复期间发现外部配置变化，保留现场并阻止覆盖恢复。

检测到历史保留的 Magpie 配置表时也会保守地保护配置，避免破坏依赖该提供商的旧聊天。接入管理模式不是“强制覆盖外部配置”的开关。

## 本轮能力

| 能力 | WSL 入口 |
| --- | --- |
| 发现、搜索、归档历史展示、按入口筛选 | 支持 |
| 当前已加载线程的发送、补充、停止 | 支持；操作前重新读取原生状态 |
| 手机恢复未加载的历史线程 | 支持；明确打开时恢复同一线程，保留原接入 |
| 原线程模型与推理强度设置 | 支持；不改变提供商、认证、工作目录或权限 |
| 原生审批及结构化问题 | 支持原请求允许的范围；过期或旧连接请求不能再次授权 |
| 工作区文件、Git、附件上传与预览、下载 | 通过 WSL 中的共享文件边界实现 |
| 后台通知、网关排队、独立终端、侧边聊天、Goal、计划/权限模式切换、Skill 选择 | 本轮禁用，避免套用桌面专用接口 |
| 从手机新建 WSL 聊天 | 支持；独立目录或服务器验证过的已有 WSL 工作目录，不需要桌面或 TUI 接管 |

关闭 WSL Codex 的应用开关只关闭 Bridge 自己的连接，不退出 Codex、不停止原任务。此应用不提供“退出电脑 App”或强制结束；需要退出 CLI 时在原终端操作。Windows Codex 的开关不会阻止单独启用的 WSL 应用读取或操作自己的聊天。断线期间可能已提交的写入保留为结果待核对，不自动重发。

模型列表通过共享的目录规范化逻辑转换原生 `model` / `id`、`displayName` 和推理能力字段。页面始终获得非空名称，缺少名称时显示原模型 ID；Magpie 的 `group/...` ID 保持原样。不会把原生目录对象直接当作页面模型选项，避免空白下拉列表。

本机实测组合是 WSL 2 / Ubuntu-22.04、CLI 0.162.1 和共享服务 0.163.0。其他版本按实际能力判断，不能把目录存在视为控制能力验证通过。详细证据与测试边界见[验证记录](architecture/windows-wsl-validation.md)。

新建请求按 WSL 应用及 UUID 保存结果，原生返回 ID 后立即落盘；不确定结果不会再次执行 thread/start。手机创建的 originator 为 codex_mobile_bridge_wsl，只进入该 WSL 应用的列表，不混入 Windows Codex。此实现不包含无桌面 Ubuntu 的纯 CLI 部署。


## 指定项目目录与旧版会话

新建聊天时选择“指定目录 / 新建项目”，点击“浏览并选择目录”。目录浏览器从对应主机的主目录开始，支持进入子文件夹、返回上一级、选择磁盘和显示隐藏目录。可选择“使用当前目录”；也可输入一个新文件夹名称，在当前目录中新建并进入，再选用它。无需手写完整路径。不会初始化 Git 或覆盖已有文件。目录先在对应系统中验证并登记在网关自己的数据中，创建线程前再次核对目录身份；手机不直接把任意 cwd 传给 thread/start。Windows 与已登记 SSH 主机采用同样的流程，各主机路径分别解析。

WSL 兼容旧版网关的 `codex_mobile_bridge` 来源，新版的 `codex_mobile_bridge_wsl` 继续可见；来源兼容用于已登记 WSL 的根会话，子代理与 exec 不会出现在聊天列表。聊天列表每批 100 条，底部“加载更多聊天”可显式翻页，也保留滚动自动续载和名称/目录搜索。

终端会话还会只读索引 history.jsonl：未命名会话优先显示最近的终端输入，并支持搜索后续输入。明确设置过的名称优先；原数据库标题与原始聊天记录不被改写。搜索匹配在分页前完成，仍沿用来源、归档和子代理过滤。
