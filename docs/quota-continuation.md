# 额度恢复后自动继续

## 开关与同步

网页和手机 App 主页、桌面网关“概览”提供“额度恢复后自动继续”总开关，默认关闭。待继续任务清单提供“排除自动继续”选项，可单独排除某条聊天。设置保存在当前网关，所有直连设备共用；可见页面每 10 秒同步，也会在重新进入前台时刷新。各电脑网关独立保存；聊天排除记录跨重启保留，取消排除后仍需重新通过全部继续条件。

开启后检查默认 Codex Desktop 中所有项目、所有未归档的桌面聊天，包括普通任务与原生目标模式。网关约每四分钟发现会话，原生 owner 提供任务状态；存在额度中断任务时约每分钟查询个人额度。手机或浏览器关闭不影响后台工作，电脑、Codex App 和网关须保持运行。

## 继续条件与手动停止

只有原生任务明确报告额度耗尽才登记等待；确认当前账号的个人额度可用后发送一次继续指令，不要求先轮询到零额度。普通任务发送“额度已恢复。请从中断处继续完成之前的任务，先检查已有进度，避免重复已完成的操作。”；原生目标从 `usageLimited` 恢复为 `active`，沿用现有目标激活通道。模型、工作目录、审批与执行 owner 沿用原会话。

发送前通过新的原生订阅即时核验 owner、最后一轮、目标身份、空闲状态、待回答请求、归档状态、当前账号和额度。已完成、手动停止、暂停、取消、预算耗尽、普通网络错误、一般 HTTP 429 和未确认的限流均不触发。已手动开始新一轮的聊天不再符合旧等待记录。

通过 Bridge 手动停止或确认暂停/取消目标时，持久化对应轮次的停止意图。此记录不随重启或开关重新开启清除；在原 Codex App 直接手动停止的任务，以原生 `interrupted` 状态排除。关闭总开关清除尚未尝试的等待记录；重新开启会重新检查当前仍因额度中断的任务。

额度错误可能表现为 `threadRuntimeStatus.type = systemError`、最后一轮 `failed` 和错误码 `usageLimitExceeded`。协议读取接受 `systemError`，但普通系统错误不能触发继续；默认生命周期空闲核验也仍拒绝该状态，只有额度专用预检在取得明确额度证据、核对预期轮次后才允许继续。

## 故障和防重放

等待记录按账号配置、owner、聊天、轮次和目标身份隔离。发送前连接、原生状态或额度查询暂时失败时保持等待并重试。只读核验全部通过后，在首次写入前持久化不可重放标记；实际写入超时、断连或重启后不会自动重放结果未知的操作。请到原聊天和发送管理核对结果。

主页固定显示待继续、已继续、结果待确认的数量，包括零值，并显示上次检查时间和待处理聊天清单。排除只阻止尚未派发的继续，不能撤回已经交给原客户端的操作。存在原生同步结构不兼容时显示错误，不因其他聊天连接正常而隐藏。

自动继续指令不能保证模型不会重复工作，原有审批要求继续生效。此功能独立于通知通道，不需要配置 Bark、ntfy 或 PushPlus；不自动切换账号或使用重置卡。

## 支持范围

- 支持默认配置、官方 ChatGPT 账号、已有原生 owner 可读取的本机 Codex Desktop 会话；其他项目不需要先在手机打开。
- 自动继续暂不覆盖 CLI、IDE、SSH、WSL、独立配置和其他客户端。
- 继续依据为明确的原生额度中断及即时个人额度，不依据第三方重置动态、预计时间或过期缓存。
- 存在通用 `codex` 额度桶时只核验其窗口；无法区分时保守核验全部已报告窗口。

## 与额度展示的关系

[通用额度展示](quota-display.md)采用共享的小环、额度池和窗口详情，独立于自动继续开关。展示缓存不能授权自动继续；后者仍通过本页所述的即时个人额度与原生任务核验。

## 验证边界

回归用合成原生状态和只读额度响应覆盖错过零额度、手动停止、账号变化、发送前临时故障、重启防重放、`systemError` 兼容以及 Bridge 发送通道。浏览器检查覆盖共享额度详情、刷新和宽窄布局。测试不使用真实任务耗尽额度；真实额度耗尽后自动恢复、Android/iOS 真机和其他操作系统仍需进一步验收。
