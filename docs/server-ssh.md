# 固定域名 · 自有服务器 + SSH

自己的服务器提供 HTTPS 入口，电脑主动建立 SSH 反向隧道。手机请求经过服务器回到电脑网关，Codex 仍在电脑上运行。

**手机 → 服务器 HTTPS → 服务器 `127.0.0.1:18787` → SSH 隧道 → 电脑网关 `127.0.0.1:8787` → Codex App**

本文使用普通用户 `try2love` 和 `https://codex.try2love.com` 举例，仅用于配置演示，不代表可访问的演示站点。请替换为自己的账号和域名；示例端口也须与 App 中的设置一致。

**管理员操作由你或服务器管理员手动完成。App 不接收 sudo 密码，不安装服务器软件，不修改服务器配置或防火墙。** App 负责 SSH 登录检查、维持转发连接，以及检测 HTTPS 入口。准备服务器只需首次完成，日常连接不需要 sudo。

## 1. 手动准备域名与公网入口

“手机访问地址”可填写完整 HTTPS 域名，也可留空。使用域名时，需要自行将域名解析到服务器公网 IP，并配置该域名的 HTTPS 证书与反向代理；App 不会自动绑定域名。

**留空使用公网 IP：** SSH 的“服务器地址”（使用别名时为 SSH 配置中的 `HostName`）必须填写公网 IPv4 或 IPv6；保存启用的配置后，App 自动填入 `https://公网IP`，IPv6 自动加方括号。不会解析域名来猜测公网 IP；使用主机名或内网地址时，应填写已经配置好的完整 HTTPS 访问地址。

公网 IP 入口仍需服务器配置 HTTPS 反向代理，以及受手机和电脑信任、且 Subject Alternative Name 包含该 IP 的有效证书。域名证书、未受信任的自签名证书不能代替；网关不会绕过证书验证或降级为 HTTP。IP 方案无需域名 DNS，手机访问 443，SSH 回环转发仍为 `127.0.0.1:18787`。导出的 IP 配置参考要求用户自行在服务器提供证书和私钥并安排续期，不会生成或收集证书私钥。

以下 DNS 与 Caddy 自动申请域名证书步骤适用于**域名入口**；IP 入口优先复用已有代理及 IP 证书，或使用 App 导出的 IP 专用配置参考。仅有 SSH 账号不能自动得到可用的 HTTPS 入口。

在域名 DNS 管理中，将 `codex.try2love.com` 的 A 记录指向服务器公网 IPv4。只有服务器具备可用的公网 IPv6 时才设置 AAAA 记录。使用下方 Caddy 默认自动 HTTPS 方案时，先使用直接指向服务器的 DNS 记录。

在服务器防火墙和云平台安全组中配置：

| 端口 | 用途 | 访问范围 |
| --- | --- | --- |
| SSH 端口，通常为 22 | 电脑主动登录服务器 | 允许电脑所在网络访问 |
| TCP 80 / 443 | 证书验证、HTTP 跳转与 HTTPS 访问 | 手机及证书服务可达 |
| 18787 | 服务器反向代理连接 SSH 隧道 | 仅服务器回环地址，不向公网开放 |

电脑不需要公网 IP 或路由器端口转发，但必须能连接服务器的 SSH 端口。仅能通过校园网、VPN 或跳板登录服务器，不代表手机能从公网访问它。

## 2. 手动准备普通 SSH 用户与转发权限

选择一个普通 SSH 用户，例如 `try2love`，使用该用户的密码、私钥或 SSH Agent。在终端确认这个账号能够登录。无需为日常隧道授予 sudo 权限，也无需让普通账号加入 Docker 管理组。

若 SSH 转发被禁用，请让管理员核对 SSH 服务端配置。可以参考以下针对普通用户的配置片段；管理员须结合现有规则放到适当位置，不能直接覆盖整个配置文件：

```text
Match User try2love
    AllowTcpForwarding remote
    GatewayPorts no
    PermitListen 127.0.0.1:18787
Match all
```

`PermitListen` 中的端口应与 App 的“服务器回环端口”一致；`GatewayPorts no` 将转发入口限制在服务器内部。管理员还需核对其他 Match 规则、`DisableForwarding` 和公钥条目的限制，避免规则冲突。

管理员修改后应先使用 `sudo sshd -t` 检查配置，并按服务器系统的服务管理方式重新加载 SSH；保留已有终端，确认新连接正常后再退出。服务名随系统而异，App 不执行这些操作。参考 [OpenSSH 官方配置说明](https://man.openbsd.org/sshd_config#AllowTcpForwarding)。

## 3. 手动配置 HTTPS 反向代理

### 已有网站或反向代理

在现有 Caddy、Nginx 或面板中添加独立域名站点，反向代理上游填写：

```text
http://127.0.0.1:18787
```

保留原始域名的 `Host` 请求头，关闭响应缓存及流式响应缓冲。不要覆盖已有站点，也不要为新入口停止原有网站。证书由现有反向代理管理。

### 尚未安装 HTTPS 服务

可由管理员按 [Caddy 官方安装教程](https://caddyserver.com/docs/install) 手动安装。以下以官方 Linux systemd 服务为例。

管理员打开现有配置：

```sh
sudoedit /etc/caddy/Caddyfile
```

保留已有站点，添加这个独立站点块：

```caddyfile
codex.try2love.com {
    reverse_proxy 127.0.0.1:18787 {
        header_up Host {http.request.host}
        flush_interval -1
    }
}
```

管理员验证配置，成功后再重新加载服务：

```sh
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
```

如果验证失败，先修正错误，不执行重新加载。服务尚未运行时，按官方安装与服务教程检查启动状态。DNS 和网络满足条件后，Caddy 会自动申请、续期 HTTPS 证书。此时电脑隧道尚未连接，访问域名可能显示 502，接下来启动连接即可。

App 的“导出手动配置参考”还提供 Caddy 配置与可选 Docker Compose 文件。导出和复制只生成参考内容，不会运行其中命令；Docker 安装、容器启动及所有管理员操作都由用户手动完成。

如需服务器内部的 Agent 协助判断现状，在 App 点击“复制服务器检查 Prompt”。它包含 HTTPS 地址、端口及普通用户信息，要求 Agent 只读检查已有服务、端口和权限，不运行 sudo、不安装或修改服务；权限不足的项目标为未验证。复制本身不会连接服务器。

## 4. 在 App 保存配置并检查 SSH 登录

在“网络与登录”添加“固定域名 · 自有服务器 + SSH”，填写：

- 手机访问地址：自己的完整 HTTPS 地址，例如 `https://codex.try2love.com`；留空则从 SSH 配置中的公网 IP 自动填入 HTTPS 地址，证书要求见第 1 节。
- SSH 认证方式：账号密码、本地私钥、SSH Agent 或已有 SSH 别名。
- 服务器地址、SSH 端口与普通用户名：使用前面已确认可登录的账号。
- 服务器回环端口：默认为 `18787`，须与反向代理及转发权限设置一致。

保存配置，再点击“检查 SSH 登录”；尚未启用的配置也可检查，准备好后再勾选启用并保存。首次连接需要与服务器控制台或管理员提供的主机指纹核对。

**检查通过只代表账号可以登录。** App 不执行远端命令；DNS 检查只判断域名能否解析，不确认它是否指向正确服务器。SSH 转发权限、证书和手机公网访问需要下一步验证。

## 5. 启动连接并检测固定入口

点击“启动 SSH 连接”，App 会启动电脑网关和所有已启用的连接。电脑主动建立到服务器的 SSH 隧道，服务器内部端口的请求沿隧道转发到电脑网关。

查看 SSH 状态，然后点击“检测固定入口”。检测会比较本机与 HTTPS 地址返回的网关实例，确认域名确实连接到当前网关。检测失败不会触发服务器安装或修改配置。

最后关闭手机 Wi-Fi，使用蜂窝网络访问自己的域名，验证登录、聊天读取、发送和回复同步。

## 6. 日常使用与排查

首次配置完成后，日常只需启动网关。隧道断开时 App 会重试连接；停止网关会关闭隧道，服务器上的 HTTPS 服务仍保留。电脑、网关与 Codex App 需要保持在线，电脑关机或休眠时无法继续访问聊天。

| 现象 | 检查位置 |
| --- | --- |
| SSH 登录失败 | 地址、SSH 端口、用户名、认证方式、主机指纹和网络 |
| 登录通过但转发失败 | 管理员检查 SSH 转发权限、回环端口占用及公钥限制 |
| 找不到域名或证书错误 | DNS 是否指向正确服务器、80/443 是否可达、证书是否就绪 |
| HTTPS 显示 502 | 隧道是否连通；反向代理上游端口与 App 配置是否一致 |
| 检测提示入口不属于当前网关 | 域名站点或反向代理是否指向其他服务 |
| 电脑能访问，手机打不开 | 用手机蜂窝网络检查公网访问；电脑上的验证不能替代手机验证 |
