# Windows / WSL 与 Magpie 验证记录

日期：2026-10-16。范围：本机双入口与 Magpie 共存；没有实现其他电脑的注册或聚合。

## 实现位置

- `bridge/features/endpoints/registry.py`：只通过明确扫描结果登记入口，保存独立身份，管理启用和连接生命周期。
- `bridge/features/endpoints/wsl.py`：会话读取、当前执行器核验、写入记录、审批和工作区操作。
- `bridge/clients/codex/shared_server.py`：受限原生 RPC 与 WebSocket 帧；连接现有服务，不启动 Codex。
- `bridge/platforms/windows/wsl.py`：运行中发行版枚举、同用户进程及套接字发现、字节中转与文件通道。内核 peer PID/UID 与配置目录须匹配。
- Codex 配置识别、账号保护和模型目录读取分别沿用 `configuration.py`、账号功能与目录模块。

`wsl:<摘要>` 是网关入口路由，不是原生 `hostId`。桌面 IPC 的原有 `hostId + conversationId + ownerClientId` 未替换；WSL 使用发行版、用户、规范化配置目录、已核验 daemon、连接世代与线程 ID 绑定。

## 真实环境只读检查

实际发现 CLI 0.162.1 使用既有的共享服务 0.163.0。桌面长度帧 IPC 能初始化，但不能找到这些 CLI 线程的 owner；共享服务的 Unix WebSocket 则可读取其已加载线程。

首次实现时的只读检查读到 2 个已加载线程，所检查线程可直接输入，提供商为 `magpie`，原生模型目录返回 69 个模型。数量只是检查时的快照，不是固定容量或准确率指标。

该检查经新的 Windows → WSL 通道运行，登记信息仅保存在 `.tmp` 的独立网关数据目录。记录的原生调用中没有 `thread/start`、`thread/resume`、`turn/start` 或设置/配置写入；检查前后真实 `config.toml`、`auth.json` 摘要和原 daemon PID 均一致。没有向真实用户聊天发送消息、审批、停止或测试模型请求。

另在 WSL 内对当前配置的 Magpie 地址进行了无凭据 TCP 连通性检查，端口可达。这不代表已验证真实上游模型回复或路由组中的每个成员。

## 隔离的真实运行时检查

`scripts/smoke-wsl-shared-server.py --codex <明确指定的 Linux Codex 程序>` 使用全新的私有 `CODEX_HOME`、独立 app-server 和 localhost 模拟模型，不使用真实 Magpie 或账号。

确认以下行为：

1. 原连接创建并执行合成线程，第二个连接继续该线程；原连接收到完成事件。
2. 相同提交 ID 重试只执行一次。
3. 仅第二个连接发送消息不能收到审批；明确订阅同一已加载线程后可收到。实现因此只在用户打开/操作时订阅，不在被动读取时恢复线程。
4. 原请求只提供 `accept`、策略修改对象和 `cancel` 时，不擅自提供 `decline` 或持久授权；使用实际提供的取消操作，原线程停止，测试命令未执行。
5. 停止请求作用于原线程的当前轮次。
6. Bridge 连接关闭后，已运行的合成任务继续并由原连接收到完成结果。
7. 测试配置逐字节不变，没有生成认证文件，全部模型请求只发往合成本机服务。

Unix 套接字需位于 Linux 自己的临时目录；Windows 挂载盘不支持绑定它。其他测试数据保存在项目 `.tmp`。测试仅清理自己启动的服务和中转进程，不发送信号给用户 daemon 或 CLI。

另以隔离 `.tmp` 工作区实测 Windows → WSL 文件元数据、二进制下载、图片附件上传和本机预览；父目录越界请求被拒绝。此测试未写入真实项目或 Codex 数据目录。

## WSL 独立应用与模型列表修复

模型白屏由数据格式不匹配引起：原生 `model/list` 使用 `model` / `displayName`，原 WSL 返回原对象，页面却要求 `id` / `name`。现统一调用 `Catalog.normalize_models`，保留 `group/...` ID、原生名称、默认及可选推理强度；名称缺失时显示模型 ID。

## 2026-10-19 会话显示、历史输入搜索和目录浏览器

定位到两种“找不到聊天”：旧版 codex_mobile_bridge 根来源被 WSL 筛选漏掉；未命名的终端聊天在 SQLite 中仍保留首次问题作为 title，但终端 resume 使用的标签来自 history.jsonl 中后续输入。现兼容旧来源，并只读索引终端输入以支持搜索和生成 display_title；明确自定义 name 优先。来源、归档及子代理限制继续在搜索和分页之前生效，不重写原数据库、历史输入或 rollout。

新建项目改用对应执行主机的目录浏览器，支持主目录、上一级、磁盘/文件系统、隐藏文件夹、选择当前目录、在当前目录新建并进入。仅列目录，不读取文件内容。新建时核对父目录身份；登记目录和创建线程仍再次验证 canonical cwd 与目录身份。浏览/新建接口只允许已登记应用和主机，保留登录、Origin、CSRF、应用启用检查。

定向检查：Node 569 项通过；WSL 27、创建/目录 17、HTTP 80、资源 5、平台依赖 4，共 133 项后端检查，132 通过、1 因 Windows 符号链接权限跳过。Edge 执行 30 项断言，实际 viewport 492 与 1280 px，包含显式翻页、进入文件夹、新建并进入、选用目录及新建线程。原生隔离运行时七组检查通过，目录浏览器选择后真实 thread/start 的 cwd 与目录一致，没有因此发送模型请求。真实上游回复及 Android WebView 仍不作为本轮实机验收。
