# 宽窄布局

这一层只根据可用尺寸组织页面。浏览器、Android、iOS 的宿主身份和原生菜单由 `web/hosts/` 管理；原生 App 也可以使用宽屏分屏，电脑浏览器也可以进入窄屏布局。

| 布局 | 修改入口 | 当前行为 |
| --- | --- | --- |
| Wide：默认并排 | `wide/` | 左侧会话列表 310px，右侧使用剩余空间；作为默认结构，在窄屏和中等宽度下由后续规则覆盖。 |
| Compact：不超过 720px | `compact/` | 会话列表与聊天切换显示，调整聊天头部、输入区及客户端会话布局。 |
| Medium：展开手机与较小平板 | `medium/` | 会话进入后给工作台完整页面宽度；保留原有 721–1099px 工作台规则与 721–1100px 客户端导航规则。 |
| 工作台分屏 | `viewport.js`、`../features/workspace/workbench.js` | 使用聊天容器的实际宽度；达到 720px 才能分屏，与 App 宿主或设备名称无关。 |

`viewport.js` 的 `BridgeLayout` 还提供窄屏媒体查询和触摸指针查询。终端输入保留“原生壳或触摸设备或窄屏”的组合条件；命令终端保留按 `innerWidth` 判断回车发送的行为。不要以 `bridge-mobile` 推断屏幕宽度。

文件、Git、终端等功能内部的响应式控件样式仍跟随对应功能 CSS；本目录负责页面级布局，不复制整套聊天界面。

## CSS 顺序

`web/assets.json` 为原有 CSS URL 定义有序源文件数组。HTTP 与中继按该顺序拼接返回，浏览器仍请求原来的地址；不需要生成文件，也不增加样式请求。

同一张样式表中，基础规则、宽窄布局规则、原生宿主规则的相对顺序必须保留。部分基础和宿主样式因此分为头部、内容、输入、导航等片段。不要把所有布局文件或宿主文件集中挪到最后；同样的选择器会因级联顺序而改变效果。

增加或移动片段时同步清单并运行 `npm run test:desktop`。尺寸行为需要真实浏览器检查，至少覆盖 390px 竖屏、844px 横屏和 1440px 宽屏，验证草稿、已打开标签、滚动位置和分屏偏好在调整宽度时保持。
